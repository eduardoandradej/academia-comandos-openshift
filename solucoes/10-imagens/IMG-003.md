# Gabarito IMG-003 — Configuração da imagem antes de rodar: usuário, portas, volumes

> Consulte só depois de tentar. Enunciado: [trilhas/10-imagens/exercicios/IMG-003.md](../../trilhas/10-imagens/exercicios/IMG-003.md)

## Desafio sem pista — uma solução possível

```bash
for img in registry.access.redhat.com/ubi9/httpd-24:latest registry.access.redhat.com/ubi9/ubi-minimal:latest docker.io/library/nginx:latest; do
  oc image info "$img" --filter-by-os=linux/amd64 -o json 2>/dev/null | jq -r --arg i "$img" '.config.config |
    "\($i)\tporta<1024=\([(.ExposedPorts // {}) | keys[] | split("/")[0] | tonumber | select(. < 1024)] | length > 0)\troot=\((.User // "") | IN("","0","root"))\tvolumes=\((.Volumes // {}) | keys | join(","))"'
done
```

`User` vazio significa root na imagem — no OpenShift o UID será arbitrário, então a imagem precisa permitir escrita
ao grupo 0 nos diretórios que usa.

## Diagnóstico controlado — explicação

Portas abaixo de 1024 exigem privilégio; o OpenShift não o concede por padrão.
