# Gabarito IMG-011 — Políticas de imagem do cluster: registries permitidos e espelhos

> Consulte só depois de tentar. Enunciado: [trilhas/10-imagens/exercicios/IMG-011.md](../../trilhas/10-imagens/exercicios/IMG-011.md)

## Desafio sem pista — uma solução possível

```bash
regra() {
  local reg=${1%%/*} src
  src=$(KUBECONFIG="$HOME/.kube/ac-admin.kubeconfig" oc get image.config.openshift.io cluster -o jsonpath='{.spec.registrySources}')
  src=${src:-'{}'}
  if jq -e --arg r "$reg" '(.blockedRegistries // []) | index($r)' <<<"$src" >/dev/null; then echo "$reg: bloqueado"
  elif jq -e --arg r "$reg" '(.allowedRegistries // []) | index($r)' <<<"$src" >/dev/null; then echo "$reg: permitido"
  elif jq -e '.allowedRegistries' <<<"$src" >/dev/null; then echo "$reg: fora da lista de permitidos (rejeitado)"
  else echo "$reg: sem regra"; fi
}
regra registry.access.redhat.com/ubi9/httpd-24:latest
```

## Diagnóstico controlado — explicação

A política é aplicada pelo runtime do nó (via `machine-config`), por isso a rejeição aparece como erro de pull.
