# Gabarito IMG-015 — Circuito de imagens e encerramento da trilha

> Consulte só depois de tentar. Enunciado: [trilhas/10-imagens/exercicios/IMG-015.md](../../trilhas/10-imagens/exercicios/IMG-015.md)

## Desafio sem pista — uma solução possível

```bash
oc image info registry.access.redhat.com/ubi9/httpd-24:latest -o json | jq -r .digest                                                    # 1
oc image info registry.access.redhat.com/ubi9/httpd-24:latest -o json | jq -c '.config.config | {User, ExposedPorts}'                   # 2
oc get pod <pod> -o jsonpath='{.status.containerStatuses[0].imageID}'                               # 3
oc run t4 --image=registry.access.redhat.com/ubi9/ubi-minimal:9.9-x --image-pull-policy=Never                                               # 4
oc create imagestream ac10-web; oc import-image ac10-web:v1 --from=registry.access.redhat.com/ubi9/httpd-24:latest --confirm             # 5
oc tag ac10-web:v1 ac10-web:prod                                                                    # 6
oc tag --alias ac10-web:v1 ac10-web:atual                                                           # 7
oc set image-lookup ac10-web; oc create deployment ac10-app --image=ac10-web:prod                   # 8
oc set triggers deployment/ac10-app --from-image=ac10-web:prod --containers=<contêiner>             # 9
oc tag registry.access.redhat.com/ubi9/ubi-minimal:latest ac10-web:auto --scheduled; oc tag -d ac10-web:auto                                # 10
oc get configs.imageregistry.operator.openshift.io cluster -o jsonpath='{.spec.managementState}'  # 11 (admin)
oc get image.config.openshift.io cluster -o jsonpath='{.spec.registrySources}'                    # 12 (admin)
oc image extract registry.access.redhat.com/ubi9/httpd-24:latest --path /etc/httpd/conf/httpd.conf:/tmp/ac10 --confirm                   # 13
oc new-app --image-stream=ac10-web:prod --name=ac10-novo                                            # 14
# 15: roteiro do IMG-014
```

## Diagnóstico controlado — explicação

Arquivos locais e cache do nó não são removidos pelo `safe-cleanup.sh`, que só atua em objetos rotulados do projeto.
