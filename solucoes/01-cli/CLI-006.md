# Gabarito CLI-006 — Anatomia do kubeconfig sem revelar segredos

> Consulte só depois de tentar. Enunciado: [trilhas/01-cli/exercicios/CLI-006.md](../../trilhas/01-cli/exercicios/CLI-006.md)

## Desafio sem pista — uma solução possível

```bash
oc config view -o jsonpath='{range .contexts[*]}{.name}{" | "}{.context.cluster}{" | "}{.context.user}{" | "}{.context.namespace}{"\n"}{end}'
```

O jsonpath mostra o **nome** do cluster de cada contexto; o servidor desse nome está em
`oc config view -o jsonpath='{range .clusters[*]}{.name}{" "}{.cluster.server}{"\n"}{end}'`.
Uma versão `jq` correta, que resolve o servidor por contexto:

```bash
oc config view -o json | jq -r '.clusters as $c | .contexts[]
  | . as $ctx | ($c[] | select(.name == $ctx.context.cluster) | .cluster.server) as $srv
  | "\($ctx.name) | \($srv) | \($ctx.context.user) | \($ctx.context.namespace // "-")"'
```

## Diagnóstico controlado — explicação

Sem `current-context` válido, `--minify` não sabe o que recortar (hipótese a ou b). `oc config get-contexts` vazio
indica arquivo vazio/inexistente.
