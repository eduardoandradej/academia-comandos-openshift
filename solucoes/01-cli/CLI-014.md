# Gabarito CLI-014 — Diagnóstico de conexão: DNS, TLS e porta

> Consulte só depois de tentar. Enunciado: [trilhas/01-cli/exercicios/CLI-014.md](../../trilhas/01-cli/exercicios/CLI-014.md)

## Desafio sem pista — uma solução possível

```bash
H=api.ocp.example.lab; P=6443
getent ahostsv4 "$H" >/dev/null || { echo "falha: DNS"; exit 1; }
timeout 3 bash -c "</dev/tcp/$H/$P" 2>/dev/null || { echo "falha: TCP"; exit 1; }
curl -sS --cacert ~/.kube/ocp-sno-ca.crt -o /dev/null "https://$H:$P/readyz" 2>/dev/null || { echo "falha: TLS (ou CA ausente)"; exit 1; }
[ "$(curl -ksS -o /dev/null -w '%{http_code}' "https://$H:$P/readyz")" = 200 ] || { echo "falha: HTTP"; exit 1; }
oc whoami >/dev/null 2>&1 || { echo "falha: autenticação"; exit 1; }; echo "todas as camadas OK"
```

Rode em um subshell (`bash roteiro.sh`) para que o `exit` não feche o seu terminal.

## Diagnóstico controlado — explicação

`i/o timeout` (sem resposta) difere de `connection refused` (resposta negativa imediata): timeout sugere host/rota
indisponível (a/b); refused sugere host vivo sem serviço na porta (c).
