# Gabarito CLI-013 — oc e kubectl: equivalências e diferenças

> Consulte só depois de tentar. Enunciado: [trilhas/01-cli/exercicios/CLI-013.md](../../trilhas/01-cli/exercicios/CLI-013.md)

## Desafio sem pista — uma solução possível

- `oc new-project`: no `kubectl`, `kubectl create namespace` costuma ser negado ao developer; o equivalente é criar
  um objeto `ProjectRequest` (`apiVersion: project.openshift.io/v1`, `kind: ProjectRequest`) com `kubectl create -f`.
- `oc login`: não há equivalente no `kubectl`; seria preciso obter um token pelo fluxo OAuth (por exemplo, na Console
  em "Copy login command") e gravá-lo com `kubectl config set-credentials` — o que expõe o token na linha de comando.

Tabela: identidade `oc whoami` / `kubectl auth whoami` · autenticar `oc login` / não existe · criar projeto
`oc new-project` / ProjectRequest via `create -f` · alternar `oc project` / `kubectl config set-context --current
--namespace=` · pods com IP `oc get pods -o wide` / igual · logs `oc logs deploy/x` / igual · documentação `oc explain`
/ `kubectl explain` · expor Route `oc expose svc/x` / criar o objeto Route via YAML.

## Diagnóstico controlado — explicação

`login` só existe no `oc`, porque depende do servidor OAuth do OpenShift.
