# Gabarito KUS-003 — Geradores: ConfigMaps e Secrets com hash

> Consulte só depois de tentar. Enunciado: [trilhas/13-kustomize/exercicios/KUS-003.md](../../trilhas/13-kustomize/exercicios/KUS-003.md)

## Desafio sem pista — uma solução possível

```bash
atual=$(oc get deployment ac13-loja -n ac13-kustomize -o jsonpath='{.spec.template.spec.volumes[0].configMap.name}')
mapfile -t todos < <(oc get cm -n ac13-kustomize -o json | jq -r '.items[] | select(.metadata.name|startswith("ac13-pagina-")) | "\(.metadata.creationTimestamp) \(.metadata.name)"' | sort -r | awk '{print $2}')
manter=("$atual"); for c in "${todos[@]}"; do [ "$c" != "$atual" ] && { manter+=("$c"); break; }; done
for c in "${todos[@]}"; do [[ " ${manter[*]} " == *" $c "* ]] || oc delete cm "$c" -n ac13-kustomize; done
oc get cm -n ac13-kustomize | grep ac13-pagina
```

Alternativa declarativa: `oc apply -k ... --prune -l app.kubernetes.io/part-of=ac13-loja --prune-allowlist=core/v1/ConfigMap`
(DCL-012) — mas o prune apaga **todas** as versões antigas, inclusive a de `rollout undo`.

## Diagnóstico controlado — explicação

O hash é o que liga "conteúdo mudou" a "template mudou"; sem ele, a mudança não gera rollout.
