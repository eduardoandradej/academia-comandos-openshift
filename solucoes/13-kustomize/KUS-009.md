# Gabarito KUS-009 — Ciclo completo com Kustomize: diff, apply e prune de versões antigas

> Consulte só depois de tentar. Enunciado: [trilhas/13-kustomize/exercicios/KUS-009.md](../../trilhas/13-kustomize/exercicios/KUS-009.md)

## Desafio sem pista — uma solução possível

```bash
atual=$(oc get deployment ac13-loja -n ac13-dev -o jsonpath='{.spec.template.spec.volumes[0].configMap.name}')
anterior=$(oc get rs -n ac13-dev -l app=ac13-loja -o json | jq -r --arg a "$atual" '[.items[] | select(.spec.replicas==0)
  | {t: .metadata.creationTimestamp, cm: .spec.template.spec.volumes[0].configMap.name} | select(.cm != $a)] | sort_by(.t) | last.cm // ""')
oc label cm "$atual" ${anterior:+"$anterior"} -n ac13-dev academy.openshift.dev/manter=sim --overwrite
oc delete cm -n ac13-dev -l 'app.kubernetes.io/part-of=ac13-loja,academy.openshift.dev/manter!=sim' --dry-run=client
oc delete cm -n ac13-dev -l 'app.kubernetes.io/part-of=ac13-loja,academy.openshift.dev/manter!=sim'
oc label cm -n ac13-dev -l academy.openshift.dev/manter=sim academy.openshift.dev/manter-
```

O ReplicaSet anterior (réplicas 0) guarda o template antigo e, nele, o nome do ConfigMap de que o `undo` precisaria.

## Diagnóstico controlado — explicação

`rollout undo` restaura o template, não os objetos referenciados por ele.
