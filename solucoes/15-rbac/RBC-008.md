# Gabarito RBC-008 — Service accounts: identidade dos pods e tokens de curta duração

> Consulte só depois de tentar. Enunciado: [trilhas/15-rbac/exercicios/RBC-008.md](../../trilhas/15-rbac/exercicios/RBC-008.md)

## Desafio sem pista — uma solução possível

```bash
T=$(oc create token ac15-robo -n ac15-rbac --duration=10m)
exp=$(cut -d. -f2 <<<"$T" | tr '_-' '/+' | base64 -d 2>/dev/null | jq -r .exp)
date -d "@$exp"
oc --token="$T" whoami                       # funciona agora
unset T
# depois do horário exibido: repetir com o mesmo token daria Unauthorized (guarde-o só na sessão, nunca em disco)
```

A parte do meio de um JWT são as reivindicações em base64url; ler `exp`/`sub` não expõe a assinatura, mas o token
inteiro continua sendo segredo até expirar.

## Diagnóstico controlado — explicação

Tokens emitidos por `oc create token` têm prazo e estão ligados ao UID da SA; recriar a SA invalida os antigos.
