# Gabarito RBC-010 — Auditoria de acesso a um projeto

> Consulte só depois de tentar. Enunciado: [trilhas/15-rbac/exercicios/RBC-010.md](../../trilhas/15-rbac/exercicios/RBC-010.md)

## Desafio sem pista — uma solução possível

```bash
acoes=("get pods" "get secrets" "create pods/exec" "create deployments" "create rolebindings")
printf '%-14s' sujeito; for a in "${acoes[@]}"; do printf '| %-19s' "$a"; done; echo
for s in developer ac15-leitor ac15-robo; do
  printf '%-14s' "$s"
  for a in "${acoes[@]}"; do
    if [ "$s" = developer ]; then r=$(oc auth can-i $a -n ac15-rbac -q && echo ✔ || echo ✘)
    else r=$(oc auth can-i $a -n ac15-rbac --as=system:serviceaccount:ac15-rbac:"$s" -q && echo ✔ || echo ✘); fi
    printf '| %-19s' "$r"
  done; echo
done
```

## Diagnóstico controlado — explicação

`who-can` é uma revisão de acesso feita pelo servidor; ela própria é uma ação autorizada por RBAC.
