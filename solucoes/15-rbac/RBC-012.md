# Gabarito RBC-012 — SCC e RBAC: por que o pod não roda como root

> Consulte só depois de tentar. Enunciado: [trilhas/15-rbac/exercicios/RBC-012.md](../../trilhas/15-rbac/exercicios/RBC-012.md)

## Desafio sem pista — uma solução possível

```bash
oc run ac15-root --image=registry.access.redhat.com/ubi9/httpd-24:latest --overrides='{"spec":{"securityContext":{"runAsUser":0}}}' \
  --dry-run=client -o yaml > /tmp/ac15-root.yaml
oc adm policy scc-subject-review -f /tmp/ac15-root.yaml -n ac15-rbac
oc adm policy scc-review -f /tmp/ac15-root.yaml -n ac15-rbac
rm -f /tmp/ac15-root.yaml
```

`scc-subject-review` responde pela identidade atual (e `-z` para uma SA); `scc-review` diz quais SAs do projeto
poderiam rodar o pod. Nenhum dos dois cria o pod.

## Diagnóstico controlado — explicação

A SCC é escolhida na admissão; sem uma SCC permitida que aceite o pod, ele nem é criado.
