## Desafio sem pista — uma solução possível

```bash
cert() {
  local h=$1 c
  c=$(openssl s_client -connect 192.168.10.200:443 -servername "$h" </dev/null 2>/dev/null | openssl x509) || { echo "$h: sem certificado"; return 1; }
  local cn emissor san fim dias
  cn=$(openssl x509 -noout -subject <<<"$c" | sed 's/.*CN *= *//')
  emissor=$(openssl x509 -noout -issuer <<<"$c" | sed 's/.*CN *= *//')
  san=$(openssl x509 -noout -ext subjectAltName <<<"$c" | tail -1 | tr -d ' ')
  fim=$(openssl x509 -noout -enddate <<<"$c" | cut -d= -f2); dias=$(( ($(date -d "$fim" +%s) - $(date +%s)) / 86400 ))
  echo "$h | CN=$cn | emissor=$emissor | $san | expira em $dias dias"
}
cert console-openshift-console.apps.ocp.example.lab
```

## Diagnóstico controlado — explicação

O cliente valida a cadeia contra as CAs em que confia; uma CA privada precisa ser informada.
