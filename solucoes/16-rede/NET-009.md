# Gabarito NET-009 — Saída só para quem precisa

> Consulte só depois de tentar. Enunciado: [trilhas/16-rede/exercicios/NET-009.md](../../trilhas/16-rede/exercicios/NET-009.md)

## Desafio sem pista — uma solução possível

```bash
ips=$(getent ahostsv4 registry.access.redhat.com | awk '{print $1}' | sort -u)
blocos=$(for i in $ips; do printf '        - ipBlock: {cidr: %s/32}\n' "$i"; done)
cat <<EOF | oc apply -n ac16-rede -f -
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: ac16-registry, labels: {academy.openshift.dev/managed-by: academia}}
spec:
  podSelector: {matchLabels: {app: ac16-cliente}}
  policyTypes: [Egress]
  egress:
    - to:
$blocos
      ports: [{protocol: TCP, port: 443}]
EOF
oc exec ac16-local -n ac16-rede -- timeout 5 bash -c '</dev/tcp/registry.access.redhat.com/443' && echo "registry ok"
```

Frágil porque o registry usa CDN: os IPs mudam e variam por região. Para destinos por nome, o caminho é o
EgressFirewall (`dnsName`), que é objeto do admin.

## Diagnóstico controlado — explicação

NetworkPolicy é avaliada nos dois pods: saída na origem e entrada no destino.
