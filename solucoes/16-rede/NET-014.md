# Gabarito NET-014 — Roteiro de diagnóstico de conectividade

> Consulte só depois de tentar. Enunciado: [trilhas/16-rede/exercicios/NET-014.md](../../trilhas/16-rede/exercicios/NET-014.md)

## Desafio sem pista — uma solução possível

```bash
diag_con() {
  local o=$1 on=$2 s=$3 dn=$4 p=${5:-8080}
  printf '1 DNS: '; oc exec "$o" -n "$on" -- getent hosts "$s.$dn.svc" >/dev/null 2>&1 && echo ok || echo FALHOU
  printf '2 endpoints prontos: %s\n' "$(oc get endpointslices -n "$dn" -l kubernetes.io/service-name="$s" -o jsonpath='{.items[*].endpoints[*].conditions.ready}')"
  printf '3 políticas de saída em %s: %s\n' "$on" "$(oc get networkpolicy -n "$on" -o json | jq -r '[.items[] | select(.spec.policyTypes | index("Egress")) | .metadata.name] | join(",") | if .=="" then "nenhuma" else . end')"
  printf '4 políticas de entrada em %s: %s\n' "$dn" "$(oc get networkpolicy -n "$dn" -o json | jq -r '[.items[] | select(.spec.policyTypes | index("Ingress")) | .metadata.name] | join(",") | if .=="" then "nenhuma" else . end')"
  printf 'teste: %s\n' "$(t "$o" "$on" "$s.$dn.svc" "$p")"
}
diag_con ac16-intruso ac16-vizinho web-azul ac16-rede
```

## Diagnóstico controlado — explicação

Com políticas de entrada, pacotes não permitidos são descartados antes de chegar ao processo: o cliente só vê timeout.
