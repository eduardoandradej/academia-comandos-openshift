# Gabarito TS-004 — KUBECONFIG apontando para o vazio

> Cenário: [cenarios/troubleshooting/TS-004.md](../../cenarios/troubleshooting/TS-004.md)

## Causa

Hipótese 1: sem configuração, o cliente não sabe qual servidor usar e cai em um padrão local (`localhost:8080`) ou recusa a configuração incompleta, conforme a versão.

## Passos que confirmam

`ls -l /tmp/nao-existe` → arquivo inexistente; `oc config get-contexts` vazio. A correção é apontar para o perfil
existente (`source scripts/perfis.sh && ac-dev`) ou refazer o ORI-004.

## Lição para a ficha de revisão

`localhost:8080` na mensagem quase sempre significa "não há kubeconfig válido", não "a API mudou de endereço".
