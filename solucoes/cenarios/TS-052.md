# Gabarito TS-052 — failed quota: must specify — o pod sem resources

> Cenário: [cenarios/troubleshooting/TS-052.md](../../cenarios/troubleshooting/TS-052.md)

## Causa

Hipótese 1: uso zero (descarta 2); o erro é de admissão, não `Forbidden` de RBAC (descarta 3).

## Passos que confirmam

A quota precisa somar os valores que limita; sem eles no pod, ela recusa. Duas correções:

```bash
oc apply -f manifests/admin/limitrange-completo.yaml -n ac17-ts052        # padrões para todos os pods
oc run x --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-ts052
oc get pod x -n ac17-ts052 -o jsonpath='{.spec.containers[0].resources}{"\n"}'
```

Ou declarar `resources` em cada workload. Remover a quota "para destravar" desfaz a proteção do SNO.

## Lição para a ficha de revisão

Quota de computação sem LimitRange com padrões obriga todo pod a declarar recursos.
