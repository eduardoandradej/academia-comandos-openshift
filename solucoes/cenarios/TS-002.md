# Gabarito TS-002 — A API "sumiu": no such host, refused ou timeout?

> Cenário: [cenarios/troubleshooting/TS-002.md](../../cenarios/troubleshooting/TS-002.md)

## Causa

`no such host` = DNS (1); `connection refused` = TCP respondeu negando (2); `i/o timeout` = nenhuma resposta (3).

## Passos que confirmam

O `getent` falha só no caso 1. O teste `/dev/tcp` falha imediatamente no 2 e demora até o timeout no 3. No cenário real
de `refused` logo após ligar o SNO, `/readyz` volta a responder em alguns minutos.

## Lição para a ficha de revisão

Diagnostique de baixo para cima: DNS → TCP → TLS → HTTP → autenticação.
