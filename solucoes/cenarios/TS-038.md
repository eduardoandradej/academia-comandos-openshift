# Gabarito TS-038 — O apply desfaz a escala (e briga com o HPA)

> Cenário: [cenarios/troubleshooting/TS-038.md](../../cenarios/troubleshooting/TS-038.md)

## Causa

Hipótese 1: o campo declarado vence mudanças feitas fora do arquivo.

## Passos que confirmam

O arquivo e o last-applied têm `replicas: 1`; o apply reimpõe o valor (regra 2 do merge de três vias). Correção em
dois passos, para não cair para 1 no primeiro apply:

```bash
sed -i '/^  replicas: 1$/d' /tmp/ac12/app.yaml
oc apply set-last-applied -f /tmp/ac12/app.yaml -n ac12-declarativo     # last-applied deixa de ter replicas
oc scale deployment/ac12-web --replicas=2 -n ac12-declarativo
oc apply -f /tmp/ac12/app.yaml -n ac12-declarativo
oc get deployment ac12-web -n ac12-declarativo -o jsonpath='{.spec.replicas}{"\n"}'   # 2
```

Com server-side apply, o equivalente é deixar o campo sem dono do pipeline (o HPA passa a ser o gerenciador).

## Lição para a ficha de revisão

Quem escala não pode ser o manifesto: com HPA, retire `replicas` do arquivo.
