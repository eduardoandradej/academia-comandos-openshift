# Gabarito TS-039 — Conflito de server-side apply entre duas ferramentas

> Cenário: [cenarios/troubleshooting/TS-039.md](../../cenarios/troubleshooting/TS-039.md)

## Causa

Hipótese 1: o campo `data.log` tem dono (`pipeline-a`) e o servidor protege a intenção dele.

## Passos que confirmam

O conflito é a proteção funcionando: sem ele, as duas automações trocariam o valor a cada execução. Opções, da melhor
para a pior:

1. **Dividir os campos:** cada pipeline declara só os seus (`pipeline-a`: `cache`; `pipeline-b`: `log`), e o
   `pipeline-a` retira `log` do arquivo dele.
2. **Transferir a posse:** `pipeline-b` usa `--force-conflicts` **uma vez**, combinado com o dono, e o `pipeline-a`
   deixa de declarar `log` (senão ele forçará de volta).
3. `--force-conflicts` permanente nas duas: briga eterna, valor oscilando.

```bash
oc create configmap ac12-flags --from-literal=log=debug --dry-run=client -o yaml \
  | oc apply --server-side --field-manager=pipeline-b --force-conflicts -f - -n ac12-declarativo
```

## Lição para a ficha de revisão

Conflito de SSA é uma pergunta sobre posse: responda com combinação, não com força.
