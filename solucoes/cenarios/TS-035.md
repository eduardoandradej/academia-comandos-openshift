# Gabarito TS-035 — HPA com TARGETS `<unknown>`

> Cenário: [cenarios/troubleshooting/TS-035.md](../../cenarios/troubleshooting/TS-035.md)

## Causa

Hipótese 1 (na maioria dos casos): `missing request for cpu`. Se `oc adm top` também falha, é a hipótese 2.

## Passos que confirmam

A condição `ScalingActive=False` com `FailedGetResourceMetric` e a mensagem `missing request for cpu in container`
apontam para a hipótese 1; `oc adm top pods` listando o pod descarta a 2; `scaleTargetRef` correto descarta a 3.

```bash
oc set resources deployment/ac11-sem-req --requests=cpu=50m,memory=64Mi --limits=cpu=100m,memory=128Mi -n ac11-resiliencia
oc rollout status deployment/ac11-sem-req -n ac11-resiliencia
sleep 60; oc get hpa ac11-sem-req -n ac11-resiliencia      # TARGETS com porcentagem
```

Observação: se o LimitRange do projeto preencher um request padrão (50m), o `<unknown>` dura só até os pods novos
terem métricas — confira os requests **do pod**, não só do template.

## Lição para a ficha de revisão

Porcentagem de CPU no HPA é relativa ao request: sem request, não há alvo.
