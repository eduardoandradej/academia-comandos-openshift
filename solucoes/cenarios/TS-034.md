# Gabarito TS-034 — Reinícios em série: a liveness que mata o que está saudável

> Cenário: [cenarios/troubleshooting/TS-034.md](../../cenarios/troubleshooting/TS-034.md)

## Causa

Hipótese 1: o comando leva 2 s e o `timeoutSeconds` é 1, com `failureThreshold: 1`.

## Passos que confirmam

Os eventos dizem `Liveness probe failed: command timed out`; `lastState.terminated` mostra término por sinal (não
`OOMKilled`, descarta 3); a aplicação responde entre reinícios (descarta 2). Correção mínima, mantendo a proteção:

```bash
oc patch deployment ac11-agressivo -n ac11-resiliencia --type=json -p '[
 {"op":"replace","path":"/spec/template/spec/containers/0/livenessProbe","value":{"tcpSocket":{"port":8080},"periodSeconds":10,"timeoutSeconds":3,"failureThreshold":3}}]'
oc rollout status deployment/ac11-agressivo -n ac11-resiliencia
```

Liveness deve ser barata, local e mais tolerante que a readiness.

## Lição para a ficha de revisão

Uma probe mal calibrada é uma falha que você mesmo instalou: meça antes de fixar timeouts.
