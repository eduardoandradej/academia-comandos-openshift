# Gabarito TS-051 — A política liberou demais: o OR escondido na lista from

> Cenário: [cenarios/troubleshooting/TS-051.md](../../cenarios/troubleshooting/TS-051.md)

## Causa

Hipótese 1: dois itens em `from` = "qualquer pod do `ac16-vizinho`" OU "pod `app=ac16-cliente` do próprio projeto".

## Passos que confirmam

O `jq` mostra **dois** objetos na lista `from`. Só há a negação e esta política (descarta 2); o intruso tem
`app=intruso` (descarta 3). Correção: os dois seletores no mesmo item:

```bash
oc delete networkpolicy ac16-ts051 -n ac16-rede
oc apply -f manifests/networkpolicies/20-permitir-cliente-vizinho.yaml -n ac16-rede
oc exec ac16-intruso -n ac16-vizinho -- timeout 3 bash -c '</dev/tcp/web-azul.ac16-rede.svc/8080' || echo "intruso bloqueado"
```

## Lição para a ficha de revisão

Em `from`/`to`, cada `-` é uma alternativa; condições que precisam valer juntas ficam no mesmo item.
