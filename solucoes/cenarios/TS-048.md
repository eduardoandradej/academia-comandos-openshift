# Gabarito TS-048 — O binding para o grupo existe, mas o acesso não

> Cenário: [cenarios/troubleshooting/TS-048.md](../../cenarios/troubleshooting/TS-048.md)

## Causa

Hipótese 1: o binding aponta para `ac15-equipes`, que não existe; nada avisou.

## Passos que confirmam

O grupo real tem `developer` (descarta 2) e o binding está no projeto certo (descarta 3), mas o sujeito é
`Group:ac15-equipes`. Bindings não validam a existência do sujeito. Correção:

```bash
oc policy remove-role-from-group edit ac15-equipes -n ac15-alheio
oc policy add-role-to-group edit ac15-equipe -n ac15-alheio
oc auth can-i create deployments -n ac15-alheio --as=developer     # yes
```

Em auditorias, procure sujeitos de bindings que não correspondem a nenhum grupo/SA existente.

## Lição para a ficha de revisão

A API aceita bindings para nomes inexistentes: confira o nome do sujeito, não só a existência do binding.
