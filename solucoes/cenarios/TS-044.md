# Gabarito TS-044 — invalid ownership metadata: o objeto que o Helm não assume

> Cenário: [cenarios/troubleshooting/TS-044.md](../../cenarios/troubleshooting/TS-044.md)

## Causa

Hipótese 1: o ConfigMap não tem `app.kubernetes.io/managed-by=Helm` nem `meta.helm.sh/release-*`.

## Passos que confirmam

Sem marcas de dono (descarta 2, que mostraria outro `release-name`) e com `create` permitido (descarta 3), as opções são:

1. **Outro nome de release** (`helm install vitrine2 ...`): nada é tocado.
2. **Remover** o objeto, se for descartável, e instalar.
3. **Adotar**: acrescentar rótulo e anotações de dono e instalar — o conteúdo manual será substituído pelo do chart:

```bash
oc label configmap vitrine-pagina -n ac14-helm app.kubernetes.io/managed-by=Helm --overwrite
oc annotate configmap vitrine-pagina -n ac14-helm meta.helm.sh/release-name=vitrine meta.helm.sh/release-namespace=ac14-helm --overwrite
helm install vitrine /tmp/ac14/ac14-loja -n ac14-helm --set route.enabled=false
```

## Lição para a ficha de revisão

O Helm não toma objetos alheios sem consentimento explícito: as marcas de dono são esse consentimento.
