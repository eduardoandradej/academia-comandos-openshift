# Gabarito HLM-007 — Escrever modelos: if, with, range, default, required

> Consulte só depois de tentar. Enunciado: [trilhas/14-helm/exercicios/HLM-007.md](../../trilhas/14-helm/exercicios/HLM-007.md)

## Desafio sem pista — uma solução possível

```bash
cat > /tmp/ac14/ac14-loja/templates/extra.yaml <<'EOF'
{{- if .Values.extra.habilitado }}
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "ac14-loja.fullname" . }}-extra
  labels:
    {{- include "ac14-loja.labels" . | nindent 4 }}
data:
  {{- range $k, $v := .Values.extra.dados }}
  {{ $k }}: {{ $v | quote }}
  {{- end }}
{{- end }}
EOF
printf 'extra:\n  habilitado: false\n  dados: {}\n' >> /tmp/ac14/ac14-loja/values.yaml
helm template loja /tmp/ac14/ac14-loja --set equipe=x --show-only templates/extra.yaml 2>&1 | head -2       # nenhum objeto
helm template loja /tmp/ac14/ac14-loja --set equipe=x --set extra.habilitado=true --set extra.dados.cor=azul --show-only templates/extra.yaml
```

Se o schema (`values.schema.json`) não declarar `extra`, ele é aceito (o schema não proíbe chaves extras).

## Diagnóstico controlado — explicação

Os modelos produzem texto; o YAML só é verificado depois, por isso a indentação é a causa mais comum de erro.
