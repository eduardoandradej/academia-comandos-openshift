# Gabarito DIA-008 — Caso 06: depois do endurecimento, nada fala com nada

> Consulte só depois de tentar. Enunciado: [trilhas/19-troubleshooting/exercicios/DIA-008.md](../../trilhas/19-troubleshooting/exercicios/DIA-008.md)

## Desafio sem pista — uma solução possível

Defeitos: a política `ac19-c6-trava-tudo` nega **entrada e saída**. A `mesmo-projeto` libera só a **entrada** vinda
do projeto; faltam: (1) saída para o DNS; (2) saída para os pods do projeto; (3) entrada vinda do router.

```bash
oc apply -f manifests/networkpolicies/50-permitir-dns.yaml -n ac19-rede
cat <<'EOF' | oc apply -n ac19-rede -f -
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: ac19-c6-saida-interna, labels: {academy.openshift.dev/managed-by: academia}}
spec:
  podSelector: {}
  policyTypes: [Egress]
  egress:
    - to: [{podSelector: {}}]
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: ac19-c6-router, labels: {academy.openshift.dev/managed-by: academia}}
spec:
  podSelector: {matchLabels: {app: ac19-c6}}
  policyTypes: [Ingress]
  ingress:
    - from: [{namespaceSelector: {matchLabels: {policy-group.network.openshift.io/ingress: ""}}}]
      ports: [{protocol: TCP, port: 8080}]
EOF
oc exec ac19-cli -n ac19-casos -- timeout 3 bash -c '</dev/tcp/ac19-c6.ac19-rede.svc/8080' || echo "outro projeto: bloqueado (correto)"
```

Três políticas: DNS, saída interna e router. Não dá para reaproveitar a `30-permitir-router.yaml` da Trilha 16:
ela seleciona `app=loja` — reaproveitar manifesto sem ler o seletor é outro defeito comum.

## Diagnóstico controlado — explicação

Negar saída sem liberar o DNS faz todo nome falhar; o sintoma parece "o serviço sumiu".
