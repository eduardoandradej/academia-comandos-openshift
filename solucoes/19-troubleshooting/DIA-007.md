# Gabarito DIA-007 — Caso 05: o robô de escala recebe Forbidden

> Consulte só depois de tentar. Enunciado: [trilhas/19-troubleshooting/exercicios/DIA-007.md](../../trilhas/19-troubleshooting/exercicios/DIA-007.md)

## Desafio sem pista — uma solução possível

Defeitos: (1) o RoleBinding cita a SA `ac19-c5-robot` (com `t`), que não existe; (2) a Role usa `apiGroups: [""]`
(core) para `deployments`, que são do grupo `apps`.

```bash
cat <<'EOF' | oc apply -n ac19-casos -f -
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: {name: ac19-c5-escalador, labels: {academy.openshift.dev/managed-by: academia}}
rules:
  - apiGroups: ["apps"]
    resources: ["deployments"]
    verbs: ["get"]
  - apiGroups: ["apps"]
    resources: ["deployments/scale"]
    verbs: ["get", "update", "patch"]
EOF
oc delete rolebinding ac19-c5-escalador -n ac19-casos      # roleRef não muda, mas aqui o sujeito muda: recriar fica explícito
oc create rolebinding ac19-c5-escalador --role=ac19-c5-escalador --serviceaccount=ac19-casos:ac19-c5-robo -n ac19-casos
S=system:serviceaccount:ac19-casos:ac19-c5-robo
oc auth can-i update deployments/scale -n ac19-casos --as=$S; oc auth can-i delete deployments -n ac19-casos --as=$S
oc scale deployment/ac19-c5 --replicas=2 -n ac19-casos --as=$S
```

## Diagnóstico controlado — explicação

A mensagem Forbidden mostra o grupo de API pedido (`apps`); a regra precisa citar o mesmo grupo.
