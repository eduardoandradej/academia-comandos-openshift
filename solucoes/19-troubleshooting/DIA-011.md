# Gabarito DIA-011 — Caso 09: aplicações que reiniciam ou somem

> Consulte só depois de tentar. Enunciado: [trilhas/19-troubleshooting/exercicios/DIA-011.md](../../trilhas/19-troubleshooting/exercicios/DIA-011.md)

## Desafio sem pista — uma solução possível

Defeitos: (1) `ac19-c9` com `limits.memory: 20Mi` — o httpd passa disso ao iniciar: **OOMKilled** (contêiner
reiniciado, mesmo pod); (2) `ac19-c9-cache` grava 24 MiB em um `emptyDir` de `sizeLimit: 8Mi`: **Evicted** (pod
inteiro substituído pelo ReplicaSet, e o novo também é despejado).

```bash
oc set resources deployment/ac19-c9 --requests=memory=48Mi --limits=memory=128Mi -n ac19-casos
oc patch deployment ac19-c9-cache -n ac19-casos --type=json -p '[{"op":"replace","path":"/spec/template/spec/volumes/0/emptyDir/sizeLimit","value":"32Mi"}]'
oc rollout status deployment/ac19-c9 -n ac19-casos; oc rollout status deployment/ac19-c9-cache -n ac19-casos
oc delete pods -n ac19-casos --field-selector=status.phase=Failed
oc exec deploy/ac19-c9 -n ac19-casos -- cat /sys/fs/cgroup/memory.current     # a medição que justifica o novo limite
```

## Diagnóstico controlado — explicação

OOMKill é do kernel, por contêiner; despejo é do kubelet, pelo pod inteiro.
