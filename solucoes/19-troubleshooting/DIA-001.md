## Desafio sem pista — uma solução possível

```bash
andares() {
  local d=$1 ns=${2:-ac19-casos} sel svc
  echo "1 sessão: $(oc whoami)@$(oc project -q)"
  oc get deployment "$d" -n "$ns" >/dev/null 2>&1 || { echo "2 objeto: deployment $d não existe"; return; }; echo "2 objeto: ok"
  sel=$(oc get deployment "$d" -n "$ns" -o json | jq -r '.spec.selector.matchLabels | to_entries | map("\(.key)=\(.value)") | join(",")')
  echo "3 admissão: $(oc get events -n "$ns" --field-selector reason=FailedCreate -o json | jq -r --arg d "$d" '[.items[] | select(.involvedObject.name|startswith($d))] | last | .message // "ok"' | cut -c1-90)"
  echo "4 agendamento: $(oc get pods -n "$ns" -l "$sel" --field-selector=status.phase=Pending --no-headers 2>/dev/null | wc -l) pod(s) Pending"
  echo "5 início: $(oc get pods -n "$ns" -l "$sel" -o jsonpath='{range .items[*]}{.status.containerStatuses[0].state.waiting.reason}{" "}{end}')"
  echo "6 execução: reinícios $(oc get pods -n "$ns" -l "$sel" -o jsonpath='{range .items[*]}{.status.containerStatuses[0].restartCount}{" "}{end}'), prontos $(oc get deployment "$d" -n "$ns" -o jsonpath='{.status.readyReplicas}')/$(oc get deployment "$d" -n "$ns" -o jsonpath='{.spec.replicas}')"
  for svc in $(oc get svc -n "$ns" -o json | jq -r --argjson l "$(oc get deployment "$d" -n "$ns" -o json | jq '.spec.template.metadata.labels')" '.items[] | select(.spec.selector as $s | ($s // {}) | to_entries | length > 0 and all(.[]; $l[.key] == .value)) | .metadata.name'); do
    echo "7 rede: svc/$svc endpoints prontos=$(oc get endpointslices -n "$ns" -l kubernetes.io/service-name="$svc" -o jsonpath='{.items[*].endpoints[*].conditions.ready}')"
  done
}
andares ac12-web
```

A linha 7 só aparece se algum Service selecionar os pods — a ausência dela já é uma evidência.

## Diagnóstico controlado — explicação

Problemas do lado do cliente (DNS, `hosts`) também são "andar 7", só que fora do cluster.
