# Gabarito DIA-004 — Caso 02: o catálogo que nunca fica estável

> Consulte só depois de tentar. Enunciado: [trilhas/19-troubleshooting/exercicios/DIA-004.md](../../trilhas/19-troubleshooting/exercicios/DIA-004.md)

## Desafio sem pista — uma solução possível

Defeitos: (1) **andar 5** — `configMapKeyRef` pede a chave `MODO`, mas o ConfigMap tem `modo` (maiúsculas importam):
`CreateContainerConfigError`; (2) **andar 6** — a liveness executa `cat /tmp/pronto`, arquivo que nunca existe:
reinícios a cada ~10 s.

```bash
oc patch deployment ac19-c2 -n ac19-casos --type=json -p '[
 {"op":"replace","path":"/spec/template/spec/containers/0/env/0/valueFrom/configMapKeyRef/key","value":"modo"},
 {"op":"replace","path":"/spec/template/spec/containers/0/livenessProbe","value":{"tcpSocket":{"port":8080},"periodSeconds":10,"failureThreshold":3}}]'
oc rollout status deployment/ac19-c2 -n ac19-casos
oc diff -f manifests/casos/caso-02.yaml -n ac19-casos | grep -E '^[-+] ' | head     # mostra exatamente o que você corrigiu
```

O `oc diff` contra o manifesto original lista as duas correções: se alguém reaplicá-lo, a diferença some — é a regressão.

## Diagnóstico controlado — explicação

A liveness só começa a agir depois que o contêiner inicia: por isso o segundo defeito só aparece após corrigir o primeiro.
