# Gabarito DIA-005 — Caso 03: a Route que responde 503

> Consulte só depois de tentar. Enunciado: [trilhas/19-troubleshooting/exercicios/DIA-005.md](../../trilhas/19-troubleshooting/exercicios/DIA-005.md)

## Desafio sem pista — uma solução possível

Defeitos: (1) **andar 6** — readiness `httpGet /` recebe 403 da página padrão: pods nunca prontos; (2) **andar 7** —
Service com `targetPort: 8000`, porta em que nada escuta.

```bash
oc create configmap ac19-c3-pagina --from-literal=index.html=ok --from-literal=saude=ok -n ac19-casos
oc set volume deployment/ac19-c3 --add --name=pagina --type=configmap --configmap-name=ac19-c3-pagina --mount-path=/var/www/html -n ac19-casos
oc patch deployment ac19-c3 -n ac19-casos --type=json -p '[{"op":"replace","path":"/spec/template/spec/containers/0/readinessProbe/httpGet/path","value":"/saude"}]'
oc patch service ac19-c3 -n ac19-casos --type=json -p '[{"op":"replace","path":"/spec/ports/0/targetPort","value":8080}]'
oc rollout status deployment/ac19-c3 -n ac19-casos
curl -sS "http://$(oc get route ac19-c3 -n ac19-casos -o jsonpath='{.spec.host}')/"     # ok
```

## Diagnóstico controlado — explicação

Com readiness falhando, o Service fica sem endpoints prontos e o `targetPort` errado nem chega a ser testado.
