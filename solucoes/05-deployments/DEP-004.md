# Gabarito DEP-004 — Voltar no tempo: rollout undo e revisões

> Consulte só depois de tentar. Enunciado: [trilhas/05-deployments/exercicios/DEP-004.md](../../trilhas/05-deployments/exercicios/DEP-004.md)

## Desafio sem pista — uma solução possível

```bash
REV=$(oc get rs -n ac05-deploy -l app=ac05-web -o json | jq -r '.items[]
  | select(.metadata.annotations["kubernetes.io/change-cause"] // "" | test("v3"))
  | .metadata.annotations["deployment.kubernetes.io/revision"]' | head -1)
oc rollout undo deployment/ac05-web --to-revision="$REV" -n ac05-deploy
oc rollout status deployment/ac05-web -n ac05-deploy
oc exec deploy/ac05-web -n ac05-deploy -- printenv VERSAO      # v3
```

## Diagnóstico controlado — explicação

Cada ReplicaSet guarda o número da revisão em `deployment.kubernetes.io/revision`. Ao ser reaproveitado por um undo, ele
recebe o número mais alto, e o número antigo deixa de existir (a).
