# Gabarito DEP-003 — Rollout: disparar, acompanhar e registrar o motivo

> Consulte só depois de tentar. Enunciado: [trilhas/05-deployments/exercicios/DEP-003.md](../../trilhas/05-deployments/exercicios/DEP-003.md)

## Desafio sem pista — uma solução possível

```bash
antes=$(oc get rs -n ac05-deploy -l app=ac05-web --no-headers | wc -l)
oc set env deployment/ac05-web VERSAO=v4 COR=azul -n ac05-deploy
oc annotate deployment/ac05-web kubernetes.io/change-cause='v4: VERSAO=v4, COR=azul' --overwrite -n ac05-deploy
oc rollout status deployment/ac05-web -n ac05-deploy
depois=$(oc get rs -n ac05-deploy -l app=ac05-web --no-headers | wc -l)
echo "ReplicaSets: $antes -> $depois"; oc rollout history deployment/ac05-web -n ac05-deploy | tail -2
```

Alternativa: `oc rollout pause`, várias mudanças, `oc rollout resume` (DEP-005).

## Diagnóstico controlado — explicação

O controlador copia a anotação do Deployment para o ReplicaSet; o histórico lê a anotação do ReplicaSet. Anotar
imediatamente após a mudança grava o motivo na revisão certa.
