## Desafio sem pista — uma solução possível

```bash
grep -nE '\b(create|apply|replace|delete|patch|edit|label|annotate|scale|drain|cordon|login|logout)\b' scripts/preflight.sh
grep -n 'ac_oc ' scripts/preflight.sh | sed -E 's/.*ac_oc ([a-z-]+ ?[a-z-]*).*/\1/' | sort -u
KUBECONFIG=/tmp/nao-existe scripts/preflight.sh; echo "rc=$?"
```

O primeiro `grep` não encontra verbos de mutação; o segundo mostra que só há `whoami`, `get`, `project -q` e `adm top`.
Os testes offline em `tests/run-tests.sh` também verificam isso com um `oc` simulado.

## Diagnóstico controlado — explicação

Sem kubeconfig válido, o `oc` não sabe qual servidor contatar e cai em um padrão local (`localhost:8080`) ou reclama de
configuração incompleta, conforme a versão. Em ambos os casos o preflight classifica como falha de acesso à API. Como a
variável foi definida só para aquele comando, o terminal continua com o perfil anterior.

## Erros comuns

- Achar que `PULADO` é erro: para `developer`, é o comportamento correto.
- Rodar o preflight como `system:admin` e concluir que "tudo está OK" para os exercícios de `developer`.
