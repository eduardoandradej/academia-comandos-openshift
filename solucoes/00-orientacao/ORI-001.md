# Gabarito ORI-001 — Onde estou: máquina, usuário e cliente oc

> Consulte só depois de tentar. Enunciado: [trilhas/00-orientacao/exercicios/ORI-001.md](../../trilhas/00-orientacao/exercicios/ORI-001.md)

## Desafio sem pista — uma solução possível

```bash
printf 'host=%s usuario=%s oc=%s\n' "$(hostnamectl --static)" "$(whoami)" \
  "$(oc version --client -o json | jq -r '.releaseClientVersion // .clientVersion.gitVersion')"
```

A linha só descreve a máquina e o cliente. A identidade no cluster depende do kubeconfig em uso e só é conhecida
com `oc whoami`, que contata a API.

## Diagnóstico controlado — explicação

Com `env -i PATH=/usr/bin:/bin`, o shell não enxerga `/usr/local/bin`, onde o `oc` costuma estar instalado.
`command -v oc` no shell normal mostra o caminho real; se ele estiver fora do `PATH` informado, a hipótese (a) se confirma.

## Alternativas válidas

- `hostname -s` em vez de `hostnamectl --static`.
- `oc version --client | awk '/Client Version/ {print $3}'` sem depender de `jq`.

## Erros comuns

- Usar `oc version` (sem `--client`) e concluir que o cliente está quebrado quando, na verdade, a API está inacessível.
- Confundir o usuário Linux `student` com o usuário `developer` do OpenShift.
