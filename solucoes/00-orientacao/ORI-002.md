# Gabarito ORI-002 — Quem sou eu para o cluster? KUBECONFIG e identidade

> Consulte só depois de tentar. Enunciado: [trilhas/00-orientacao/exercicios/ORI-002.md](../../trilhas/00-orientacao/exercicios/ORI-002.md)

## Desafio sem pista — uma solução possível

```bash
oc whoami                      # identidade
oc whoami --show-server        # servidor
oc config current-context      # contexto
oc auth can-i '*' '*' --all-namespaces
```

Se a identidade for `system:admin` (ou `kube:admin`) e `can-i` responder `yes`, a identidade **não** é adequada para
exercícios comuns: ela tem poder total e mascara erros de permissão que o exercício quer ensinar.

## Diagnóstico controlado — explicação

A causa típica é a hipótese (a): cada shell novo lê o `~/.bashrc` e volta a exportar o kubeconfig do instalador. O login
feito no outro terminal gravou o token no arquivo que **aquele** terminal usava. A saída de `printenv KUBECONFIG`
diferente nos dois terminais confirma.

## Erros comuns

- Rodar `oc login` com o `KUBECONFIG` do instalador ativo: o token do novo usuário é gravado dentro do arquivo sigiloso.
- Concluir que "o login não funcionou" quando apenas o terminal é outro.
