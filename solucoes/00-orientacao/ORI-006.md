# Gabarito ORI-006 — ClusterVersion e o nó único

> Consulte só depois de tentar. Enunciado: [trilhas/00-orientacao/exercicios/ORI-006.md](../../trilhas/00-orientacao/exercicios/ORI-006.md)

## Desafio sem pista — uma solução possível

```bash
oc get clusterversion version -o jsonpath='versao={.status.desired.version}{"\n"}'
oc get clusterversion version -o jsonpath='available={.status.conditions[?(@.type=="Available")].status} progressing={.status.conditions[?(@.type=="Progressing")].status}{"\n"}'
oc get nodes -o json | jq -r '.items[] | .metadata.name
  + " ready=" + ([.status.conditions[] | select(.type=="Ready") | .status][0])
  + " papeis=" + ([.metadata.labels | keys[] | select(startswith("node-role.kubernetes.io/"))
                   | sub("node-role.kubernetes.io/"; "")] | join(","))'
```

A terceira linha também pode ser obtida com `oc get nodes` (coluna `ROLES`), que já resume os papéis.

## Diagnóstico controlado — explicação

`nodes` é um recurso de cluster; o papel padrão de usuários autenticados não concede `list nodes`. A resposta `no` de
`oc auth can-i list nodes` como developer e `yes` com `--as=admin` confirmam a hipótese (a).

## Erros comuns

- Usar `oc adm upgrade` "só para ver": nesta Academia ele é tratado como VERMELHO para nunca entrar em scripts.
- Ler `Progressing=True` e começar um exercício mesmo assim.
