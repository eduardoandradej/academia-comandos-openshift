# Gabarito ORI-004 — Um kubeconfig dedicado para cada perfil

> Consulte só depois de tentar. Enunciado: [trilhas/00-orientacao/exercicios/ORI-004.md](../../trilhas/00-orientacao/exercicios/ORI-004.md)

## Desafio sem pista — uma solução possível

```bash
# Em cada terminal:
source scripts/perfis.sh
ac-perfil                      # imprime KUBECONFIG e oc whoami
# Encerrar e restabelecer developer:
ac-dev
oc logout
oc whoami                      # erro: Unauthorized / must be logged in
oc login -u developer          # servidor e CA vêm do contexto já gravado
oc whoami                      # developer
```

O terminal de recuperação é o único cujo `printenv KUBECONFIG` aponta para `install/auth/kubeconfig` e cujo
`oc whoami` responde `system:admin`.

## Diagnóstico controlado — explicação

Se o arquivo de CA estiver vazio, o `jsonpath` foi executado sem permissão ou no namespace errado. Se tiver conteúdo, mas
o emissor do certificado servido em `:6443` não estiver entre os `subject` do pacote, a hipótese (b) se confirma e o
caminho honesto é o login interativo inseguro no HomeLab. A hipótese (c) aparece como erro mencionando o nome do host,
e não a autoridade.

## Alternativas válidas

- `oc login --server=https://api.ocp.example.lab:6443 --username=developer` (formas longas).
- `oc login https://api.ocp.example.lab:6443 -u developer --insecure-skip-tls-verify` — aceitável **só** no HomeLab, nunca em ambiente real.

## Erros comuns

- Esquecer o `export`: a variável vale só para o comando seguinte.
- Passar a senha com a opção de senha na linha de comando: fica no histórico do shell e na lista de processos.
