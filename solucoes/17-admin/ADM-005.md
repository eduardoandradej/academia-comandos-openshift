# Gabarito ADM-005 — LimitRange: padrões, mínimos, máximos e razão

> Consulte só depois de tentar. Enunciado: [trilhas/17-admin/exercicios/ADM-005.md](../../trilhas/17-admin/exercicios/ADM-005.md)

## Desafio sem pista — uma solução possível

```bash
oc patch limitrange ac17-limites -n ac17-cotas --type=json -p '[{"op":"replace","path":"/spec/limits/0/max/cpu","value":"50m"}]'
oc get pod ac17-padrao -n ac17-cotas -o jsonpath='{.status.phase}{"\n"}'      # Running
ac-dev; oc run ac17-padrao2 --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas 2>&1 | tail -1; ac-admin    # recusado: o default (100m) passa do max
```

Note que o **padrão** (100m) agora viola o próprio máximo: um LimitRange incoerente recusa pods sem resources. O
`oc apply` da limpeza restaura a versão coerente.

## Diagnóstico controlado — explicação

O LimitRange compara o valor pedido (ou o padrão aplicado) com min/max; acima, a admissão recusa.
