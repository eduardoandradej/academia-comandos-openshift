# Gabarito ADM-010 — Varredura do cluster: pods com problema e eventos de aviso

> Consulte só depois de tentar. Enunciado: [trilhas/17-admin/exercicios/ADM-010.md](../../trilhas/17-admin/exercicios/ADM-010.md)

## Desafio sem pista — uma solução possível

```bash
varredura() {
  local ruins reinicios termos avisos
  ruins=$(oc get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded --no-headers 2>/dev/null)
  reinicios=$(oc get pods -A -o json | jq -r '.items[] | select(([.status.containerStatuses[]?.restartCount] | add // 0) > 5) | "\(.metadata.namespace)/\(.metadata.name)"')
  termos=$(oc get pods -A -o json | jq -r '.items[] | .status.containerStatuses[]? | select(.lastState.terminated.reason == "OOMKilled") | .name')
  avisos=$(oc get events -A --field-selector type=Warning --no-headers 2>/dev/null | tail -10)
  for s in "pods não saudáveis:ruins" "mais de 5 reinícios:reinicios" "OOMKilled:termos" "avisos recentes:avisos"; do
    v=${s##*:}; printf '== %s\n%s\n' "${s%%:*}" "${!v}"
  done
  [ -z "$ruins$reinicios$termos$avisos" ] && echo "nada a investigar"
}
varredura
```

## Diagnóstico controlado — explicação

Eventos expiram (cerca de 1 h por padrão): para histórico, use a observabilidade do cluster.
