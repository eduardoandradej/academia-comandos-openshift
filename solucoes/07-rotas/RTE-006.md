# Gabarito RTE-006 — HTTPS com terminação edge e certificado padrão

> Consulte só depois de tentar. Enunciado: [trilhas/07-rotas/exercicios/RTE-006.md](../../trilhas/07-rotas/exercicios/RTE-006.md)

## Desafio sem pista — uma solução possível

```bash
# Opção 1 (sem privilégios): extrair a cadeia servida e usar o último certificado (a CA) como confiança
mkdir -p /tmp/ac07
openssl s_client -connect 192.168.10.200:443 -servername seguro-ac07.apps.ocp.example.lab -showcerts </dev/null 2>/dev/null \
  | awk '/BEGIN CERT/{c++} c>=2' | sed -n '/BEGIN CERT/,/END CERT/p' > /tmp/ac07/ingress-ca.crt
curl -sS --cacert /tmp/ac07/ingress-ca.crt https://seguro-ac07.apps.ocp.example.lab/
# Opção 2 (admin): CA publicada pelo cluster
# oc get configmap default-ingress-cert -n openshift-config-managed -o jsonpath='{.data.ca-bundle\.crt}' > /tmp/ac07/ingress-ca.crt
```

A opção 1 depende de o router enviar a cadeia completa; se só vier o certificado final, use a opção 2. Confiar em uma
CA "porque o servidor mandou" só é aceitável aqui porque você está no seu próprio HomeLab.

## Diagnóstico controlado — explicação

O certificado curinga `*.apps.ocp.example.lab` é emitido pela CA do Ingress Operator, gerada na instalação; nenhum
sistema confia nela por padrão.
