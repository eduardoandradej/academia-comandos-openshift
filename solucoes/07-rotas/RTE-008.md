# Gabarito RTE-008 — Passthrough: o TLS vai até o pod

> Consulte só depois de tentar. Enunciado: [trilhas/07-rotas/exercicios/RTE-008.md](../../trilhas/07-rotas/exercicios/RTE-008.md)

## Desafio sem pista — uma solução possível

```bash
f1=$(openssl s_client -connect 192.168.10.200:443 -servername direto-ac07.apps.ocp.example.lab </dev/null 2>/dev/null | openssl x509 -noout -fingerprint -sha256)
oc port-forward deploy/web-azul 18443:8443 -n ac07-rotas >/dev/null 2>&1 & PF=$!; sleep 3
f2=$(openssl s_client -connect 127.0.0.1:18443 </dev/null 2>/dev/null | openssl x509 -noout -fingerprint -sha256)
kill $PF; echo "$f1"; echo "$f2"; [ "$f1" = "$f2" ] && echo "mesmo certificado"
```

Repetição 1: a 8080 do httpd é HTTP simples; passthrough exige um destino que fale TLS — por isso o Service `web-azul-tls` na 8443. Repetição 2: Routes
passthrough não aceitam `path` (o router não vê o HTTP).

## Diagnóstico controlado — explicação

Se o Service não lista a porta 8443, o router não tem para onde repassar; se a porta existe mas não fala TLS, o handshake falha.
