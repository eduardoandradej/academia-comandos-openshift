# Gabarito PRJ-008 — Seletores que ligam objetos: Service, Deployment e pods

> Consulte só depois de tentar. Enunciado: [trilhas/03-projetos/exercicios/PRJ-008.md](../../trilhas/03-projetos/exercicios/PRJ-008.md)

## Desafio sem pista — uma solução possível

```bash
POD=$(oc get pods -n ac03-projetos -l app=obs-web -o name | head -1)
oc label "$POD" app=depuracao --overwrite -n ac03-projetos
oc wait --for=jsonpath='{.status.readyReplicas}'=2 deployment/obs-web -n ac03-projetos --timeout=120s
oc get endpointslices -n ac03-projetos -l kubernetes.io/service-name=obs-web -o jsonpath='{range .items[*].endpoints[*]}{.targetRef.name}{"\n"}{end}'   # 2 nomes
oc get pods -n ac03-projetos -l app=depuracao -o name                                                                                                   # o órfão
oc delete pod -l app=depuracao -n ac03-projetos
```

Repetição 1: com 3 pods casando para 2 desejados, o ReplicaSet apaga um (escolhe pelo critério interno de remoção, em geral o mais novo/menos pronto).

## Diagnóstico controlado — explicação

O pod com `app=depuracao` não tem `ownerReferences` e continua consumindo cota. O Deployment segue com 2 réplicas; a
contagem extra é o órfão (a).
