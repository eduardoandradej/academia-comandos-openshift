# Gabarito PRJ-009 — ownerReferences e coleta de lixo

> Consulte só depois de tentar. Enunciado: [trilhas/03-projetos/exercicios/PRJ-009.md](../../trilhas/03-projetos/exercicios/PRJ-009.md)

## Desafio sem pista — uma solução possível

```bash
UID_SVC=$(oc get svc obs-web -n ac03-projetos -o jsonpath='{.metadata.uid}')
oc create configmap ac03-do-servico --from-literal=x=1 --dry-run=client -o json \
  | jq --arg uid "$UID_SVC" '.metadata.labels={"academy.openshift.dev/managed-by":"academia"}
      | .metadata.ownerReferences=[{apiVersion:"v1",kind:"Service",name:"obs-web",uid:$uid}]' \
  | oc apply -n ac03-projetos -f -
oc delete deployment obs-web -n ac03-projetos && oc get configmap ac03-do-servico -n ac03-projetos -o name   # fica
oc delete svc obs-web -n ac03-projetos && sleep 5 && oc get configmap ac03-do-servico -n ac03-projetos 2>&1 | head -1   # some
oc apply -f manifests/apps-exemplo/observacao-httpd.yaml -n ac03-projetos
```

## Diagnóstico controlado — explicação

O coletor de lixo casa dono e dependente pelo `uid`. Um objeto recriado tem `uid` novo, então a referência antiga
aponta para um dono inexistente.
