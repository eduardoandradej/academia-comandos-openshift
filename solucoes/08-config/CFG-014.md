# Gabarito CFG-014 — Quem pode ler seus Secrets

> Consulte só depois de tentar. Enunciado: [trilhas/08-config/exercicios/CFG-014.md](../../trilhas/08-config/exercicios/CFG-014.md)

## Desafio sem pista — uma solução possível

```bash
ac-admin
oc new-project ac08-rascunho --skip-config-write
oc create configmap cm1 --from-literal=a=1 -n ac08-rascunho
oc create secret generic s1 --from-literal=b=ficticio -n ac08-rascunho
oc create sa leitor -n ac08-rascunho
oc policy add-role-to-user view -z leitor -n ac08-rascunho
oc auth can-i list configmaps -n ac08-rascunho --as=system:serviceaccount:ac08-rascunho:leitor   # yes
oc auth can-i get secrets -n ac08-rascunho --as=system:serviceaccount:ac08-rascunho:leitor      # no
oc delete project ac08-rascunho
ac-dev
```

Usar uma service account como "usuário de teste" evita criar identidades novas no HTPasswd.

## Diagnóstico controlado — explicação

O papel `view` foi desenhado para leitura **sem** dados sensíveis: ele exclui Secrets de propósito.
