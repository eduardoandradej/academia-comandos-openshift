# Gabarito CON-014 — Acompanhar mudanças: watch e wait

> Consulte só depois de tentar. Enunciado: [trilhas/02-consultas/exercicios/CON-014.md](../../trilhas/02-consultas/exercicios/CON-014.md)

## Desafio sem pista — uma solução possível

```bash
inicio=$(date +%s)
oc rollout restart deployment/obs-web -n ac02-consultas
if oc wait --for=condition=Available deployment/obs-web -n ac02-consultas --timeout=180s; then
  echo "disponível em $(( $(date +%s) - inicio ))s"
else oc get events -n ac02-consultas --field-selector type=Warning; exit 1; fi
```

Observação: logo após o restart, `Available` pode continuar `True` (os pods antigos ainda atendem). Para esperar o
**novo** ReplicaSet, `oc rollout status deployment/obs-web -n ac02-consultas --timeout=180s` é mais preciso.

## Diagnóstico controlado — explicação

`oc rollout status` mostra em que passo o rollout está; os eventos `Warning` dizem a causa (pull, quota, agendamento).
