# Gabarito STO-014 — Roteiro de diagnóstico de storage

> Consulte só depois de tentar. Enunciado: [trilhas/09-storage/exercicios/STO-014.md](../../trilhas/09-storage/exercicios/STO-014.md)

## Desafio sem pista — uma solução possível

```bash
diag_vol() {
  local pod=$1 ns=${2:-ac09-storage} c
  for c in $(oc get pod "$pod" -n "$ns" -o jsonpath='{.spec.volumes[*].persistentVolumeClaim.claimName}'); do
    printf '%s: ' "$c"
    oc get pvc "$c" -n "$ns" -o jsonpath='{.status.phase} classe={.spec.storageClassName}{"\n"}' 2>/dev/null || echo "PVC não existe"
  done
  oc get events -n "$ns" --field-selector type=Warning --sort-by=.lastTimestamp -o json \
    | jq -r --arg p "$pod" '[.items[] | select(.involvedObject.name==$p or .involvedObject.kind=="PersistentVolumeClaim")] | last | "último aviso: \(.reason // "-") \(.message // "")"'
}
diag_vol ac09-falha2
```

## Diagnóstico controlado — explicação

Um pod só é agendado quando todos os PVCs que monta existem; o erro aparece como evento `FailedScheduling`.
