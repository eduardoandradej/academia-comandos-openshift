# Gabarito STO-005 — Armazenamento efêmero: requests, limits e despejo

> Consulte só depois de tentar. Enunciado: [trilhas/09-storage/exercicios/STO-005.md](../../trilhas/09-storage/exercicios/STO-005.md)

## Desafio sem pista — uma solução possível

```bash
oc get pod ac09-guloso -n ac09-storage -o json \
  | jq 'del(.status, .metadata.uid, .metadata.resourceVersion, .metadata.creationTimestamp, .spec.nodeName)
        | .metadata.name="ac09-guloso2"
        | del(.spec.containers[0].resources.limits["ephemeral-storage"], .spec.containers[0].resources.requests["ephemeral-storage"])
        | .spec.volumes += [{"name":"lixo","emptyDir":{"sizeLimit":"16Mi"}}]
        | .spec.containers[0].volumeMounts = ((.spec.containers[0].volumeMounts // []) + [{"name":"lixo","mountPath":"/lixo"}])
        | .spec.containers[0].command = ["/bin/sh","-c","dd if=/dev/zero of=/lixo/x bs=1M count=32; sleep 3600"]' \
  | oc apply -n ac09-storage -f -
oc get pod ac09-guloso2 -n ac09-storage -o jsonpath='{.status.message}{"\n"}'
# Usage of EmptyDir volume "lixo" exceeds the limit "16Mi".
```

## Diagnóstico controlado — explicação

Disco não é "matável" como memória: o kubelet mede o uso periodicamente e despeja o pod inteiro.
