# Gabarito STO-008 — Primeiro PVC: dados que sobrevivem ao pod

> Consulte só depois de tentar. Enunciado: [trilhas/09-storage/exercicios/STO-008.md](../../trilhas/09-storage/exercicios/STO-008.md)

## Desafio sem pista — uma solução possível

```bash
oc exec deploy/ac09-app -n ac09-storage -- sh -c 'echo prova > /dados/prova.txt'
oc delete deployment ac09-app -n ac09-storage
oc run ac09-leitor -n ac09-storage --image=registry.access.redhat.com/ubi9/httpd-24:latest --restart=Never \
  --labels=academy.openshift.dev/managed-by=academia \
  --overrides='{"spec":{"volumes":[{"name":"d","persistentVolumeClaim":{"claimName":"ac09-dados"}}],
  "containers":[{"name":"ac09-leitor","image":"registry.access.redhat.com/ubi9/httpd-24:latest","command":["cat","/dados/prova.txt"],
  "volumeMounts":[{"name":"d","mountPath":"/dados"}]}]}}'
sleep 10; oc logs ac09-leitor -n ac09-storage        # prova
oc delete pod ac09-leitor -n ac09-storage
```

Recrie o `ac09-app` (STO-003 e o `oc set volume` acima) antes dos próximos exercícios.

## Diagnóstico controlado — explicação

Em NFS, o servidor decide as permissões; o UID arbitrário do OpenShift só grava se o diretório permitir.
