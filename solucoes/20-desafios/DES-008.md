# Gabarito DES-008 — Missão 8: acesso da equipe com menor privilégio

> Consulte só depois de tentar. Enunciado: [trilhas/20-desafios/exercicios/DES-008.md](../../trilhas/20-desafios/exercicios/DES-008.md)

## Desafio sem pista — uma solução possível

```bash
N=ac20-loja
oc create rolebinding m8-leitor --clusterrole=view --serviceaccount=$N:leitor -n $N
oc create rolebinding m8-operador-view --clusterrole=view --serviceaccount=$N:operador -n $N
oc create role m8-escalar-loja --verb=get,update,patch --resource=deployments.apps/scale --resource-name=loja -n $N
oc create rolebinding m8-operador-escala --role=m8-escalar-loja --serviceaccount=$N:operador -n $N
oc create rolebinding m8-ci --clusterrole=edit --serviceaccount=$N:ci -n $N
oc label role/m8-escalar-loja rolebinding/m8-leitor rolebinding/m8-operador-view rolebinding/m8-operador-escala rolebinding/m8-ci \
  academy.openshift.dev/managed-by=academia academy.openshift.dev/missao=8 -n $N
```

`edit` dá ao `ci` exatamente o que a matriz pede (inclusive Secrets) e não dá RBAC. A Role `m8-escalar-loja` vale só
para o Deployment `loja` (`--resource-name`). Os bindings têm nomes próprios e rótulo `missao=8`: a limpeza
nunca toca os RoleBindings do sistema (`admin`, `system:image-pullers`...). Para o desafio, leve a tabela da validação para um arquivo
`matriz.txt` e reutilize o laço em qualquer projeto.

## Diagnóstico controlado — explicação

`deployments/scale` cobre o subrecurso; o `oc scale` também lê o Deployment, que precisa de `get` próprio (no `view`).
