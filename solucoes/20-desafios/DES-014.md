# Gabarito DES-014 — Missão 14: migrar a loja para outro projeto sem perder nada

> Consulte só depois de tentar. Enunciado: [trilhas/20-desafios/exercicios/DES-014.md](../../trilhas/20-desafios/exercicios/DES-014.md)

## Desafio sem pista — uma solução possível

```bash
A=ac20-loja; B=ac20-loja-nova; D=/tmp/ac20/migracao
for t in serviceaccount configmap secret deployment service route poddisruptionbudget horizontalpodautoscaler role rolebinding networkpolicy imagestream; do
  oc get "$t" -n $A -l academy.openshift.dev/managed-by=academia -o json | jq --arg a $A --arg b $B '
    .items |= map(del(.status, .metadata.uid, .metadata.resourceVersion, .metadata.generation, .metadata.creationTimestamp,
                      .metadata.managedFields, .metadata.namespace, .metadata.ownerReferences)
      | .metadata.annotations |= ((. // {}) | with_entries(select(.key | test("kubectl.kubernetes.io|deployment.kubernetes.io|openshift.io/host.generated") | not)))
      | if .kind=="Service" then del(.spec.clusterIP, .spec.clusterIPs) else . end
      | if .kind=="Route" then del(.spec.host) else . end
      | if .kind=="ServiceAccount" then del(.secrets, .imagePullSecrets) else . end
      | if .kind=="RoleBinding" then .subjects |= map(if .namespace == $a then .namespace = $b else . end) else . end)' > "$D/$t.json"
done
oc apply -f $D/ -n $B
diff <(oc get deploy loja -n $A -o json | jq -S '.spec.template.spec | del(.containers[0].image)') \
     <(oc get deploy loja -n $B -o json | jq -S '.spec.template.spec | del(.containers[0].image)') && echo "especificação equivalente"
```

Os `secrets`/`imagePullSecrets` da SA são gerados pelo projeto antigo e não existem no novo; o novo projeto gera os seus.
A imagem é excluída do `diff` porque, com gatilho, o digest pode diferir até a ImageStream nova importar as tags.

## Diagnóstico controlado — explicação

Recursos dependentes (SA, ConfigMap, Secret) precisam existir antes dos pods; `oc apply -f dir/` tolera a ordem, mas não a ausência.
