# Gabarito DES-004 — Missão 4: a loja resiliente

> Consulte só depois de tentar. Enunciado: [trilhas/20-desafios/exercicios/DES-004.md](../../trilhas/20-desafios/exercicios/DES-004.md)

## Desafio sem pista — uma solução possível

```bash
N=ac20-loja
oc patch deployment loja -n $N --type=merge -p '{"spec":{"strategy":{"type":"RollingUpdate","rollingUpdate":{"maxUnavailable":0,"maxSurge":1}}}}'
oc patch deployment loja -n $N --type=json -p '[
 {"op":"add","path":"/spec/template/spec/terminationGracePeriodSeconds","value":20},
 {"op":"add","path":"/spec/template/spec/containers/0/lifecycle","value":{"preStop":{"exec":{"command":["sh","-c","sleep 5"]}}}}]'
oc create poddisruptionbudget loja --selector=app=loja --max-unavailable=1 -n $N
oc label pdb loja academy.openshift.dev/managed-by=academia -n $N
oc autoscale deployment/loja --min=1 --max=2 --cpu-percent=60 -n $N && oc label hpa loja academy.openshift.dev/managed-by=academia -n $N
sed -i '/^ *replicas: /d' /tmp/ac20/loja.yaml && oc apply set-last-applied -f /tmp/ac20/loja.yaml -n $N
```

`--max-unavailable=1` (em vez de `--min-available=1`) mantém uma interrupção permitida mesmo com 1 réplica: a
manutenção nunca trava, ao custo de uma breve indisponibilidade nesse caso.

## Diagnóstico controlado — explicação

O percentual do HPA é sempre relativo ao request de CPU.
