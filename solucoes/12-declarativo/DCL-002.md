# Gabarito DCL-002 — Validar antes de aplicar: client, server e strict

> Consulte só depois de tentar. Enunciado: [trilhas/12-declarativo/exercicios/DCL-002.md](../../trilhas/12-declarativo/exercicios/DCL-002.md)

## Desafio sem pista — uma solução possível

```bash
valida() {
  local f=$1 ns=${2:-ac12-declarativo}
  oc apply --dry-run=client -f "$f" -n "$ns" >/dev/null || { echo "falhou: client (YAML/estrutura)"; return 1; }
  oc apply --dry-run=server --validate=strict -f "$f" -n "$ns" >/dev/null || { echo "falhou: server (esquema/admissão)"; return 1; }
  echo "ok: $f"
}
valida /tmp/ac12/app.yaml
```

## Diagnóstico controlado — explicação

A validação estrita é feita pelo servidor, que conhece o esquema exato da versão do cluster.
