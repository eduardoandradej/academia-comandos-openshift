# Gabarito DCL-006 — Server-side apply: donos de campos e conflitos

> Consulte só depois de tentar. Enunciado: [trilhas/12-declarativo/exercicios/DCL-006.md](../../trilhas/12-declarativo/exercicios/DCL-006.md)

## Desafio sem pista — uma solução possível

```bash
oc delete configmap ac12-ssa -n ac12-declarativo
oc apply --server-side --field-manager=equipe-a -f /tmp/ac12/ssa-a.yaml -n ac12-declarativo
cat > /tmp/ac12/ssa-b2.yaml <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata:
  name: ac12-ssa
data:
  tamanho: g
EOF
oc apply --server-side --field-manager=equipe-b --force-conflicts -f /tmp/ac12/ssa-b2.yaml -n ac12-declarativo
oc get configmap ac12-ssa -n ac12-declarativo --show-managed-fields -o json | jq '.metadata.managedFields[] | {manager, campos: (.fieldsV1."f:data" // {} | keys)}'
```

No SSA, o arquivo declara só os campos que aquele gerenciador quer possuir; o resto continua da `equipe-a`.

## Diagnóstico controlado — explicação

O servidor recusa a mudança para não apagar silenciosamente a intenção de outro gerenciador.
