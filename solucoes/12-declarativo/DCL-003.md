# Gabarito DCL-003 — create × apply: criar uma vez ou declarar sempre

> Consulte só depois de tentar. Enunciado: [trilhas/12-declarativo/exercicios/DCL-003.md](../../trilhas/12-declarativo/exercicios/DCL-003.md)

## Desafio sem pista — uma solução possível

```bash
oc apply view-last-applied deployment/ac12-web -n ac12-declarativo -o json > /tmp/ac12/declarado.json
oc get deployment ac12-web -n ac12-declarativo -o json | jq 'del(.status, .metadata.managedFields)' > /tmp/ac12/real.json
jq -n --slurpfile d /tmp/ac12/declarado.json --slurpfile r /tmp/ac12/real.json \
  '[$r[0] | paths(scalars)] - [$d[0] | paths(scalars)] | map(join(".")) | map(select(test("^spec")))' | head -30
```

Aparecem `spec.revisionHistoryLimit`, `spec.progressDeadlineSeconds`, `spec.strategy...`, `terminationMessagePath`,
`dnsPolicy`, `imagePullPolicy` etc.: defaults preenchidos pelo servidor.

## Diagnóstico controlado — explicação

Sem a anotação, o `apply` não sabe o que foi declarado antes; ele a cria no primeiro uso.
