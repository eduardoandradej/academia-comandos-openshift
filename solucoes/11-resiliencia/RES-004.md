# Gabarito RES-004 — Readiness probe: tirar do Service quem não está pronto

> Consulte só depois de tentar. Enunciado: [trilhas/11-resiliencia/exercicios/RES-004.md](../../trilhas/11-resiliencia/exercicios/RES-004.md)

## Desafio sem pista — uma solução possível

```bash
oc set probe deployment/ac11-app --readiness --period-seconds=3 -n ac11-resiliencia -- test -f /tmp/pronto
oc rollout status deployment/ac11-app -n ac11-resiliencia --timeout=20s || true     # não fica pronto
P=$(oc get pod -n ac11-resiliencia -l app=ac11-app -o name | head -1)
oc exec -n ac11-resiliencia "$P" -- touch /tmp/pronto; sleep 6; oc get -n ac11-resiliencia "$P"     # 1/1
oc exec -n ac11-resiliencia "$P" -- rm /tmp/pronto;   sleep 10; oc get -n ac11-resiliencia "$P"     # 0/1, sem reinício
oc set probe deployment/ac11-app --readiness --open-tcp=8080 --period-seconds=5 -n ac11-resiliencia
```

Note que o rollout da probe nova pode ficar parado enquanto o pod novo não fica pronto — use o pod mais recente.

## Diagnóstico controlado — explicação

Probes HTTP consideram sucesso só os códigos 200–399; 403 é falha.
