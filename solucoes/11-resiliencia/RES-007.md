# Gabarito RES-007 — Parâmetros das probes: calcular o tempo de reação

> Consulte só depois de tentar. Enunciado: [trilhas/11-resiliencia/exercicios/RES-007.md](../../trilhas/11-resiliencia/exercicios/RES-007.md)

## Desafio sem pista — uma solução possível

```bash
# readiness: timeout 5 (> 3 s de pico), período 5, falhas 2 -> sai do Service em ~10-15 s
oc set probe deployment/ac11-app --readiness --open-tcp=8080 --timeout-seconds=5 --period-seconds=5 --failure-threshold=2 -n ac11-resiliencia
# liveness: mais tolerante que a readiness (não reiniciar por lentidão passageira): período 10, falhas 3, timeout 5
oc set probe deployment/ac11-app --liveness --open-tcp=8080 --timeout-seconds=5 --period-seconds=10 --failure-threshold=3 -n ac11-resiliencia
```

Regra prática: a readiness reage primeiro (tira tráfego); a liveness só age se o problema persistir (reinicia).

## Diagnóstico controlado — explicação

Uma probe que mede o tempo de resposta com folga zero transforma lentidão normal em falha.
