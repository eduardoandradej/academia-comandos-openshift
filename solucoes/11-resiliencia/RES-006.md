# Gabarito RES-006 — Startup probe: proteger aplicações lentas para iniciar

> Consulte só depois de tentar. Enunciado: [trilhas/11-resiliencia/exercicios/RES-006.md](../../trilhas/11-resiliencia/exercicios/RES-006.md)

## Desafio sem pista — uma solução possível

```bash
oc set probe deployment/ac11-lento --startup --open-tcp=8080 --period-seconds=4 --failure-threshold=10 -n ac11-resiliencia
oc rollout status deployment/ac11-lento -n ac11-resiliencia --timeout=90s                 # sleep 25 passa
oc patch deployment ac11-lento -n ac11-resiliencia --type=json -p '[{"op":"replace","path":"/spec/template/spec/containers/0/command","value":["sh","-c","sleep 50; exec run-httpd"]}]'
sleep 70; oc get pods -n ac11-resiliencia -l app=ac11-lento                               # reinício após ~40 s
```

`oc create deployment ... -- cmd` grava o comando em `command`; se a sua versão do cliente usar `args`, confira com
`oc get deploy ac11-lento -o jsonpath='{.spec.template.spec.containers[0]}'` e ajuste o caminho do patch.

## Diagnóstico controlado — explicação

Sem startup probe, a liveness não sabe distinguir "iniciando" de "travado".
