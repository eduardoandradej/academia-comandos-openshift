# Gabarito RES-010 — Rollout sem indisponibilidade

> Consulte só depois de tentar. Enunciado: [trilhas/11-resiliencia/exercicios/RES-010.md](../../trilhas/11-resiliencia/exercicios/RES-010.md)

## Desafio sem pista — uma solução possível

```bash
teste() {  # roda o cliente por 50 s e faz um rollout no meio
  oc exec ac11-cliente -n ac11-resiliencia -- bash -c 'ok=0; f=0; end=$((SECONDS+50)); while [ $SECONDS -lt $end ]; do
    if timeout 2 bash -c "exec 3<>/dev/tcp/ac11-app/8080 && printf \"GET / HTTP/1.0\r\n\r\n\" >&3 && head -1 <&3" >/dev/null 2>&1; then ok=$((ok+1)); else f=$((f+1)); fi; sleep 0.2
  done; echo "ok=$ok falhas=$f"' & sleep 5
  oc rollout restart deployment/ac11-app -n ac11-resiliencia >/dev/null; oc rollout status deployment/ac11-app -n ac11-resiliencia >/dev/null; wait
}
echo -n "completa:      "; teste
oc patch deployment ac11-app -n ac11-resiliencia --type=json -p '[{"op":"remove","path":"/spec/template/spec/containers/0/lifecycle"}]'
oc rollout status deployment/ac11-app -n ac11-resiliencia >/dev/null
echo -n "sem preStop:   "; teste
oc set probe deployment/ac11-app --readiness --remove -n ac11-resiliencia; oc rollout status deployment/ac11-app -n ac11-resiliencia >/dev/null
echo -n "sem readiness: "; teste
```

Esperado: 0; algumas falhas (conexões ao pod que já está parando); mais falhas (tráfego para pods que ainda não
abriram a porta). Recoloque readiness e `preStop` depois (RES-004 e RES-009).

## Diagnóstico controlado — explicação

A remoção dos endpoints é assíncrona: o `preStop` dá tempo para todos os componentes pararem de enviar tráfego.
