## Desafio sem pista — uma solução possível

```bash
porta_ok() {
  s=$1; ns=${2:-ac06-servicos}
  tp=$(oc get svc "$s" -n "$ns" -o jsonpath='{.spec.ports[0].targetPort}')
  sel=$(oc get svc "$s" -n "$ns" -o json | jq -r '.spec.selector | to_entries | map("\(.key)=\(.value)") | join(",")')
  oc get pods -n "$ns" -l "$sel" -o json | jq -e --arg tp "$tp" \
    '[.items[].spec.containers[].ports[]? | select((.containerPort|tostring)==$tp or .name==$tp)] | length > 0' >/dev/null \
    && echo "5 ok: targetPort $tp declarado no contêiner" || echo "5 FALHA: targetPort $tp não declarado nos contêineres"
}
porta_ok quebrado; porta_ok web-azul
```

Uma porta declarada não garante que o processo escute nela, mas a ausência é um forte indício de erro.

## Diagnóstico controlado — explicação

Seletor, prontidão e endpoints corretos com conexão recusada apontam para a porta: o tráfego chega ao pod, mas nada escuta ali.
