# Gabarito POD-010 — attach, logs e exec: três formas de "olhar" um contêiner

> Consulte só depois de tentar. Enunciado: [trilhas/04-pods/exercicios/POD-010.md](../../trilhas/04-pods/exercicios/POD-010.md)

## Desafio sem pista — uma solução possível

```bash
oc attach -i pod/ac04-eco -n ac04-pods     # digite "um", depois Ctrl+C
oc attach -i pod/ac04-eco -n ac04-pods     # digite "dois", depois Ctrl+C
oc logs ac04-eco -n ac04-pods | tail -2     # recebi: um / recebi: dois
oc get pod ac04-eco -n ac04-pods -o jsonpath='{.status.phase} restarts={.status.containerStatuses[0].restartCount}{"\n"}'   # Running restarts=0
```

Com `stdinOnce: false` (o que `oc run -i --attach=false` gera), a entrada do processo principal permanece aberta entre
conexões. O `oc exec` cria outro processo, com entrada própria: nada do que ele lê chega ao laço.

## Diagnóstico controlado — explicação

`stdin: true` é o que mantém a entrada do processo aberta; `oc run -i` o define. Sem ele, não há para onde enviar o
que você digita (a). Sem `-i` no `attach`, o cliente não envia a entrada (b).
