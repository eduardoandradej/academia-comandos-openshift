## Desafio sem pista — uma solução possível

```bash
cat <<'EOF' | oc apply -n ac04-pods -f -
apiVersion: v1
kind: Pod
metadata:
  name: ac04-dw
  labels: {academy.openshift.dev/managed-by: academia}
spec:
  restartPolicy: Never
  containers:
    - name: dw
      image: registry.access.redhat.com/ubi9/httpd-24:latest
      command: ["echo", "pod=$(MEU_POD) ns=$(MEU_NS)"]
      env:
        - name: MEU_POD
          valueFrom: {fieldRef: {fieldPath: metadata.name}}
        - name: MEU_NS
          valueFrom: {fieldRef: {fieldPath: metadata.namespace}}
      resources: {requests: {cpu: 10m, memory: 16Mi}, limits: {cpu: 50m, memory: 32Mi}}
EOF
sleep 10; oc logs ac04-dw -n ac04-pods     # pod=ac04-dw ns=ac04-pods
```

## Diagnóstico controlado — explicação

O Kubernetes substitui `$(VAR)` em `command`/`args` antes de iniciar o contêiner; `$VAR` só é interpretado por um shell
(`sh -c`), que não existe no `ac04-sem`.
