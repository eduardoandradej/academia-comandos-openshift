## Objetivo e indicador de sucesso

Usar `oc diff` como portão antes de todo `apply`: ler a saída, interpretar o código de saída e usar um diff externo.

**Indicador de sucesso:** você altera duas coisas no arquivo e o `oc diff` mostra exatamente essas duas, com `rc=1`.

## Conceito

> **Arquivo de trabalho.** Os exercícios editam a cópia `/tmp/ac12/app.yaml`, nunca o manifesto do repositório.
> Para recomeçar: `cp manifests/apps-exemplo/declarativo-app.yaml /tmp/ac12/app.yaml`.

`oc diff -f arquivo` envia o objeto ao servidor em **dry-run** e compara com o atual — inclui defaults e mutações de
admissão, por isso é mais fiel que comparar arquivos.

| Código | Significado |
|---|---|
| 0 | nada mudaria |
| 1 | há diferenças (mostradas) |
| > 1 | erro (arquivo inválido, sem permissão...) |

`KUBECTL_EXTERNAL_DIFF="diff -u --color=always"` troca o programa de comparação.

## Comandos guiados

```bash
oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo; echo "rc=$?"           # 0
sed -i 's/value: treino/value: producao/; s/versao 1/versao 2/' /tmp/ac12/app.yaml
oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo; echo "rc=$?"           # 1
KUBECTL_EXTERNAL_DIFF="diff -u --color=always" oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo | head -40
oc apply -f /tmp/ac12/app.yaml -n ac12-declarativo
oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo; echo "rc=$?"           # 0
```

## Repetições

1. Rode `oc diff` em um arquivo com erro de sintaxe: qual o código?
2. Mostre o diff só dos nomes de arquivo alterados (`KUBECTL_EXTERNAL_DIFF="diff -qr"`).
3. Faça um `oc scale --replicas=2` imperativo e rode `oc diff`: aparece?
4. `oc diff` de um objeto que ainda não existe (Route nova no arquivo).
5. Faça um "portão" de uma linha: só aplica se o diff retornar 1.

## Desafio sem pista

Escreva `aplica_com_portao <arquivo>` que mostra o diff, aborta em erro (rc>1), não faz nada em rc=0 e só aplica em
rc=1 após confirmação.

## Diagnóstico controlado

- **Sintoma:** `oc diff` mostra mudança em um campo que você não alterou (ex.: `imagePullPolicy`).
- **Hipóteses:** default do servidor ou mutação de admissão diferente do que está no cluster (objeto antigo, versão nova).
- **Investigação:** procure o campo no arquivo e no `oc get -o yaml`.
- **Reversão:** declare o campo explicitamente no arquivo se quiser fixá-lo.

## Validação

```bash
oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo >/dev/null; echo "rc=$?"   # 0
```
