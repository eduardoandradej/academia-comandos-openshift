# DCL-013 — Delete declarativo e o ciclo completo

## Identificação

- **ID:** DCL-013

- **Referência didática:** DO280 — gerenciamento declarativo (ciclo de vida).
- **Fichas de comando:** [`oc-apply-patch-diff`](../../../catalogo/fichas/oc-apply-patch-diff.md)

## Objetivo e indicador de sucesso

Remover exatamente o que um manifesto criou com `oc delete -f`, e repetir o ciclo completo (gerar, validar, diff,
aplicar, alterar, remover) só com arquivos.

**Indicador de sucesso:** o ciclo completo roda sem nenhum comando imperativo além de `oc get`.

## Conceito

> **Arquivo de trabalho.** Os exercícios editam a cópia `/tmp/ac12/app.yaml`, nunca o manifesto do repositório.
> Para recomeçar: `cp manifests/apps-exemplo/declarativo-app.yaml /tmp/ac12/app.yaml`.

`oc delete -f arquivo` apaga os objetos **nomeados** no arquivo (não usa seletor). Com `--dry-run=client` mostra a
lista. `--wait=true` espera a remoção completa; `--cascade=foreground` espera os dependentes (pods) primeiro.

## Comandos guiados

```bash
oc delete -f /tmp/ac12/app.yaml -n ac12-declarativo --dry-run=client
oc delete -f /tmp/ac12/app.yaml -n ac12-declarativo --cascade=foreground --wait=true
oc get all,cm,route -n ac12-declarativo -l app=ac12-web
oc apply --dry-run=server -f /tmp/ac12/app.yaml -n ac12-declarativo -o name
oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo | head -5
oc apply -f /tmp/ac12/app.yaml -n ac12-declarativo
sed -i 's/versao [0-9]*/versao 3/' /tmp/ac12/app.yaml
oc diff -f /tmp/ac12/app.yaml -n ac12-declarativo | grep '^[-+] ' ; oc apply -f /tmp/ac12/app.yaml -n ac12-declarativo
```

## Repetições

1. Por que mudar só o ConfigMap não reinicia o Deployment? (Trilha 08) Como resolver de forma declarativa?
2. `--cascade=orphan`: apague o Deployment e veja o ReplicaSet e os pods ficarem.
3. Apague só o Service do arquivo usando `oc delete -f` com um arquivo de um documento.
4. Rode o ciclo inteiro cronometrado.
5. O que acontece com `oc delete -f` em um arquivo com um objeto que já não existe? (`--ignore-not-found`)

## Desafio sem pista

Torne a mudança de conteúdo do ConfigMap um rollout automático de forma **declarativa**: o próprio arquivo deve
mudar o template do Deployment quando o conteúdo muda (dica: CFG-004).

## Diagnóstico controlado

- **Sintoma:** depois de `oc delete --cascade=orphan`, pods "fantasmas" continuam atendendo.
- **Hipóteses:** ReplicaSet órfão ainda existe.
- **Investigação:** `oc get rs -n ac12-declarativo -l app=ac12-web`.
- **Reversão:** `oc delete rs -l app=ac12-web -n ac12-declarativo` (ou reaplique o Deployment, que adota o RS).
