# DCL-010 — Exportar um objeto vivo para um manifesto limpo

## Identificação

- **ID:** DCL-010
- **Trilha:** [12 — Manifestos declarativos](../README.md)
- **Referência didática:** DO280 — gerenciamento declarativo (adoção).
- **Fichas de comando:** [`oc-apply-patch-diff`](../../../catalogo/fichas/oc-apply-patch-diff.md), [`jq`](../../../catalogo/fichas/jq.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Transformar o `oc get -o yaml` de um objeto criado à mão em um manifesto reaplicável, sem `status`, `uid`,
`resourceVersion`, `managedFields` e anotações geradas.

**Indicador de sucesso:** o manifesto limpo, aplicado em um projeto rascunho com `--dry-run=server`, é aceito.

## Conceito

Campos que **não** pertencem a um manifesto:

| Campo | Por quê |
|---|---|
| `status` | estado observado, escrito pelos controladores |
| `metadata.uid`, `resourceVersion`, `generation`, `creationTimestamp` | identidade e versão do objeto vivo |
| `metadata.managedFields` | contabilidade do SSA |
| anotações `kubectl.kubernetes.io/last-applied-configuration`, `deployment.kubernetes.io/revision` | geradas |
| Service: `spec.clusterIP(s)` | atribuído pelo cluster |
| Route: `spec.host` gerado | depende do projeto |

`oc get --export` não existe mais: limpe com `jq`.

## Comandos guiados

```bash
oc create deployment ac12-manual --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac12-declarativo
oc expose deployment ac12-manual --port=8080 -n ac12-declarativo
oc get deployment,service ac12-manual -n ac12-declarativo -o json | jq '
  .items |= map(
    del(.status, .metadata.uid, .metadata.resourceVersion, .metadata.generation, .metadata.creationTimestamp, .metadata.managedFields)
    | .metadata.annotations |= ((. // {}) | with_entries(select(.key | test("kubectl.kubernetes.io|deployment.kubernetes.io") | not)))
    | if .kind=="Service" then del(.spec.clusterIP, .spec.clusterIPs) else . end)' > /tmp/ac12/manual.json
jq -r '.items[] | "\(.kind) \(.metadata.name) campos-metadata=\(.metadata|keys|join(","))"' /tmp/ac12/manual.json
oc new-project ac12-rascunho >/dev/null 2>&1 || true
oc apply --dry-run=server -f /tmp/ac12/manual.json -n ac12-rascunho
oc project ac12-declarativo >/dev/null
```

## Repetições

1. O que aconteceria se `resourceVersion` ficasse no arquivo (DCL-007)?
2. E se `clusterIP` ficasse e o IP já estivesse em uso no projeto destino?
3. Tire também os defaults (`terminationMessagePath`, `dnsPolicy`...) e compare o tamanho do arquivo.
4. Converta o JSON em YAML (`oc apply --dry-run=client -f manual.json -o yaml`).
5. Adote os objetos: `oc apply -f manual.json -n ac12-declarativo` (passa a ter last-applied).

## Desafio sem pista

Faça uma função `exporta <tipo/nome>` que imprime o objeto já limpo em YAML, pronta para ir para o Git.

## Diagnóstico controlado

- **Sintoma:** ao aplicar o export em outro projeto: `metadata.namespace: Invalid value: ... does not match the namespace`.
- **Hipóteses:** o `namespace` do objeto original ficou no arquivo.
- **Investigação:** `jq '.items[].metadata.namespace' manual.json`.
- **Reversão:** remova `metadata.namespace` do manifesto e use sempre `-n`.

## Validação

```bash
jq -e '[.items[] | .metadata | has("uid") or has("resourceVersion")] | any | not' /tmp/ac12/manual.json >/dev/null && echo "limpo"
```

## Limpeza segura

```bash
oc delete deployment,service ac12-manual -n ac12-declarativo --ignore-not-found
oc delete project ac12-rascunho --ignore-not-found
rm -f /tmp/ac12/manual.json
```
