# DCL-007 — replace e replace --force: substituir inteiro

## Identificação

- **ID:** DCL-007
- **Trilha:** [12 — Manifestos declarativos](../README.md)
- **Referência didática:** DO280 — gerenciamento declarativo (replace).
- **Fichas de comando:** [`oc-apply-patch-diff`](../../../catalogo/fichas/oc-apply-patch-diff.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Usar `oc replace` com um manifesto completo, perceber o que se perde com um manifesto incompleto e quando `--force` é necessário.

**Indicador de sucesso:** você mostra um rótulo sumindo por `replace` e um campo imutável alterado só com `replace --force`.

## Conceito

| | `apply` | `replace` | `replace --force` |
|---|---|---|---|
| Objeto não existe | cria | erro | cria |
| Campos ausentes no arquivo | preserva os de outros | **somem** | somem |
| Campo imutável diferente | erro | erro | **apaga e recria** (indisponibilidade!) |

`replace` exige o objeto inteiro; é útil com `oc get -o yaml | edição | oc replace -f -`.

## Comandos guiados

```bash
oc label deployment ac12-web extra=sim -n ac12-declarativo
oc get deployment ac12-web -n ac12-declarativo -o yaml > /tmp/ac12/vivo.yaml
oc replace -f /tmp/ac12/app.yaml -n ac12-declarativo                    # arquivo sem o rótulo "extra"
oc get deployment ac12-web -n ac12-declarativo --show-labels | grep -c extra=sim || echo "rótulo extra sumiu"
oc replace -f /tmp/ac12/vivo.yaml -n ac12-declarativo; echo "rc=$?"     # resourceVersion antigo: conflito
sed -i '/resourceVersion:/d' /tmp/ac12/vivo.yaml
oc replace -f /tmp/ac12/vivo.yaml -n ac12-declarativo                   # sem resourceVersion: aceito
```

## Repetições

1. Por que o segundo `replace` deu `the object has been modified`?
2. Edite um ConfigMap com `oc get -o yaml | sed | oc replace -f -`.
3. Mude o `selector` do Deployment no arquivo e tente `apply` e `replace` (TS-037).
4. Faça o mesmo com `replace --force` e observe o Deployment ser recriado (pods novos).
5. Quando `replace --force` é inaceitável em produção?

## Desafio sem pista

Mude `spec.selector.matchLabels` do `ac12-web` (de `app: ac12-web` para `app: ac12-web, ver: "2"`, com o rótulo
correspondente no template) da forma **menos arriscada** que conseguir, e explique o impacto.

## Diagnóstico controlado

- **Sintoma:** `Operation cannot be fulfilled on deployments.apps "ac12-web": the object has been modified; please apply your changes to the latest version`.
- **Hipóteses:** o arquivo carrega um `resourceVersion` antigo (concorrência otimista).
- **Investigação:** `grep resourceVersion arquivo`.
- **Reversão:** obtenha a versão atual ou retire `resourceVersion`.
