## Objetivo e indicador de sucesso

Organizar a aplicação em um diretório, aplicar com `-f dir/` (e `-R`), e lidar com ordem e espera entre objetos.

**Indicador de sucesso:** `oc apply -f /tmp/ac12/dir/` cria tudo em uma passada e um `oc wait` confirma a disponibilidade.

## Conceito

- `oc apply -f dir/` aplica todos os `.yaml/.yml/.json` do diretório em ordem **alfabética**; `-R` entra em subdiretórios.
- Objetos que referenciam outros (Route → Service, Deployment → ConfigMap) costumam tolerar ordem errada: o
  controlador espera. Exceções: CRD antes dos recursos do CRD; namespace antes dos objetos dele.
- `oc apply` continua nos demais arquivos se um falhar e retorna erro no fim.
- `oc wait --for=condition=Available deployment/x` e `oc rollout status` dão o sinal de "pronto".

## Comandos guiados

```bash
oc delete -f /tmp/ac12/app.yaml -n ac12-declarativo --wait=true
mkdir -p /tmp/ac12/dir && cd /tmp/ac12/dir
python3 - <<'EOF'
docs = open('/tmp/ac12/app.yaml').read().split('\n---\n')
nomes = ['10-configmap.yaml', '20-deployment.yaml', '30-service.yaml', '40-route.yaml']
for n, d in zip(nomes, docs):
    open(n, 'w').write(d.strip() + '\n')
EOF
ls; cd - >/dev/null
oc apply -f /tmp/ac12/dir/ -n ac12-declarativo
oc wait --for=condition=Available deployment/ac12-web -n ac12-declarativo --timeout=120s
oc get all,cm,route -n ac12-declarativo -l app=ac12-web
```

## Repetições

1. Renomeie para que a Route seja aplicada primeiro (`00-route.yaml`): funciona? Ela fica admitida quando o Service chega?
2. Coloque um arquivo com erro no meio e veja o comportamento (os outros são aplicados?).
3. Crie um subdiretório `extras/` com um ConfigMap e use `-R`.
4. `oc delete -f /tmp/ac12/dir/ -n ac12-declarativo --dry-run=client` — o que seria apagado?
5. Compare `oc wait` com `oc rollout status` (o que cada um espera?).

## Desafio sem pista

Faça um `implanta <dir>` que valida no servidor, aplica, espera todos os Deployments do diretório ficarem `Available`
e falha (código ≠ 0) se algum não ficar em 120 s.

## Diagnóstico controlado

- **Sintoma:** `error: unable to recognize "dir/05-crd-uso.yaml": no matches for kind "X" in version "y"`.
- **Hipóteses:** recurso de um CRD aplicado antes do próprio CRD (ou CRD inexistente).
- **Investigação:** `oc api-resources | grep -i <kind>`.
- **Reversão:** aplique o CRD primeiro (como admin) e espere `Established`. Na Academia, CRDs ficam para a Trilha 18.

## Validação

oc get deployment ac12-web -n ac12-declarativo -o jsonpath='{.status.conditions[?(@.type=="Available")].status}{"\n"}'   # True
