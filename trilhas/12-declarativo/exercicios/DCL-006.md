# DCL-006 — Server-side apply: donos de campos e conflitos

## Objetivo e indicador de sucesso

Aplicar com `--server-side`, ler `managedFields` e provocar um conflito entre dois "gerenciadores".

**Indicador de sucesso:** `oc apply --server-side --field-manager=equipe-b` falha com `conflict` em um campo da `equipe-a`, e você o resolve conscientemente.

## Conceito

No **server-side apply** (SSA), o servidor registra em `metadata.managedFields` qual **gerenciador** (`field-manager`)
é dono de cada campo. Se outro gerenciador tenta mudar um campo que não é seu, recebe **conflito** — em vez de
sobrescrever em silêncio. Opções: ajustar o arquivo, abrir mão do campo, ou `--force-conflicts` (assumir o campo).
Não usa a anotação `last-applied`.

## Comandos guiados

```bash
oc create configmap ac12-ssa --from-literal=cor=azul --from-literal=tamanho=m --dry-run=client -o yaml \
  | oc label --local -f - academy.openshift.dev/managed-by=academia -o yaml > /tmp/ac12/ssa-a.yaml
oc apply --server-side --field-manager=equipe-a -f /tmp/ac12/ssa-a.yaml -n ac12-declarativo
oc get configmap ac12-ssa -n ac12-declarativo --show-managed-fields -o json | jq '.metadata.managedFields[] | {manager, operation, campos: (.fieldsV1."f:data" | keys)}'
oc create configmap ac12-ssa --from-literal=cor=verde --dry-run=client -o yaml > /tmp/ac12/ssa-b.yaml
oc apply --server-side --field-manager=equipe-b -f /tmp/ac12/ssa-b.yaml -n ac12-declarativo; echo "rc=$?"   # conflito em data.cor
oc apply --server-side --field-manager=equipe-b --force-conflicts -f /tmp/ac12/ssa-b.yaml -n ac12-declarativo
oc get configmap ac12-ssa -n ac12-declarativo --show-managed-fields -o json | jq '.metadata.managedFields[] | {manager, campos: (.fieldsV1."f:data" // {} | keys)}'
oc get configmap ac12-ssa -n ac12-declarativo -o jsonpath='{.data}{"\n"}'
```

## Repetições

1. Depois do `--force-conflicts`, a `equipe-a` aplica o arquivo original de novo: o que acontece?
2. A `equipe-b` aplica um arquivo **sem** `cor`: o campo some? (só se ela for a única dona)
3. Veja os managers do `ac12-web` (`oc-client-side-apply`, `kube-controller-manager`...).
4. Converta o `ac12-web` para SSA: `oc apply --server-side -f /tmp/ac12/app.yaml`.
5. Compare SSA com o apply do cliente (DCL-005) em uma tabela.

## Desafio sem pista

Faça a `equipe-b` gerenciar **apenas** o campo `tamanho` (e só ele), sem conflito com a `equipe-a`, e prove pelos `managedFields`.

## Diagnóstico controlado

- **Sintoma:** `Apply failed with 1 conflict: conflict with "equipe-a": .data.cor`.
- **Hipóteses:** outro gerenciador é dono do campo.
- **Investigação:** `--show-managed-fields`.
- **Reversão:** combine com o dono, retire o campo do seu arquivo ou assuma-o com `--force-conflicts`. Veja TS-039.

## Validação

```bash
oc get configmap ac12-ssa -n ac12-declarativo --show-managed-fields -o json | jq -r '[.metadata.managedFields[].manager] | join(",")'
```

## Limpeza segura

```bash
oc delete configmap ac12-ssa -n ac12-declarativo --ignore-not-found
```
