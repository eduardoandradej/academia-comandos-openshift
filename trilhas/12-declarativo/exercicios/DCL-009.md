# DCL-009 — Editar arquivos sem cluster: --local e patch local

## Identificação

- **ID:** DCL-009
- **Trilha:** [12 — Manifestos declarativos](../README.md)
- **Referência didática:** DO280 — gerenciamento declarativo (pipelines).
- **Fichas de comando:** [`oc-apply-patch-diff`](../../../catalogo/fichas/oc-apply-patch-diff.md), [`oc-set`](../../../catalogo/fichas/oc-set.md)

## Objetivo e indicador de sucesso

Transformar manifestos em arquivo com `oc label/annotate/set ... --local` e `oc patch --local`, sem contatar o cluster.

**Indicador de sucesso:** você gera `/tmp/ac12/prod.yaml` a partir de `app.yaml` com outra imagem, 2 réplicas e um rótulo, só com comandos locais.

## Conceito

Muitos comandos de edição aceitam `--local -f arquivo -o yaml`: aplicam a mudança no **arquivo** e imprimem o
resultado, sem ler nem gravar no cluster. É o princípio de ferramentas como Kustomize (Trilha 13): o manifesto base
fica intacto e as variações são geradas.

| Comando local | Mudança |
|---|---|
| `oc label --local` / `oc annotate --local` | metadados |
| `oc set image/env/resources/probe --local` | contêineres |
| `oc patch --local --type=merge/json` | qualquer campo |

## Comandos guiados

```bash
cd /tmp/ac12
python3 -c "d=[x for x in open('app.yaml').read().split('\n---\n') if 'kind: Deployment' in x][0]; open('deploy-only.yaml','w').write(d+'\n')"
oc label --local -f deploy-only.yaml ambiente=prod -o yaml > p1.yaml
oc set image --local -f p1.yaml web=registry.access.redhat.com/ubi8/httpd-24:latest -o yaml > p2.yaml
oc patch --local -f p2.yaml --type=merge -p '{"spec":{"replicas":2}}' -o yaml > prod.yaml
grep -E 'ambiente|image:|replicas' prod.yaml
diff <(oc create --dry-run=client -f deploy-only.yaml -o yaml) prod.yaml | head -30
oc label --local -f app.yaml ambiente=prod -o name           # label funciona nos 4 documentos
oc set image --local -f app.yaml web=x -o name 2>&1 | head -3 # set image reclama dos objetos sem pod template
cd - >/dev/null
```

## Repetições

1. Rode o `oc patch --local` de `replicas` no `app.yaml` inteiro (4 documentos): o que acontece com o ConfigMap?
2. Separe também o Service em um arquivo e mude a porta com `oc patch --local --type=json`.
3. Aplique `prod.yaml` só com `--dry-run=server` (não aplique de verdade no `ac12-declarativo`).
4. Use `oc set env --local` para acrescentar `MODO=producao`.
5. Encadeie tudo em um único pipe.

## Desafio sem pista

Escreva `gera_ambiente <nome> <réplicas> <imagem>` que lê `app.yaml` e imprime o manifesto do ambiente (rótulo
`ambiente=<nome>`, réplicas e imagem só no Deployment), validado com `--dry-run=client`.

## Diagnóstico controlado

- **Sintoma:** `oc patch --local` falha ou altera objetos que não deveria em um arquivo multidocumento.
- **Hipóteses:** o patch é aplicado a **cada** documento; nem todos têm o campo.
- **Investigação:** `grep -c '^kind:' arquivo`.
- **Reversão:** separe os documentos, ou use JSON Patch com `test` por `kind`, ou Kustomize (Trilha 13).

## Validação

```bash
grep -q 'ambiente: prod' /tmp/ac12/p1.yaml && echo OK
```

## Limpeza segura

```bash
rm -f /tmp/ac12/p1.yaml /tmp/ac12/p2.yaml /tmp/ac12/prod.yaml /tmp/ac12/deploy-only.yaml
```
