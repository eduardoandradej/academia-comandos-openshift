## Conceito

> **Arquivo de trabalho.** Os exercícios editam a cópia `/tmp/ac12/app.yaml`, nunca o manifesto do repositório.
> Para recomeçar: `cp manifests/apps-exemplo/declarativo-app.yaml /tmp/ac12/app.yaml`.

| Validação | Contata a API | Pega |
|---|---|---|
| `--dry-run=client` | não | YAML inválido, `kind` desconhecido localmente |
| `--dry-run=server` | sim | esquema, campos desconhecidos (`--validate=strict`), defaults, **admissão**: quota, LimitRange, SCC |
| `--validate=strict` (padrão em versões recentes) | sim | campo desconhecido ou duplicado vira **erro** (e não só aviso) |

O dry-run de servidor não grava nada, mas passa por toda a admissão — é o teste mais fiel.

## Comandos guiados

```bash
mkdir -p /tmp/ac12 && cp manifests/apps-exemplo/declarativo-app.yaml /tmp/ac12/app.yaml
oc apply --dry-run=server -f /tmp/ac12/app.yaml -n ac12-declarativo
sed 's/^  replicas: 1/  replicaz: 1/' /tmp/ac12/app.yaml > /tmp/ac12/erro1.yaml
oc apply --dry-run=client -f /tmp/ac12/erro1.yaml -n ac12-declarativo; echo "client rc=$?"
oc apply --dry-run=server --validate=strict -f /tmp/ac12/erro1.yaml -n ac12-declarativo; echo "server rc=$?"
sed 's/^  replicas: 1/  replicas: "um"/' /tmp/ac12/app.yaml > /tmp/ac12/erro2.yaml
oc apply --dry-run=server -f /tmp/ac12/erro2.yaml -n ac12-declarativo; echo "rc=$?"
sed 's/limits: {cpu: 100m, memory: 128Mi}/limits: {cpu: 100m, memory: 2Gi}/' /tmp/ac12/app.yaml > /tmp/ac12/erro3.yaml
oc apply --dry-run=server -f /tmp/ac12/erro3.yaml -n ac12-declarativo; echo "rc=$?"   # LimitRange/quota (se houver baseline)
oc explain deployment.spec.replicas
```

## Repetições

1. Use `--validate=warn` no `erro1` e compare a saída.
2. Erre a indentação de `containers` e leia o erro de YAML.
3. Troque `apiVersion: apps/v1` por `apps/v1beta1`: qual validação pega?
4. Valide o arquivo inteiro com `-o name` para ver o que seria criado.
5. Por que o `erro3` passa no client e pode falhar no server?

## Desafio sem pista

Escreva uma função `valida <arquivo>` que roda as validações em ordem (client, server strict) e para na primeira que
falhar, dizendo qual foi.

## Diagnóstico controlado

- **Sintoma:** `Error from server (BadRequest): ... strict decoding error: unknown field "spec.replicaz"`.
- **Hipóteses:** erro de digitação em nome de campo.
- **Investigação:** `oc explain deployment.spec | grep -i replica`.
- **Reversão:** nada foi aplicado; corrija o arquivo.

## Validação
