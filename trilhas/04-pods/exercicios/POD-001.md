## Conceito

Um **Pod** é a menor unidade que o Kubernetes agenda: um ou mais contêineres que compartilham rede (mesmo IP e
portas) e podem compartilhar volumes. Pontos essenciais do `spec`:

| Campo | Significado |
|---|---|
| `containers[].image` | imagem a executar |
| `containers[].command` / `args` | substituem o `ENTRYPOINT` / `CMD` da imagem |
| `containers[].ports` | portas documentadas (informativo; não abre nada sozinho) |
| `containers[].resources` | requests e limits (POD-012) |
| `restartPolicy` | `Always` (padrão), `OnFailure` ou `Never` |
| `initContainers[]` | rodam em sequência, até terminar, antes dos contêineres principais |

Pods criados "soltos" (sem Deployment) **não se recuperam** se forem apagados ou se o nó falhar — ótimos para treino,
ruins para produção.

## Comandos guiados

```bash
oc new-project ac04-pods --display-name='Academia 04 - Pods'
oc run ac04-web --image=registry.access.redhat.com/ubi9/httpd-24:latest --dry-run=client -o yaml
oc run ac04-web --image=registry.access.redhat.com/ubi9/httpd-24:latest \
  --labels=app=ac04-web,academy.openshift.dev/managed-by=academia --port=8080 \
  --env=MODO=treino --restart=Never --dry-run=client -o yaml
oc explain pod.spec.restartPolicy
oc explain pod.spec.containers.command
oc explain pod.spec.initContainers | head -15
```

## Repetições

1. Gere o YAML com `--command -- /bin/sh -c 'echo oi'` e localize `command`.
2. Gere sem `--command` e com `-- echo oi`: o texto vai para `command` ou para `args`?
3. Gere com `--restart=OnFailure` e com `--restart=Always` e compare.
4. Salve o YAML em `/tmp/ac04-pod.yaml` e valide com `oc apply --dry-run=server -f /tmp/ac04-pod.yaml -n ac04-pods`.
5. `oc run --help | sed -n '/Examples:/,/Options:/p'`.

## Desafio sem pista

Sem criar o Pod, produza um YAML com: nome `ac04-teste`, rótulo da Academia, variável `NIVEL=1`, porta 8080, política
`Never` e comando `sleep 30`. Valide-o no servidor e explique cada linha de `spec`.

## Diagnóstico controlado

- **Sintoma:** `error: unknown flag: --limits` (ou `--requests`) ao tentar definir recursos no `oc run`.
- **Hipóteses:** opções removidas do `run` em versões recentes do cliente.
- **Investigação:** `oc run --help | grep -E 'limits|requests|overrides'`.
- **Reversão:** nada a reverter. Defina recursos no YAML (POD-012) ou com `--overrides`.

## Validação

```bash
oc get project ac04-pods -o name
oc apply --dry-run=server -f /tmp/ac04-pod.yaml -n ac04-pods 2>/dev/null && echo "YAML válido"
```

## Limpeza segura

