## Objetivo e indicador de sucesso

Usar `oc debug` para abrir um shell em uma **cópia** de um pod (ou de um Deployment), inclusive trocando o comando, sem afetar o original.

**Indicador de sucesso:** você investiga uma cópia do `ac04-crash` (que não para de reiniciar) com shell e explica por que a cópia não recebe tráfego do Service.

## Conceito

`oc debug <pod|deploy/nome>` cria um pod novo copiando o spec, mas troca o comando por um shell (ou pelo comando que
você passar) e **remove os rótulos** por padrão — assim a cópia não entra em Services nem é contada por controladores.
Ao sair do shell, o pod de debug é apagado.

Opções úteis: `-- <comando>` (executa e sai), `--image=` (outra imagem com mais ferramentas), `-c` (contêiner),
`--keep-labels` (mantém rótulos — cuidado). **`oc debug node/...` é VERMELHO nesta Academia**: cria um pod
privilegiado no nó único.

## Comandos guiados

```bash
oc apply -f manifests/apps-exemplo/cenario-crashloop.yaml -n ac04-pods     # pod que termina com erro
oc get pod ac04-crash -n ac04-pods -w                                      # Ctrl+C ao ver CrashLoopBackOff
oc debug pod/ac04-crash -n ac04-pods
#   dentro da cópia (o comando foi trocado por um shell):
#   env | grep -i config; ls /; exit
oc debug pod/ac04-crash -n ac04-pods -- sh -c 'echo "cópia viva: $(hostname)"; id'
oc get pods -n ac04-pods                                                   # a cópia já sumiu
oc debug pod/ac04-web -n ac04-pods -o yaml | grep -E 'name:|labels:|command' | head   # o que seria criado
```

## Repetições

1. Abra `oc debug pod/ac04-web` e, em outro terminal, veja o pod `ac04-web-debug-*` e seus rótulos.
2. `oc debug pod/ac04-web -n ac04-pods --keep-labels -o yaml | grep -A5 labels` — compare.
3. `oc debug pod/ac04-crash -n ac04-pods -- cat /proc/1/cmdline`.
4. Se o alvo da Trilha 02 existir: `oc debug deploy/obs-web -n ac02-consultas -- id`.
5. `oc debug --help | sed -n '/Examples:/,/Options:/p'`.

## Desafio sem pista

Descubra, usando uma cópia de debug e sem alterar o pod original, qual comando o `ac04-crash` executa e qual
mensagem de erro ele escreve antes de terminar.

## Diagnóstico controlado

- **Sintoma:** depois de `oc debug`, o pod `...-debug` continua listado.
- **Hipóteses:** (a) a sessão ainda está aberta em outro terminal; (b) o cliente foi interrompido de forma abrupta.
- **Investigação:** `oc get pods -n ac04-pods | grep debug`.
- **Reversão:** `oc delete pod <nome>-debug-<sufixo> -n ac04-pods`.

## Validação

```bash
oc get pods -n ac04-pods -o name | grep -c debug || echo "0 pods de debug restantes"
```

## Limpeza segura

```bash
oc delete pod ac04-crash -n ac04-pods --ignore-not-found
oc get pods -n ac04-pods -o name | grep debug | xargs -r oc delete -n ac04-pods
```
