## Objetivo e indicador de sucesso

Ligar o Pod ao contêiner real no CRI-O: `containerID`, `imageID` (digest), nó e horários — e, se autorizado, conferir no nó em modo leitura.

**Indicador de sucesso:** você extrai o digest exato da imagem que está rodando e explica por que ele é mais confiável que a tag.

## Conceito

| Campo | Exemplo | Significado |
|---|---|---|
| `spec.containers[].image` | `.../httpd-24:latest` | o que você **pediu** (tag pode mudar) |
| `status.containerStatuses[].imageID` | `...@sha256:...` | o que está **rodando** (digest imutável) |
| `status.containerStatuses[].containerID` | `cri-o://...` | ID do contêiner no runtime |
| `spec.nodeName` | `ocp-sno.ocp.example.lab` | onde roda |

No nó, o runtime é o CRI-O. `crictl` (somente leitura, via `ssh core@ocp-sno`) mostra os mesmos IDs. Acessar o nó é
opcional e exige autorização; **nunca** pare ou remova contêineres pelo `crictl`.

## Comandos guiados

```bash
oc get pod ac04-web -n ac04-pods -o jsonpath='{.spec.containers[0].image}{"\n"}'
oc get pod ac04-web -n ac04-pods -o jsonpath='{.status.containerStatuses[0].imageID}{"\n"}'
oc get pod ac04-web -n ac04-pods -o jsonpath='{.status.containerStatuses[0].containerID}{"\n"}'
oc get pod ac04-web -n ac04-pods -o jsonpath='{.spec.nodeName} {.status.hostIP} {.status.podIP}{"\n"}'
oc get pod ac04-web -n ac04-pods -o jsonpath='{.status.containerStatuses[0].state.running.startedAt}{"\n"}'
oc get pod ac04-web -n ac04-pods -o jsonpath='{.spec.containers[0].imagePullPolicy}{"\n"}'
oc get pods -n ac04-pods -o custom-columns=POD:.metadata.name,DIGEST:.status.containerStatuses[0].imageID | sed 's/@sha256:\(.\{12\}\).*/@sha256:\1.../'
```

Opcional, somente leitura, com autorização para SSH no nó:

```bash
ssh core@192.168.10.200 sudo crictl ps --name ac04-web          # mesmo containerID (prefixo)
ssh core@192.168.10.200 sudo crictl images | grep httpd-24      # imagem em cache no nó
```

## Repetições

1. Compare o `imageID` de `ac04-web` e de `ac04-duplo` (contêiner `web`): é o mesmo digest?
2. `oc get pod ac04-duplo -n ac04-pods -o jsonpath='{range .status.containerStatuses[*]}{.name} {.containerID}{"\n"}{end}'`.
3. Leia `imagePullPolicy`: por que tags `latest` costumam vir com `Always`?
4. Recrie `ac04-web` e confira que o `containerID` muda e o `imageID` não.
5. `oc describe pod ac04-web -n ac04-pods | grep -E 'Image|Container ID'`.

## Desafio sem pista

Crie um Pod que use a imagem **pelo digest** (o `imageID` lido do `ac04-web`) em vez da tag, e prove que ele roda exatamente a mesma imagem.

## Diagnóstico controlado

- **Sintoma:** dois pods com a mesma tag `latest` se comportam diferente.
- **Hipóteses:** a tag apontou para imagens diferentes em momentos diferentes.
- **Investigação:** compare os `imageID` dos dois pods.
- **Reversão:** nada a reverter; fixe pelo digest quando a reprodutibilidade importar.

## Validação

```bash
oc get pod ac04-web -n ac04-pods -o jsonpath='{.status.containerStatuses[0].imageID}' | grep -q '@sha256:' && echo OK
```
