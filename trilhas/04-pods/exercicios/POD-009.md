# POD-009 — port-forward: acessar um pod ou Service pela ocp-admin

## Identificação

- **ID:** POD-009

## Objetivo e indicador de sucesso

Abrir um túnel temporário da `ocp-admin` até um Pod e até um Service, testar com `curl` e encerrar o túnel.

**Indicador de sucesso:** `curl` na `ocp-admin` recebe resposta HTTP do httpd do Pod, e nenhum processo de port-forward fica para trás.

## Conceito

`oc port-forward <pod|svc/nome|deploy/nome> <local>:<remota>` abre uma porta **na sua máquina** e encaminha o tráfego,
pela API, até o pod. Serve para diagnóstico sem criar Route nem expor nada. Ele roda em primeiro plano até Ctrl+C;
por padrão escuta só em `127.0.0.1`.

Com `svc/nome`, o `oc` escolhe **um** pod do Service (não há balanceamento). Use portas locais acima de 1024.

## Comandos guiados

```bash
oc port-forward pod/ac04-web 18080:8080 -n ac04-pods &     # em segundo plano
PF=$!; sleep 3
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:18080/   # 403 = página padrão do httpd (normal)
curl -sSI http://127.0.0.1:18080/ | head -5                               # cabeçalhos: Server: Apache
kill $PF

oc expose pod ac04-web --port=8080 --name=ac04-web -n ac04-pods            # Service para o pod
oc label svc ac04-web academy.openshift.dev/managed-by=academia -n ac04-pods
oc port-forward svc/ac04-web 18081:8080 -n ac04-pods &
PF=$!; sleep 3
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:18081/
kill $PF
jobs; ss -tlnp 2>/dev/null | grep -E ':1808[01]' || echo "nenhum túnel aberto"
```

## Repetições

1. Repita com a porta local escolhida automaticamente: `oc port-forward pod/ac04-web :8080 -n ac04-pods` (veja a porta na saída).
2. Faça o túnel em primeiro plano em um terminal e o `curl` em outro; encerre com Ctrl+C.
3. Tente uma porta local já em uso e leia o erro.
4. Grave uma página e teste: `oc exec ac04-web -n ac04-pods -- sh -c 'echo ola > /var/www/html/index.html'` (se der `Permission denied`, fique com o 403 como prova).
5. Compare a resposta via `svc/` com a via `pod/`.

## Desafio sem pista

Escreva uma sequência que abre o túnel, espera ele ficar pronto (sem `sleep` fixo), testa o HTTP e fecha o túnel
mesmo que o teste falhe.

## Diagnóstico controlado

- **Sintoma:** `Unable to listen on port 18080: ... address already in use`.
- **Hipóteses:** um port-forward anterior ainda está rodando.
- **Investigação:** `jobs`; `ss -tlnp | grep 18080`; `pgrep -af 'oc port-forward'`.
- **Reversão:** `kill %1` (ou o PID) e repita.

## Validação

```bash
pgrep -af 'oc port-forward' || echo "nenhum port-forward ativo"
```

## Limpeza segura

```bash
pkill -f 'oc port-forward .* -n ac04-pods' || true
oc delete svc ac04-web -n ac04-pods --ignore-not-found
```
