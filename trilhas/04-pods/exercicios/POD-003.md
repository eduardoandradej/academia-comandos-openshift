## Objetivo e indicador de sucesso

Observar como `restartPolicy` (`Never`, `OnFailure`, `Always`) muda o destino de um contêiner que termina com sucesso ou com erro.

**Indicador de sucesso:** uma tabela 3×2 (política × saída 0/1) preenchida com o `STATUS` e o número de reinícios observados.

## Conceito

| Política | Saída 0 | Saída ≠ 0 |
|---|---|---|
| `Never` | `Completed` (fase `Succeeded`) | `Error` (fase `Failed`) |
| `OnFailure` | `Completed` | reinicia com backoff → `CrashLoopBackOff` |
| `Always` | reinicia mesmo com sucesso → `CrashLoopBackOff` | reinicia → `CrashLoopBackOff` |

O backoff de reinício cresce (10 s, 20 s, 40 s… até 5 min). Pods com `Always` são o padrão de servidores; para tarefas
que terminam, use `Never`/`OnFailure` — ou um Job (Trilha 05).

## Comandos guiados

```bash
L=academy.openshift.dev/managed-by=academia
IMG=registry.access.redhat.com/ubi9/httpd-24:latest
oc run ac04-n0 --image=$IMG --labels=$L --restart=Never     -n ac04-pods --command -- /bin/sh -c 'echo ok; exit 0'
oc run ac04-n1 --image=$IMG --labels=$L --restart=Never     -n ac04-pods --command -- /bin/sh -c 'echo falhou; exit 1'
oc run ac04-o1 --image=$IMG --labels=$L --restart=OnFailure -n ac04-pods --command -- /bin/sh -c 'echo falhou; exit 1'
oc run ac04-a0 --image=$IMG --labels=$L --restart=Always    -n ac04-pods --command -- /bin/sh -c 'echo ok; exit 0'
sleep 60
oc get pods -n ac04-pods -l $L -o custom-columns=NOME:.metadata.name,POLITICA:.spec.restartPolicy,STATUS:.status.phase,REINICIOS:.status.containerStatuses[0].restartCount,SAIDA:.status.containerStatuses[0].lastState.terminated.exitCode
oc get pod ac04-n1 -n ac04-pods -o jsonpath='{.status.containerStatuses[0].state.terminated}' | jq .
oc delete pod ac04-n0 ac04-n1 ac04-o1 ac04-a0 -n ac04-pods
```

## Repetições

1. Complete a tabela com as duas combinações que faltam (`OnFailure`+0 e `Always`+1).
2. `oc get pods -n ac04-pods -w` durante um `OnFailure`+1 e observe o intervalo entre reinícios crescer.
3. `oc logs ac04-o1 -n ac04-pods --previous` — o que mostra?
4. Leia `exitCode`, `reason` e `finishedAt` de um contêiner terminado.
5. Use `exit 3` e confira o código no `status`.

## Desafio sem pista

Escreva um único comando que liste, para todos os pods rotulados do projeto, `nome | política | estado atual (running/terminated/waiting) | último código de saída`.

## Diagnóstico controlado

- **Sintoma:** um Pod com `--restart=Always` e comando `echo ok` vai para `CrashLoopBackOff`, embora o comando funcione.
- **Hipóteses:** a política reinicia o contêiner mesmo após saída 0.
- **Investigação:** `oc get pod ac04-a0 -n ac04-pods -o jsonpath='{.spec.restartPolicy} {.status.containerStatuses[0].lastState.terminated.exitCode}{"\n"}'`.
- **Reversão:** `oc delete pod ac04-a0 -n ac04-pods`.
