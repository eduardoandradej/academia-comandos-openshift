## Conceito

| Camada | Prova | Falha típica |
|---|---|---|
| DNS | `getent ahostsv4 api.ocp.example.lab` | `no such host` |
| TCP | `timeout 3 bash -c '</dev/tcp/api.ocp.example.lab/6443' && echo aberta` | `connection refused` / `i/o timeout` |
| TLS | `openssl s_client -connect ...:6443 -servername ...` | `x509: certificate signed by unknown authority` |
| HTTP | `curl -ksS .../readyz` | código diferente de 200 |
| Autenticação | `oc whoami` | `Unauthorized` |

Diagnosticar de baixo para cima evita "consertar" a camada errada.

## Comandos guiados

```bash
getent ahostsv4 api.ocp.example.lab                                   # DNS pelo resolvedor do sistema
timeout 3 bash -c '</dev/tcp/api.ocp.example.lab/6443' && echo "porta 6443 aberta"
openssl s_client -connect api.ocp.example.lab:6443 -servername api.ocp.example.lab </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -enddate                     # certificado servido
curl -ksS -o /dev/null -w '%{http_code}\n' https://api.ocp.example.lab:6443/readyz
oc whoami
getent ahostsv4 console-openshift-console.apps.ocp.example.lab       # wildcard *.apps
```

## Repetições

Quebre uma camada por vez, **só no comando**, e anote a mensagem:

1. DNS: `oc --server=https://api.ocp.example.lab.invalid:6443 whoami`
2. TCP: `oc --server=https://api.ocp.example.lab:6444 whoami --request-timeout=5s`
3. TLS: `oc --server=https://192.168.10.200:6443 whoami` (o IP não consta no certificado? compare a mensagem)
4. HTTP: `curl -ksS -o /dev/null -w '%{http_code}\n' https://api.ocp.example.lab:6443/nao-existe`
5. Autenticação: `oc --token=invalido whoami`

## Desafio sem pista

Escreva um mini-roteiro de 5 linhas que, executado em ordem, aponta a primeira camada que falhar entre DNS, TCP, TLS,
HTTP e autenticação.

## Diagnóstico controlado

- **Sintoma:** `dial tcp 192.168.10.200:6443: i/o timeout`.
- **Hipóteses:** (a) VM `ocp-sno` desligada; (b) rota entre a rede NAT da `ocp-admin` e a bridge `br-ex`; (c) API reiniciando.
- **Investigação:** `ip route`; `timeout 3 bash -c '</dev/tcp/192.168.10.200/443' && echo 443-aberta`; no `kvm-server`
  (com autorização), `virsh domstate ocp-sno`.
- **Reversão:** nada a reverter. Não altere rotas ou bridges (fora do escopo e VERMELHO).

## Validação
