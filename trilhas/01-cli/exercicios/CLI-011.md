## Objetivo e indicador de sucesso

## Conceito

`-v=N` (ou `--loglevel=N`) liga logs do cliente:

| Nível | Mostra |
|---|---|
| 6 | método, URL, código HTTP e tempo de cada requisição |
| 7 | + cabeçalhos da requisição |
| 8+ | + corpos de resposta — **pode incluir dados sensíveis**; não use nesta Academia |

`--request-timeout=10s` limita a espera por resposta. Útil em scripts e no diagnóstico de API lenta.

## Comandos guiados

```bash
oc get pods -n ac01-cli -v=6 2>&1 | grep -E 'GET|POST'          # logs vão para stderr
oc get deploy obs-web -n ac01-cli -v=6 2>&1 | grep GET
oc get --raw /api/v1/namespaces/ac01-cli/pods | jq -r '.items[].metadata.name'
oc get --raw /apis/apps/v1/namespaces/ac01-cli/deployments/obs-web | jq '.status'
oc get pods -n ac01-cli --request-timeout=5s
time oc get pods -n ac01-cli --request-timeout=1ms; echo "rc=$?"   # força timeout
```

## Repetições

1. Descubra a URL de `oc get svc -n ac01-cli` com `-v=6`.
2. Descubra a URL de `oc get routes -n ac01-cli` (grupo `route.openshift.io`).
3. Descubra a URL de `oc whoami` (qual API do OpenShift ela consulta?).
4. Reproduza o item 1 com `oc get --raw`.
5. Compare o tempo de `oc get pods -A` (como admin) com `oc get pods -n ac01-cli`.

## Desafio sem pista

Para `oc get configmap obs-config -n ac01-cli`, descubra a URL exata da API e obtenha **somente** o campo `data.MODO`
com `oc get --raw` + `jq`.

## Diagnóstico controlado

- **Sintoma:** `error: context deadline exceeded` ou `Client.Timeout exceeded`.
- **Como reproduzir sem risco:** `--request-timeout=1ms` (guiados, último comando).
- **Hipóteses:** (a) timeout curto demais; (b) API lenta/sobrecarregada; (c) rede.
- **Investigação:** repita com `--request-timeout=10s`; `time oc get --raw /readyz`; `oc adm top nodes` (perfil admin).
- **Reversão:** nada a reverter.

## Validação

```bash
oc get --raw /api/v1/namespaces/ac01-cli/configmaps/obs-config | jq -r .data.MODO    # observacao
```
