## Conceito

`oc version` mostra o cliente e, se a API estiver acessível, o servidor (`Server Version` = versão do OpenShift e
`Kubernetes Version`). `--client` restringe ao cliente. `-o yaml|json` muda o formato e facilita filtros.

O `kubectl` instalado na `ocp-admin` é distribuído junto com o `oc` e compartilha a mesma base. Para o estudante,
`oc` é um superconjunto: tudo que o `kubectl` faz, o `oc` faz, mais os comandos de OpenShift (`login`, `new-project`,
`new-app`, `adm`...).

Para `developer`, a versão do OpenShift no servidor pode não aparecer (ela é lida do ClusterVersion, que exige
permissão); a do Kubernetes aparece, pois vem de `/version`.

## Comandos guiados

```bash
oc version                                    # cliente + servidor
oc version --client                           # só o cliente
oc version -o yaml                            # mesma informação em YAML
oc version -o json | jq 'keys'                # quais campos existem
oc version -o json | jq -r '.serverVersion.gitVersion'      # Kubernetes do servidor
oc version -o json | jq -r '.openshiftVersion // "sem permissão para ler"'
kubectl version                               # visão do kubectl
oc get --raw /version | jq -r .gitVersion     # mesma resposta, pelo endpoint bruto
```

## Repetições

1. Rode `oc version` como `developer` e como `admin`; qual linha muda?
2. `oc version --client -o json | jq -r '.releaseClientVersion // .clientVersion.gitVersion'`.
3. `kubectl version -o json | jq -r '.clientVersion.minor'`.
4. Compare `oc version` com `oc version --client` com a API inacessível: `KUBECONFIG=/tmp/nao-existe oc version`.
5. `oc version --help | grep -E '^\s+-'` — liste as flags do subcomando.

## Desafio sem pista

Em uma única linha, imprima `cliente=<versão do oc> servidor_k8s=<versão do Kubernetes>`. Depois explique por que um
dos campos de versão do OpenShift pode ficar ausente para `developer`.

## Diagnóstico controlado

- **Sintoma:** `oc version` imprime o cliente e depois um erro de conexão.
- **Como reproduzir sem risco:** `KUBECONFIG=/tmp/nao-existe oc version`.
- **Hipóteses:** (a) kubeconfig ausente; (b) API inacessível; (c) cliente quebrado.
- **Investigação:** `oc version --client` (funciona = cliente íntegro); `oc whoami --show-server`; `oc get --raw /readyz`.
- **Reversão:** nada a reverter.

## Validação

```bash
oc version --client | grep -q 4.22 && oc get --raw /version | jq -e .gitVersion >/dev/null && echo OK
```
