# CLI-009 — Vários kubeconfigs, contextos e --context

## Objetivo e indicador de sucesso

Combinar os kubeconfigs de `developer` e `admin` em uma lista `KUBECONFIG`, usar `--context` para comandos pontuais e organizar nomes de contexto — sem alterar o kubeconfig do instalador.

**Indicador de sucesso:** um único terminal executa um comando como `developer` e o seguinte como `admin`, só com `--context`.

## Conceito

`KUBECONFIG=a:b` faz o `oc` **fundir** os arquivos em memória: clusters, usuários e contextos de ambos ficam
disponíveis; em conflito de nomes, vale o primeiro arquivo. Alterações feitas por `oc config` vão para o arquivo onde a
entrada já existe (ou para o primeiro da lista, se for nova).

`--context=<nome>` usa outro contexto **só naquele comando**. `oc config use-context` muda o padrão de forma
persistente no arquivo. Dar nomes curtos (`dev`, `adm`) com `oc config rename-context` reduz erros.

## Comandos guiados

```bash
export KUBECONFIG="$HOME/.kube/ac-developer.kubeconfig:$HOME/.kube/ac-admin.kubeconfig"
oc config get-contexts                                       # contextos dos dois arquivos
DEV_CTX=$(KUBECONFIG="$HOME/.kube/ac-developer.kubeconfig" oc config current-context)
ADM_CTX=$(KUBECONFIG="$HOME/.kube/ac-admin.kubeconfig" oc config current-context)
oc config rename-context "$DEV_CTX" dev                      # grava no arquivo do developer
oc config rename-context "$ADM_CTX" adm                      # grava no arquivo do admin
oc --context=dev whoami                                      # developer
oc --context=adm whoami                                      # admin
oc --context=dev auth can-i list nodes                       # no
oc --context=adm auth can-i list nodes                       # yes
oc config use-context dev
```

## Repetições

1. Alterne 10× com `--context` entre `dev` e `adm` executando `oc whoami`.
2. `oc --context=adm get nodes` seguido de `oc get nodes` (contexto padrão `dev`).
3. Inverta a ordem da lista `KUBECONFIG` e rode `oc config current-context`. Mudou? Por quê?
4. `oc config get-contexts -o name`.
5. `oc --context=dev --namespace=ac01-cli get cm -o name`.

## Desafio sem pista

Mostre, em um único comando composto, a resposta de `oc auth can-i create resourcequotas -n ac01-cli` para os dois
perfis, rotulando cada linha com o nome do perfil.

## Diagnóstico controlado

- **Sintoma:** `error: context "adm" does not exist`.
- **Hipóteses:** (a) `KUBECONFIG` só contém o arquivo do developer; (b) o rename foi feito em outro terminal sem a lista.
- **Investigação:** `printenv KUBECONFIG`; `KUBECONFIG="$HOME/.kube/ac-admin.kubeconfig" oc config get-contexts`.
- **Reversão:** redefina a lista `KUBECONFIG`. Para voltar ao estado anterior dos nomes: `oc config rename-context dev "$DEV_CTX"`.

## Validação

```bash
oc --context=dev whoami; oc --context=adm whoami
stat -c '%y' "$HOME/openshift-lab/ocp422-sno/install/auth/kubeconfig"    # inalterado
```
