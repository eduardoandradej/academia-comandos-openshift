## Objetivo e indicador de sucesso

Ler o resumo de um projeto com `oc status`, antes e depois de implantar o alvo de observação, e interpretar as sugestões.

**Indicador de sucesso:** você explica cada linha do `oc status` com o alvo implantado e relaciona-a aos objetos de `oc get`.

## Conceito

`oc status` agrupa o que existe no projeto — Services, Deployments, pods, Routes — e mostra as ligações entre eles.
`--suggest` acrescenta recomendações (por exemplo, falta de probes). É um comando de **leitura**, útil como "primeira
olhada" em um projeto desconhecido. Em um projeto vazio, ele apenas diz que não há nada para mostrar.

## Comandos guiados

```bash
oc status -n ac01-cli                                     # projeto ainda vazio
F=manifests/apps-exemplo/observacao-httpd.yaml
less "$F"                                                 # revise: 1 Deployment, 1 Service, 1 ConfigMap, rotulados
oc apply --dry-run=server -f "$F" -n ac01-cli
oc apply -f "$F" -n ac01-cli
oc wait --for=condition=Available deployment/obs-web -n ac01-cli --timeout=180s
oc status -n ac01-cli                                     # agora com svc/obs-web -> deployment/obs-web
oc status --suggest -n ac01-cli
oc get deploy,rs,pods,svc -n ac01-cli -l app=obs-web      # os objetos citados pelo status
```

## Repetições

1. `oc status` (sem `-n`, com o contexto em `ac01-cli`).
2. `oc status -n ac00-orientacao` — se o projeto ainda existir.
3. `oc status --help | sed -n '/Examples:/,/Options:/p'`.
4. Compare a linha do Service no `oc status` com `oc get svc obs-web -n ac01-cli -o wide`.
5. `oc scale deployment/obs-web --replicas=1 -n ac01-cli` e veja o `oc status` refletir a mudança; volte para 2.

## Desafio sem pista

Sem olhar o manifesto, descreva pela saída do `oc status` quantos pods o Deployment quer, qual porta o Service expõe e
se há Route. Confirme cada resposta com um `oc get` específico.

## Diagnóstico controlado

- **Sintoma:** `oc wait` termina em `timed out waiting for the condition`.
- **Hipóteses:** (a) imagem não baixada (`ErrImagePull`/`ImagePullBackOff`); (b) quota excedida; (c) pods `Pending` por falta de recursos.
- **Investigação:** `oc get pods -n ac01-cli -l app=obs-web`; `oc describe pod -n ac01-cli -l app=obs-web | sed -n '/Events:/,$p'`;
  `oc get events -n ac01-cli --sort-by=.lastTimestamp | tail`.
- **Reversão:** `scripts/safe-cleanup.sh -n ac01-cli --execute`.

## Validação

```bash
oc get deployment obs-web -n ac01-cli -o jsonpath='{.status.availableReplicas}{"\n"}'   # 2
```
