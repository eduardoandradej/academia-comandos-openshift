## Objetivo e indicador de sucesso

Comparar a visão `Project` (API do OpenShift) e `Namespace` (API do Kubernetes) do mesmo objeto e saber o que cada perfil enxerga.

**Indicador de sucesso:** você explica por que `developer` lista `projects` mas não `namespaces`, e encontra as anotações `openshift.io/*` de um projeto.

## Conceito

`Project` (`project.openshift.io/v1`) é uma **visão** sobre `Namespace` (`v1`): não existe um sem o outro. Diferenças práticas:

| | `oc get projects` | `oc get namespaces` |
|---|---|---|
| Grupo de API | `project.openshift.io` | core (`v1`) |
| Quem lista | qualquer usuário: vê **só os projetos em que tem papel** | exige permissão de cluster |
| Anotações típicas | `openshift.io/display-name`, `openshift.io/description`, `openshift.io/requester` | as mesmas, mais as do sistema |
| Criação por usuário comum | via `oc new-project` (ProjectRequest) | normalmente negada |

O nome do projeto é o nome do namespace. Apagar um apaga o outro.

## Comandos guiados

```bash
oc get projects                                         # só os seus
oc get projects -o custom-columns=NOME:.metadata.name,EXIBICAO:.metadata.annotations.openshift\.io/display-name,STATUS:.status.phase
oc get namespaces 2>&1 | head -2                        # developer: Forbidden (escopo de cluster)
oc auth can-i list namespaces                           # no
oc auth can-i list projects                             # yes
oc api-resources | grep -E '^(projects|namespaces) '    # grupos e escopo
ac-admin
oc get namespaces --no-headers | wc -l                  # todos os namespaces
oc get projects --no-headers | wc -l                    # admin vê todos os projetos
oc get namespace openshift-console -o jsonpath='{.metadata.annotations}' | jq 'keys'
ac-dev
```

## Repetições

1. `oc describe project <um-projeto-seu>` × `oc describe namespace <o-mesmo>` (no perfil admin).
2. `oc get project <projeto> -o yaml | sed -n '1,25p'` — `apiVersion` e `kind`.
3. `oc get namespaces -l kubernetes.io/metadata.name=default` (admin) — rótulo automático com o próprio nome.
4. Conte os namespaces `openshift-*` (admin): `oc get ns -o name | grep -c '/openshift-'`.
5. Repita o item 1 com `kubectl` e compare.

## Desafio sem pista

Liste, como `admin`, todos os namespaces que **não** são do sistema (sem prefixo `openshift`, `kube` e sem `default`),
mostrando quem solicitou cada um, quando foi criado e o nome de exibição.

## Diagnóstico controlado

- **Sintoma:** como `developer`, `oc get namespaces` responde `Forbidden`, mas `oc get projects` funciona.
- **Hipóteses:** (a) diferença de escopo e de API; (b) erro de RBAC.
- **Investigação:** `oc auth can-i list namespaces`; `oc auth can-i list projects`; `oc api-resources | grep -E '^(projects|namespaces) '`.
- **Reversão:** nada a reverter.

## Validação

```bash
oc auth can-i list projects && ! oc auth can-i list namespaces >/dev/null 2>&1 && echo "visões confirmadas"
```
