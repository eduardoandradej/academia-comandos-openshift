## Objetivo e indicador de sucesso

Aplicar o conjunto de rótulos recomendados pelo Kubernetes e consultar uma "aplicação" composta por vários objetos.

## Conceito

| Rótulo | Significado | Exemplo |
|---|---|---|
| `app.kubernetes.io/name` | nome da aplicação | `loja` |
| `app.kubernetes.io/instance` | instância (permite várias da mesma app) | `loja-treino` |
| `app.kubernetes.io/component` | papel na arquitetura | `frontend`, `api`, `banco` |
| `app.kubernetes.io/part-of` | sistema maior | `academia` |
| `app.kubernetes.io/version` | versão | `1.0` |
| `app.kubernetes.io/managed-by` | ferramenta que gerencia | `oc`, `helm`, `kustomize` |

A Console do OpenShift usa `app.kubernetes.io/part-of` para agrupar componentes na visão de Topologia. Services sem
seletor não criam pods — boa forma de praticar sem consumir CPU/memória.

## Comandos guiados

```bash
for c in frontend api banco; do
  oc create service clusterip "loja-$c" --tcp=8080:8080 --dry-run=client -o yaml \
    | oc label --local -f - academy.openshift.dev/managed-by=academia \
        app.kubernetes.io/name=loja app.kubernetes.io/instance=loja-treino \
        app.kubernetes.io/component="$c" app.kubernetes.io/part-of=academia -o yaml \
    | oc apply -n ac03-projetos -f -
done
oc get svc -n ac03-projetos -l app.kubernetes.io/instance=loja-treino \
  -L app.kubernetes.io/component,app.kubernetes.io/part-of
oc get svc -n ac03-projetos -l 'app.kubernetes.io/component in (frontend,api)' -o name
oc get svc loja-api -n ac03-projetos -o jsonpath='{.spec.selector}{"\n"}'   # app=loja-api, gerado pelo create service
```

## Repetições

1. Adicione `app.kubernetes.io/version=1.0` a todos os Services da instância (lote).
2. Crie uma segunda instância `loja-revisao` só com o componente `api` e liste cada instância separadamente.
3. Liste todos os objetos `part-of=academia` de vários tipos (`svc,cm`).
4. Abra a Console, perspectiva Developer → Topology, projeto `ac03-projetos` (opcional).
5. Ordene os Services por componente (`--sort-by=.metadata.labels.app\.kubernetes\.io/component`).

## Desafio sem pista

Monte uma tabela `instância | componente | nome do Service` para todos os Services com `app.kubernetes.io/name=loja`, ordenada por instância e componente.

## Diagnóstico controlado

- **Sintoma:** `oc create service clusterip` grava um seletor `app=loja-api` que não corresponde a nenhum pod.
- **Hipóteses:** o subcomando gera o seletor a partir do nome; isso não é erro enquanto não houver pods.
- **Investigação:** `oc get endpointslices -n ac03-projetos -l kubernetes.io/service-name=loja-api -o yaml | grep -A3 endpoints`.
- **Reversão:** nada a reverter; é o comportamento esperado (Services sem endpoints).
