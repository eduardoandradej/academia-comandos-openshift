## Conceito

Ao criar um namespace, controladores do OpenShift acrescentam metadados:

| Metadado | Origem | Para que serve |
|---|---|---|
| `kubernetes.io/metadata.name` (rótulo) | Kubernetes | permite selecionar o namespace pelo próprio nome |
| `openshift.io/sa.scc.uid-range` (anotação) | OpenShift | faixa de UIDs atribuída aos pods do projeto (SCC `restricted-v2`) |
| `openshift.io/sa.scc.mcs`, `openshift.io/sa.scc.supplemental-groups` | OpenShift | rótulo SELinux e grupos suplementares do projeto |
| `pod-security.kubernetes.io/audit`, `warn` (rótulos) | sincronização de Pod Security | nível de admissão do Pod Security (avisos/auditoria) |

É por isso que um contêiner roda com um UID "estranho" (por exemplo, 1000xxxxxx) no OpenShift. **Observação apenas**:
alterar esses metadados muda a segurança dos pods do projeto.

## Comandos guiados

```bash
oc get namespace ac03-projetos -o json | jq '.metadata.labels'
oc get namespace ac03-projetos -o json | jq '.metadata.annotations'
oc get namespace ac03-projetos -o jsonpath='{.metadata.annotations.openshift\.io/sa\.scc\.uid-range}{"\n"}'
oc get namespace ac03-extra -o jsonpath='{.metadata.annotations.openshift\.io/sa\.scc\.uid-range}{"\n"}'   # faixa diferente
oc get namespaces -L pod-security.kubernetes.io/enforce,pod-security.kubernetes.io/warn | grep -E '^(NAME|ac0)'
oc describe namespace ac03-projetos
```

## Repetições

1. Compare as faixas de UID de três projetos `ac*-*`: alguma se sobrepõe?
2. Compare os rótulos `pod-security.*` de `ac03-projetos` com os de `openshift-monitoring` (leitura).
3. Se o alvo `obs-web` estiver implantado (PRJ-008), rode `oc exec deploy/obs-web -n ac03-projetos -- id` e confira se o UID cai na faixa.
4. `oc get namespace ac03-projetos -o jsonpath='{.spec.finalizers}{"\n"}'`.
5. `oc get namespace ac03-projetos -o yaml --show-managed-fields | grep -E 'manager:'` — quem escreveu cada parte.

## Desafio sem pista

Para cada namespace de laboratório (`ac*-*`), mostre nome, primeiro UID da faixa e nível `pod-security.kubernetes.io/warn`.

## Diagnóstico controlado

- **Sintoma:** um colega pergunta por que o pod roda como UID `1000690000` e não como `1001`, que a imagem define.
- **Hipóteses:** a SCC `restricted-v2` atribui um UID da faixa do projeto.
- **Investigação:** anotação `openshift.io/sa.scc.uid-range`; `oc get pod <pod> -o jsonpath='{.metadata.annotations.openshift\.io/scc}'`.
- **Reversão:** nada a reverter.

## Validação

```bash
oc get namespace ac03-projetos -o jsonpath='{.metadata.annotations.openshift\.io/sa\.scc\.uid-range}' | grep -Eq '^[0-9]+/[0-9]+$' && echo OK
```
