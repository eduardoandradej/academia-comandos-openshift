## Objetivo e indicador de sucesso

Ver como rótulos e seletores conectam Deployment → pods e Service → pods, e o que acontece quando um rótulo de pod muda.

**Indicador de sucesso:** você "tira" um pod do Service mudando um rótulo, observa o Deployment repor outro e explica o que ficou órfão.

## Conceito

- O Deployment cria um ReplicaSet, cujo `selector` (`app=obs-web`) define **quais pods ele conta**.
- O Service tem `selector` `app=obs-web`: os pods que casam viram endpoints.
- Se você mudar o rótulo `app` de um pod, ele deixa de ser contado pelo ReplicaSet (que cria outro para repor) **e**
  sai do Service. O pod antigo continua rodando, órfão — útil para depurar um pod "fora do tráfego".

## Comandos guiados

```bash
oc apply -f manifests/apps-exemplo/observacao-httpd.yaml -n ac03-projetos
oc wait --for=condition=Available deployment/obs-web -n ac03-projetos --timeout=180s
oc get deployment obs-web -n ac03-projetos -o jsonpath='{.spec.selector}{"\n"}'
oc get svc obs-web -n ac03-projetos -o jsonpath='{.spec.selector}{"\n"}'
oc get endpointslices -n ac03-projetos -l kubernetes.io/service-name=obs-web -o jsonpath='{range .items[*].endpoints[*]}{.addresses[0]}{" "}{.targetRef.name}{"\n"}{end}'
POD=$(oc get pods -n ac03-projetos -l app=obs-web -o name | head -1)
oc label "$POD" app=depuracao --overwrite -n ac03-projetos          # tira o pod do RS e do Service
oc get pods -n ac03-projetos -L app -w                               # Ctrl+C quando surgir o pod de reposição
oc get endpointslices -n ac03-projetos -l kubernetes.io/service-name=obs-web -o jsonpath='{range .items[*].endpoints[*]}{.targetRef.name}{"\n"}{end}'
oc get "$POD" -n ac03-projetos -o jsonpath='{.metadata.ownerReferences}{"\n"}'   # vazio: o RS soltou o pod
```

## Repetições

1. Devolva `app=obs-web` ao pod órfão e observe: o ReplicaSet agora tem 3 pods para 2 desejados — o que ele faz?
2. Repita o ciclo (tirar → observar → devolver) 5×, anotando a ordem dos eventos.
3. `oc describe svc obs-web -n ac03-projetos` antes e depois de tirar um pod.
4. `oc get rs -n ac03-projetos -o jsonpath='{.items[0].spec.selector}{"\n"}'`.
5. Compare `oc get pods -l app=obs-web` com `oc get pods -l academy.openshift.dev/managed-by=academia` durante o ciclo.

## Desafio sem pista

Deixe o projeto com 2 pods no Service e 1 pod órfão para depuração, prove cada parte com um comando e depois retorne ao estado normal (2 pods, nenhum órfão).

## Diagnóstico controlado

- **Sintoma:** depois do ciclo, o projeto tem 3 pods e a quota de pods acusa uso maior que o esperado.
- **Hipóteses:** (a) pod órfão ainda rodando; (b) réplicas alteradas.
- **Investigação:** `oc get pods -n ac03-projetos -L app`; `oc get deploy obs-web -n ac03-projetos -o jsonpath='{.spec.replicas}'`.
- **Reversão:** apague o órfão pelo rótulo: `oc delete pod -l app=depuracao -n ac03-projetos`.

## Validação

```bash
oc get pods -n ac03-projetos -l app=obs-web --no-headers | wc -l     # 2
oc get pods -n ac03-projetos -l app=depuracao --no-headers | wc -l   # 0
```
