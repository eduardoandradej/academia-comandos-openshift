## Objetivo e indicador de sucesso

Interpretar os campos de identidade e versão de um objeto e usar `generation`/`observedGeneration` para saber se um controlador já processou uma mudança.

**Indicador de sucesso:** você prevê corretamente quais campos mudam em 4 operações (rótulo, escala, restart, nenhuma).

## Conceito

| Campo | Muda quando |
|---|---|
| `metadata.uid` | nunca (só em um objeto novo) |
| `metadata.resourceVersion` | **qualquer** gravação no objeto (metadata, spec ou status) |
| `metadata.generation` | só mudanças em `spec` |
| `status.observedGeneration` | quando o controlador processou aquela `generation` |
| `metadata.creationTimestamp` | nunca |

Se `observedGeneration < generation`, o controlador ainda não reagiu à última mudança — útil para scripts e diagnóstico.

## Comandos guiados

```bash
show() { oc get deployment obs-web -n ac03-projetos -o jsonpath='uid={.metadata.uid} rv={.metadata.resourceVersion} gen={.metadata.generation} obs={.status.observedGeneration}{"\n"}'; }
show
oc label deployment obs-web ac03-teste=1 -n ac03-projetos; show                 # rótulo: rv muda, gen não
oc scale deployment obs-web --replicas=1 -n ac03-projetos; show                 # spec: gen muda
oc wait --for=jsonpath='{.status.readyReplicas}'=1 deployment/obs-web -n ac03-projetos --timeout=120s; show
oc scale deployment obs-web --replicas=2 -n ac03-projetos
oc rollout restart deployment/obs-web -n ac03-projetos; show                    # template muda: gen muda
oc label deployment obs-web ac03-teste- -n ac03-projetos
```

## Repetições

Para cada operação, **escreva a previsão** (uid / rv / gen / obs) e só depois execute `show`:

1. `oc annotate deployment obs-web academy.openshift.dev/nota=x -n ac03-projetos`
2. `oc get deployment obs-web -n ac03-projetos` (só leitura)
3. `oc set env deployment/obs-web NIVEL_LOG=debug -n ac03-projetos` (volte depois com `NIVEL_LOG-`)
4. Apagar e reaplicar o manifesto inteiro
5. Um pod reiniciando (o Deployment muda?)

## Desafio sem pista

Escreva uma função que, após qualquer mudança no Deployment, espera até `observedGeneration` alcançar `generation`
(máximo 60 s) e só então imprime `processado`.

## Diagnóstico controlado

- **Sintoma:** um script lê `readyReplicas` logo após `oc scale` e conclui que nada mudou.
- **Hipóteses:** leitura antes de o controlador processar a nova `generation`.
- **Investigação:** compare `generation` e `observedGeneration` imediatamente após a mudança.
- **Reversão:** nada a reverter; use `oc wait` ou a função do desafio.

## Validação

```bash
oc get deployment obs-web -n ac03-projetos -o json | jq -e '.metadata.generation == .status.observedGeneration and .status.readyReplicas == 2' && echo OK
```

## Limpeza segura

Garanta 2 réplicas e sem rótulos/anotações de teste:
`oc scale deployment obs-web --replicas=2 -n ac03-projetos; oc annotate deployment obs-web academy.openshift.dev/nota- -n ac03-projetos`.
