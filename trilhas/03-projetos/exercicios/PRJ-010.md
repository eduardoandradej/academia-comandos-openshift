**Indicador de sucesso:** você captura o projeto rascunho em `Terminating`, lê `deletionTimestamp` e os finalizers, e explica por que não se deve removê-los à mão.

## Conceito

Excluir um objeto com finalizers acontece em **duas fases**:

1. a API grava `metadata.deletionTimestamp` — o objeto entra em remoção, mas continua existindo;
2. cada controlador responsável faz sua limpeza e retira o seu finalizer; quando a lista fica vazia, o objeto some.

Namespaces têm o finalizer `kubernetes` em `spec.finalizers` (o controlador de namespace apaga todo o conteúdo antes).
Remover finalizers à mão "destrava" a exclusão, mas pode deixar recursos órfãos e inconsistências — é **VERMELHO** nesta Academia.

## Comandos guiados

```bash
oc new-project ac03-finalizador --skip-config-write
oc get project ac03-finalizador -o jsonpath='{.spec.finalizers}{"\n"}'              # ["kubernetes"]
oc create configmap fin-demo --from-literal=x=1 -n ac03-finalizador
oc get configmap fin-demo -n ac03-finalizador -o jsonpath='{.metadata.finalizers}{"\n"}'   # vazio: ConfigMap sem finalizer
oc delete project ac03-finalizador --wait=false
oc get project ac03-finalizador -o jsonpath='{.status.phase} {.metadata.deletionTimestamp}{"\n"}'   # Terminating <data>
oc get project ac03-finalizador -w                                                  # Ctrl+C ao ver NotFound/sumir
```

No perfil `admin`, enquanto ainda estiver em `Terminating`:

```bash
oc get namespace ac03-finalizador -o jsonpath='{range .status.conditions[*]}{.type}={.status} {.message}{"\n"}{end}'
```

## Repetições

1. Repita o ciclo 5× e cronometre quanto tempo o projeto fica em `Terminating`.
2. Encontre objetos do seu projeto `ac03-projetos` com finalizers: `oc get all,cm,svc -n ac03-projetos -o json | jq -r '.items[] | select(.metadata.finalizers) | .kind+"/"+.metadata.name+" "+(.metadata.finalizers|join(","))'`.
3. `oc explain namespace.spec.finalizers` e `oc explain pod.metadata.finalizers`.
4. Observe um pod sendo apagado: `oc delete pod <pod> -n ac03-projetos --wait=false` e leia `deletionTimestamp` logo em seguida.
5. Compare `deletionTimestamp` com `deletionGracePeriodSeconds` do pod do item 4.

## Desafio sem pista

Prove, com saídas de comando e sem alterar finalizers, as duas fases da exclusão de um projeto: o instante em que ele
passa a ter `deletionTimestamp` e o instante em que deixa de existir.

## Diagnóstico controlado

- **Sintoma:** um projeto fica em `Terminating` por mais de 10 minutos.
- **Hipóteses:** (a) conteúdo ainda sendo apagado (pods com grace period longo); (b) um recurso com finalizer cujo controlador está indisponível; (c) APIService indisponível impede listar algum tipo.
- **Investigação (admin):** condições do namespace (`NamespaceContentRemaining`, `NamespaceFinalizersRemaining`, `NamespaceDeletionDiscoveryFailure`); `oc get apiservices | grep False`.
- **Reversão:** aguarde e registre. Não edite finalizers. Veja o cenário TS-011.

## Validação

```bash
oc get project ac03-finalizador 2>&1 | grep -q NotFound && echo "rascunho removido"
```
