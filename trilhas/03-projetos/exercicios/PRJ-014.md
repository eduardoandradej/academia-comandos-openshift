## Conceito

Anotações de namespace podem ser **descritivas** ou **operacionais**:

| Anotação | Tipo | Efeito |
|---|---|---|
| `openshift.io/display-name`, `openshift.io/description` | descritiva | só exibição |
| `openshift.io/node-selector` | operacional | força um seletor de nó a todos os pods do projeto |
| `openshift.io/sa.scc.*` | operacional | faixas de UID/SELinux (PRJ-007) |

No SNO há um único nó: um `node-selector` que não case com ele deixaria **todos** os pods do projeto em `Pending`.
Por isso, nesta Academia, operacionais são só leitura.

## Comandos guiados

```bash
oc annotate namespace ac03-extra openshift.io/display-name='Academia 03 - Extra' --overwrite
oc annotate namespace ac03-extra openshift.io/description='Namespace criado por admin no PRJ-002' --overwrite
oc get project ac03-extra -o custom-columns=NOME:.metadata.name,EXIBICAO:.metadata.annotations.openshift\.io/display-name,DESC:.metadata.annotations.openshift\.io/description
oc get namespaces -l academy.openshift.dev/managed-by=academia -L academy.openshift.dev/trilha
oc get namespace ac03-extra -o jsonpath='{.metadata.annotations.openshift\.io/node-selector}{"\n"}'   # vazio
oc get node ocp-sno.ocp.example.lab --show-labels | tr ',' '\n' | grep -E 'node-role|kubernetes.io/hostname'
```

## Repetições

1. Troque e restaure a descrição (5×), conferindo como `developer` (se tiver acesso) e como `admin`.
2. Liste projetos ordenados por data com nome de exibição.
3. `oc describe project ac03-extra`.
4. Leia a configuração de cluster de projetos: `oc get project.config.openshift.io cluster -o yaml` (leitura).
5. `oc get namespaces -o json | jq -r '.items[] | select(.metadata.annotations["openshift.io/node-selector"] != null) | .metadata.name'`.

## Desafio sem pista

Sem alterar `openshift.io/node-selector`, explique com evidências o que aconteceria com os pods de `ac03-extra` se ela
fosse definida como `regiao=sul` no SNO, e qual comando mostraria o problema.

## Diagnóstico controlado

- **Sintoma:** em um projeto qualquer, todos os pods novos ficam `Pending` com `0/1 nodes are available: 1 node(s) didn't match Pod's node affinity/selector`.
- **Hipóteses:** (a) `openshift.io/node-selector` no namespace; (b) `nodeSelector` no próprio pod.
- **Investigação:** anotação do namespace; `oc get pod <pod> -o jsonpath='{.spec.nodeSelector}'`.
- **Reversão:** quem definiu a anotação a remove (`... openshift.io/node-selector-`) — tarefa do admin, com autorização.
