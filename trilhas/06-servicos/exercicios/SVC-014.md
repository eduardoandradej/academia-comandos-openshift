## Conceito

1. O Service existe no namespace certo?
2. O seletor casa com algum pod?
3. Esses pods estão prontos?
4. A EndpointSlice tem endpoints prontos?
5. O `targetPort` corresponde a uma porta em que o contêiner escuta?
6. O nome resolve (DNS) a partir do cliente?
7. A conexão e o HTTP respondem a partir do cliente?

## Comandos guiados

```bash
diag() {
  s=$1; ns=${2:-ac06-servicos}
  oc get svc "$s" -n "$ns" >/dev/null 2>&1 || { echo "1 FALHA: Service não existe"; return; }; echo "1 ok: Service existe"
  sel=$(oc get svc "$s" -n "$ns" -o json | jq -r '.spec.selector // {} | to_entries | map("\(.key)=\(.value)") | join(",")')
  [ -n "$sel" ] || { echo "2 AVISO: Service sem seletor"; }
  n=$(oc get pods -n "$ns" -l "$sel" --no-headers 2>/dev/null | wc -l); [ "$n" -gt 0 ] || { echo "2 FALHA: seletor '$sel' não casa com pods"; return; }; echo "2 ok: $n pod(s) com '$sel'"
  r=$(oc get pods -n "$ns" -l "$sel" -o jsonpath='{range .items[*]}{.status.conditions[?(@.type=="Ready")].status}{"\n"}{end}' | grep -c True)
  [ "$r" -gt 0 ] || { echo "3 FALHA: nenhum pod pronto"; return; }; echo "3 ok: $r pronto(s)"
  e=$(oc get endpointslices -n "$ns" -l kubernetes.io/service-name="$s" -o json | jq '[.items[].endpoints[]? | select(.conditions.ready)] | length')
  [ "$e" -gt 0 ] || { echo "4 FALHA: sem endpoints prontos"; return; }; echo "4 ok: $e endpoint(s)"
  p=$(oc get svc "$s" -n "$ns" -o jsonpath='{.spec.ports[0].port}')
  oc exec ac06-cliente -n ac06-servicos -- getent hosts "$s.$ns" >/dev/null || { echo "6 FALHA: DNS"; return; }; echo "6 ok: DNS"
  oc exec ac06-cliente -n ac06-servicos -- bash -c "timeout 3 bash -c '</dev/tcp/$s.$ns/$p'" 2>/dev/null \
    || { echo "5/7 FALHA: conexão recusada na porta $p (confira targetPort × porta do contêiner)"; return; }
  echo "7 ok: porta $p responde"
}
diag web-azul
oc create service clusterip quebrado --tcp=8080:9999 -n ac06-servicos && oc set selector svc/quebrado app=loja,cor=azul -n ac06-servicos
diag quebrado                      # falha no passo 5/7
```

## Repetições

Provoque um defeito por vez em `quebrado` e rode `diag`:

1. Seletor sem pods (`cor=amarela`).
2. `targetPort` errado (o caso dos guiados).
3. Service em outro namespace (rode `diag quebrado default`).
4. Backend com 0 réplicas.
5. Pod com readiness falhando (cenário TS-021).

## Desafio sem pista

Complete a função para também verificar o passo 5 de forma explícita: comparar o `targetPort` do Service com as portas
declaradas (`containerPort`, por número ou nome) nos pods selecionados, **antes** de tentar a conexão.

## Diagnóstico controlado

- **Sintoma:** passos 1–4 ok, mas a conexão é recusada.
- **Hipóteses:** `targetPort` aponta para uma porta em que o contêiner não escuta.
- **Investigação:** `oc get svc quebrado -o jsonpath='{.spec.ports[0].targetPort}'` × `containerPort` dos pods. Veja TS-019.
- **Reversão:** `oc delete svc quebrado -n ac06-servicos`.
