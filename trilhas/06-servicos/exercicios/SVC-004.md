Carregue a função de teste HTTP usada nesta trilha (faz um GET de dentro do pod cliente, sem precisar de `curl` na imagem):

```bash
http() { oc exec ac06-cliente -n ac06-servicos -- bash -c "exec 3<>/dev/tcp/$1/${2:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && cat <&3" | tail -1; }
```

## Conceito

A `ocp-admin` está **fora** da rede de pods: não alcança ClusterIPs nem IPs de pod. Para testar um Service, rode o
teste de **dentro** do cluster (um pod cliente) ou use `oc port-forward` (Trilha 04).

Sem `curl` na imagem, o bash oferece `/dev/tcp/<host>/<porta>`: abrir a conexão já prova DNS + TCP; enviar um
`GET` e ler a resposta prova HTTP.

## Comandos guiados

```bash
oc exec ac06-cliente -n ac06-servicos -- sh -c 'command -v curl wget getent || true'      # o que a imagem tem
oc exec ac06-cliente -n ac06-servicos -- bash -c 'timeout 3 bash -c "</dev/tcp/web-azul/8080" && echo "TCP ok"'
CIP=$(oc get svc web-azul -n ac06-servicos -o jsonpath='{.spec.clusterIP}')
http "$CIP"                        # pelo ClusterIP
http web-azul                      # pelo nome curto
http web-azul.ac06-servicos        # pelo nome com namespace
http web-azul.ac06-servicos.svc.cluster.local     # pelo FQDN
oc exec ac06-cliente -n ac06-servicos -- bash -c "exec 3<>/dev/tcp/web-azul/8080; printf 'GET / HTTP/1.0\r\n\r\n' >&3; head -1 <&3"   # linha de status
curl -sS --max-time 3 "http://$CIP:8080/" || echo "a ocp-admin não alcança o ClusterIP (esperado)"
```

## Repetições

1. Teste a porta 8443 do pod azul pelo IP do pod.
2. Teste uma porta fechada (`web-azul:9999`) e leia a mensagem.
3. Teste um nome inexistente (`nao-existe:8080`) e compare a mensagem com a do item 2.
4. Repita os testes com `oc debug deploy/web-verde -n ac06-servicos -- bash -c '...'` em vez do cliente.
5. Cronometre `http web-azul` 10×.

## Desafio sem pista

Escreva a função `testa <host> <porta>` que imprime `DNS falhou`, `porta fechada` ou `HTTP <código>` conforme o caso,
executando tudo dentro do pod cliente.

## Diagnóstico controlado

- **Sintoma:** `curl` na `ocp-admin` para o ClusterIP expira.
- **Hipóteses:** a `ocp-admin` está fora da rede de serviços do cluster.
- **Investigação:** `ip route` na `ocp-admin` (não há rota para a rede de Services).
- **Reversão:** nada a reverter; teste de dentro do cluster ou com `oc port-forward svc/web-azul`.

## Validação

```bash
oc exec ac06-cliente -n ac06-servicos -- bash -c "exec 3<>/dev/tcp/web-azul/8080; printf 'GET / HTTP/1.0\r\n\r\n' >&3; head -1 <&3" | grep -q ' 200 ' && echo "HTTP 200"
```
