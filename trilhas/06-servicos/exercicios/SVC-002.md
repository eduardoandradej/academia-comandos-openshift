# SVC-002 — Anatomia de um Service: port, targetPort e portas nomeadas

## Objetivo e indicador de sucesso

Criar Services com `oc create service clusterip` e com YAML, distinguindo `port`, `targetPort` (número e nome) e protocolo.

**Indicador de sucesso:** um Service que escuta na porta 80 e entrega na 8080 do pod usando a porta **nomeada** `http`.

```bash
http() { oc exec ac06-cliente -n ac06-servicos -- bash -c "exec 3<>/dev/tcp/$1/${2:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && cat <&3" | tail -1; }
```

## Conceito

| Campo | Significado |
|---|---|
| `port` | porta do **Service** (a que o cliente usa) |
| `targetPort` | porta do **contêiner** (número ou **nome** declarado em `containerPort`) |
| `protocol` | `TCP` (padrão), `UDP`, `SCTP` |
| `selector` | rótulos dos pods de destino |

`targetPort` nomeado (`http`) desacopla o Service do número: se a imagem mudar de porta, só o pod muda.

## Comandos guiados

```bash
oc create service clusterip loja-80 --tcp=80:8080 -n ac06-servicos --dry-run=client -o yaml
cat <<'EOF' | oc apply -n ac06-servicos -f -
apiVersion: v1
kind: Service
metadata:
  name: loja-80
  labels: {academy.openshift.dev/managed-by: academia}
spec:
  selector: {app: loja, cor: azul}
  ports:
    - name: web
      port: 80
      targetPort: http
EOF
oc get svc loja-80 -n ac06-servicos -o jsonpath='{.spec.ports}{"\n"}'
http loja-80 80                      # azul, pela porta 80 do Service
oc explain service.spec.ports.targetPort
oc get pod -n ac06-servicos -l cor=azul -o jsonpath='{.items[0].spec.containers[0].ports}{"\n"}'
```

## Repetições

1. Troque `targetPort: http` por `targetPort: 8080` e teste.
2. Crie `loja-alt` com `--tcp=9090:8080` e teste na 9090.
3. `oc describe svc loja-80 -n ac06-servicos | grep -E 'Port|Endpoints'`.
4. Tente `targetPort: inexistente` e veja o que acontece com os endpoints.
5. Recrie `loja-80` de memória, só com YAML.

## Desafio sem pista

Crie o Service `loja-https` que atende na porta 443 e entrega na porta **nomeada** `https` (8443) dos pods azuis, e
prove que a porta abre (o protocolo é TLS; basta mostrar a conexão TCP aberta).

## Diagnóstico controlado

- **Sintoma:** com `targetPort: inexistente`, a EndpointSlice não lista portas utilizáveis e a conexão falha.
- **Hipóteses:** o nome não corresponde a nenhum `containerPort.name`.
- **Investigação:** compare `spec.ports[].targetPort` do Service com `containers[].ports[].name` do pod.
- **Reversão:** volte para `targetPort: http`.

## Validação

```bash
http loja-80 80    # azul
```
