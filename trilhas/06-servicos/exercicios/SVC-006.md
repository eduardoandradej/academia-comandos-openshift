## Objetivo e indicador de sucesso

Usar o seletor de um Service para trocar o tráfego entre duas versões instantaneamente (azul → verde) e voltar.

**Indicador de sucesso:** o Service `loja` responde `azul`, depois `verde`, depois `azul`, com uma única alteração por troca.

http() { oc exec ac06-cliente -n ac06-servicos -- bash -c "exec 3<>/dev/tcp/$1/${2:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && cat <&3" | tail -1; }

## Conceito

Um Service não "pertence" a um Deployment: ele seleciona pods por rótulos. Mudando o seletor, o tráfego passa a outro
conjunto de pods **sem** recriar nada. É o princípio da liberação azul/verde:

1. a versão nova (verde) sobe ao lado da atual (azul), sem tráfego;
2. você testa a verde diretamente;
3. troca o seletor do Service; se der problema, troca de volta.

## Comandos guiados

```bash
oc create service clusterip loja --tcp=8080:8080 -n ac06-servicos
oc label svc loja academy.openshift.dev/managed-by=academia -n ac06-servicos
oc set selector svc/loja app=loja,cor=azul -n ac06-servicos
http loja                                        # azul
oc set selector svc/loja app=loja,cor=verde -n ac06-servicos
http loja                                        # verde
oc patch svc loja -n ac06-servicos --type=merge -p '{"spec":{"selector":{"app":"loja","cor":"azul"}}}'
http loja                                        # azul de novo
oc get svc loja -n ac06-servicos -o jsonpath='{.spec.selector}{"\n"}'
```

## Repetições

1. Faça 10 trocas seguidas, conferindo cada uma.
2. Use `oc set selector --dry-run=server -o yaml` antes de trocar.
3. Meça quanto tempo leva entre a troca e a primeira resposta da nova cor.
4. Troque para um seletor sem pods (`cor=amarela`) e teste: o que o cliente recebe?
5. Compare `oc set selector` com `oc patch`.

## Desafio sem pista

Faça uma "liberação" completa: confirme que a verde responde por um Service de teste próprio (`loja-verde-teste`),
troque o Service `loja` para verde, valide, e deixe um comando pronto de "volta" — sem nunca deixar `loja` sem backend.

## Diagnóstico controlado

- **Sintoma:** após a troca, o cliente recebe `Connection refused` ou espera até expirar.
- **Hipóteses:** o novo seletor não casa com nenhum pod pronto.
- **Investigação:** `oc get pods -n ac06-servicos -l <novo seletor>`; EndpointSlices do Service.
- **Reversão:** volte o seletor anterior.

## Validação

http loja    # azul (estado final)
