## Conceito

Um Service pode ter várias portas; quando tem mais de uma, **todas precisam de nome** (`name`). Os nomes aparecem nas
EndpointSlices e em registros DNS SRV (`_<porta>._<protocolo>.<svc>...`). O httpd da imagem UBI escuta em 8080 (HTTP)
e 8443 (HTTPS com certificado próprio).

## Comandos guiados

```bash
cat <<'EOF' | oc apply -n ac06-servicos -f -
apiVersion: v1
kind: Service
metadata: {name: loja-multi, labels: {academy.openshift.dev/managed-by: academia}}
spec:
  selector: {app: loja, cor: azul}
  ports:
    - {name: http, port: 8080, targetPort: http}
    - {name: https, port: 8443, targetPort: https}
EOF
oc describe svc loja-multi -n ac06-servicos | grep -E 'Port|Endpoints'
http loja-multi 8080
oc exec ac06-cliente -n ac06-servicos -- bash -c 'timeout 3 bash -c "</dev/tcp/loja-multi/8443" && echo "8443 aberta"'
oc get endpointslices -n ac06-servicos -l kubernetes.io/service-name=loja-multi -o jsonpath='{.items[0].ports}{"\n"}'
```

## Repetições

1. Tente criar com duas portas sem `name` e leia o erro.
2. Remova a porta https com `oc patch --type=json` (`op: remove`).
3. Use `oc create service clusterip loja-dupla --tcp=8080:8080 --tcp=8443:8443` e veja os nomes gerados.
4. Leia a porta pelo nome: `oc get svc loja-multi -o jsonpath='{.spec.ports[?(@.name=="https")].port}'`.
5. Recrie de memória.

## Desafio sem pista

Mostre o certificado servido na 8443 pelo Service (emissor e validade), executando o `openssl` dentro do pod cliente, se ele existir na imagem; senão, explique a alternativa.

## Diagnóstico controlado

- **Sintoma:** `spec.ports[0].name: Required value` (ou mensagem similar).
- **Hipóteses:** várias portas sem nome.
- **Investigação:** releia o YAML.
- **Reversão:** nada foi criado; dê nome a cada porta.

## Validação

```bash
oc get svc loja-multi -n ac06-servicos -o jsonpath='{.spec.ports[*].name}{"\n"}'   # http https
```
