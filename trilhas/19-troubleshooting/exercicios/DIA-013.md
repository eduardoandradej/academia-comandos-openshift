## Objetivo e indicador de sucesso

Montar a linha do tempo de um incidente juntando eventos, mudanças de revisão, términos de contêiner e logs, em ordem cronológica.

**Indicador de sucesso:** para o caso 07 (refeito), uma linha do tempo que mostra a ordem: mudança de imagem → pods novos falhando → prazo esgotado → undo recusado → correção.

## Conceito

Diagnóstico responde "o quê"; a linha do tempo responde "**quando** e **em que ordem**" — essencial para separar
**gatilho** (o que mudou) de **causa raiz** (por que a mudança quebrou) e de **agravante** (por que não deu para
voltar). Fontes com horário: eventos (`lastTimestamp`), ReplicaSets (`creationTimestamp`), `lastState.terminated`,
condições (`lastTransitionTime`) e logs (`--timestamps`).

## Comandos guiados

```bash
oc apply -f manifests/casos/caso-07.yaml -n ac19-casos && oc rollout status deployment/ac19-c7 -n ac19-casos
oc set image deployment/ac19-c7 web=registry.access.redhat.com/ubi9/httpd-24:9.9-inexistente -n ac19-casos
sleep 75; oc rollout undo deployment/ac19-c7 -n ac19-casos 2>&1 | tail -1
linha_do_tempo() {
  local ns=$1 app=$2
  { oc get events -n "$ns" -o json | jq -r --arg a "$app" '.items[] | select(.involvedObject.name|startswith($a)) | "\(.lastTimestamp // .eventTime)\tevento\t\(.reason)\t\(.message | .[0:90])"'
    oc get rs -n "$ns" -l app="$app" -o json | jq -r '.items[] | "\(.metadata.creationTimestamp)\trs\tcriado\t\(.metadata.name) \(.spec.template.spec.containers[0].image)"'
    oc get deployment "$app" -n "$ns" -o json | jq -r '.status.conditions[] | "\(.lastTransitionTime)\tcondição\t\(.type)=\(.status)\t\(.reason)"'
  } | sort
}
linha_do_tempo ac19-casos ac19-c7
```

## Repetições

1. Marque na linha do tempo: gatilho, causa raiz, agravante.
2. Acrescente os logs com `--timestamps` dos pods novos (há algum? por quê?).
3. Os eventos expiram: o que você perderia se olhasse amanhã?
4. Faça a linha do tempo do caso 02.
5. Escreva a função de memória.

## Desafio sem pista

Converta a linha do tempo em um relatório com horários **relativos** (T+0 s no gatilho), para que um colega entenda a sequência sem fazer contas.

## Diagnóstico controlado

- **Sintoma:** a linha do tempo tem eventos fora de ordem.
- **Hipóteses:** eventos agregados (`count` > 1) guardam o **último** horário; o primeiro está em `firstTimestamp`.
- **Investigação:** `firstTimestamp`, `lastTimestamp` e `count` dos eventos.
- **Reversão:** use `firstTimestamp` para a primeira ocorrência.
