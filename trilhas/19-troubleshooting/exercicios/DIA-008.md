# DIA-008 — Caso 06: depois do endurecimento, nada fala com nada

## Identificação

- **ID:** DIA-008

- **Referência didática:** Metodologia própria da Academia (diagnóstico transversal).

## Objetivo e indicador de sucesso

Diagnosticar e corrigir o caso 06 (rede) sem apagar as políticas: o projeto deve continuar isolado de outros projetos.

**Indicador de sucesso:** o cliente do projeto resolve nomes e acessa o `ac19-c6`; a Route responde; um pod de outro projeto continua bloqueado.

## Conceito

> **Diagnóstico cego.** Aplique o caso **sem ler o manifesto**: o arquivo diz só o sintoma. Cada caso tem
> **mais de um defeito**, em camadas diferentes. Siga o método do DIA-001 e anote cada hipótese antes de testá-la.
> Corrija no cluster (`oc patch`, `oc set ...`) ou em uma cópia em `/tmp/ac19`, nunca no repositório.

Sintoma relatado: "depois do endurecimento, nada fala com nada" — nem a Route, nem o cliente interno. O caso roda no projeto `ac19-rede`.

## Comandos guiados

```bash
oc new-project ac19-rede >/dev/null 2>&1 || true; oc project ac19-casos >/dev/null
oc apply -f manifests/casos/caso-06.yaml -n ac19-rede
sleep 20
oc exec ac19-c6-cliente -n ac19-rede -- timeout 5 getent hosts ac19-c6 || echo "DNS FALHOU"
oc exec ac19-c6-cliente -n ac19-rede -- timeout 3 bash -c '</dev/tcp/ac19-c6/8080' && echo "conexão ok" || echo "conexão FALHOU"
curl -sS -m 5 -o /dev/null -w '%{http_code}\n' "http://$(oc get route ac19-c6 -n ac19-rede -o jsonpath='{.spec.host}')/"
oc get networkpolicy -n ac19-rede
```

## Repetições

1. Quantas coisas distintas estavam bloqueadas?
2. Qual delas a política "mesmo projeto" já resolvia, e por que não bastou?
3. Em que ordem você liberou? Por quê?
4. Prove que `ac19-casos/ac19-cli` continua bloqueado.
5. Refaça do zero sem notas.

## Desafio sem pista

Resolva com no máximo três políticas novas, todas com o rótulo da Academia, sem alterar nem apagar as duas existentes.

## Diagnóstico controlado

- **Sintoma:** `getent hosts` expira dentro do projeto.
- **Hipóteses:** saída negada também para o DNS (TS-050).
- **Investigação:** políticas com `Egress`.
- **Reversão:** libere o DNS (porta 5353 do `openshift-dns`).

## Validação

