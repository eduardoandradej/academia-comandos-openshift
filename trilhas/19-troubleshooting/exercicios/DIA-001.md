# DIA-001 — O método dos sete andares

## Identificação

- **ID:** DIA-001

- **Fichas de comando:** [`oc-describe`](../../../catalogo/fichas/oc-describe.md), [`oc-get-events`](../../../catalogo/fichas/oc-get-events.md)

## Objetivo e indicador de sucesso

Fixar um método único de diagnóstico, do terminal até a rede, e aplicá-lo a uma aplicação **saudável** para conhecer o "normal" de cada andar.

**Indicador de sucesso:** para a aplicação de referência, você mostra a evidência de "ok" em cada um dos sete andares em até 10 comandos.

## Conceito

Os sintomas das trilhas anteriores se encaixam em sete andares, sempre na mesma ordem. Subir de andar só depois de
ver evidência de que o de baixo está ok evita o erro mais caro do troubleshooting: corrigir o andar errado.

| Andar | Pergunta | Primeiro comando |
|---|---|---|
| 1 sessão | sou quem penso, no projeto certo? | `oc whoami; oc project -q` |
| 2 objeto | o objeto existe e está como declarei? | `oc get <tipo> <nome> -o yaml` |
| 3 admissão | a API aceitou criar os pods? | eventos do ReplicaSet/Job (`FailedCreate`) |
| 4 agendamento | o pod tem nó? | `Pending` + `FailedScheduling` |
| 5 início | a imagem baixou e o contêiner iniciou? | `ErrImagePull`, `CreateContainerConfigError` |
| 6 execução | o processo continua vivo e pronto? | `RESTARTS`, `lastState`, probes, `oc logs --previous` |
| 7 rede | o tráfego chega? | endpoints, `targetPort`, NetworkPolicy, Route |

Regras: **leia antes de mudar**; uma hipótese por vez; anote o que descartou; a primeira mensagem nem sempre é a causa (TS-025).

## Comandos guiados

```bash
oc whoami; oc project -q
oc apply -f manifests/apps-exemplo/declarativo-app.yaml -n ac19-casos
oc rollout status deployment/ac12-web -n ac19-casos
oc get deployment,rs,pods -n ac19-casos -l app=ac12-web                                    # andares 2 a 4
oc get pod -n ac19-casos -l app=ac12-web -o jsonpath='{.items[0].status.containerStatuses[0].state}{"\n"}'   # 5 e 6
oc get endpointslices -n ac19-casos -l kubernetes.io/service-name=ac12-web -o jsonpath='{.items[0].endpoints[*].conditions.ready}{"\n"}'   # 7
curl -sS -m 5 "http://$(oc get route ac12-web -n ac19-casos -o jsonpath='{.spec.host}')/"
oc get events -n ac19-casos --field-selector type=Warning
```

## Repetições

1. Para cada andar, anote o comando e a resposta "normal".
2. Recite os sete andares de memória, com uma pergunta cada.
3. Qual andar a Trilha 15 (RBAC) toca? E a 16 (rede)?
4. Por que o andar 1 vem primeiro, se "nunca é ele"?
5. Monte seu cartão de bolso (uma linha por andar).

## Desafio sem pista

Escreva `andares <deployment>` que imprime uma linha por andar com `ok` ou a evidência do problema, para um Deployment qualquer do projeto.

## Diagnóstico controlado

- **Sintoma:** tudo parece certo, mas `curl` na Route falha.
- **Hipóteses:** andar 7 (DNS do cliente, router, Route) — ou o andar 1 do **cliente** (estação errada, `hosts` do Windows).
- **Investigação:** `getent ahostsv4 <host>`; `curl -H 'Host: ...' http://192.168.10.200/` (RTE-002).
- **Reversão:** nada a reverter.

```bash
oc get deployment ac12-web -n ac19-casos -o jsonpath='{.status.readyReplicas}{"\n"}'    # 1
```
