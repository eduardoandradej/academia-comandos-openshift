## Objetivo e indicador de sucesso

Construir a função `triagem <projeto>`, que responde em uma tela: o que não está pronto, o que reinicia, que Services
estão sem endpoints, que Routes não foram admitidas e quais os últimos avisos.

**Indicador de sucesso:** a triagem de um projeto saudável mostra "nada" em todas as seções; a de um caso quebrado aponta o primeiro lugar para olhar.

## Conceito

A triagem não diagnostica: ela **prioriza**. Cinco seções cobrem quase todos os casos das trilhas anteriores:

| Seção | Fonte |
|---|---|
| Deployments/StatefulSets incompletos | `readyReplicas` × `replicas` |
| pods não prontos ou reiniciando | `status.containerStatuses` |
| Services sem endpoints prontos | EndpointSlices |
| Routes não admitidas | `status.ingress[].conditions` |
| últimos avisos | `oc get events --field-selector type=Warning` |

## Comandos guiados

```bash
triagem() {
  local ns=${1:-$(oc project -q)}
  echo "== workloads incompletos"; oc get deploy,sts -n "$ns" -o json | jq -r '.items[] | select((.status.readyReplicas // 0) < .spec.replicas) | "\(.kind)/\(.metadata.name) \(.status.readyReplicas // 0)/\(.spec.replicas)"'
  echo "== pods com problema"; oc get pods -n "$ns" -o json | jq -r '.items[] | select(.status.phase!="Succeeded") | . as $p | .status.containerStatuses[]? | select(.ready|not or .restartCount>0) | "\($p.metadata.name) pronto=\(.ready) reinícios=\(.restartCount) \(.state|keys[0]) \(.state[].reason // "")"'
  echo "== services sem endpoints"; for s in $(oc get svc -n "$ns" -o name | cut -d/ -f2); do [ -z "$(oc get endpointslices -n "$ns" -l kubernetes.io/service-name="$s" -o jsonpath='{.items[*].endpoints[?(@.conditions.ready==true)].addresses[0]}')" ] && echo "$s"; done
  echo "== routes não admitidas"; oc get routes -n "$ns" -o json | jq -r '.items[] | select(([.status.ingress[]?.conditions[]? | select(.type=="Admitted" and .status=="True")] | length) == 0) | .metadata.name'
  echo "== últimos avisos"; oc get events -n "$ns" --field-selector type=Warning --sort-by=.lastTimestamp -o custom-columns=QUANDO:.lastTimestamp,OBJ:.involvedObject.name,MOTIVO:.reason --no-headers 2>/dev/null | tail -5
}
triagem ac19-casos
```

## Desafio sem pista

Estenda a triagem com uma sexta seção, "recusas de admissão", que mostre eventos `FailedCreate` de ReplicaSets e Jobs (quota, LimitRange, SCC).

## Diagnóstico controlado

- **Sintoma:** a triagem mostra um Service sem endpoints, mas os pods estão prontos.
- **Hipóteses:** seletor do Service não casa (TS-010), ou pods prontos em outro Service.
- **Investigação:** `oc get svc <s> -o jsonpath='{.spec.selector}'` × rótulos dos pods.
- **Reversão:** corrija o seletor.
