# DIA-009 — Caso 07: o rollout que não termina e o undo que não volta

## Identificação

- **ID:** DIA-009
- **Trilha:** [19 — Troubleshooting transversal](../README.md)
- **Referência didática:** Metodologia própria da Academia (diagnóstico transversal).
- **Fichas de comando:** [`oc-rollout`](../../../catalogo/fichas/oc-rollout.md)

## Objetivo e indicador de sucesso

Provocar o defeito do caso 07 (uma atualização ruim), diagnosticar o rollout travado e voltar à versão boa — descobrindo por que `rollout undo` não funciona.

**Indicador de sucesso:** o Deployment volta a `2/2` com a imagem boa, e você explica por que o undo falhou.

## Nível

**Nível:** Intermediário

## Duração e repetições

- **Duração sugerida:** 25 min
- **Repetições:** 3× (com intervalo de dias)

- **Perfil:** `developer`

- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL (aplicação de caso)

## Conceito

> **Diagnóstico cego.** Aplique o caso **sem ler o manifesto**: o arquivo diz só o sintoma. Cada caso tem
> **mais de um defeito**, em camadas diferentes. Siga o método do DIA-001 e anote cada hipótese antes de testá-la.
> Corrija no cluster (`oc patch`, `oc set ...`) ou em uma cópia em `/tmp/ac19`, nunca no repositório.

Sintoma relatado (depois da atualização): "o deploy de ontem nunca terminou; mandei desfazer e deu erro".

## Comandos guiados

```bash
oc apply -f manifests/casos/caso-07.yaml -n ac19-casos
oc rollout status deployment/ac19-c7 -n ac19-casos
oc set image deployment/ac19-c7 web=registry.access.redhat.com/ubi9/httpd-24:9.9-inexistente -n ac19-casos   # a "atualização de ontem"
sleep 70; oc rollout status deployment/ac19-c7 -n ac19-casos --timeout=5s
oc rollout undo deployment/ac19-c7 -n ac19-casos
# por que não voltou? leia o Deployment
```

## Repetições

1. Os pods antigos continuaram atendendo durante o rollout ruim? Por quê? (`maxUnavailable: 0`)
2. Que condição mostrou o travamento? (`Progressing`, `ProgressDeadlineExceeded`)
3. Por que o `undo` respondeu que não há histórico?
4. Qual o valor seguro de `revisionHistoryLimit`?
5. Refaça do zero sem notas.

## Desafio sem pista

Volte à versão boa **sem** `rollout undo`, corrija a configuração que impediu o undo e prove que o próximo undo funcionaria.

## Diagnóstico controlado

- **Sintoma:** `error: no rollout history found for deployment "ac19-c7"`.
- **Hipóteses:** `revisionHistoryLimit: 0` apaga os ReplicaSets antigos.
- **Investigação:** `oc get rs -n ac19-casos -l app=ac19-c7`; `spec.revisionHistoryLimit`.
- **Reversão:** volte declarando a imagem boa e aumente o limite.

## Validação

```bash
oc get deployment ac19-c7 -n ac19-casos -o jsonpath='{.status.readyReplicas}/{.spec.replicas} {.spec.revisionHistoryLimit}{"\n"}'   # 2/2 e > 0
```

## Limpeza segura

```bash
oc delete -f manifests/casos/caso-07.yaml -n ac19-casos --ignore-not-found
```
