## Objetivo e indicador de sucesso

Diagnosticar e corrigir o caso 01 (dois defeitos), registrando em que andar cada um apareceu.

**Indicador de sucesso:** `t` de dentro do projeto recebe a página pelo Service `ac19-c1`, e você nomeia os dois andares envolvidos.

**Nível:** Intermediário

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Diagnóstico cego.** Aplique o caso **sem ler o manifesto**: o arquivo diz só o sintoma. Cada caso tem
> **mais de um defeito**, em camadas diferentes. Siga o método do DIA-001 e anote cada hipótese antes de testá-la.
> Corrija no cluster (`oc patch`, `oc set ...`) ou em uma cópia em `/tmp/ac19`, nunca no repositório.

Sintoma relatado: "a vitrine nova não responde pelo Service". Teste de dentro do cluster com um pod cliente (Trilha 06).

## Comandos guiados

```bash
oc apply -f manifests/casos/caso-01.yaml -n ac19-casos
oc run ac19-cli --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac19-casos --labels=academy.openshift.dev/managed-by=academia --command -- sleep 86400 2>/dev/null || true
t() { oc exec ac19-cli -n ac19-casos -- timeout 3 bash -c "exec 3<>/dev/tcp/$1/${2:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && head -1 <&3" 2>/dev/null || echo FALHOU; }
sleep 20; triagem ac19-casos 2>/dev/null || oc get pods,svc -n ac19-casos
t ac19-c1
# agora: andar por andar, uma hipótese por vez
```

## Repetições

1. Qual defeito você encontrou primeiro? Ele explicava todo o sintoma?
2. Depois de corrigir o primeiro, o sintoma mudou? Para qual?
3. Que comando revelou o segundo defeito?
4. Refaça o caso do zero sem consultar suas notas.
5. Quanto tempo levou (1ª, 2ª e 3ª vez)?

## Desafio sem pista

Resolva o caso sem `oc edit`: só com `oc set image`, `oc set selector` ou `oc patch`, e prove com `t ac19-c1`.

## Diagnóstico controlado

- **Sintoma:** depois de corrigir a imagem, o pod fica `Running`, mas `t` continua `FALHOU`.
- **Hipóteses:** o sintoma tinha duas causas; agora o problema está no andar 7.
- **Investigação:** EndpointSlices do Service; seletor × rótulos.
- **Reversão:** corrija a segunda causa.

## Validação

```bash
oc get endpointslices -n ac19-casos -l kubernetes.io/service-name=ac19-c1 -o jsonpath='{.items[0].endpoints[*].conditions.ready}{"\n"}'   # true
```
