## Objetivo e indicador de sucesso

Aplicar um roteiro fixo para qualquer problema de volume: pod, PVC, PV/classe, quota, permissões e uso de espaço.

**Indicador de sucesso:** você classifica três falhas provocadas (PVC pendente, volume ausente, sem permissão) pelo passo do roteiro em que aparecem.

As falhas 1 e 2 não precisam de preparação; a 3 precisa de um PVC (REQUER PREPARAÇÃO).

## Conceito

| # | Pergunta | Comando |
|---|---|---|
| 1 | Em que estado está o pod e o que dizem os eventos? | `oc describe pod <pod> \| sed -n '/Events:/,$p'` |
| 2 | O PVC existe e está `Bound`? | `oc get pvc <pvc>`; `oc describe pvc <pvc>` |
| 3 | Há classe/PV que atenda? | `oc get sc`; (admin) `oc get pv` |
| 4 | A quota permite? | `oc describe quota` |
| 5 | O contêiner consegue gravar? | `oc exec ... -- sh -c 'id; ls -ldn <caminho>; touch <caminho>/t'` |
| 6 | Há espaço? | `oc exec ... -- df -h <caminho>` |

## Comandos guiados

```bash
# falha 1: PVC que nunca liga (classe inexistente)
oc apply -n ac09-storage -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: ac09-falha1
  labels:
    academy.openshift.dev/managed-by: academia
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: classe-que-nao-existe
  resources:
    requests:
      storage: 100Mi
EOF
oc describe pvc ac09-falha1 -n ac09-storage | sed -n '/Events:/,$p'
# falha 2: pod que monta um PVC inexistente
oc run ac09-falha2 -n ac09-storage --image=registry.access.redhat.com/ubi9/httpd-24:latest \
  --labels=academy.openshift.dev/managed-by=academia \
  --overrides='{"spec":{"volumes":[{"name":"d","persistentVolumeClaim":{"claimName":"pvc-que-nao-existe"}}],"containers":[{"name":"ac09-falha2","image":"registry.access.redhat.com/ubi9/httpd-24:latest","volumeMounts":[{"name":"d","mountPath":"/d"}]}]}}'
oc describe pod ac09-falha2 -n ac09-storage | sed -n '/Events:/,$p'
# falha 3 (REQUER PREPARAÇÃO): montagem somente leitura
oc set volume deployment/ac09-app --add --name=dados --type=pvc --claim-name=ac09-dados --mount-path=/dados --read-only=true --overwrite -n ac09-storage
oc rollout status deployment/ac09-app -n ac09-storage
oc exec deploy/ac09-app -n ac09-storage -- sh -c 'touch /dados/t' ; echo "rc=$?"
```

## Repetições

1. Para cada falha, diga em qual passo do roteiro ela apareceu.
2. Sem preparação, a falha 1 dá `Forbidden` (quota) em vez de `Pending`: em que passo isso entra?
3. Encontre a falha 2 só pelos eventos do projeto (`oc get events --field-selector type=Warning`).
4. Corrija a falha 3 voltando a montagem para leitura e escrita.
5. Escreva o roteiro de memória.

## Desafio sem pista

Escreva uma função `diag_vol <pod>` que, para cada PVC montado pelo pod, imprima a fase do PVC, a classe e o último
evento de aviso relacionado ao pod ou ao PVC.

## Diagnóstico controlado

- **Sintoma:** pod em `Pending` com `persistentvolumeclaim "pvc-que-nao-existe" not found`.
- **Hipóteses:** nome do PVC errado ou PVC em outro projeto (PVC é do namespace).
- **Investigação:** `oc get pvc -n ac09-storage`; `claimName` no pod.
- **Reversão:** `oc delete pod ac09-falha2 -n ac09-storage`.

## Validação

```bash
oc get pvc ac09-falha1 -n ac09-storage -o jsonpath='{.status.phase}{"\n"}' 2>/dev/null || echo "recusado pela quota (sem preparação)"
```

## Limpeza segura

```bash
oc delete pvc ac09-falha1 -n ac09-storage --ignore-not-found
oc delete pod ac09-falha2 -n ac09-storage --ignore-not-found
oc set volume deployment/ac09-app --add --name=dados --type=pvc --claim-name=ac09-dados --mount-path=/dados --overwrite -n ac09-storage 2>/dev/null || true
```
