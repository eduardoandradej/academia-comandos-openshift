## Objetivo e indicador de sucesso

Classificar os tipos de volume pelo tempo de vida dos dados e descobrir quais volumes os seus pods já usam.

**Indicador de sucesso:** você lista os volumes dos pods de um projeto seu e classifica cada um (efêmero, configuração, persistente).

## Conceito

| Tipo | Os dados vivem até | Uso típico | Trilha |
|---|---|---|---|
| sistema de arquivos do contêiner | o contêiner reiniciar | nada importante | 04 |
| `emptyDir` | o **pod** ser removido | cache, troca entre contêineres | 09 |
| `emptyDir` com `medium: Memory` | o pod ser removido (em RAM) | dados temporários rápidos | 09 |
| `configMap`, `secret`, `projected`, `downwardAPI` | o objeto de origem existir | configuração | 08 |
| `persistentVolumeClaim` | o PVC (e a política do PV) | dados da aplicação | 09 (REQUER PREPARAÇÃO) |
| `hostPath` | o nó | — **proibido** na Academia (SCC `restricted-v2` bloqueia) | — |

No OpenShift, a SCC `restricted-v2` (padrão para `developer`) só permite tipos seguros: `configMap`, `downwardAPI`,
`emptyDir`, `ephemeral`, `persistentVolumeClaim`, `projected` e `secret`.

## Comandos guiados

```bash
oc explain pod.spec.volumes | sed -n '1,25p'
oc explain pod.spec.volumes.emptyDir
oc explain pod.spec.containers.volumeMounts
oc get pods -A -l academy.openshift.dev/managed-by=academia 2>/dev/null | head      # pode ser Forbidden: normal
oc get pods -n ac08-config -o jsonpath='{range .items[*]}{.metadata.name}{": "}{.spec.volumes[*].name}{"\n"}{end}' 2>/dev/null
oc get pods -n ac08-config -o json 2>/dev/null | jq -r '.items[] | .metadata.name as $p | .spec.volumes[] | "\($p)\t\(.name)\t\(keys - ["name"] | join(","))"'
oc get scc restricted-v2 -o jsonpath='{.volumes}{"\n"}' 2>/dev/null || echo "leitura de SCC exige perfil admin"
```

## Repetições

1. Rode o `jq` em outro projeto seu e classifique cada volume pela tabela.
2. Encontre o volume que todo pod recebe automaticamente (`kube-api-access-*`). De que tipo ele é?
3. `oc explain pod.spec.volumes.persistentVolumeClaim`.
4. (admin) Compare `oc get scc restricted-v2 -o jsonpath='{.volumes}'` com `oc get scc anyuid -o jsonpath='{.volumes}'`.
5. Explique por que `hostPath` é perigoso em um SNO.

## Desafio sem pista

Escreva um único comando que liste, para cada pod de um projeto, os **caminhos de montagem** de cada contêiner e o
**tipo** do volume montado ali.

## Diagnóstico controlado

- **Sintoma:** um Deployment com `hostPath` fica sem pods; o ReplicaSet mostra `FailedCreate ... unable to validate against any security context constraint`.
- **Hipóteses:** a SCC do usuário não permite o tipo `hostPath`.
- **Investigação:** `oc describe rs -l app=<nome> | sed -n '/Events:/,$p'`.
- **Reversão:** use `emptyDir` ou PVC. Pedir SCC `privileged` "para resolver" é exatamente o atalho proibido.

## Validação

```bash
oc explain pod.spec.volumes.emptyDir.sizeLimit >/dev/null && echo "esquema consultado"
```
