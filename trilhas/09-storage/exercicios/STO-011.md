## Conceito

| Modo | Limite real |
|---|---|
| `ReadWriteOnce` (RWO) | montado como leitura/escrita por **um nó** — em um SNO, por todos os pods |
| `ReadWriteMany` (RWX) | vários nós (NFS suporta; LVMS não) |
| `ReadOnlyMany` (ROX) | vários nós, só leitura |
| `ReadWriteOncePod` (RWOP) | **um pod** no cluster inteiro (só volumes CSI: opção B) |

Consequência: em clusters com vários nós, um Deployment RWO com `RollingUpdate` pode travar (`Multi-Attach error`)
quando o pod novo cai em outro nó. Por isso workloads com PVC RWO costumam usar estratégia `Recreate`.

## Comandos guiados

```bash
oc scale deployment/ac09-app --replicas=2 -n ac09-storage
oc rollout status deployment/ac09-app -n ac09-storage
oc get pods -n ac09-storage -l app=ac09-app -o wide                       # 2 pods, mesmo nó, mesmo PVC
for p in $(oc get pods -n ac09-storage -l app=ac09-app -o name); do oc exec -n ac09-storage "$p" -- sh -c "hostname >> /dados/quem.txt"; done
oc exec deploy/ac09-app -n ac09-storage -- cat /dados/quem.txt            # as duas réplicas gravaram
oc scale deployment/ac09-app --replicas=1 -n ac09-storage
oc patch deployment ac09-app -n ac09-storage --type=merge -p '{"spec":{"strategy":{"type":"Recreate","rollingUpdate":null}}}'
oc get deployment ac09-app -n ac09-storage -o jsonpath='{.spec.strategy.type}{"\n"}'
```

## Repetições

1. (opção B) Crie um PVC `ReadWriteOncePod`, monte-o em um Deployment com 2 réplicas e leia o motivo do `Pending`.
2. (opção A) Crie um PVC `ReadWriteMany` e veja se liga a um PV NFS.
3. Por que a estratégia `Recreate` causa uma pequena indisponibilidade?
4. O que aconteceria com o RWO em um cluster de 3 nós? (conceitual)
5. Volte o `ac09-app` para `RollingUpdate` e depois para `Recreate` de memória.

## Desafio sem pista

Explique, e prove com o que o seu armazenamento permite, por que duas réplicas gravando o mesmo arquivo ao mesmo
tempo é um problema da **aplicação**, não do Kubernetes.

## Diagnóstico controlado

- **Sintoma (multinó):** `Multi-Attach error for volume "pvc-..." Volume is already exclusively attached to one node`.
- **Hipóteses:** RWO montado em outro nó por um pod antigo durante o rolling update.
- **Investigação:** `oc describe pod <novo>`; nós dos pods (`-o wide`).
- **Reversão:** estratégia `Recreate`, ou armazenamento RWX. No SNO, o sintoma não aparece — mas o hábito vale.
