# STO-003 — emptyDir em Deployment: o que sobrevive a quê

## Identificação

- **ID:** STO-003
- **Trilha:** [09 — Storage](../README.md)
- **Referência didática:** DO180 — armazenamento para aplicações (ciclo de vida).
- **Fichas de comando:** [`oc-set-volume`](../../../catalogo/fichas/oc-set-volume.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Acrescentar um `emptyDir` a um Deployment com `oc set volume` e provar o ciclo de vida: sobrevive ao reinício do
contêiner, some quando o pod é substituído.

**Indicador de sucesso:** o arquivo continua após o reinício do contêiner (`RESTARTS` 1) e some após `rollout restart`.

## Conceito

> **SSD do HomeLab.** `emptyDir` e armazenamento efêmero gravam no disco do único nó (QCOW2 no SSD). Os exercícios
> usam no máximo algumas dezenas de MiB; não aumente esses valores.

| Evento | Sistema de arquivos do contêiner | `emptyDir` |
|---|---|---|
| contêiner reinicia (crash, liveness) | perdido | **mantido** |
| pod apagado / `rollout restart` / nova revisão | perdido | perdido |

Por isso `emptyDir` serve para cache e arquivos temporários, nunca para dados que precisam sobreviver a um deploy.

## Comandos guiados

```bash
oc create deployment ac09-app --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac09-storage
oc label deployment ac09-app academy.openshift.dev/managed-by=academia -n ac09-storage
oc set volume deployment/ac09-app --add --name=cache --type=emptyDir --mount-path=/cache -n ac09-storage
oc rollout status deployment/ac09-app -n ac09-storage
oc exec deploy/ac09-app -n ac09-storage -- sh -c 'date > /cache/marca.txt; date > /tmp/marca.txt'
oc exec deploy/ac09-app -n ac09-storage -- sh -c 'kill 1'                     # derruba o processo principal
sleep 15; oc get pods -n ac09-storage -l app=ac09-app                           # RESTARTS 1
oc exec deploy/ac09-app -n ac09-storage -- sh -c 'cat /cache/marca.txt; cat /tmp/marca.txt'   # /cache sim, /tmp não
oc rollout restart deployment/ac09-app -n ac09-storage && oc rollout status deployment/ac09-app -n ac09-storage
oc exec deploy/ac09-app -n ac09-storage -- ls /cache                            # vazio
```

## Repetições

1. Repita o ciclo e anote o nome do pod em cada etapa: quando ele muda?
2. Liste os volumes com `oc set volume deployment/ac09-app -n ac09-storage`.
3. Remova e recoloque o volume (`--remove --name=cache`).
4. Escale para 2 réplicas: os pods compartilham o `/cache`?
5. Explique por que o `kill 1` não apagou o `/cache`.

## Desafio sem pista

Acrescente ao `ac09-app` um `emptyDir` chamado `trabalho` com `sizeLimit` de 32Mi montado em `/trabalho`, sem
`oc edit`, e prove o limite no YAML do pod.

## Diagnóstico controlado

- **Sintoma:** "os dados do cache sumiram depois do deploy de ontem".
- **Hipóteses:** `emptyDir` é recriado a cada pod novo.
- **Investigação:** `oc rollout history deployment/ac09-app`; idade dos pods (`oc get pods`).
- **Reversão:** é o comportamento esperado; dados que precisam ficar vão para PVC. Veja TS-029.

## Validação

```bash
oc set volume deployment/ac09-app -n ac09-storage | grep -q 'empty directory as cache' && echo OK
```
