# STO-012 — Expandir um PVC

## Identificação

- **ID:** STO-012
- **Trilha:** [09 — Storage](../README.md)
- **Referência didática:** DO280 — armazenamento persistente (expansão).
- **Fichas de comando:** [`oc-pvc-storage`](../../../catalogo/fichas/oc-pvc-storage.md)

## Objetivo e indicador de sucesso

Aumentar o tamanho de um PVC em uso, acompanhar as condições da expansão e entender por que não é possível diminuir.

**Indicador de sucesso:** `status.capacity.storage` passa de 500Mi para 1Gi e o `df` dentro do pod mostra o tamanho novo.

**REQUER PREPARAÇÃO** — feita uma vez, pelo admin, conforme [docs/10-preparacao-storage.md](../../../docs/10-preparacao-storage.md):
PVs estáticos por NFS (opção A) ou LVM Storage (opção B), e a quota do `ac09-storage` liberando PVCs.

```bash
export SC=ac09-nfs        # opção A; na opção B: export SC=lvms-vg1
oc get resourcequota -n ac09-storage -o jsonpath='{range .items[*]}{.metadata.name}{": pvc="}{.spec.hard.persistentvolumeclaims}{" storage="}{.spec.hard.requests\.storage}{"\n"}{end}'
# esperado: pvc >= 3 e storage >= 3Gi; "pvc=0" significa que a preparação não foi feita
```

Sem a preparação, leia o exercício e faça só as partes de leitura e `--dry-run=client`.

Este exercício exige a **opção B** (provisionamento dinâmico com `allowVolumeExpansion`). Na opção A, faça só a leitura.

## Conceito

Expansão exige `allowVolumeExpansion: true` na StorageClass. Basta aumentar `spec.resources.requests.storage`; o
controlador expande o volume e, se preciso, o sistema de arquivos (condição `FileSystemResizePending` até o pod
remontar). **Reduzir não é permitido.** PVs estáticos NFS (opção A) não expandem — o tamanho NFS é só um rótulo.

## Comandos guiados

```bash
oc get storageclass "$SC" -o jsonpath='{.allowVolumeExpansion}{"\n"}'            # true na opção B
oc exec deploy/ac09-app -n ac09-storage -- df -h /dados
oc patch pvc ac09-dados -n ac09-storage --type=merge -p '{"spec":{"resources":{"requests":{"storage":"1Gi"}}}}'
oc get pvc ac09-dados -n ac09-storage -o jsonpath='{.spec.resources.requests.storage} -> {.status.capacity.storage}{"\n"}'
oc get pvc ac09-dados -n ac09-storage -o jsonpath='{range .status.conditions[*]}{.type}={.status} {.message}{"\n"}{end}'
oc describe pvc ac09-dados -n ac09-storage | sed -n '/Events:/,$p'
oc exec deploy/ac09-app -n ac09-storage -- df -h /dados
```

## Repetições

1. Tente reduzir para 500Mi e leia o erro.
2. Tente passar do `requests.storage` da quota (3Gi no total do projeto).
3. Se aparecer `FileSystemResizePending`, faça `rollout restart` e confira.
4. Na opção A, rode o mesmo patch e leia a recusa.
5. `oc explain storageclass.allowVolumeExpansion`.

## Desafio sem pista

Expanda o PVC para 1536Mi garantindo antes, só com leitura, que a quota do projeto comporta o aumento.

## Diagnóstico controlado

- **Sintoma:** `spec.resources.requests.storage: Forbidden: field can not be less than previous value` (redução), ou `only dynamically provisioned pvc can be resized and the storageclass that provisions the pvc must support resize`.
- **Hipóteses:** redução proibida; classe sem `allowVolumeExpansion`; PV estático.
- **Investigação:** `oc get sc "$SC" -o yaml | grep allowVolumeExpansion`; `oc get pvc -o jsonpath='{.spec.storageClassName}'`.
- **Reversão:** nada foi alterado na recusa. Para "diminuir", crie um PVC menor e copie os dados.

## Validação

```bash
oc get pvc ac09-dados -n ac09-storage -o jsonpath='{.status.capacity.storage}{"\n"}'     # 1Gi (opção B)
```

## Limpeza segura

Não há como desfazer a expansão; o PVC é apagado no STO-015.
