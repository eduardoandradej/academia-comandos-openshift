## Conceito

| Campo | Significado |
|---|---|
| `accessModes` | `ReadWriteOnce` (um **nó** grava), `ReadOnlyMany`, `ReadWriteMany`, `ReadWriteOncePod` (um **pod**) |
| `resources.requests.storage` | tamanho mínimo pedido |
| `storageClassName` | classe (dinâmico) ou rótulo de ligação com PVs estáticos; `""` = só PVs sem classe |
| `volumeMode` | `Filesystem` (padrão) ou `Block` |
| `selector` | ligar só a PVs com certos rótulos (estático) |

Em um SNO, `ReadWriteOnce` permite vários pods **no mesmo nó** — ou seja, todos. Para exclusividade real, `ReadWriteOncePod` (só drivers CSI).

## Comandos guiados

```bash
oc explain persistentvolumeclaim.spec
oc explain persistentvolumeclaim.spec.accessModes
cat > /tmp/ac09-pvc.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: ac09-rascunho
  labels:
    academy.openshift.dev/managed-by: academia
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: ac09-nfs
  resources:
    requests:
      storage: 500Mi
EOF
oc apply --dry-run=client -f /tmp/ac09-pvc.yaml -n ac09-storage -o yaml | head -20
oc apply --dry-run=server -f /tmp/ac09-pvc.yaml -n ac09-storage; echo "rc=$?"
oc describe quota -n ac09-storage 2>/dev/null | grep -Ei 'persistentvolumeclaims|requests.storage' || echo "sem quota no projeto"
```

## Repetições

1. Troque `accessModes` para `ReadWriteMany` e valide no cliente.
2. Escreva `storage: 500MB` (sem o `i`) e compare com `500Mi` (`oc explain` não ajuda: veja a diferença de bytes).
3. Tire `storageClassName`: o que o cluster faria com uma StorageClass padrão? E sem nenhuma?
4. Gere o mesmo PVC com `oc set volume ... --claim-size --dry-run=client -o yaml` (STO-009).
5. Reescreva o YAML de memória.

## Desafio sem pista

Sem criar nada, preveja e depois confirme pelo `--dry-run=server` qual das restrições do projeto barra um PVC de
5Gi: a contagem de PVCs ou `requests.storage`? (Se a preparação foi feita, use 5Gi para estourar `requests.storage`.)

## Diagnóstico controlado

- **Sintoma:** `Error from server (Forbidden): ... exceeded quota: ac-quota, requested: persistentvolumeclaims=1, used: persistentvolumeclaims=0, limited: persistentvolumeclaims=0`.
- **Hipóteses:** a baseline da Academia proíbe PVCs (limite 0) de propósito.
- **Investigação:** `oc describe quota -n ac09-storage`.
- **Reversão:** nada foi criado. Liberar PVCs é a etapa de preparação do admin (docs/10).

## Validação

```bash
oc apply --dry-run=client -f /tmp/ac09-pvc.yaml -n ac09-storage -o name     # persistentvolumeclaim/ac09-rascunho
```
