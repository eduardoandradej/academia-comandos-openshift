## Conceito

| Objeto | Escopo | Pergunta que responde |
|---|---|---|
| StorageClass | cluster | existe provisionamento dinâmico? qual é a padrão? |
| PersistentVolume | cluster | que volumes existem e a quem estão ligados? |
| PersistentVolumeClaim | namespace | o que cada aplicação pediu? |
| CSIDriver / CSINode | cluster | que drivers estão instalados no nó? |
| ResourceQuota | namespace | quantos PVCs/GiB o projeto pode pedir? |

No checkpoint do HomeLab: **0 StorageClasses e 0 PVs** — por isso PV/PVC REQUER PREPARAÇÃO
([docs/10-preparacao-storage.md](../../../docs/10-preparacao-storage.md)).

## Comandos guiados

```bash
oc get storageclass
oc get sc -o jsonpath='{range .items[*]}{.metadata.name}{" padrão="}{.metadata.annotations.storageclass\.kubernetes\.io/is-default-class}{" provisioner="}{.provisioner}{"\n"}{end}'
oc get pv
oc get pvc -A
oc get csidrivers
oc get csinode -o jsonpath='{range .items[*]}{.metadata.name}{": "}{.spec.drivers[*].name}{"\n"}{end}'
oc get resourcequota -A -o json | jq -r '.items[] | select(.spec.hard.persistentvolumeclaims) | "\(.metadata.namespace)\t\(.spec.hard.persistentvolumeclaims)"'
ac-dev
```

## Repetições

1. `oc get pv -o custom-columns=NOME:.metadata.name,TAM:.spec.capacity.storage,STATUS:.status.phase,DONO:.spec.claimRef.name`.
2. `oc explain storageclass` e `oc explain persistentvolume.spec.persistentVolumeReclaimPolicy`.
3. Por que o Prometheus do HomeLab perde histórico em reinícios? (procure PVCs em `openshift-monitoring`)
4. Como developer: `oc get storageclass` funciona? E `oc get pv`?
5. Depois da preparação (opção A ou B), repita tudo e compare.

## Desafio sem pista

Escreva um relatório de uma linha por PV: nome, capacidade, política de retenção, status e `namespace/pvc` ligado (ou `livre`).

## Diagnóstico controlado

- **Sintoma:** `oc get pv` como developer → `Forbidden ... cannot list resource "persistentvolumes" ... at the cluster scope`.
- **Hipóteses:** PV é recurso de cluster; developer não tem leitura nele.
- **Investigação:** `oc auth can-i list persistentvolumes`.
- **Reversão:** use o perfil admin para leitura; developer vê o próprio PVC e o nome do PV em `spec.volumeName`.
