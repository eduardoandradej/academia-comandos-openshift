## Objetivo e indicador de sucesso

## Conceito

| `imagePullPolicy` | Comportamento | Padrão quando |
|---|---|---|
| `Always` | consulta o registry a cada início de contêiner (baixa só se o digest mudou) | tag `latest` ou sem tag |
| `IfNotPresent` | usa o cache do nó se existir | qualquer outra tag ou digest |
| `Never` | nunca baixa; falha se não estiver no cache | — |

Em um SNO, o cache é um só: depois do primeiro pull, `IfNotPresent` não toca o registry — e uma tag atualizada no
registry **não** chega ao pod.

## Comandos guiados

```bash
oc get project ac10-imagens >/dev/null 2>&1 || oc new-project ac10-imagens --display-name='Academia 10 - Imagens'
oc run ac10-always --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac10-imagens --labels=academy.openshift.dev/managed-by=academia
oc run ac10-ifnp --image=registry.access.redhat.com/ubi9/httpd-24:latest --image-pull-policy=IfNotPresent -n ac10-imagens --labels=academy.openshift.dev/managed-by=academia
oc run ac10-never --image=registry.access.redhat.com/ubi9/ubi-minimal:9.9-naoexiste --image-pull-policy=Never -n ac10-imagens --labels=academy.openshift.dev/managed-by=academia
sleep 20
oc get pods -n ac10-imagens -l academy.openshift.dev/managed-by=academia -o custom-columns=POD:.metadata.name,POLITICA:.spec.containers[0].imagePullPolicy,STATUS:.status.containerStatuses[0].state
oc get events -n ac10-imagens --sort-by=.lastTimestamp | grep -E 'Pull|already present|ErrImageNeverPull' | tail -8
```

## Repetições

1. Qual política o `oc run` atribuiu ao pod com `:latest` sem `--image-pull-policy`?
2. Apague e recrie o `ac10-always`: aparece `Pulling` de novo? (sim: consulta o registry)
3. Crie um pod com `registry.access.redhat.com/ubi9/ubi-minimal:latest` e `Never`. Funciona? (depende do cache do nó)
4. Leia o motivo de `ac10-never` (`ErrImageNeverPull`).
5. Por que `Always` não significa "baixar tudo de novo"?

## Desafio sem pista

Descubra, sem acesso ao nó, se a imagem `ubi-minimal:latest` já está no cache do SNO (dica: um pod com `Never`).

## Diagnóstico controlado

- **Sintoma:** `ErrImageNeverPull: Container image "..." is not present with pull policy of Never`.
- **Hipóteses:** a imagem não está no cache do nó e a política proíbe o pull.
- **Investigação:** eventos do pod.
- **Reversão:** apague o pod; use `IfNotPresent` (ou baixe a imagem com outro pod antes).

## Validação

```bash
oc get pod ac10-ifnp -n ac10-imagens -o jsonpath='{.spec.containers[0].imagePullPolicy}{"\n"}'    # IfNotPresent
```

## Limpeza segura

```bash
oc delete pod ac10-always ac10-ifnp ac10-never ac10-cache -n ac10-imagens --ignore-not-found
```
