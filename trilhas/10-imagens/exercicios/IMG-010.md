## Conceito

| `managementState` | Significado |
|---|---|
| `Managed` | registry ativo; precisa de armazenamento configurado |
| `Removed` | registry desligado (padrão em instalações bare metal/SNO sem storage compartilhado) |
| `Unmanaged` | operador não gerencia |

Ativar o registry exige armazenamento (PVC RWX, ou `emptyDir` só para testes — os dados somem a cada reinício) e é
uma **mudança de cluster**: **REQUER PREPARAÇÃO** com autorização, fora da Academia. Com ele desligado, builds com
saída em ImageStream (Trilha futura) e `referencePolicy: Local` não funcionam; ImageStreams com `Source` funcionam.

## Comandos guiados

```bash
oc get configs.imageregistry.operator.openshift.io cluster -o jsonpath='{.spec.managementState}{"\n"}'
oc get configs.imageregistry.operator.openshift.io cluster -o json | jq '.spec.storage, .spec.defaultRoute, .spec.replicas'
oc get co image-registry
oc get pods -n openshift-image-registry
oc get route -n openshift-image-registry 2>/dev/null
oc get image.config.openshift.io cluster -o json | jq '.spec, .status.internalRegistryHostname'
ac-dev
```

## Repetições

1. Qual é o `internalRegistryHostname`? Ele responde se o registry está `Removed`?
2. Leia as condições do ClusterOperator `image-registry` (`oc get co image-registry -o yaml | grep -A3 'type: Available'`).
3. O que o `image-pruner` (CronJob em `openshift-image-registry`) faz? (leitura)
4. Liste os ImageStreams do namespace `openshift` (imagens de exemplo do cluster).
5. Explique por que `emptyDir` no registry é ruim em um SNO com SSD limitado.

## Desafio sem pista

Escreva um "relatório de prontidão" de 4 linhas: estado do registry, tipo de armazenamento, Route padrão (sim/não) e
se `referencePolicy: Local` funcionaria — tudo por comandos.

## Diagnóstico controlado

- **Sintoma:** uma tag com `--reference-policy=local` importa, mas o pod falha ao baixar `image-registry.openshift-image-registry.svc:5000/...`.
- **Hipóteses:** registry interno `Removed`; o Service não tem endpoints.
- **Investigação:** `managementState`; `oc get svc,endpoints -n openshift-image-registry` (leitura).
- **Reversão:** use `referencePolicy: Source`. Ativar o registry é decisão de manutenção do cluster.
