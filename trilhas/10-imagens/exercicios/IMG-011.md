## Objetivo e indicador de sucesso

Ler (sem alterar) as políticas de imagem do cluster: registries bloqueados/permitidos, inseguros, espelhos (IDMS/ITMS/ICSP).

## Conceito

| Objeto | Para que serve |
|---|---|
| `image.config.openshift.io/cluster` | `registrySources` (`allowedRegistries`, `blockedRegistries`, `insecureRegistries`), CA adicional |
| `ImageDigestMirrorSet` (IDMS) | espelhos para referências por **digest** |
| `ImageTagMirrorSet` (ITMS) | espelhos para referências por **tag** |
| `ImageContentSourcePolicy` (ICSP) | forma **legada** de espelhos (catálogo 137) |

Alterar esses objetos gera atualização do `machine-config` e reinício do nó em um SNO — **proibido** pela Academia.

## Comandos guiados

```bash
oc get image.config.openshift.io cluster -o jsonpath='{.spec.registrySources}{"\n"}'
oc get image.config.openshift.io cluster -o jsonpath='{.spec.additionalTrustedCA}{"\n"}'
oc get imagedigestmirrorsets,imagetagmirrorsets 2>/dev/null
oc get imagecontentsourcepolicy 2>/dev/null
oc get image.config.openshift.io cluster -o jsonpath='{.status}{"\n"}'
ac-dev
```

## Repetições

1. `oc explain image.spec.registrySources`.
2. Se `allowedRegistries` existisse com só `registry.redhat.io`, o `httpd-24` da `registry.access.redhat.com` rodaria?
3. Por que uma mudança aqui reinicia o nó? (o que é renderizado no `machine-config`?)
4. Encontre a lista de registries de busca (`unqualified-search-registries`) — conceitual: ela vive no nó.
5. Explique quando um IDMS é usado (instalação desconectada).

## Desafio sem pista

Faça um comando que diga, para uma referência de imagem qualquer, se o registry dela está explicitamente bloqueado,
explicitamente permitido ou sem regra no cluster.

## Diagnóstico controlado

- **Sintoma:** pod com `ErrImagePull` e mensagem `Source image rejected: Running image ... is rejected by policy`.
- **Hipóteses:** registry fora de `allowedRegistries` ou em `blockedRegistries`.
- **Investigação:** `registrySources` acima.
- **Reversão:** use uma imagem de registry permitido. Mudar a política é manutenção do cluster (reinicia o nó).
