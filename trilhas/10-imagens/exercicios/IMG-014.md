# IMG-014 — Roteiro de diagnóstico de imagens

## Identificação

- **ID:** IMG-014
- **Trilha:** [10 — Imagens e registries](../README.md)
- **Referência didática:** Metodologia própria da Academia (troubleshooting).
- **Fichas de comando:** [`oc-image-imagestream`](../../../catalogo/fichas/oc-image-imagestream.md), [`oc-get-events`](../../../catalogo/fichas/oc-get-events.md)

## Objetivo e indicador de sucesso

Classificar falhas de imagem pela mensagem: nome inválido, tag/repo inexistente, nome curto, credencial, política e cache.

**Indicador de sucesso:** quatro pods quebrados de jeitos diferentes, cada um classificado em um passo do roteiro.

## Nível

**Nível:** Avançado

- **Duração sugerida:** 20 min
- **Repetições:** 5×

## Conceito

| # | Pergunta | Mensagem típica |
|---|---|---|
| 1 | O nome é válido? | `InvalidImageName` (maiúsculas, `:` duplo) — nem tenta baixar |
| 2 | O registry responde? | `no such host`, `connection refused`, `i/o timeout` |
| 3 | O repositório/tag existe? | `manifest unknown`, `not found` |
| 4 | Precisa de credencial? | `unauthorized`, `authentication required` |
| 5 | É nome curto sem lookup? | `short name`, `docker.io/library/...` |
| 6 | A política permite? | `rejected by policy`, `ErrImageNeverPull` |

## Comandos guiados

```bash
L=academy.openshift.dev/managed-by=academia
oc run ac10-f1 --image='Registry.Access.RedHat.com/UBI9/httpd-24:latest' -n ac10-imagens -l $L
oc run ac10-f2 --image=registry.access.redhat.com/ubi9/httpd-24:tag-que-nao-existe -n ac10-imagens -l $L
oc run ac10-f3 --image=registry.exemplo.invalid/app:1 -n ac10-imagens -l $L
oc run ac10-f4 --image=nao-existe-is:v1 -n ac10-imagens -l $L
sleep 30
oc get pods -n ac10-imagens -l $L -o custom-columns=POD:.metadata.name,MOTIVO:.status.containerStatuses[0].state.waiting.reason | grep ac10-f
for p in ac10-f1 ac10-f2 ac10-f3 ac10-f4; do echo "== $p"; oc get events -n ac10-imagens --field-selector involvedObject.name=$p,type=Warning -o jsonpath='{.items[-1:].message}{"\n"}' | cut -c1-200; done
```

## Repetições

1. Classifique cada pod em um passo do roteiro.
2. Qual dos quatro nunca chegou a contatar um registry?
3. Por que `ac10-f4` tenta um registry público?
4. Crie um quinto: `registry.redhat.io/ubi9/httpd-24:latest` (exige login) e classifique.
5. Repita o roteiro de memória.

## Desafio sem pista

Escreva `classifica_pull <pod>` que lê o último evento de aviso do pod e imprime o passo do roteiro (1 a 6) que explica a falha.

## Diagnóstico controlado

- **Sintoma:** `InvalidImageName: Failed to apply default image tag "Registry.Access..."`.
- **Hipóteses:** nomes de repositório precisam ser minúsculos.
- **Investigação:** a própria mensagem.
- **Reversão:** `oc delete pod ac10-f1`. Veja TS-033.

## Validação

```bash
oc get pod ac10-f1 -n ac10-imagens -o jsonpath='{.status.containerStatuses[0].state.waiting.reason}{"\n"}'    # InvalidImageName
```

## Limpeza segura

```bash
oc delete pod ac10-f1 ac10-f2 ac10-f3 ac10-f4 ac10-f5 -n ac10-imagens --ignore-not-found
```
