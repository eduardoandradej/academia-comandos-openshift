# ORI-003 — admin e developer existem? Conferir o provedor HTPasswd

## Identificação

- **ID:** ORI-003
- **Trilha:** [00 — Orientação e segurança](../README.md)
- **Referência didática:** DO280 — autenticação e identidades (HTPasswd). DO180 — usuários do ambiente de curso.
- **Fichas de comando:** [`oc-get`](../../../catalogo/fichas/oc-get.md), [`oc-auth-can-i`](../../../catalogo/fichas/oc-auth-can-i.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Verificar, **somente com leitura**, se o provedor HTPasswd `homelab-users` está configurado, se `admin` tem
`cluster-admin` e se `developer` já fez o primeiro login.

**Indicador de sucesso:** você entrega três respostas com evidência (saída de comando) para cada uma.

## Nível

**Nível:** Iniciante

- **Duração sugerida:** 15 min
- **Repetições:** 5× (variar formatos de saída)

## Pré-flight

```bash
oc whoami                     # admin (preferido) ou system:admin (exceção documentada)
oc get --raw /readyz; echo    # esperado: ok
```

## Conceito

A autenticação do OpenShift é configurada no recurso de cluster `oauth/cluster`, campo `spec.identityProviders`. A
apostila do HomeLab prevê um provedor HTPasswd chamado `homelab-users`, cujo arquivo fica no Secret
`homelab-users-htpasswd` do namespace `openshift-config`.

Pontos que confundem:

- O objeto `User` só é criado no **primeiro login** (com `mappingMethod: claim`). Um `developer` que nunca entrou
  não aparece em `oc get users`, mesmo existindo no arquivo HTPasswd.
- Permissão de cluster-admin vem de um `ClusterRoleBinding` para o papel `cluster-admin`.
- Dados de Secret **nunca** são exibidos neste repositório: listamos só nomes.

Os nomes `localusers`/`myusers` ficam reservados para o exercício de identidade do DO280 — não os crie agora.

## Comandos guiados

```bash
# 1. Provedores configurados (nome e tipo); lista vazia = HTPasswd ainda não configurado
oc get oauth cluster -o jsonpath='{range .spec.identityProviders[*]}{.name}{" ("}{.type}{")"}{"\n"}{end}'

# 2. O Secret existe? Só o NOME — nunca use -o yaml em Secrets
oc get secret -n openshift-config -o name | grep htpasswd

# 3. Usuários e identidades já materializados por login
oc get users
oc get identities

# 4. Quem tem cluster-admin (jq monta "binding -> sujeitos")
oc get clusterrolebindings -o json | jq -r '.items[]
  | select(.roleRef.name=="cluster-admin")
  | .metadata.name + " -> " + ([.subjects[]? | .kind + ":" + .name] | join(", "))'

# 5. O operador de autenticação está saudável?
oc get co authentication
oc get pods -n openshift-authentication
```

## Repetições

1. `oc describe oauth cluster` — compare com o jsonpath do passo 1.
2. `oc get users -o custom-columns=NOME:.metadata.name,IDENTIDADES:.identities` — usuário ligado a qual identidade.
3. `oc get groups` — há grupos? (Os do DO280 serão criados no exercício correspondente.)
4. `oc auth can-i create projectrequests --as=developer` — personificação (impersonation) só de leitura.
5. `oc auth can-i get nodes --as=developer` — resposta esperada: `no`.

## Desafio sem pista

Sem alterar nada, determine: (1) qual provedor de identidade está ativo e de que tipo; (2) se o usuário `developer`
já fez login alguma vez; (3) se `admin` tem `cluster-admin` e por qual binding. Registre a evidência de cada resposta.

## Diagnóstico controlado

- **Sintoma A:** `oc get user developer` retorna `NotFound`, mas o login de `developer` na Console funcionou ontem.
- **Sintoma B:** o passo 1 não imprime nada.
- **Hipóteses:** A — o login não chegou a concluir, ou foi em outro provedor; B — HTPasswd não configurado.
- **Investigação:** `oc get identities`, `oc get oauth cluster -o yaml | grep -A8 identityProviders`, `oc get co authentication`.
- **Reversão:** nada a reverter. Se B se confirmar, a configuração do HTPasswd é uma **MUTAÇÃO DE CLUSTER**
  (VERMELHO): siga a apostila do HomeLab (seção 12.1) manualmente, nunca por script desta Academia.

## Validação

```bash
oc get oauth cluster -o jsonpath='{.spec.identityProviders[*].name}{"\n"}'   # esperado: homelab-users
oc auth can-i '*' '*' --all-namespaces --as=admin                           # esperado: yes
oc auth can-i get nodes --as=developer                                       # esperado: no
```
