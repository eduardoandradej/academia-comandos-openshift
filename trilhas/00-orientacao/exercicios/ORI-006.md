## Conceito

O `ClusterVersion` chamado `version` é o objeto que o Cluster Version Operator (CVO) usa para descrever a versão
desejada e o progresso. Condições importantes:

- `Available=True`: a versão está implantada e funcional;
- `Progressing=True`: há reconciliação ou atualização em andamento — **não inicie exercícios**;
- `Failing=True`: algo impede a convergência.

No SNO, o mesmo nó tem os papéis `control-plane`, `master` e `worker`. Não há outro nó para assumir: drenar,
cordonar ou reiniciar o nó derruba o cluster inteiro. `oc adm upgrade` fica fora desta Academia (VERMELHO).

## Comandos guiados

```bash
oc get clusterversion                                          # VERSION, AVAILABLE, PROGRESSING, SINCE, STATUS
oc get clusterversion version -o jsonpath='{.status.desired.version}{"\n"}'
oc get clusterversion version -o jsonpath='{range .status.conditions[*]}{.type}{"="}{.status}{"\n"}{end}'
oc get clusterversion version -o jsonpath='{.spec.channel}{"\n"}'         # canal (pode estar vazio)
oc get clusterversion version -o jsonpath='{range .status.history[*]}{.version}{" "}{.state}{"\n"}{end}'
oc get nodes                                                   # STATUS deve ser Ready
oc get nodes -o wide                                           # IP interno, SO, kernel, runtime
oc get node ocp-sno.ocp.example.lab --show-labels | tr ',' '\n' | grep node-role
oc get nodes -o jsonpath='{range .items[*]}{.metadata.name}{" Ready="}{.status.conditions[?(@.type=="Ready")].status}{"\n"}{end}'
oc describe node ocp-sno.ocp.example.lab | sed -n '/Conditions:/,/Addresses:/p'
```

## Repetições

1. Extraia só `Progressing` com um filtro `?(@.type=="Progressing")`.
2. `oc get nodes -o custom-columns=NOME:.metadata.name,KUBELET:.status.nodeInfo.kubeletVersion,SO:.status.nodeInfo.osImage`.
3. `oc get node ocp-sno.ocp.example.lab -o jsonpath='{.status.addresses}' | jq .`.
4. Liste as condições do nó (`MemoryPressure`, `DiskPressure`, `PIDPressure`, `Ready`) com `range`.
5. Repita como `developer` (`ac-dev`) o comando `oc get nodes` e explique o resultado.

## Desafio sem pista

Produza um relatório de três linhas: versão desejada do cluster; condições `Available` e `Progressing`; nome do nó,
condição `Ready` e papéis. Use somente `oc` (com jsonpath ou custom-columns) e anote qual comando gerou cada linha.

## Diagnóstico controlado

- **Sintoma:** como `developer`, `oc get nodes` responde `Error from server (Forbidden): nodes is forbidden`.
- **Hipóteses:** (a) perfil errado para a tarefa; (b) falha de RBAC no cluster.
- **Investigação:** `oc whoami`; `oc auth can-i list nodes`; `oc auth can-i list nodes --as=admin` (no perfil admin).
- **Reversão:** nada a reverter: `Forbidden` é o comportamento esperado para `developer`. Troque de perfil com `ac-admin`.

## Validação

```bash
oc get clusterversion version -o jsonpath='{.status.conditions[?(@.type=="Available")].status}{"\n"}'   # True
oc get nodes --no-headers | awk '{print $2}'                                                            # Ready
```
