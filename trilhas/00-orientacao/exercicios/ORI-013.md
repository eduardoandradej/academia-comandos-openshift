# ORI-013 — Ler cotas e limites como developer

## Identificação

- **ID:** ORI-013
- **Trilha:** [00 — Orientação e segurança](../README.md)
- **Referência didática:** DO180 — limites de recursos. DO280 — cotas de projeto.
- **Fichas de comando:** [`oc-describe`](../../../catalogo/fichas/oc-describe.md), [`oc-auth-can-i`](../../../catalogo/fichas/oc-auth-can-i.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Interpretar quota e LimitRange do seu projeto, calcular a folga e ver a quota rejeitar uma requisição.

**Indicador de sucesso:** você diz quanto resta de cada recurso e explica a mensagem `exceeded quota` produzida no diagnóstico.

## Nível

**Nível:** Iniciante

## Pré-flight

```bash
scripts/preflight.sh          # deve terminar sem FALHA; PULADO é normal para developer
oc whoami                     # esperado: developer

```

## Conceito

`developer` pode **ler** quota e LimitRange do próprio projeto, mas não alterá-los. A quota mostra pares `Used`/`Hard`.
A admissão de quota acontece **antes** de gravar: se a requisição ultrapassa o limite, nada é criado e a mensagem traz
`requested`, `used` e `limited`.

## Comandos guiados

```bash
oc describe resourcequota ac-quota -n ac00-orientacao        # tabela Resource / Used / Hard
oc get resourcequota ac-quota -n ac00-orientacao -o jsonpath='{.status.used}{"\n"}'
oc get resourcequota ac-quota -n ac00-orientacao -o json | jq '.status | {hard, used}'
oc describe limitrange ac-limits -n ac00-orientacao          # Default Request, Default Limit, Max
oc auth can-i create resourcequotas -n ac00-orientacao       # no
oc auth can-i delete limitranges -n ac00-orientacao          # no
oc explain resourcequota.spec.hard                           # documentação do campo
```

## Repetições

1. `oc get quota -n ac00-orientacao` — `quota` é o nome curto.
2. `oc get resourcequota ac-quota -n ac00-orientacao -o jsonpath='{.status.hard.pods}{" / usados "}{.status.used.pods}{"\n"}'`.
3. Calcule com `jq` a folga de `requests.memory` (dica: compare as strings; conversão de unidades fica para o gabarito).
4. `oc get limitrange ac-limits -n ac00-orientacao -o jsonpath='{.spec.limits[0].default}{"\n"}'`.
5. `oc api-resources | grep -i -E 'quota|limitrange'` — nomes curtos e escopo.

## Desafio sem pista

Escreva uma linha que imprima, para cada recurso da quota, `recurso: usado/limite`, ordenado pelo nome.

## Diagnóstico controlado

- **Sintoma esperado:** a tentativa abaixo é recusada.

```bash
oc create service loadbalancer ac00-lb --tcp=80:8080 -n ac00-orientacao
```

- **Hipóteses:** (a) quota `services.loadbalancers: 0`; (b) falta de permissão.
- **Investigação:** leia a mensagem (`exceeded quota: ac-quota, requested: services.loadbalancers=1, ...`) e `oc describe quota ac-quota -n ac00-orientacao`.
- **Reversão:** se, por algum motivo, o Service tiver sido criado, apague-o: `oc delete service ac00-lb -n ac00-orientacao`.

## Validação

```bash
oc get service ac00-lb -n ac00-orientacao 2>&1 | grep -q NotFound && echo "nada foi criado"
```

Nenhum recurso deve ter sido criado. Confirme com a validação acima.
