## Conceito

Três números diferentes descrevem a capacidade do nó:

| Medida | Onde ver | O que significa |
|---|---|---|
| `Capacity` | `oc describe node` | recursos totais da VM (6 vCPU, ~20 GiB) |
| `Allocatable` | `oc describe node` | o que sobra para pods depois das reservas do sistema |
| `Allocated resources` (requests) | `oc describe node` | quanto os pods **reservaram**, usado pelo agendador |
| uso real | `oc adm top nodes` | consumo medido pela pilha de métricas |

O agendador decide por **requests**, não pelo uso real. Um nó pode estar com 60% de uso real e mesmo assim recusar pods
se os requests já estiverem perto do `Allocatable`. Regra prática da Academia: com memória real acima de ~85% ou
requests de memória acima de ~90%, não inicie exercícios que criem workloads.

## Comandos guiados

```bash
oc adm top nodes                                                      # uso real de CPU e memória
NODE=ocp-sno.ocp.example.lab
oc describe node "$NODE" | sed -n '/^Capacity:/,/^System Info:/p'      # capacity e allocatable
oc describe node "$NODE" | sed -n '/^Allocated resources:/,/^Events:/p'   # requests/limits somados
oc get node "$NODE" -o jsonpath='{.status.allocatable.cpu}{" CPU | "}{.status.allocatable.memory}{"\n"}'
oc adm top pods -A --sort-by=memory | head -15                        # maiores consumidores
oc get pods -A --no-headers | wc -l                                   # total de pods no nó
oc get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded   # pods fora do normal
```

## Repetições

1. `oc adm top pods -A --sort-by=cpu | head -10`.
2. `oc adm top pods -n openshift-monitoring` — quanto a pilha de métricas consome.
3. `oc get pods -A -o jsonpath='{range .items[*]}{.status.qosClass}{"\n"}{end}' | sort | uniq -c` — classes de QoS.
4. Repita o comando de `Allocated resources` e anote o percentual de memória em três horários diferentes.
5. `oc get node "$NODE" -o jsonpath='{.status.conditions[?(@.type=="MemoryPressure")].status}{"\n"}'`.

## Desafio sem pista

Monte uma decisão "pratica / não pratica" para hoje com quatro evidências: uso real de memória, percentual de requests
de memória, quantidade de pods fora de `Running`/`Succeeded` e condição `MemoryPressure`.

## Diagnóstico controlado

- **Sintoma:** `error: Metrics API not available`.
- **Hipóteses:** (a) pilha de métricas ainda iniciando; (b) APIService de métricas indisponível.
- **Investigação:** `oc get co monitoring`; `oc get apiservice v1beta1.metrics.k8s.io`;
  `oc get pods -n openshift-monitoring | grep -i metrics`.
- **Reversão:** nada a reverter. Sem métricas, use apenas `Allocated resources` e adie a decisão.

## Validação

```bash
oc adm top nodes --no-headers | awk '{print "memoria real:", $5}'
oc describe node ocp-sno.ocp.example.lab | grep -A6 '^Allocated resources:' | grep memory
```
