## Conceito

O HomeLab tem três máquinas com papéis distintos:

| Máquina | Papel | Onde você digita |
|---|---|---|
| `kvm-server` | hipervisor Rocky Linux; guarda o disco QCOW2 do SNO | só em tarefas de host, com autorização |
| `ocp-admin` | estação administrativa RHEL 9.8 com `oc`, `kubectl`, `jq` | **todos os exercícios** |
| `ocp-sno` | nó único do OpenShift (control plane + worker) | nunca diretamente nos exercícios |

O `oc` é um **cliente**: ele envia requisições HTTPS para a API em `api.ocp.example.lab:6443`. Com `--client`, o comando
`oc version` não contata a API — útil para separar "problema no cliente" de "problema no cluster".

`whoami` (Linux) informa o usuário do sistema operacional; `oc whoami` informa a identidade **no cluster**. São coisas
independentes: o mesmo `student` pode estar autenticado como `developer`, `admin` ou `system:admin`.

## Comandos guiados

```bash
hostnamectl --static            # nome estático da máquina; esperado: algo como ocp-admin
whoami                          # usuário Linux; esperado: student
id -un; id -Gn                  # -u = usuário, -G = grupos, -n = nomes em vez de números
ip -br addr                     # -br = "brief": uma linha por interface; esperado 192.168.122.x
command -v oc kubectl jq        # imprime o caminho de cada binário; linha ausente = não instalado
type -a oc                      # mostra se existe alias ou função escondendo o binário
oc version --client             # versão do cliente oc; não contata a API
kubectl version --client        # versão do cliente kubectl
```

Saída ilustrativa de `oc version --client` (os detalhes do seu ambiente prevalecem):

```text
Client Version: 4.22.0
Kustomize Version: v5.x.x
```

## Repetições

1. `oc version --client -o yaml` — mesma informação em YAML.
2. `oc version --client -o json | jq 'keys'` — descubra os nomes dos campos antes de filtrar.
3. `oc version --client -o json | jq -r '.releaseClientVersion // .clientVersion.gitVersion'` — extraia só a versão.
4. `kubectl version --client -o json | jq -r .clientVersion.gitVersion` — versão do Kubernetes embarcada no kubectl.
5. `which -a oc` e compare com `command -v oc`: qual delas é um builtin do bash?

## Desafio sem pista

Produza **uma única linha** no formato `host=<nome> usuario=<linux> oc=<versão>` usando apenas comandos locais
(sem contatar a API). Depois explique, em uma frase, por que essa linha não diz nada sobre sua identidade no cluster.

## Diagnóstico controlado

- **Sintoma:** `bash: oc: command not found`.
- **Como reproduzir sem risco:** `env -i PATH=/usr/bin:/bin bash -c 'oc version --client'` — um shell temporário com `PATH` reduzido.
- **Hipóteses:** (a) o diretório do binário não está no `PATH`; (b) o binário não está instalado; (c) um alias quebrado.
- **Investigação:** `command -v oc`, `echo "$PATH" | tr ':' '\n'`, `ls -l /usr/local/bin/oc`, `type -a oc`.
- **Reversão:** nada a reverter: o shell temporário termina sozinho.

## Validação

```bash
command -v oc kubectl jq | wc -l       # esperado: 3
oc version --client | grep -q '4.22' && echo "cliente 4.22 OK"
```
