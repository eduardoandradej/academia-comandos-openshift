## Objetivo e indicador de sucesso

Executar o preflight em dois perfis, interpretar cada linha e provar que o script é somente leitura.

**Indicador de sucesso:** você explica por que o mesmo script dá `PULADO` para `developer` e `OK` para `admin`, e mostra que ele não contém comandos de mutação.

## Pré-flight

```bash
source scripts/perfis.sh && ac-perfil
```

## Conceito

`scripts/preflight.sh` (também acessível por `scripts/academy doctor`) reúne as verificações dos exercícios ORI-001 a
ORI-008: ferramentas, permissões do kubeconfig, identidade, `/readyz`, ClusterVersion, nó, operadores, métricas,
StorageClasses, registry e projetos `ac*-*`. Ele classifica cada item como:

- `OK` — dentro do esperado;
- `AVISO` — merece atenção, mas não impede;
- `FALHA` — impede os exercícios (o script sai com código 1);
- `PULADO` — sem permissão ou não aplicável (normal para `developer`).

O espaço físico do SSD no `kvm-server` só é consultado com `--kvm-ssh`, se você tiver acesso autorizado.

## Comandos guiados

```bash
ac-dev
scripts/preflight.sh; echo "código de saída: $?"
ac-admin
scripts/academy doctor; echo "código de saída: $?"
scripts/preflight.sh --no-color | grep -E 'AVISO|FALHA'        # só o que exige atenção
scripts/preflight.sh --help
grep -nE '\b(create|apply|delete|patch|label|annotate|scale|drain|cordon)\b' scripts/preflight.sh \
  || echo "nenhum verbo de mutação no script"
```

## Repetições

1. Compare lado a lado as saídas de `developer` e `admin`: quais seções mudam de `PULADO` para `OK`?
2. `ACADEMY_TIMEOUT=3s scripts/preflight.sh` — o que muda?
3. `scripts/preflight.sh --kvm-ssh <usuario>@192.168.10.25` — só se você tem SSH autorizado ao host.
4. Leia `scripts/lib/common.sh` e explique a expressão regular de namespaces `ac*-*`.
5. Rode `scripts/academy list --trilha 00` e encontre este exercício.

## Desafio sem pista

Prove, sem executar nada contra o cluster, que o preflight não altera recursos; depois, faça-o falhar de propósito de
forma segura e explique a mensagem.

## Diagnóstico controlado

- **Sintoma:** o preflight termina com `FALHA` em "API inacessível" e código de saída 1.
- **Como reproduzir sem risco:** `KUBECONFIG=/tmp/nao-existe scripts/preflight.sh` (kubeconfig inexistente só neste comando).
- **Hipóteses:** (a) kubeconfig ausente → o cliente tenta um servidor padrão local; (b) API realmente fora do ar; (c) DNS.
- **Investigação:** compare com `scripts/preflight.sh` sem o prefixo; `oc whoami --show-server`.
- **Reversão:** nada a reverter; a variável valeu só para aquele comando.

## Validação

```bash
ac-dev && scripts/preflight.sh >/dev/null && echo "preflight developer sem FALHA"
ac-admin && scripts/preflight.sh >/dev/null && echo "preflight admin sem FALHA"
```
