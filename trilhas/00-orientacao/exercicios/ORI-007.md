## Objetivo e indicador de sucesso

**Indicador de sucesso:** uma única linha de comando que lista apenas os operadores problemáticos, e a leitura correta da mensagem de pelo menos um deles.

## Conceito

Cada componente da plataforma é gerido por um operador que publica um `ClusterOperator` (`co`). As colunas de
`oc get co` são: `NAME VERSION AVAILABLE PROGRESSING DEGRADED SINCE MESSAGE`.

- `Available=False`: o componente não está entregando o serviço.
- `Progressing=True`: está convergindo (comum por alguns minutos após reinício ou mudança).
- `Degraded=True`: está funcionando abaixo do esperado e precisa de atenção.

No HomeLab, o operador `monitoring` pode comentar que o Prometheus roda **sem armazenamento persistente** — isso é
esperado (0 StorageClasses) e não exige ação agora. Regra da Academia: operadores são **somente observação**; nunca
edite, escale ou apague nada em `openshift-*`.

## Comandos guiados

```bash
oc get co                                           # visão geral
oc get co --no-headers | wc -l                      # quantos operadores existem
oc get co --no-headers | awk '$3!="True" || $4!="False" || $5!="False"'   # só os fora do ideal
oc get co -o jsonpath='{range .items[*]}{.metadata.name}{" degraded="}{.status.conditions[?(@.type=="Degraded")].status}{"\n"}{end}'
oc describe co monitoring | sed -n '/Conditions:/,/Extension:/p'   # condições com mensagens
oc get co monitoring -o jsonpath='{range .status.conditions[*]}{.type}{": "}{.message}{"\n"}{end}'
oc get co -o json | jq -r '.items[]
  | select(any(.status.conditions[]?; .type=="Degraded" and .status=="True"))
  | .metadata.name'                                 # nenhum resultado = nenhum degradado
```

## Repetições

1. `oc get co authentication ingress console dns` — vários nomes em uma chamada.
2. `oc get co -o custom-columns=NOME:.metadata.name,DESDE:.status.conditions[0].lastTransitionTime`.
3. `oc get co --sort-by=.metadata.name -o name`.
4. Adapte o filtro `jq` para listar os que estão `Progressing=True`.
5. `oc get co monitoring -o yaml | grep -n -A3 'type: Upgradeable'` — o que essa condição informa?

## Desafio sem pista

Com uma única linha de comando, liste nome e mensagem de cada operador que não esteja no estado ideal. Se nenhum
estiver, prove isso com uma saída vazia e uma contagem total.

## Diagnóstico controlado

- **Sintoma:** o filtro `awk` lista `monitoring` com `PROGRESSING=True` logo após o cluster ser ligado.
- **Hipóteses:** (a) inicialização normal após boot; (b) problema real de recursos (memória).
- **Investigação:** `oc get co monitoring -o jsonpath='{.status.conditions[?(@.type=="Progressing")].lastTransitionTime}{"\n"}'`;
  `oc get pods -n openshift-monitoring --field-selector=status.phase!=Running`; `oc adm top nodes`.
- **Reversão:** nada a reverter. Espere alguns minutos e repita; nunca reinicie pods de operadores para "acelerar".

## Validação

```bash
oc get co --no-headers | awk '$3!="True" || $4!="False" || $5!="False"' | wc -l   # ideal: 0
```
