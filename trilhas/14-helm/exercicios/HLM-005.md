## Objetivo e indicador de sucesso

Atualizar a release com `-f` e `--set`, entender a ordem de precedência dos valores e o efeito de `--reuse-values` e `--reset-values`.

**Indicador de sucesso:** você prevê o valor final de `pagina.conteudo` e `replicaCount` para três combinações de opções, e confirma com `helm get values --all`.

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac14/ac14-loja`, nunca `manifests/helm/ac14-loja` do repositório.
> Para recomeçar: `rm -rf /tmp/ac14/ac14-loja && cp -r manifests/helm/ac14-loja /tmp/ac14/`.

Precedência (o de baixo vence):

1. `values.yaml` do chart
2. arquivos `-f`, na ordem dada
3. `--set` / `--set-string` / `--set-file`, na ordem dada

No `upgrade`, sem opção, os valores **passados antes são descartados** (padrão `--reset-values`), e só os desta vez
valem. `--reuse-values` reaproveita os da revisão anterior — e ignora defaults novos do chart (TS-045).

## Comandos guiados

```bash
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm -f /tmp/ac14/ac14-loja/values-prod.yaml
helm get values loja -n ac14-helm
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm -f /tmp/ac14/ac14-loja/values-prod.yaml --set pagina.conteudo='prod via set'
helm get values loja -n ac14-helm --all | grep -A1 -E '^pagina:|^replicaCount'
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --set env.EXTRA=sim                 # sem -f: os de prod somem!
helm get values loja -n ac14-helm --all | grep -E 'replicaCount|EXTRA|AMBIENTE'
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --reuse-values --set replicaCount=2
helm get values loja -n ac14-helm
helm history loja -n ac14-helm
```

## Repetições

1. Antes de cada upgrade, escreva o valor esperado de `replicaCount`, `pagina.conteudo` e `env`.
2. Use dois `-f` (`values-prod.yaml` e um seu) e prove que o último vence.
3. `--set-string replicaCount=2`: o schema aceita? Por quê?
4. Passe uma lista com `--set` (`--set 'x[0]=a'`) e veja o formato.
5. `helm upgrade --install` com uma release nova.

## Desafio sem pista

Faça um upgrade que mude **só** a página, mantendo exatamente todos os outros valores efetivos da revisão atual,
sem usar `--reuse-values` (dica: `helm get values -o yaml` para um arquivo).

## Diagnóstico controlado

- **Sintoma:** depois de um `helm upgrade --set x=y`, a produção voltou para 1 réplica.
- **Hipóteses:** o upgrade sem `-f values-prod.yaml` descartou os valores anteriores (padrão).
- **Investigação:** `helm get values loja --revision N` para a revisão anterior e a atual.
- **Reversão:** `helm rollback` (HLM-006) ou upgrade com todos os valores.

## Validação

```bash
helm get values loja -n ac14-helm --all -o json | jq '.replicaCount'    # 2
```
