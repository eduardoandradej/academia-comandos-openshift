## Objetivo e indicador de sucesso

Instalar o `helm` para o usuário `student` (preparação) e provar que ele age com a identidade `developer`, não com o kubeconfig do instalador.

**Indicador de sucesso:** `helm version` responde e `helm list -A` recebe `Forbidden` como developer (sinal de que não é admin).

## Conceito

O Helm 3 é **só um cliente**: não há componente no cluster. Ele renderiza modelos e envia os objetos à API com as
credenciais do `KUBECONFIG` atual — as mesmas do `oc`. O estado de cada instalação (**release**) fica em Secrets no
próprio namespace.

| Comando | Mostra |
|---|---|
| `helm version` | versão do cliente |
| `helm env` | diretórios, contexto e namespace padrão |
| `helm list -n NS` | releases do projeto |

## Comandos guiados

```bash
helm version
helm env | grep -E 'HELM_(KUBECONTEXT|NAMESPACE|CONFIG_HOME|CACHE_HOME)'
echo "KUBECONFIG=$KUBECONFIG"; oc whoami
helm list -A 2>&1 | head -2                       # developer: Forbidden (bom sinal)
( unset KUBECONFIG; source ~/.bashrc >/dev/null 2>&1; oc whoami )   # o que um terminal "cru" usaria
helm completion bash > ~/.helm-completion.bash && echo 'source ~/.helm-completion.bash' >> ~/.bashrc
```

## Repetições

1. Por que um terminal novo, sem `ac-dev`, é perigoso para o Helm?
2. Onde ficam os dados do Helm (`helm env`)?
3. `helm --help | head -40`: localize `--namespace`, `--kube-context`, `--kubeconfig`.
4. Use `helm list --kubeconfig ~/.kube/ac-developer.kubeconfig -n default`.
5. Explique por que o Helm 3 não precisa de permissões de cluster.

## Desafio sem pista

Crie um alias/função `hdev` que só executa `helm` se `oc whoami` responder `developer` e, caso contrário, recusa com uma mensagem.

## Diagnóstico controlado

- **Sintoma:** `helm list -A` lista releases de vários namespaces como se fosse admin.
- **Hipóteses:** o terminal está com o kubeconfig do instalador (`system:admin`).
- **Investigação:** `oc whoami`; `echo $KUBECONFIG`.
- **Reversão:** `source scripts/perfis.sh && ac-dev`. Nunca rode Helm como `system:admin` nos exercícios.

## Validação

```bash
helm version --short && [ "$(oc whoami)" = developer ] && echo "helm pronto como developer"
```
