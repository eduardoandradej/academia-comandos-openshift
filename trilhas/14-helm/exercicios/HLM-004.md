# HLM-004 — Instalar uma release e ler o que ela é

## Identificação

- **ID:** HLM-004
- **Trilha:** [14 — Helm](../README.md)
- **Referência didática:** DO280 — Helm (install).
- **Fichas de comando:** [`helm`](../../../catalogo/fichas/helm.md)

## Objetivo e indicador de sucesso

Instalar o chart como release `loja`, ler status, manifesto, valores e notas, e encontrar o Secret em que o Helm guarda a release.

**Indicador de sucesso:** `helm list -n ac14-helm` mostra `loja` em `deployed`, e você mostra o Secret `sh.helm.release.v1.loja.v1`.

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # OBRIGATÓRIO: o Helm usa o mesmo KUBECONFIG do oc
oc whoami                            # developer (nunca system:admin)
command -v helm && helm version --short   # REQUER PREPARAÇÃO: docs/11-preparacao-helm.md
test -d /tmp/ac14/ac14-loja || { mkdir -p /tmp/ac14; cp -r manifests/helm/ac14-loja /tmp/ac14/; }
```

```bash
oc get project ac14-helm -o name     # criado no HLM-003; se faltar: oc new-project ac14-helm
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac14/ac14-loja`, nunca `manifests/helm/ac14-loja` do repositório.
> Para recomeçar: `rm -rf /tmp/ac14/ac14-loja && cp -r manifests/helm/ac14-loja /tmp/ac14/`.

| Comando | Mostra |
|---|---|
| `helm install NOME CHART -n NS` | instala (revisão 1) |
| `helm list -n NS` | releases, revisão, status, versão do chart |
| `helm status NOME` | status e NOTES |
| `helm get manifest/values/notes/all NOME` | o que foi aplicado e com quais valores |

Cada revisão é um Secret `sh.helm.release.v1.<release>.v<N>` do tipo `helm.sh/release.v1` no namespace.

## Comandos guiados

```bash
helm install loja /tmp/ac14/ac14-loja -n ac14-helm --dry-run=server | head -20
helm install loja /tmp/ac14/ac14-loja -n ac14-helm
helm list -n ac14-helm
helm status loja -n ac14-helm
helm get values loja -n ac14-helm                 # só o que você passou (nada)
helm get values loja -n ac14-helm --all | head    # todos os valores efetivos
helm get manifest loja -n ac14-helm | grep -E '^kind:'
oc get secrets -n ac14-helm -l owner=helm -o custom-columns=NOME:.metadata.name,TIPO:.type,STATUS:.metadata.labels.status
oc rollout status deployment/loja -n ac14-helm
curl -sS "http://$(oc get route loja -n ac14-helm -o jsonpath='{.spec.host}')/"
```

## Repetições

1. Que rótulos e anotações o Helm pôs nos objetos (`meta.helm.sh/release-name`, `app.kubernetes.io/managed-by`)?
2. Tente instalar `loja` de novo: qual o erro?
3. Instale uma segunda release `vitrine` do mesmo chart, com `--set route.enabled=false`.
4. `helm get notes loja -n ac14-helm`.
5. Por que você **não** deve editar o Secret da release?

## Desafio sem pista

Decodifique (só para leitura) o conteúdo do Secret da release e mostre o nome do chart e o status gravados lá.

## Diagnóstico controlado

- **Sintoma:** `Error: INSTALLATION FAILED: cannot re-use a name that is still in use`.
- **Hipóteses:** já existe uma release `loja` no namespace.
- **Investigação:** `helm list -n ac14-helm -a`.
- **Reversão:** use `helm upgrade` (ou outro nome).

## Validação

```bash
helm list -n ac14-helm -o json | jq -r '.[] | select(.name=="loja") | .status'    # deployed
```

## Limpeza segura

```bash
helm uninstall vitrine -n ac14-helm 2>/dev/null || true
```

A release `loja` é usada até o HLM-012.
