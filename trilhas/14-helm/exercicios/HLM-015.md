## Conceito

O circuito diz **o que** obter, não **como**. Itens que exigiram consulta vão para a revisão D+1.

## Comandos guiados

Circuito sem pistas:

1. Conferir que o Helm agirá como `developer`.
2. Validar o chart local.
3. Renderizar com os valores de produção, só o Deployment.
4. Instalar a release e encontrar seu Secret.
5. Upgrade mudando só a página, sem perder os outros valores.
6. Rollback para uma revisão escolhida.
7. Modelo com bloco opcional e valor obrigatório.
8. Valor barrado pelo schema.
9. Teste da release aprovado e reprovado.
10. Upgrade quebrado revertido automaticamente.
11. Objeto existente adotado por uma release.
12. Chart de terceiros auditado sem instalar.
13. Saída do Helm pós-processada com Kustomize.
14. Release destravada de um estado `pending-*`.
15. Limpeza completa (abaixo).

## Repetições

Repita o circuito em D+1, D+3 e D+7, anotando tempo e itens que exigiram consulta.

## Desafio sem pista

Faça o circuito completo sem consulta e encerre a trilha com a limpeza abaixo.

## Diagnóstico controlado

- **Sintoma:** depois de `helm uninstall`, ainda há Secrets `sh.helm.release.v1.*`.
- **Hipóteses:** desinstalação com `--keep-history`.
- **Investigação:** `helm list -n ac14-helm -a` (status `uninstalled`).
- **Reversão:** `helm uninstall <release> -n ac14-helm` de novo (sem `--keep-history`) ou apague o projeto.

## Validação

```bash
oc get project ac14-helm 2>&1 | grep -q NotFound && echo "trilha 14 limpa"
```

## Limpeza segura

```bash
for r in $(helm list -n ac14-helm -a -q 2>/dev/null); do helm uninstall "$r" -n ac14-helm; done
scripts/safe-cleanup.sh -n ac14-helm                              # simula
scripts/safe-cleanup.sh -n ac14-helm --execute --delete-project   # apaga rotulados e o projeto
oc get project ac14-helm                                          # até NotFound
rm -rf /tmp/ac14
helm repo remove openshift-helm-charts 2>/dev/null || true
```
