## Objetivo e indicador de sucesso

## Conceito

Cada `install`/`upgrade`/`rollback` cria uma revisão (e um Secret). `helm rollback NOME N` reaplica o manifesto e os
valores da revisão N como uma revisão nova — o histórico nunca é reescrito. `--history-max` (padrão 10) limita
quantas revisões ficam guardadas.

| Helm | Equivalente em Deployment |
|---|---|
| `helm history` | `oc rollout history` |
| `helm rollback` | `oc rollout undo` (mas para **todos** os objetos da release) |

## Comandos guiados

```bash
helm history loja -n ac14-helm
N=$(helm history loja -n ac14-helm -o json | jq '.[] | select(.description|test("Install|Upgrade")) | .revision' | head -1)
helm get values loja -n ac14-helm --revision "$N" --all | grep -A1 '^pagina:'
diff <(helm get manifest loja -n ac14-helm --revision "$N") <(helm get manifest loja -n ac14-helm) | head -20
helm rollback loja "$N" -n ac14-helm
helm history loja -n ac14-helm | tail -3
curl -sS "http://$(oc get route loja -n ac14-helm -o jsonpath='{.spec.host}')/"
```

## Repetições

1. Faça rollback para a revisão anterior (sem número: `helm rollback loja`).
2. Quantos Secrets de release existem agora?
3. Um rollback desfaz também mudanças em ConfigMap e Route? (compare com `oc rollout undo`)
4. Instale com `--history-max 3` e faça 5 upgrades: quantas revisões ficam?
5. Leia o campo `DESCRIPTION` de cada revisão.

## Desafio sem pista

Escreva `volta_ate <texto>` que encontra a revisão mais recente cuja página contém `<texto>` e faz rollback para ela.

## Diagnóstico controlado

- **Sintoma:** `Error: release: not found` ao fazer rollback.
- **Hipóteses:** nome da release ou namespace errado; release desinstalada sem `--keep-history`.
- **Investigação:** `helm list -n ac14-helm -a`.
- **Reversão:** confira o namespace (`-n`).

## Validação

```bash
helm history loja -n ac14-helm -o json | jq -r '.[-1].description'    # Rollback to N
```

## Limpeza segura

Nada a limpar (o rollback é uma revisão como as outras).
