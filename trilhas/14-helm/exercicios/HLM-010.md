## Objetivo e indicador de sucesso

Fazer um upgrade com imagem inexistente e ver a diferença entre o padrão (release `deployed` com pods quebrados),
`--wait` (falha com timeout) e `--atomic` (rollback automático).

**Indicador de sucesso:** com `--atomic`, a release volta sozinha à revisão anterior e o histórico mostra `failed` + `Rollback`.

## Conceito

| Opção | Comportamento |
|---|---|
| (nenhuma) | aplica e marca `deployed` sem esperar os pods |
| `--wait --timeout 2m` | espera Deployments/pods prontos; marca `failed` se não ficarem |
| `--atomic` | `--wait` + rollback automático em caso de falha |
| `--rollback-on-failure` (versões recentes) | nome novo do mesmo comportamento, se disponível |

Em pipelines, prefira `--atomic` (ou `--wait` + decisão explícita).

## Comandos guiados

```bash
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --set image.tag=tag-que-nao-existe
helm list -n ac14-helm                                       # deployed (!)
oc get pods -n ac14-helm -l app.kubernetes.io/instance=loja  # ErrImagePull no pod novo
helm rollback loja -n ac14-helm
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --set image.tag=tag-que-nao-existe --wait --timeout 60s; echo "rc=$?"
helm list -n ac14-helm -a                                    # failed
helm rollback loja -n ac14-helm
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --set image.tag=tag-que-nao-existe --atomic --timeout 60s; echo "rc=$?"
helm history loja -n ac14-helm | tail -3                     # failed e "Rollback to N"
```

## Repetições

1. Por que o primeiro upgrade ficou `deployed` com o pod quebrado?
2. Durante o `--wait`, abra outro terminal e veja o rollout (`oc rollout status`).
3. Com `--atomic`, o pod quebrado chegou a ser criado?
4. Teste `--wait` com uma mudança boa: quanto tempo leva?
5. Escreva a regra para pipelines de memória.

## Desafio sem pista

Escreva `entrega <valores.yaml>` que faz `helm upgrade --install --atomic --timeout 2m`, roda `helm test` em seguida
e, se o teste falhar, faz rollback para a revisão anterior.

## Diagnóstico controlado

- **Sintoma:** `Error: UPGRADE FAILED: context deadline exceeded` e a release em `failed`.
- **Hipóteses:** pods não ficaram prontos no `--timeout` (imagem, probe, quota).
- **Investigação:** `oc get pods`; eventos; `helm history`.
- **Reversão:** `helm rollback loja -n ac14-helm`.

## Validação

```bash
helm list -n ac14-helm -o json | jq -r '.[] | select(.name=="loja") | .status'    # deployed
```
