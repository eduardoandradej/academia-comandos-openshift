## Objetivo e indicador de sucesso

Renderizar o chart e pós-processá-lo com Kustomize (`helm template | kustomize`), e decidir quando cada ferramenta deve ser a dona do ciclo de vida.

**Indicador de sucesso:** um overlay Kustomize que acrescenta um rótulo aos objetos gerados pelo Helm, renderizado com sucesso.

## Conceito

| | Helm | Kustomize | `oc apply` |
|---|---|---|---|
| Estado | release (Secrets) com histórico | nenhum | `last-applied` / managedFields |
| Rollback | `helm rollback` (tudo) | Git + `apply -k` | Git + `apply` |
| Parâmetros | valores | overlays | — |
| Combinação comum | `helm template` → Kustomize → `oc apply` (sem release!) | | |

Escolha **um** dono por objeto. Misturar `helm upgrade` com `oc apply` no mesmo objeto gera brigas (HLM-011).

## Comandos guiados

```bash
mkdir -p /tmp/ac14/pos && cd /tmp/ac14/pos
helm template loja /tmp/ac14/ac14-loja -n ac14-helm --skip-tests > gerado.yaml
cat > kustomization.yaml <<'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - gerado.yaml
labels:
  - pairs:
      pos-processado: kustomize
    includeSelectors: false
EOF
oc kustomize . | grep -c 'pos-processado: kustomize'
oc kustomize . | oc apply --dry-run=server -n ac14-helm -f - -o name 2>&1 | head
cd - >/dev/null
```

## Desafio sem pista

Escreva a recomendação (sem consulta) para: (a) chart de terceiros que precisa de um ajuste que o `values.yaml` não
oferece; (b) aplicação interna com três ambientes; (c) instalar e atualizar com rollback de um clique.

## Diagnóstico controlado

- **Sintoma:** `oc kustomize` falha com `accumulating resources ... already registered id` ao processar o gerado.
- **Hipóteses:** o `helm template` incluiu o pod de teste ou objetos duplicados.
- **Investigação:** `grep -c '^kind:' gerado.yaml`; `--skip-tests`.
- **Reversão:** gere de novo com `--skip-tests`.

## Validação

```bash
oc kustomize /tmp/ac14/pos | grep -q 'pos-processado: kustomize' && echo OK
```
