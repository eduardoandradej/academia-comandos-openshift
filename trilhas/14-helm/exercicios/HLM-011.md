## Objetivo e indicador de sucesso

alguém muda pelo `oc` um campo que o chart controla.

## Conceito

Todo objeto de uma release tem:

- rótulo `app.kubernetes.io/managed-by: Helm`;
- anotações `meta.helm.sh/release-name` e `meta.helm.sh/release-namespace`.

O Helm recusa instalar um objeto que já existe sem essas marcas (`invalid ownership metadata`), para não "tomar"
objetos de outra ferramenta. Mudanças feitas com `oc` em campos do chart só são desfeitas quando um `upgrade` muda
aquele campo no chart; enquanto isso, a deriva fica invisível para o Helm.

## Comandos guiados

```bash
oc get all,cm,route -n ac14-helm -l app.kubernetes.io/managed-by=Helm -o name
oc get deployment loja -n ac14-helm -o jsonpath='{.metadata.annotations}' | jq 'with_entries(select(.key|startswith("meta.helm.sh")))'
oc create configmap vitrine-pagina --from-literal=index.html=manual -n ac14-helm
helm install vitrine /tmp/ac14/ac14-loja -n ac14-helm --set route.enabled=false; echo "rc=$?"   # invalid ownership metadata
oc scale deployment/loja --replicas=2 -n ac14-helm
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --reuse-values
oc get deployment loja -n ac14-helm -o jsonpath='{.spec.replicas}{"\n"}'        # continua 2: deriva preservada
```

## Repetições

1. Por que o `upgrade` **não** voltou as réplicas para 1? (o campo não mudou entre a revisão anterior e a nova)
2. Apague o ConfigMap manual e instale `vitrine` de novo.
3. Liste todas as releases do projeto e os objetos de cada uma pelo rótulo `app.kubernetes.io/instance`.
4. `helm get manifest vitrine | oc diff -f -`.
5. Desinstale `vitrine`.

## Desafio sem pista

"Adote" o ConfigMap manual na release `vitrine` (sem apagá-lo), acrescentando rótulo e anotações de dono, e
instale a release com sucesso. Explique o risco.

## Diagnóstico controlado

- **Sintoma:** `Error: INSTALLATION FAILED: rendered manifests contain a resource that already exists. Unable to continue with install: ConfigMap "vitrine-pagina" ... exists and cannot be imported into the current release: invalid ownership metadata`.
- **Hipóteses:** objeto com o mesmo nome criado fora do Helm.
- **Investigação:** `oc get cm vitrine-pagina -o yaml | grep -A3 annotations`.
- **Reversão:** escolha outro nome de release, apague o objeto (se for descartável) ou adote-o (desafio). Veja TS-044.

## Validação


## Limpeza segura

```bash
helm uninstall vitrine -n ac14-helm 2>/dev/null || true
oc delete configmap vitrine-pagina -n ac14-helm --ignore-not-found
```
