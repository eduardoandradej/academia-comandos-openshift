## Conceito

1. O host resolve para o IP do router no **cliente**?
2. A porta 80/443 do router abre?
3. A Route existe e está **admitida**?
4. O Service da Route existe?
5. O Service tem endpoints prontos?
6. A porta da Route (`spec.port.targetPort`) existe no Service?
7. A resposta HTTP é a esperada (e não o 503 do router)?

## Comandos guiados

```bash
rdiag() {
  r=$1; ns=${2:-ac07-rotas}
  h=$(oc get route "$r" -n "$ns" -o jsonpath='{.spec.host}' 2>/dev/null) || { echo "3 FALHA: Route não existe"; return; }
  getent ahostsv4 "$h" >/dev/null || { echo "1 FALHA: $h não resolve no cliente"; return; }; echo "1 ok: $h resolve"
  timeout 3 bash -c '</dev/tcp/192.168.10.200/80' || { echo "2 FALHA: router inacessível"; return; }; echo "2 ok: router responde"
  a=$(oc get route "$r" -n "$ns" -o jsonpath='{.status.ingress[0].conditions[?(@.type=="Admitted")].status}')
  [ "$a" = True ] || { echo "3 FALHA: Route não admitida"; return; }; echo "3 ok: admitida"
  s=$(oc get route "$r" -n "$ns" -o jsonpath='{.spec.to.name}')
  oc get svc "$s" -n "$ns" >/dev/null 2>&1 || { echo "4 FALHA: Service $s não existe"; return; }; echo "4 ok: Service $s"
  e=$(oc get endpointslices -n "$ns" -l kubernetes.io/service-name="$s" -o json | jq '[.items[].endpoints[]? | select(.conditions.ready)] | length')
  [ "$e" -gt 0 ] || { echo "5 FALHA: Service sem endpoints prontos"; return; }; echo "5 ok: $e endpoint(s)"
  c=$(curl -sS -o /dev/null -w '%{http_code}' "http://$h/")
  [ "$c" != 503 ] || { echo "6/7 FALHA: router devolveu 503 (porta da Route/Service?)"; return; }; echo "7 ok: HTTP $c"
}
rdiag web-azul
oc scale deployment/web-verde --replicas=0 -n ac07-rotas
rdiag web-verde                         # falha no passo 5
oc scale deployment/web-verde --replicas=1 -n ac07-rotas
```

## Repetições

Provoque um defeito por vez e rode `rdiag`:

1. Backend com 0 réplicas (guiados).
2. Route apontando para um Service inexistente (`oc patch route ... -p '{"spec":{"to":{"name":"nao-existe"}}}'`).
3. Host fora de `*.apps` (cenário TS-024).
4. Route não admitida por conflito de host (cenário TS-023).
5. `spec.port.targetPort` com nome inexistente.

## Desafio sem pista

Estenda `rdiag` para Routes TLS: se `spec.tls` existir, use `https://` com `-k` e o SNI correto, e informe a terminação.

## Diagnóstico controlado

- **Sintoma:** `curl` devolve a página `Application is not available` (503).
- **Hipóteses:** sem endpoints prontos, Service inexistente, porta errada, ou (reencrypt) falha de TLS até o pod.
- **Investigação:** passos 4–6 do roteiro. Veja TS-022.
- **Reversão:** corrija o elo quebrado.

## Validação

```bash
rdiag web-azul | tail -1    # 7 ok
```

## Limpeza segura

Garanta `web-verde` com 1 réplica e desfaça os defeitos provocados.
