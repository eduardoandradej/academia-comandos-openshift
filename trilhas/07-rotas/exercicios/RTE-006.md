## Objetivo e indicador de sucesso

Criar uma Route `edge` (TLS termina no router), ler o certificado servido e configurar o redirecionamento de HTTP para HTTPS.

**Indicador de sucesso:** `http://` responde 302 para `https://`, e `https://` serve o certificado curinga do Ingress.

## Conceito

| Terminação | TLS entre cliente e router | Router → pod | Certificado do cliente vê |
|---|---|---|---|
| `edge` | sim | HTTP simples | do router (padrão: curinga `*.apps`) ou o que você fornecer |
| `passthrough` | sim, direto até o pod | o router só repassa | do pod |
| `reencrypt` | sim | **novo** TLS até o pod | do router; o pod usa outro |

`insecureEdgeTerminationPolicy`: `None` (HTTP recusado), `Allow` (HTTP aceito) ou `Redirect` (HTTP → HTTPS).
O certificado padrão é assinado pela CA do Ingress Operator — não confiável para o `curl` sem `--cacert` ou `-k`.

## Comandos guiados

```bash
oc create route edge seguro --service=web-azul --hostname=seguro-ac07.apps.ocp.example.lab --insecure-policy=Redirect -n ac07-rotas
oc get route seguro -n ac07-rotas
curl -sS -o /dev/null -w '%{http_code} -> %{redirect_url}\n' http://seguro-ac07.apps.ocp.example.lab/
curl -sSk https://seguro-ac07.apps.ocp.example.lab/                     # azul (-k: sem validar a CA)
curl -sS https://seguro-ac07.apps.ocp.example.lab/ 2>&1 | tail -1       # erro de certificado sem -k
openssl s_client -connect 192.168.10.200:443 -servername seguro-ac07.apps.ocp.example.lab </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -ext subjectAltName
```

## Repetições

1. Troque a política para `Allow` (`oc patch route seguro --type=merge -p '{"spec":{"tls":{"insecureEdgeTerminationPolicy":"Allow"}}}'`) e teste HTTP.
2. Troque para `None` e teste HTTP de novo.
3. Leia `spec.tls` da Route.
4. (admin) Obtenha a CA do Ingress e use `--cacert` em vez de `-k` (veja o gabarito).
5. `oc create route edge --help | sed -n '/Examples:/,/Options:/p'`.

## Desafio sem pista

Acesse `https://seguro-ac07.apps.ocp.example.lab/` **validando** o certificado (sem `-k`), usando a CA certa.

## Diagnóstico controlado

- **Sintoma:** `curl: (60) SSL certificate problem: self-signed certificate in certificate chain` (ou `unable to get local issuer certificate`).
- **Hipóteses:** a CA do Ingress não está na lista de confiança da `ocp-admin`.
- **Investigação:** o `openssl s_client` mostra o emissor (`ingress-operator@...`).
- **Reversão:** nada a reverter; use `--cacert` com a CA do Ingress (desafio).

## Validação

```bash
curl -sSk https://seguro-ac07.apps.ocp.example.lab/    # azul
```
