## Conceito

Todas as Routes do cluster chegam ao **mesmo** IP e porta. O router decide o destino pelo nome pedido:

- HTTP: cabeçalho `Host`;
- HTTPS: SNI (o nome enviado no início do TLS).

Por isso `curl -H 'Host: <host da route>' http://192.168.10.200/` funciona mesmo sem DNS, e
`curl --resolve <host>:443:192.168.10.200 https://<host>/` faz o mesmo para TLS. Um `Host` desconhecido recebe a
página padrão do router (`Application is not available`, HTTP 503).

## Comandos guiados

```bash
HA=$(oc get route web-azul -n ac07-rotas -o jsonpath='{.spec.host}')
oc expose svc/web-verde -n ac07-rotas 2>/dev/null; HV=$(oc get route web-verde -n ac07-rotas -o jsonpath='{.spec.host}')
curl -sS -H "Host: $HA" http://192.168.10.200/          # azul
curl -sS -H "Host: $HV" http://192.168.10.200/          # verde
curl -sS -o /dev/null -w '%{http_code}\n' -H 'Host: nao-existe.apps.ocp.example.lab' http://192.168.10.200/   # 503
curl -sS --resolve "$HA:80:192.168.10.200" "http://$HA/"
curl -v "http://$HA/" 2>&1 | grep -E '^> (GET|Host)|^< (HTTP|Set-Cookie)'
```

## Diagnóstico controlado

- **Sintoma:** `curl http://192.168.10.200/` (sem `Host` de Route) devolve 503.
- **Hipóteses:** o router não sabe qual Route servir para o `Host: 192.168.10.200`.
- **Investigação:** compare com `-H "Host: $HA"`.
- **Reversão:** nada a reverter.

## Validação

```bash
[ "$(curl -sS -H "Host: $HV" http://192.168.10.200/)" = verde ] && echo OK
```
