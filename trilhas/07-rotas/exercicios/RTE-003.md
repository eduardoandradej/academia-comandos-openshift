# RTE-003 — Hostname próprio e o arquivo hosts do Windows

## Identificação

- **ID:** RTE-003
- **Trilha:** [07 — Routes e Ingress](../README.md)
- **Referência didática:** DO180 — Routes (hostnames).
- **Fichas de comando:** [`oc-route`](../../../catalogo/fichas/oc-route.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Criar uma Route com hostname escolhido por você e acessá-la pelo navegador do Windows, entendendo a limitação do arquivo `hosts`.

**Indicador de sucesso:** `loja-ac07.apps.ocp.example.lab` abre no navegador do Windows mostrando `azul`.

## Conceito

`--hostname` define o host da Route. Ele precisa resolver para o IP do router **no cliente**:

- na `ocp-admin`, o curinga `*.apps` do DNS do HomeLab resolve qualquer nome terminado em `.apps.ocp.example.lab`;
- no Windows, o acesso foi configurado pelo arquivo `hosts`, que **não aceita curinga**: cada Route nova precisa de
  uma linha `192.168.10.200 <host>`.

Hostnames fora de `*.apps.ocp.example.lab` não resolvem em lugar nenhum sem entrada própria (TS-024).

## Comandos guiados

```bash
oc expose svc/web-azul --name=loja --hostname=loja-ac07.apps.ocp.example.lab -n ac07-rotas
oc get route loja -n ac07-rotas
curl -sS http://loja-ac07.apps.ocp.example.lab/
```

No Windows (PowerShell como Administrador), acrescente a linha e teste:

```powershell
Add-Content -Path C:\Windows\System32\drivers\etc\hosts -Value "192.168.10.200 loja-ac07.apps.ocp.example.lab"
ipconfig /flushdns
[System.Net.Dns]::GetHostAddresses('loja-ac07.apps.ocp.example.lab')
# navegador: http://loja-ac07.apps.ocp.example.lab/
```

## Repetições

1. Crie uma segunda Route `loja2-ac07.apps.ocp.example.lab` e confirme que o Windows **não** a resolve sem nova linha.
2. `oc get route loja -n ac07-rotas -o jsonpath='{.spec.host}{"\n"}'`.
3. Tente alterar o host de uma Route existente com `oc patch` e veja se é aceito.
4. No Windows, `nslookup loja-ac07.apps.ocp.example.lab`: por que ele pode ignorar o `hosts`?
5. Remova a linha do `hosts` ao terminar a trilha.

## Desafio sem pista

Faça a Route `loja` responder também como `www-loja-ac07.apps.ocp.example.lab` (uma segunda Route para o mesmo
Service) e prove os dois nomes pela `ocp-admin`.

## Diagnóstico controlado

- **Sintoma:** o navegador do Windows mostra "não foi possível encontrar o servidor" para a Route nova.
- **Hipóteses:** falta a linha no `hosts` (sem curinga).
- **Investigação:** `[System.Net.Dns]::GetHostAddresses('<host>')` no PowerShell.
- **Reversão:** acrescente a linha ou use um DNS com curinga no Windows.

## Validação

```bash
curl -sS http://loja-ac07.apps.ocp.example.lab/    # azul
```

## Limpeza segura

```bash
oc delete route loja2 www-loja -n ac07-rotas --ignore-not-found
```

No Windows, remova as linhas `...ac07...` do `hosts` quando encerrar a trilha.
