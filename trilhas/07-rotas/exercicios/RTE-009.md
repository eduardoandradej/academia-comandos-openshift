## Conceito

Em `reencrypt`, o router decifra o TLS do cliente e abre **outro** TLS até o pod, validando o certificado do pod com
`destinationCACertificate` (ou com a CA de serviço do cluster, quando omitido). O certificado do pod precisa ser emitido
para o nome do Service (`<svc>.<ns>.svc`).

O OpenShift oferece isso pronto: a anotação `service.beta.openshift.io/serving-cert-secret-name=<secret>` no Service faz
o **service CA operator** gerar um Secret com certificado para `<svc>.<ns>.svc`. Montar esse Secret no httpd e
configurá-lo para usá-lo é trabalho de configuração da Trilha 08 — por isso aqui a parte prática completa fica
**REQUER PREPARAÇÃO**.

## Comandos guiados

```bash
oc create route reencrypt cifrado --service=web-azul --port=8443 --hostname=cifrado-ac07.apps.ocp.example.lab \
  -n ac07-rotas --dry-run=client -o yaml
oc explain route.spec.tls.destinationCACertificate
oc annotate svc web-azul service.beta.openshift.io/serving-cert-secret-name=web-azul-tls -n ac07-rotas --dry-run=server -o yaml \
  | grep -A2 annotations
oc get configmap -n ac07-rotas openshift-service-ca.crt -o jsonpath='{.data.service-ca\.crt}' | openssl x509 -noout -subject
```

## Repetições

1. Desenhe as duas conexões TLS de uma reencrypt e diga qual certificado o navegador vê.
2. Compare as três terminações em uma tabela: onde o tráfego está cifrado em cada uma?
3. `oc explain route.spec.tls --recursive`.
4. Por que o ConfigMap `openshift-service-ca.crt` existe em todo namespace?
5. (Opcional, prático) aplique a anotação de verdade e veja o Secret `web-azul-tls` surgir com `tls.crt` e `tls.key` — **não** imprima a chave.

## Desafio sem pista

Explique, com base nos campos do YAML gerado, o que o router faria com uma Route reencrypt apontando para o httpd atual
(certificado autoassinado para outro nome) e qual seria a resposta para o cliente.

## Diagnóstico controlado

- **Sintoma:** uma Route reencrypt responde 503 embora o pod esteja pronto.
- **Hipóteses:** o router não confia no certificado do pod (CA ou nome errados).
- **Investigação:** certificado servido pelo pod (subject, issuer) × `destinationCACertificate` / service CA.
- **Reversão:** use um certificado de serviço (anotação no Service) ou informe a CA correta.
