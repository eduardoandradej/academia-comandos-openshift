# RTE-001 — Primeira Route: do navegador ao pod

## Identificação

- **ID:** RTE-001
- **Trilha:** [07 — Routes e Ingress](../README.md)
- **Referência didática:** DO180 — expor aplicações para acesso externo (Routes).
- **Fichas de comando:** [`oc-route`](../../../catalogo/fichas/oc-route.md), [`oc-expose-service`](../../../catalogo/fichas/oc-expose-service.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Implantar os backends azul/verde, criar Services e uma Route HTTP com `oc expose svc`, e acessá-la pela `ocp-admin`.

**Indicador de sucesso:** `curl http://web-azul-ac07-rotas.apps.ocp.example.lab/` responde `azul` a partir da `ocp-admin`.

## Nível

**Nível:** Iniciante

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
scripts/preflight.sh                 # sem FALHA
oc whoami                            # developer
getent ahostsv4 teste.apps.ocp.example.lab   # o curinga *.apps resolve para 192.168.10.200?
```

REQUER PREPARAÇÃO: o curinga `*.apps.ocp.example.lab` precisa resolver na `ocp-admin` (DNS `192.168.10.25`) e o cluster precisa baixar a imagem httpd.

## Conceito

Uma **Route** publica um Service para fora do cluster, por HTTP/HTTPS, através do **router** (HAProxy) do Ingress
Controller, que no SNO escuta nas portas 80/443 do próprio nó (`192.168.10.200`).

```text
curl/navegador ──DNS *.apps──▶ 192.168.10.200:80 (router) ──Host──▶ Route ──▶ Service ──▶ pods
```

`oc expose svc/<nome>` cria uma Route com host gerado: `<route>-<namespace>.apps.ocp.example.lab`.

## Comandos guiados

```bash
oc new-project ac07-rotas --display-name='Academia 07 - Routes'
oc apply -f manifests/apps-exemplo/servicos-azul-verde.yaml -n ac07-rotas
oc wait --for=condition=Available deploy/web-azul deploy/web-verde -n ac07-rotas --timeout=180s
oc expose deployment/web-azul --port=8080 -n ac07-rotas
oc expose deployment/web-verde --port=8080 -n ac07-rotas
oc expose svc/web-azul -n ac07-rotas
oc get route web-azul -n ac07-rotas
H=$(oc get route web-azul -n ac07-rotas -o jsonpath='{.spec.host}'); echo "$H"
curl -sS "http://$H/"                     # azul
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' "http://$H/"
oc describe route web-azul -n ac07-rotas
```

## Repetições

1. Exponha `web-verde` também e teste.
2. Apague a Route e recrie-a 5× de memória.
3. `oc get route web-azul -n ac07-rotas -o yaml | sed -n '/^spec:/,/^status:/p'`.
4. `oc expose svc/web-azul --name=loja -n ac07-rotas` e veja o host gerado com outro nome.
5. Abra a URL no navegador do Windows (veja RTE-003 para o arquivo `hosts`).

## Desafio sem pista

Mostre, com um comando por camada, que (1) o nome da Route resolve para o IP do nó, (2) o router responde na porta 80 e
(3) a Route entrega a página certa.

## Diagnóstico controlado

- **Sintoma:** `curl: (6) Could not resolve host: web-azul-ac07-rotas.apps.ocp.example.lab`.
- **Hipóteses:** (a) a `ocp-admin` não usa o DNS do HomeLab; (b) o curinga `*.apps` não existe no `dnsmasq-ocp`.
- **Investigação:** `getent ahostsv4 qualquer.apps.ocp.example.lab`; `grep nameserver /etc/resolv.conf`.
- **Reversão:** nada a reverter. Enquanto isso, teste com `curl -H "Host: $H" http://192.168.10.200/` (RTE-002).

## Validação

```bash
[ "$(curl -sS "http://$(oc get route web-azul -n ac07-rotas -o jsonpath='{.spec.host}')/")" = azul ] && echo OK
```
