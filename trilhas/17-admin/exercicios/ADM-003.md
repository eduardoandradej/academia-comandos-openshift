# ADM-003 — ResourceQuota completa: computação, objetos e escopos

## Identificação

- **ID:** ADM-003
- **Trilha:** [17 — Administração de recursos](../README.md)
- **Referência didática:** DO280 — cotas de projeto.
- **Fichas de comando:** [`oc-quota-limitrange`](../../../catalogo/fichas/oc-quota-limitrange.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Aplicar três quotas a um projeto de treino (computação, contagem de objetos e escopo `BestEffort`) e ler `used`/`hard`
como admin e como developer.

**Indicador de sucesso:** `oc describe quota -n ac17-cotas` mostra as três quotas, e o developer consegue lê-las mas não alterá-las.

## Nível

**Nível:** Intermediário

## Duração e repetições

- **Duração sugerida:** 15 min
- **Repetições:** 5×

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `admin` (e `developer` para ler)
- **Projeto:** `ac17-cotas`
- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL (quotas no projeto de treino)

## Pré-flight

```bash
source scripts/perfis.sh && ac-admin
oc whoami                            # admin
scripts/preflight.sh                 # sem FALHA; memória do nó abaixo de 85%
```

## Conceito

> **Perfil admin, escopo de treino.** Os exercícios usam o perfil `admin`, mas só criam objetos em projetos `ac17-*`
> ou objetos de cluster rotulados `academy.openshift.dev/trilha=17`. Nada em `openshift-*`, `kube-*`, nó ou rede.

| Tipo de limite | Exemplos |
|---|---|
| computação | `requests.cpu`, `limits.memory`, `pods` |
| contagem de objetos | `count/deployments.apps`, `services`, `count/secrets` |
| armazenamento | `persistentvolumeclaims`, `requests.storage` |
| escopos | `BestEffort`, `NotBestEffort`, `Terminating`, `NotTerminating`, `PriorityClass` |

Várias quotas no mesmo projeto valem **todas ao mesmo tempo**: a mais restritiva decide.

## Comandos guiados

```bash
oc new-project ac17-cotas --display-name='Academia 17 - Cotas' >/dev/null 2>&1 || true
oc label namespace ac17-cotas academy.openshift.dev/managed-by=academia --overwrite
oc policy add-role-to-user admin developer -n ac17-cotas
oc apply --dry-run=server -f manifests/admin/quota-completa.yaml -n ac17-cotas
oc apply -f manifests/admin/quota-completa.yaml -n ac17-cotas
oc describe quota -n ac17-cotas
oc get resourcequota -n ac17-cotas -o custom-columns=NOME:.metadata.name,ESCOPOS:.spec.scopes,HARD:.status.hard
ac-dev
oc describe quota -n ac17-cotas | head -12
oc delete resourcequota ac17-objetos -n ac17-cotas 2>&1 | head -1       # Forbidden: quota é do admin
ac-admin
```

## Repetições

1. Que recursos você pode contar com `count/<recurso>.<grupo>`? Tente `count/routes.route.openshift.io`.
2. Crie dois Deployments e veja `count/deployments.apps` subir.
3. O escopo `BestEffort` conta quais pods?
4. Como developer, `oc auth can-i update resourcequotas -n ac17-cotas`?
5. Por que o projeto foi criado pelo admin e não pelo developer? (quem cria é admin do projeto)

## Desafio sem pista

Faça um relatório de uma linha por recurso limitado no projeto: `recurso usado/limite (porcentagem)`, juntando as três quotas.

## Diagnóstico controlado

- **Sintoma:** `oc describe quota` mostra `used` vazio por alguns segundos após criar.
- **Hipóteses:** o controlador de quota ainda está calculando o uso.
- **Investigação:** repita em alguns segundos; `oc get resourcequota -o yaml` (status).
- **Reversão:** nada a fazer.

## Validação

```bash
oc get resourcequota -n ac17-cotas --no-headers | wc -l     # 3
```
