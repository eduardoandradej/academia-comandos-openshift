# ADM-009 — PriorityClass: prioridade baixa para o treino

## Identificação

- **ID:** ADM-009
- **Trilha:** [17 — Administração de recursos](../README.md)
- **Referência didática:** DO280 — prioridade e preempção.
- **Fichas de comando:** [`oc-quota-limitrange`](../../../catalogo/fichas/oc-quota-limitrange.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Ler as PriorityClasses do cluster e criar uma de prioridade **baixa**, sem preempção, para pods de treino — e
limitar o uso dela por quota com escopo.

**Indicador de sucesso:** um pod com `priorityClassName: ac17-baixa` roda com `priority: -10`, e a quota por escopo `PriorityClass` conta só esses pods.

## Conceito

> **Perfil admin, escopo de treino.** Os exercícios usam o perfil `admin`, mas só criam objetos em projetos `ac17-*`
> ou objetos de cluster rotulados `academy.openshift.dev/trilha=17`. Nada em `openshift-*`, `kube-*`, nó ou rede.

A prioridade decide a ordem de agendamento e quem pode ser **despejado** (preempção) quando falta espaço. As classes
`system-cluster-critical` e `system-node-critical` protegem o próprio cluster. Por isso a Academia **só** cria
prioridade abaixo do padrão (0) e com `preemptionPolicy: Never`: pods de treino nunca desalojam ninguém e são os
primeiros a sair em caso de aperto.

## Comandos guiados

```bash
oc get priorityclasses -o custom-columns=NOME:.metadata.name,VALOR:.value,PADRAO:.globalDefault,PREEMPCAO:.preemptionPolicy
oc apply -f manifests/admin/priorityclass-ac17-baixa.yaml
oc run ac17-baixo --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas --overrides='{"spec":{"priorityClassName":"ac17-baixa"}}'
oc get pod ac17-baixo -n ac17-cotas -o jsonpath='{.spec.priorityClassName} {.spec.priority} {.spec.preemptionPolicy}{"\n"}'
cat <<'EOF' | oc apply -n ac17-cotas -f -
apiVersion: v1
kind: ResourceQuota
metadata:
  name: ac17-prioridade-baixa
  labels: {academy.openshift.dev/managed-by: academia}
spec:
  hard: {pods: "2"}
  scopeSelector:
    matchExpressions:
      - {operator: In, scopeName: PriorityClass, values: ["ac17-baixa"]}
EOF
oc describe quota ac17-prioridade-baixa -n ac17-cotas
```

## Repetições

1. Qual a prioridade dos pods do `openshift-etcd`? E dos seus pods sem classe?
2. Existe classe com `globalDefault: true`? O que ela faria?
3. Crie 2 pods com a classe e veja o terceiro ser recusado pela quota de escopo.
4. Por que nunca criar uma PriorityClass de valor alto na Academia?
5. Explique `preemptionPolicy: Never`.

## Desafio sem pista

Liste os pods do cluster agrupados por PriorityClass (com a contagem), e diga quantos pods têm prioridade maior que a dos seus.

## Diagnóstico controlado

- **Sintoma:** `pods "x" is forbidden: no PriorityClass with name ac17-alta was found`.
- **Hipóteses:** classe inexistente (ou nome errado).
- **Investigação:** `oc get priorityclasses`.
- **Reversão:** use uma classe existente; criar classes é decisão do admin.

## Validação

```bash
oc get pod ac17-baixo -n ac17-cotas -o jsonpath='{.spec.priority}{"\n"}'    # -10
```

## Limpeza segura

```bash
oc delete pod ac17-baixo ac17-baixo2 ac17-baixo3 -n ac17-cotas --ignore-not-found
oc delete resourcequota ac17-prioridade-baixa -n ac17-cotas --ignore-not-found
```

A PriorityClass `ac17-baixa` é removida no ADM-015.
