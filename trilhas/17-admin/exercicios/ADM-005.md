## Objetivo e indicador de sucesso

limite/request recusada.

## Conceito

> **Perfil admin, escopo de treino.** Os exercícios usam o perfil `admin`, mas só criam objetos em projetos `ac17-*`
> ou objetos de cluster rotulados `academy.openshift.dev/trilha=17`. Nada em `openshift-*`, `kube-*`, nó ou rede.

| Campo | Efeito |
|---|---|
| `defaultRequest` / `default` | preenche request/limit ausentes |
| `min` / `max` | recusa valores fora da faixa |
| `maxLimitRequestRatio` | recusa limit maior que N × request |
| `type: Pod` | limite para a soma dos contêineres |
| `type: PersistentVolumeClaim` | faixa de tamanho de PVC |

O LimitRange age na **admissão do pod**: pods existentes não mudam.

## Comandos guiados

```bash
oc apply -f manifests/admin/limitrange-completo.yaml -n ac17-cotas
oc describe limitrange ac17-limites -n ac17-cotas
ac-dev
oc run ac17-padrao --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas
oc get pod ac17-padrao -n ac17-cotas -o jsonpath='{.spec.containers[0].resources}{"\n"}'     # padrões preenchidos
p() { oc run "$1" --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas --overrides="{\"spec\":{\"containers\":[{\"name\":\"$1\",\"image\":\"registry.access.redhat.com/ubi9/httpd-24:latest\",\"resources\":$2}]}}" 2>&1 | tail -1; }
p ac17-min   '{"requests":{"cpu":"5m","memory":"32Mi"},"limits":{"cpu":"10m","memory":"64Mi"}}'     # abaixo do mínimo
p ac17-max   '{"requests":{"cpu":"50m","memory":"32Mi"},"limits":{"cpu":"400m","memory":"128Mi"}}'   # acima do máximo
p ac17-razao '{"requests":{"cpu":"10m","memory":"32Mi"},"limits":{"cpu":"200m","memory":"128Mi"}}'   # razão 20 > 10
ac-admin
```

## Repetições

1. Leia cada mensagem e diga qual campo do LimitRange recusou.
2. Um pod com dois contêineres de 200m de limite passa? (`type: Pod`, máximo 500m)
3. Mude o `defaultRequest` e crie outro pod: o primeiro mudou?
4. O que acontece com `oc set resources` acima do máximo em um Deployment? (o ReplicaSet não cria pods)
5. Escreva o LimitRange de memória.

## Desafio sem pista

Mostre que o LimitRange não afeta pods existentes: reduza o `max` de CPU para 50m, confirme que o `ac17-padrao` (100m de limite) continua rodando, e que um pod igual novo é recusado.

## Diagnóstico controlado

- **Sintoma:** `Invalid value: "400m": maximum cpu usage per Container is 250m, but limit is 400m`.
- **Hipóteses:** limit acima do `max` do LimitRange.
- **Investigação:** `oc describe limitrange -n ac17-cotas`.
- **Reversão:** ajuste o pedido; mudar o LimitRange é decisão do admin.

## Validação

```bash
oc get pod ac17-padrao -n ac17-cotas -o jsonpath='{.spec.containers[0].resources.requests.cpu}{"\n"}'    # 25m
```

## Limpeza segura

```bash
oc delete pod ac17-padrao ac17-min ac17-max ac17-razao ac17-padrao2 -n ac17-cotas --ignore-not-found
oc apply -f manifests/admin/limitrange-completo.yaml -n ac17-cotas      # volta o max original
```
