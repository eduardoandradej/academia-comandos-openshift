## Conceito

O circuito diz **o que** obter, não **como**. Itens que exigiram consulta vão para a revisão D+1.

## Comandos guiados

Circuito sem pistas:

1. Capacidade, alocável, reservado e uso do nó.
2. Ranking de projetos por requests.
3. Três quotas em um projeto de treino, lidas por developer.
4. As três recusas típicas de quota.
5. LimitRange com padrão, mínimo, máximo e razão em ação.
6. Pod sem resources aceito graças ao LimitRange.
7. Cota compartilhada entre dois projetos.
8. Controles de agendamento do cluster lidos.
9. Prioridade baixa e quota por escopo de prioridade.
10. Varredura diária do cluster.
11. Parecer de saúde do plano de controle.
12. Logs do kubelet sem entrar no nó.
13. Coleta de um projeto revisada; plano de must-gather.
14. Quatro falhas classificadas por camada de recursos.
15. Limpeza completa (abaixo).

## Repetições

Repita o circuito em D+1, D+3 e D+7, anotando tempo e itens que exigiram consulta.

## Desafio sem pista

Faça o circuito completo sem consulta e encerre a trilha com a limpeza abaixo.

## Diagnóstico controlado

- **Sintoma:** depois da limpeza, o projeto de outra trilha recusa pods com `exceeded quota: ac17-equipe`.
- **Hipóteses:** a ClusterResourceQuota ainda existe e o projeto recebeu o rótulo `equipe=ac17` por engano.
- **Investigação:** `oc get clusterresourcequota`; `oc get namespaces -l academy.openshift.dev/equipe=ac17`.
- **Reversão:** remova a CRQ e o rótulo.

## Validação

```bash
oc get projects -o name | grep -c 'ac17-' || echo "nenhum projeto ac17"
oc get clusterresourcequota,priorityclass -l academy.openshift.dev/trilha=17 -o name | wc -l    # 0
```

## Limpeza segura

```bash
for p in ac17-cotas ac17-equipe-a ac17-equipe-b; do oc delete project "$p" --ignore-not-found; done
oc get clusterresourcequota,priorityclass -l academy.openshift.dev/managed-by=academia,academy.openshift.dev/trilha=17
oc delete clusterresourcequota,priorityclass -l academy.openshift.dev/managed-by=academia,academy.openshift.dev/trilha=17
rm -rf /tmp/ac17-*
ac-dev
```

Os projetos foram criados pelo admin; por isso a remoção é feita com o perfil admin (o `safe-cleanup.sh` atua como o usuário atual).
