# ADM-001 — Capacidade do nó: o que cabe e o que está reservado

## Objetivo e indicador de sucesso

Ler capacidade, alocável, reservado (requests) e uso real do único nó, e calcular a folga para os exercícios.

**Indicador de sucesso:** você diz, em porcentagem, quanto de CPU e memória está **reservado** e quanto está **em uso**, e por que os números diferem.

## Conceito

| Número | Fonte | Significa |
|---|---|---|
| `capacity` | nó | hardware visto pelo kubelet |
| `allocatable` | nó | o que sobra para pods (tirando sistema e kubelet) |
| requests alocados | `oc describe node` (Allocated resources) | **reservado** por pods; o agendador usa isto |
| uso | `oc adm top node` | consumo real agora |

Um pod fica `Pending` por falta de **reserva** (requests), mesmo com uso baixo (TS-054).

## Comandos guiados

```bash
N=$(oc get nodes -o jsonpath='{.items[0].metadata.name}')
oc get node "$N" -o jsonpath='capacidade: {.status.capacity.cpu} CPU, {.status.capacity.memory}{"\n"}alocável: {.status.allocatable.cpu} CPU, {.status.allocatable.memory}{"\n"}pods: {.status.allocatable.pods}{"\n"}'
oc describe node "$N" | sed -n '/Allocated resources:/,/Events:/p'
oc adm top node
oc get pods -A --field-selector=spec.nodeName="$N",status.phase=Running --no-headers | wc -l
```

## Repetições

1. Converta o alocável de memória para GiB.
2. Que porcentagem de CPU está reservada? E em uso?
3. Quantos pods ainda cabem pelo limite de `pods` do nó?
4. Compare com o ORI-008 (mesma leitura, perfil de iniciante).
5. Quanto um projeto com a baseline (500m/768Mi de requests) pode reservar no máximo?

## Desafio sem pista

Calcule, só com `jq`, a soma de `requests.cpu` de todos os pods em execução no nó e compare com o valor de
"Allocated resources" do `describe`.

## Diagnóstico controlado

- **Sintoma:** `oc adm top node` mostra 40% de CPU, mas pods novos ficam `Pending` com `Insufficient cpu`.
- **Hipóteses:** requests reservados já somam perto de 100% do alocável.
- **Investigação:** "Allocated resources" do `describe node`.
- **Reversão:** reduza requests superdimensionados nos **seus** projetos; nunca nos do sistema. Veja TS-054.

## Validação

```bash
oc get nodes -o jsonpath='{.items[0].status.allocatable.cpu}{"\n"}'
```
