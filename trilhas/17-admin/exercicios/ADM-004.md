## Conceito

Quando uma quota limita `requests.cpu` (ou `limits.*`), **todo** pod novo precisa declarar esse valor — senão a
admissão recusa (`must specify`). Um LimitRange com padrões resolve isso preenchendo os valores (ADM-006).

## Comandos guiados

```bash
ac-dev
oc run ac17-sem-req --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas 2>&1 | head -2                       # must specify requests/limits
oc run ac17-a --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas --requests=cpu=100m,memory=128Mi --limits=cpu=200m,memory=256Mi 2>/dev/null \
  || oc run ac17-a --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas --overrides='{"spec":{"containers":[{"name":"ac17-a","image":"registry.access.redhat.com/ubi9/httpd-24:latest","resources":{"requests":{"cpu":"100m","memory":"128Mi"},"limits":{"cpu":"200m","memory":"256Mi"}}}]}}'
oc create deployment ac17-d1 --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas --dry-run=client -o yaml \
  | oc set resources --local -f - --requests=cpu=150m,memory=128Mi --limits=cpu=300m,memory=256Mi -o yaml | oc apply -n ac17-cotas -f -
oc create deployment ac17-d2 --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas --dry-run=client -o yaml \
  | oc set resources --local -f - --requests=cpu=150m,memory=128Mi --limits=cpu=300m,memory=256Mi -o yaml | oc apply -n ac17-cotas -f -
sleep 10; oc describe rs -n ac17-cotas -l app=ac17-d2 | grep -m2 -i 'exceeded quota'
for i in 3 4; do oc create deployment ac17-d$i --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-cotas 2>&1 | tail -1; done   # count/deployments.apps
oc describe quota -n ac17-cotas | grep -E 'requests.cpu|count/deployments'
ac-admin
```

## Repetições

4. Crie um pod `BestEffort` (sem requests) depois de remover a exigência: o escopo `BestEffort` deixa quantos?
5. Escreva as três mensagens de memória.

## Desafio sem pista

Sem apagar nada, descubra quantos pods de 50m/64Mi (requests) ainda cabem no projeto, considerando as três quotas.

## Diagnóstico controlado

- **Sintoma:** `Error from server (Forbidden): pods "x" is forbidden: failed quota: ac17-computacao: must specify limits.cpu for: x; limits.memory ...; requests.cpu ...`.
- **Hipóteses:** quota de computação sem LimitRange com padrões.
- **Investigação:** `oc get limitrange -n ac17-cotas`.
- **Reversão:** declare requests/limits no pod, ou peça o LimitRange ao admin (ADM-006). Veja TS-052.
