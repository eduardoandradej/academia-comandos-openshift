## Conceito

| Controle | Onde | Efeito |
|---|---|---|
| rótulos do nó | `node.metadata.labels` | alvo de `nodeSelector`/afinidade |
| taints | `node.spec.taints` | afastam pods sem `tolerations` |
| `mastersSchedulable` | `scheduler.config.openshift.io/cluster` | permite workloads em control plane (SNO: sim) |
| `defaultNodeSelector` | mesmo objeto | seletor aplicado a todos os projetos |
| `openshift.io/node-selector` | anotação do namespace | seletor aplicado aos pods do projeto |

**Nunca** rotule, aplique taint, isole (`cordon`) ou drene o nó do SNO: os exercícios só leem.

## Comandos guiados

```bash
N=$(oc get nodes -o jsonpath='{.items[0].metadata.name}')
oc get node "$N" --show-labels | tr ',' '\n' | grep -E 'node-role|kubernetes.io/(os|arch|hostname)'
oc get node "$N" -o jsonpath='{.spec.taints}{"\n"}'
oc get scheduler cluster -o jsonpath='{.spec}{"\n"}'
oc get namespace ac17-cotas -o jsonpath='{.metadata.annotations.openshift\.io/node-selector}{"\n"}'
oc get pods -n openshift-dns -o jsonpath='{.items[0].spec.tolerations}{"\n"}' | head -c 400; echo
```

## Repetições

1. Que papel o nó tem (`node-role.kubernetes.io/...`)?
2. Algum taint `NoSchedule`? O que aconteceria com seus pods se houvesse?
3. Por que os pods de sistema têm tantas `tolerations`?
4. Um pod com `nodeSelector: {disco: ssd}` rodaria? (TS-014)
5. O que mudaria em um cluster com nós de trabalho separados?

## Desafio sem pista

Prove, com `oc run --dry-run=server`, que um pod com `nodeSelector` inexistente é aceito pela API (o problema só aparece no agendamento), e explique a diferença para uma recusa de admissão.

## Diagnóstico controlado

- **Sintoma:** todos os pods de um projeto ficam `Pending` com `didn't match Pod's node affinity/selector`.
- **Hipóteses:** anotação `openshift.io/node-selector` no namespace apontando para rótulo inexistente.
- **Investigação:** anotações do namespace; rótulos do nó.
- **Reversão:** decisão do admin; corrigir a anotação do namespace (nunca rotular o nó "para encaixar").
