## Objetivo e indicador de sucesso

Ler os dois tipos de patch dos overlays e escrever novos: um estratégico (arquivo) e um JSON 6902 com `target`.

**Indicador de sucesso:** você acrescenta uma liveness TCP só na `prod` (estratégico) e um rótulo só no Service da `dev` (JSON), e prova pela renderização.

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac13/kustomize/...`, nunca `manifests/kustomize/` do repositório.
> Para recomeçar: `rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/`.

| Patch | Forma em `patches:` | Quando |
|---|---|---|
| estratégico | `- path: arquivo.yaml` (objeto parcial com `kind`/`name`) | mudanças "parecidas com YAML", listas por nome |
| JSON 6902 | `- target: {kind, name}` + `patch: \|-` com operações | caminho exato, remoções, listas por índice |

Mesmas regras da Trilha 12 (DCL-008), aplicadas na renderização em vez de no cluster.

## Comandos guiados

```bash
cat /tmp/ac13/kustomize/overlays/prod/patch-recursos.yaml
cat > /tmp/ac13/kustomize/overlays/prod/patch-liveness.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ac13-loja
spec:
  template:
    spec:
      containers:
        - name: web
          livenessProbe:
            tcpSocket:
              port: 8080
            periodSeconds: 10
            failureThreshold: 3
EOF
printf '  - path: patch-liveness.yaml\n' >> /tmp/ac13/kustomize/overlays/prod/kustomization.yaml
cat >> /tmp/ac13/kustomize/overlays/dev/kustomization.yaml <<'EOF'
  - target:
      kind: Service
      name: ac13-loja
    patch: |-
      - op: add
        path: /metadata/labels/exposto
        value: "interno"
EOF
oc kustomize /tmp/ac13/kustomize/overlays/prod | grep -A4 livenessProbe
oc kustomize /tmp/ac13/kustomize/overlays/dev | awk '/^kind: Service/,/^---/' | grep exposto
oc apply -k /tmp/ac13/kustomize/overlays/prod && oc apply -k /tmp/ac13/kustomize/overlays/dev
```

## Repetições

1. Por que o patch estratégico não precisou repetir `image` nem `ports`?
2. Reescreva a liveness como JSON 6902.
3. Remova a readiness só na `dev` com `op: remove`.
4. Use `target` com `labelSelector` em vez de `name`.
5. O que acontece se dois patches mexem no mesmo campo? (o último vence)

## Desafio sem pista

Crie um patch que se aplique a **todos** os Deployments do overlay `prod` (sem citar nome) acrescentando a anotação
`academy.openshift.dev/revisado: "sim"` ao template de pods.

## Diagnóstico controlado

- **Sintoma:** `Error: no matches for Id Deployment.v1.apps/ac13-lojja.[noNs]; failed to find unique target for patch`.
- **Hipóteses:** nome do alvo errado no patch (estratégico ou `target`).
- **Investigação:** `oc kustomize ../../base | grep -A1 '^kind: Deployment'`.
- **Reversão:** corrija o nome. Veja TS-041.

## Validação

```bash
oc get deployment ac13-loja -n ac13-prod -o jsonpath='{.spec.template.spec.containers[0].livenessProbe.tcpSocket.port}{"\n"}'   # 8080
```
