# KUS-011 — oc process: parâmetros, arquivos de parâmetros e valores gerados

## Identificação

- **ID:** KUS-011
- **Trilha:** [13 — Kustomize e Templates](../README.md)
- **Referência didática:** DO180/DO280 — Templates do OpenShift.
- **Fichas de comando:** [`oc-kustomize-process`](../../../catalogo/fichas/oc-kustomize-process.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Renderizar o template com `oc process` passando parâmetros por linha de comando e por arquivo, e aplicá-lo.

**Indicador de sucesso:** duas instâncias (`ac13-tpl-a`, `ac13-tpl-b`) no mesmo projeto, com mensagens e réplicas diferentes.

## Nível

**Nível:** Intermediário

- **Duração sugerida:** 15 min
- **Repetições:** 5×

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev
oc get project ac13-kustomize -o name   # se faltar: oc new-project ac13-kustomize
oc process -f manifests/templates/ac13-template.yaml --parameters
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24`.

## Conceito

| Forma | Exemplo |
|---|---|
| parâmetro avulso | `-p NOME=ac13-tpl-a -p REPLICAS=2` |
| arquivo de parâmetros | `--param-file=/tmp/ac13/b.env` (linhas `CHAVE=valor`) |
| ver só o resultado | `-o yaml` (padrão é JSON de uma `List`) |
| aplicar | `oc process ... \| oc apply -f -` |

Parâmetros com `generate` mudam a cada processamento: reaplicar gera **outro** valor (atenção com Secrets).

## Comandos guiados

```bash
oc process -f manifests/templates/ac13-template.yaml -p NOME=ac13-tpl-a -o yaml | grep -E '^- apiVersion|^  kind|name:|replicas'
oc process -f manifests/templates/ac13-template.yaml -p NOME=ac13-tpl-a -p MENSAGEM='instancia A' \
  | oc apply -n ac13-kustomize -f -
printf 'NOME=ac13-tpl-b\nMENSAGEM=instancia B\nREPLICAS=2\n' > /tmp/ac13/b.env
oc process -f manifests/templates/ac13-template.yaml --param-file=/tmp/ac13/b.env | oc apply -n ac13-kustomize -f -
oc get deploy,svc,cm,secret -n ac13-kustomize -l app.kubernetes.io/part-of=ac13-template
oc rollout status deployment/ac13-tpl-b -n ac13-kustomize
oc get deployment ac13-tpl-a ac13-tpl-b -n ac13-kustomize -o custom-columns=NOME:.metadata.name,REPLICAS:.spec.replicas
```

## Repetições

1. Processe duas vezes e compare a `senha` gerada (`oc process ... -o json | jq -r '.items[1].stringData.senha'` — valor de treino).
2. Reaplique `ac13-tpl-a`: a senha do Secret mudou? Como evitar? (passe `-p SENHA=...` ou não reaplique o Secret)
3. Passe um parâmetro que não existe (`-p COR=azul`) e leia o erro.
4. Esqueça o `NOME` obrigatório e leia o erro.
5. `--ignore-unknown-parameters` — quando faz sentido?

## Desafio sem pista

Faça uma reaplicação idempotente da instância A (nenhum objeto `configured` no segundo apply), apesar do parâmetro gerado.

## Diagnóstico controlado

- **Sintoma:** `error: unknown parameter name "COR"`.
- **Hipóteses:** parâmetro inexistente no template.
- **Investigação:** `oc process -f ... --parameters`.
- **Reversão:** nada foi aplicado; corrija o nome (ou `--ignore-unknown-parameters`).

## Validação

```bash
oc get deployment ac13-tpl-b -n ac13-kustomize -o jsonpath='{.spec.replicas}{"\n"}'    # 2
```

## Limpeza segura

```bash
oc delete all,cm,secret -n ac13-kustomize -l app.kubernetes.io/part-of=ac13-template
rm -f /tmp/ac13/b.env
```
