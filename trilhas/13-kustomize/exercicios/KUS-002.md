# KUS-002 — Aplicar, comparar e remover com -k

## Identificação

- **ID:** KUS-002
- **Trilha:** [13 — Kustomize e Templates](../README.md)
- **Referência didática:** DO280 — implantação com Kustomize.
- **Fichas de comando:** [`oc-kustomize-process`](../../../catalogo/fichas/oc-kustomize-process.md), [`oc-apply-patch-diff`](../../../catalogo/fichas/oc-apply-patch-diff.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Aplicar a base em um projeto com `oc apply -k`, comparar com `oc diff -k` e remover com `oc delete -k`.

**Indicador de sucesso:** `oc diff -k` retorna 0 logo após o apply, e 1 depois de mudar a página.

**Nível:** Iniciante

```bash

```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac13/kustomize/...`, nunca `manifests/kustomize/` do repositório.
> Para recomeçar: `rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/`.

Os mesmos verbos declarativos da Trilha 12 aceitam `-k <diretório>` no lugar de `-f <arquivo>`: `oc apply -k`,
`oc diff -k`, `oc delete -k`. A base não define namespace, então use `-n`.

## Comandos guiados

```bash
oc new-project ac13-kustomize --display-name='Academia 13 - Kustomize' 2>/dev/null || oc project ac13-kustomize
oc apply -k /tmp/ac13/kustomize/base -n ac13-kustomize
oc rollout status deployment/ac13-loja -n ac13-kustomize
oc get cm,deploy,svc,route -n ac13-kustomize -l app.kubernetes.io/part-of=ac13-loja
oc diff -k /tmp/ac13/kustomize/base -n ac13-kustomize; echo "rc=$?"           # 0
echo 'loja da academia (base v2)' > /tmp/ac13/kustomize/base/index.html
oc diff -k /tmp/ac13/kustomize/base -n ac13-kustomize | head -30; echo "rc=${PIPESTATUS[0]}"
H=$(oc get route ac13-loja -n ac13-kustomize -o jsonpath='{.spec.host}'); curl -sS "http://$H/"
```

## Repetições

1. Aplique a mudança da página e confira o rollout automático (`oc rollout history`).
2. Quantos ConfigMaps `ac13-pagina-*` existem agora? Por quê?
3. `oc delete -k ... --dry-run=client`: o ConfigMap antigo está na lista?
4. Faça `oc apply -k` duas vezes seguidas e leia `unchanged`.
5. Compare `oc apply -k dir` com `oc kustomize dir | oc apply -f -`.

## Desafio sem pista

Explique (e prove) por que mudar só o conteúdo da página fez o Deployment criar pods novos, quando na Trilha 08 isso exigia `rollout restart`.

## Diagnóstico controlado

- **Sintoma:** `error: unable to find one or more files in ... kustomization` ou `must build at directory`.
- **Hipóteses:** `-k` recebeu um arquivo, ou o diretório não tem `kustomization.yaml`.
- **Investigação:** `ls <dir>/kustomization.yaml`.
- **Reversão:** aponte para o diretório.

## Validação

```bash
oc get deployment ac13-loja -n ac13-kustomize -o jsonpath='{.status.readyReplicas}{"\n"}'    # 1
```
