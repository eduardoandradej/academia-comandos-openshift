## Conceito

O circuito diz **o que** obter, não **como**. Itens que exigiram consulta vão para a revisão D+1.

## Comandos guiados

Circuito sem pistas:

1. Renderizar a base e apontar o nome gerado do ConfigMap.
2. Aplicar, comparar e remover com `-k`.
3. Secret gerado e consumido por `envFrom`.
4. Rótulo comum sem tocar seletores.
5. Dois ambientes aplicados a partir da mesma base.
6. Imagem de produção fixada por digest.
7. Patch estratégico e patch JSON com `target`.
8. Overlay novo escrito de memória.
9. ConfigMaps antigos removidos mantendo o anterior.
10. Parâmetros de um Template lidos.
11. Duas instâncias do Template com parâmetros diferentes.
12. Template guardado no projeto e instanciado com `new-app`.
13. Recomendação Kustomize × Template × Helm.
14. Seis erros classificados.
15. Limpeza completa (abaixo).

## Diagnóstico controlado

- **Sintoma:** `oc get projects | grep ac13` ainda mostra `ac13-homolog` ou `ac13-qa`.
- **Hipóteses:** projetos auxiliares criados em repetições.
- **Investigação:** `oc get projects -o name | grep ac13`.
- **Reversão:** apague cada um com `oc delete project`.

## Validação

```bash
oc get projects -o name | grep -c 'ac13-' || echo "nenhum projeto ac13 restante"
```

## Limpeza segura

```bash
for p in ac13-kustomize ac13-dev ac13-prod ac13-homolog ac13-qa; do
  oc get project "$p" >/dev/null 2>&1 && scripts/safe-cleanup.sh -n "$p" --execute --delete-project
done
oc get projects -o name | grep ac13- || echo "projetos removidos"
rm -rf /tmp/ac13
```

Se o `safe-cleanup.sh` pedir confirmação, digite o nome do projeto. Ele só remove projetos criados pelo próprio usuário.
