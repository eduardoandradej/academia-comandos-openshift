# KUS-003 — Geradores: ConfigMaps e Secrets com hash

## Identificação

- **ID:** KUS-003

## Objetivo e indicador de sucesso

Usar `configMapGenerator` e `secretGenerator` com arquivos e literais, controlar o sufixo de hash e limpar as versões antigas.

**Indicador de sucesso:** um Secret de treino gerado e referenciado por `envFrom`, e os ConfigMaps antigos removidos com segurança.

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac13/kustomize/...`, nunca `manifests/kustomize/` do repositório.
> Para recomeçar: `rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/`.

| Opção | Efeito |
|---|---|
| `files`, `literals`, `envs` | origens (como `oc create configmap --from-file/--from-literal/--from-env-file`) |
| `generatorOptions.disableNameSuffixHash: true` | sem hash: nome fixo, **sem** rollout automático |
| `generatorOptions.labels/annotations` | metadados nos gerados |
| `behavior: create/merge/replace` | em overlays: criar, mesclar ou substituir o gerado da base |

Cada mudança deixa o ConfigMap anterior no cluster (útil para `rollout undo`); limpe periodicamente.

## Comandos guiados

```bash
cd /tmp/ac13/kustomize/base
cat >> kustomization.yaml <<'EOF'
secretGenerator:
  - name: ac13-api
    literals:
      - TOKEN=token-ficticio-de-treino
generatorOptions:
  labels:
    academy.openshift.dev/gerado: kustomize
EOF
python3 - <<'EOF'
p = 'deployment.yaml'; s = open(p).read()
if 'envFrom' not in s:
    s = s.replace("          ports:\n", "          envFrom:\n            - secretRef:\n                name: ac13-api\n          ports:\n", 1)
open(p, 'w').write(s)
EOF
cd - >/dev/null
oc kustomize /tmp/ac13/kustomize/base | grep -E 'name: ac13-(api|pagina)'
oc apply -k /tmp/ac13/kustomize/base -n ac13-kustomize && oc rollout status deployment/ac13-loja -n ac13-kustomize
oc get cm,secret -n ac13-kustomize -l academy.openshift.dev/gerado=kustomize
oc exec deploy/ac13-loja -n ac13-kustomize -- printenv TOKEN | wc -c
```

## Repetições

1. Mude o `TOKEN` e aplique: o Secret mudou de nome? O Deployment fez rollout?
2. Ligue `disableNameSuffixHash` e repita: e agora?
3. Liste os ConfigMaps `ac13-pagina-*` por idade.
4. Use `envs:` com um arquivo `app.env` no `configMapGenerator`.
5. Por que `literals` em `secretGenerator` não é adequado para segredos reais em um repositório Git?

## Desafio sem pista

Apague com segurança os ConfigMaps `ac13-pagina-*` antigos, mantendo apenas o que o Deployment atual usa e o
imediatamente anterior (para `rollout undo`).

## Diagnóstico controlado

- **Sintoma:** depois de ligar `disableNameSuffixHash`, a página mudou no ConfigMap mas os pods mostram o conteúdo antigo.
- **Hipóteses:** sem hash, o nome não muda; o template não muda; não há rollout (e o arquivo montado pode demorar a atualizar).
- **Investigação:** nome do ConfigMap no volume; `oc rollout history`.
- **Reversão:** volte o hash (padrão) ou faça `oc rollout restart`.

## Validação

```bash
oc get secret -n ac13-kustomize -l academy.openshift.dev/gerado=kustomize -o name | grep -c ac13-api
```

## Limpeza segura

```bash
rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/      # volta a base original
oc apply -k /tmp/ac13/kustomize/base -n ac13-kustomize
oc delete secret -n ac13-kustomize -l academy.openshift.dev/gerado=kustomize
```
