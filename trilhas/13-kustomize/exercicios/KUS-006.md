# KUS-006 — Transformadores de imagem e réplicas

## Identificação

- **ID:** KUS-006
- **Trilha:** [13 — Kustomize e Templates](../README.md)
- **Referência didática:** DO280 — Kustomize (images, replicas).
- **Fichas de comando:** [`oc-kustomize-process`](../../../catalogo/fichas/oc-kustomize-process.md), [`oc-image-imagestream`](../../../catalogo/fichas/oc-image-imagestream.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Fixar a imagem da `prod` por **digest** com o transformador `images` e ajustar réplicas com `replicas`, sem patches.

**Indicador de sucesso:** a renderização da `prod` mostra `httpd-24@sha256:...` e o pod em execução tem esse digest.

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac13/kustomize/...`, nunca `manifests/kustomize/` do repositório.
> Para recomeçar: `rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/`.

```yaml
images:
  - name: registry.access.redhat.com/ubi9/httpd-24   # casa com o nome da imagem nos contêineres
    newName: ...                                      # opcional: outro repositório
    newTag: "1-123"                                   # ou
    digest: sha256:...                                # fixa o conteúdo (preferível em prod)
replicas:
  - name: ac13-loja
    count: 2
```

Promover uma versão para produção vira uma mudança de **uma linha** no overlay (revisável no Git).

## Comandos guiados

```bash
D=$(oc image info registry.access.redhat.com/ubi9/httpd-24:latest --filter-by-os=linux/amd64 -o json | jq -r .digest); echo "$D"
cd /tmp/ac13/kustomize/overlays/prod
sed -i "s|    newTag: latest.*|    digest: $D|" kustomization.yaml
grep -A3 '^images:' kustomization.yaml
oc kustomize . | grep 'image:'
cd - >/dev/null
oc diff -k /tmp/ac13/kustomize/overlays/prod | grep -E '^[-+].*image:'
oc apply -k /tmp/ac13/kustomize/overlays/prod && oc rollout status deployment/ac13-loja -n ac13-prod
oc get pods -n ac13-prod -l app=ac13-loja -o jsonpath='{range .items[*]}{.status.containerStatuses[0].imageID}{"\n"}{end}'
```

## Repetições

1. Use `newName` para trocar o repositório (ex.: `ubi8/httpd-24`) só na `dev` e renderize (não aplique se não quiser baixar).
2. Mude `count` para 1 e de volta para 2.
3. O que acontece se o `name` do transformador não casar com nenhuma imagem? (renderização sem mudança e sem erro)
4. O transformador `replicas` funciona em StatefulSet?
5. Compare com `oc set image` (Trilha 05): qual é auditável no Git?

## Desafio sem pista

Escreva `promove_digest <tag>` que resolve o digest atual da tag, grava-o no overlay `prod`, mostra o `oc diff -k` e só aplica com confirmação.

## Diagnóstico controlado

- **Sintoma:** o overlay tem `images`, mas a imagem renderizada não mudou.
- **Hipóteses:** `name` do transformador diferente do nome usado no Deployment (ex.: com tag, ou outro registry).
- **Investigação:** `oc kustomize ../../base | grep image:` e compare com `name:`.
- **Reversão:** o `name` deve ser a imagem **sem** tag/digest.

## Validação

```bash
oc kustomize /tmp/ac13/kustomize/overlays/prod | grep -q 'httpd-24@sha256:' && echo "digest fixado"
```

## Limpeza segura

Mantenha o digest na cópia; o original no repositório continua com `newTag: latest`.
