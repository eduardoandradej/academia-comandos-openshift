# KUS-008 — Criar um overlay novo do zero

## Identificação

- **ID:** KUS-008
- **Trilha:** [13 — Kustomize e Templates](../README.md)
- **Referência didática:** DO280 — Kustomize (overlays).
- **Fichas de comando:** [`oc-kustomize-process`](../../../catalogo/fichas/oc-kustomize-process.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Escrever, sem copiar dos outros, um overlay `homolog` com namespace próprio, página própria, 1 réplica e um rótulo de ambiente.

**Indicador de sucesso:** `oc apply -k overlays/homolog` cria a loja em `ac13-homolog` e a página diz "homolog".

## Nível

**Nível:** Intermediário

- **Duração sugerida:** 15 min
- **Repetições:** 3×

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
scripts/preflight.sh                 # sem FALHA

test -d /tmp/ac13/kustomize || { mkdir -p /tmp/ac13; cp -r manifests/kustomize /tmp/ac13/; }
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac13/kustomize/...`, nunca `manifests/kustomize/` do repositório.
> Para recomeçar: `rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/`.

Um overlay mínimo precisa de `resources: [../../base]`; o resto é opcional. Escreva-o de memória: é a forma de
verificar se você entendeu cada campo dos KUS-001 a KUS-007.

## Comandos guiados

```bash
oc new-project ac13-homolog --display-name='Academia 13 - homolog' >/dev/null 2>&1 || true
oc project ac13-kustomize >/dev/null
mkdir -p /tmp/ac13/kustomize/overlays/homolog
# escreva /tmp/ac13/kustomize/overlays/homolog/kustomization.yaml (desafio) e então:
oc kustomize /tmp/ac13/kustomize/overlays/homolog | grep -E '^kind:|namespace:|ambiente'
oc apply -k /tmp/ac13/kustomize/overlays/homolog
curl -sS "http://$(oc get route ac13-loja -n ac13-homolog -o jsonpath='{.spec.host}')/"
```

## Repetições

1. Faça o `homolog` herdar da `prod` (resources: `../prod`) em vez da base: o que muda?
2. Acrescente um `namePrefix: hml-`: a Route ainda aponta para o Service certo? (renderize e confira `spec.to.name`)
3. Valide no servidor: `oc kustomize ... | oc apply --dry-run=server -f -`.
4. Apague o `homolog` com `oc delete -k`.
5. Reescreva o overlay de memória em menos de 3 minutos.

## Desafio sem pista

Escreva a `kustomization.yaml` do overlay `homolog` (namespace `ac13-homolog`, rótulo `ambiente: homolog` sem tocar
seletores, página "loja da academia (homolog)", 1 réplica).

## Diagnóstico controlado

- **Sintoma:** com `namePrefix`, a Route renderizada aponta para `ac13-loja`, mas o Service virou `hml-ac13-loja`.
- **Hipóteses:** o Kustomize não conhece a referência `Route.spec.to.name` (tipo do OpenShift) por padrão.
- **Investigação:** renderize e compare os nomes.
- **Reversão:** evite `namePrefix` com Routes, ou ensine a referência com `configurations` (nameReference) — avançado.

## Validação

```bash
oc get deployment ac13-loja -n ac13-homolog -o jsonpath='{.metadata.labels.ambiente}{"\n"}'    # homolog
```

## Limpeza segura

```bash
oc delete -k /tmp/ac13/kustomize/overlays/homolog --ignore-not-found
oc delete project ac13-homolog --ignore-not-found
```
