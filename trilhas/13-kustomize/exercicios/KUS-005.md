# KUS-005 — Overlays: dev e prod a partir da mesma base

## Identificação

- **ID:** KUS-005
- **Trilha:** [13 — Kustomize e Templates](../README.md)
- **Referência didática:** DO280 — Kustomize (overlays).
- **Fichas de comando:** [`oc-kustomize-process`](../../../catalogo/fichas/oc-kustomize-process.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Aplicar os overlays `dev` e `prod` em seus projetos e comparar as renderizações para ver exatamente o que cada ambiente muda.

**Indicador de sucesso:** `ac13-dev` com 1 réplica e página "dev"; `ac13-prod` com 2 réplicas e página "prod"; o diff entre as renderizações mostra só as diferenças intencionais.

## Nível

**Nível:** Intermediário

## Duração e repetições

- **Duração sugerida:** 20 min
- **Repetições:** 5×

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `developer`
- **Projeto:** `ac13-dev` e `ac13-prod`
- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL (até 3 pods ao todo)

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
scripts/preflight.sh                 # sem FALHA
oc get project ac13-kustomize -o name   # criado no KUS-002; se faltar: oc new-project ac13-kustomize
test -d /tmp/ac13/kustomize || { mkdir -p /tmp/ac13; cp -r manifests/kustomize /tmp/ac13/; }
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Cópia de trabalho.** Edite `/tmp/ac13/kustomize/...`, nunca `manifests/kustomize/` do repositório.
> Para recomeçar: `rm -rf /tmp/ac13/kustomize && cp -r manifests/kustomize /tmp/ac13/`.

Um **overlay** é uma kustomization que inclui a base em `resources` e acrescenta transformações. A base nunca é
copiada nem editada por ambiente. Os overlays deste repositório definem `namespace`, por isso **não** se usa `-n`
ao aplicá-los (TS-040).

## Comandos guiados

```bash
oc new-project ac13-dev --display-name='Academia 13 - dev' >/dev/null 2>&1 || true
oc new-project ac13-prod --display-name='Academia 13 - prod' >/dev/null 2>&1 || true
oc project ac13-kustomize >/dev/null
diff <(oc kustomize /tmp/ac13/kustomize/overlays/dev) <(oc kustomize /tmp/ac13/kustomize/overlays/prod)
oc apply -k /tmp/ac13/kustomize/overlays/dev
oc apply -k /tmp/ac13/kustomize/overlays/prod
oc rollout status deployment/ac13-loja -n ac13-dev && oc rollout status deployment/ac13-loja -n ac13-prod
for n in ac13-dev ac13-prod; do
  echo "== $n: réplicas $(oc get deploy ac13-loja -n $n -o jsonpath='{.spec.replicas}')"
  curl -sS "http://$(oc get route ac13-loja -n $n -o jsonpath='{.spec.host}')/"
done
oc exec deploy/ac13-loja -n ac13-dev -- printenv AMBIENTE
```

## Repetições

1. Liste os rótulos `ambiente` de cada objeto nos dois projetos.
2. Mude a página só da `dev` (no overlay) e aplique: a `prod` foi afetada?
3. Mude a base (`index.html` não, pois os overlays a substituem; mude o `periodSeconds` da readiness) e aplique os dois.
4. Compare `oc diff -k` dos dois overlays com o cluster.
5. Desenhe a árvore base → overlays de memória.

## Desafio sem pista

Mostre, com um comando, todas as diferenças entre o Deployment renderizado de `dev` e o de `prod`, campo a campo (não linha a linha).

## Diagnóstico controlado

- **Sintoma:** `error: the namespace from the provided object "ac13-dev" does not match the namespace "ac13-kustomize". You must pass '--namespace=ac13-dev' to perform this operation.`
- **Hipóteses:** `-n` (ou o projeto atual) diferente do `namespace` definido no overlay.
- **Investigação:** `grep namespace overlays/dev/kustomization.yaml`; `oc project -q`.
- **Reversão:** aplique sem `-n`, ou com `-n` igual ao do overlay. Veja TS-040.

## Validação

```bash
oc get deployment ac13-loja -n ac13-prod -o jsonpath='{.spec.replicas}{"\n"}'    # 2
```
