# NET-004 — Liberar o próprio projeto

## Identificação

- **ID:** NET-004
- **Trilha:** [16 — Rede e isolamento](../README.md)
- **Referência didática:** DO280 — NetworkPolicy (isolamento entre projetos).
- **Fichas de comando:** [`oc-networkpolicy`](../../../catalogo/fichas/oc-networkpolicy.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Somar à negação uma política que libera tráfego vindo de pods do mesmo projeto, isolando o projeto dos vizinhos.

**Indicador de sucesso:** `ac16-local` acessa a loja; `ac16-cliente` e `ac16-intruso` (outro projeto) não.


```bash
oc get pods -n ac16-rede -l app=loja -o name       # web-azul e web-verde (NET-002)
oc get pod ac16-cliente -n ac16-vizinho -o name    # cliente do projeto vizinho (NET-002)
oc get pod ac16-local -n ac16-rede -o name         # cliente do próprio projeto (NET-002)
t() { oc exec "$1" -n "$2" -- timeout 3 bash -c "exec 3<>/dev/tcp/$3/${4:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && tail -1 <&3" 2>/dev/null || echo FALHOU; }
t ac16-local ac16-rede web-azul                    # função de teste: imprime a página ou FALHOU
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Função de teste `t`** (definida no pré-flight): `t <pod> <projeto> <destino> [porta]` abre uma conexão HTTP de
> dentro do pod (sem `curl`, por `/dev/tcp`) e imprime a última linha da resposta — ou `FALHOU` em 3 s.
> Bloqueio por NetworkPolicy aparece como **timeout** (os pacotes são descartados), não como "connection refused".

Políticas são **aditivas** (união de permissões): a negação continua, e a nova política acrescenta uma permissão.
`from: [{podSelector: {}}]` sem `namespaceSelector` significa "pods do **mesmo** namespace".

## Comandos guiados

```bash
oc apply -f manifests/networkpolicies/10-permitir-mesmo-projeto.yaml -n ac16-rede
oc get networkpolicy -n ac16-rede
t ac16-local   ac16-rede    web-azul                       # azul
t ac16-cliente ac16-vizinho web-azul.ac16-rede.svc         # FALHOU
t ac16-intruso ac16-vizinho web-verde.ac16-rede.svc        # FALHOU
```

## Repetições

1. Apague só a negação (`ac16-negar-entrada`): o resultado muda? Por quê? (a outra política também seleciona todos os pods)
2. Recoloque a negação.
3. Leia `oc describe networkpolicy ac16-mesmo-projeto`.
4. Qual a diferença entre `from: [{podSelector: {}}]` e `from: [{namespaceSelector: {}}]`?
5. Escreva a política de memória.

## Desafio sem pista

Explique (e prove) por que, com só a `ac16-mesmo-projeto` aplicada (sem a negação), o vizinho já fica bloqueado.

## Diagnóstico controlado

- **Sintoma:** depois de liberar o "mesmo projeto", a Route parou de funcionar.
- **Hipóteses:** o router está em outro namespace (`openshift-ingress`).
- **Investigação:** NET-007.
- **Reversão:** libere o router explicitamente (NET-007). Veja TS-049.
