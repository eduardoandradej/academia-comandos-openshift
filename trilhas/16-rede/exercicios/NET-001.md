## Objetivo e indicador de sucesso

Ler a configuração de rede do cluster — plugin, faixas de pods e Services, DNS e Ingress — sem alterar nada.

**Indicador de sucesso:** você diz de que faixa vêm os IPs dos pods e dos Services, qual plugin de rede está em uso e se ele aplica NetworkPolicy.

## Conceito

| Objeto | Responde |
|---|---|
| `network.config.openshift.io/cluster` | plugin (`OVNKubernetes`), `clusterNetwork` (pods), `serviceNetwork` (Services) |
| `network.operator.openshift.io/cluster` | configuração detalhada do plugin (somente leitura!) |
| `dns.operator/default` | DNS do cluster (CoreDNS em `openshift-dns`) |
| `ingresscontroller/default` | router das Routes |

O OVN-Kubernetes aplica NetworkPolicy, AdminNetworkPolicy e EgressFirewall. **Qualquer** alteração nesses objetos
é mudança de rede global — proibida na Academia.

## Comandos guiados

```bash
oc get network.config.openshift.io cluster -o jsonpath='{.status.networkType}{"\n"}{.status.clusterNetwork}{"\n"}{.status.serviceNetwork}{"\n"}'
oc get network.operator cluster -o jsonpath='{.spec.defaultNetwork.type}{"\n"}'
oc get co network dns ingress
oc get dns.operator/default -o jsonpath='{.status.clusterIP} {.status.clusterDomain}{"\n"}'
oc get ingresscontroller -n openshift-ingress-operator
oc get pods -A -o wide --field-selector=status.phase=Running | awk 'NR>1{print $7}' | cut -d. -f1-2 | sort | uniq -c | head
ac-dev
```

## Repetições

1. Que IP tem o Service `kubernetes` em `default`? Está na `serviceNetwork`?
2. Os pods com `hostNetwork` (ex.: do próprio OVN) usam que IP? (o do nó)
3. `oc get networkpolicy -A | head` — existem políticas em namespaces do sistema?
4. `oc get adminnetworkpolicy,baselineadminnetworkpolicy 2>/dev/null`.
5. Desenhe o caminho cliente → router → Service → pod com as faixas de IP.

## Desafio sem pista

Prove, só com leitura, que o IP de um pod seu está dentro da `clusterNetwork` e o do Service dentro da `serviceNetwork`.

## Diagnóstico controlado

- **Sintoma:** um colega sugere "trocar a faixa de pods" para resolver um conflito com a rede de casa.
- **Hipóteses:** a faixa é fixada na instalação; mudar exige migração de rede.
- **Investigação:** `clusterNetwork` × rede local (`192.168.10.0/24`, `192.168.122.0/24`).
- **Reversão:** nada a fazer pela Academia; registre e trate como projeto de manutenção.
