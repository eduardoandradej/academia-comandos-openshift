# NET-008 — Negar a saída sem quebrar o DNS

## Identificação

- **ID:** NET-008
- **Trilha:** [16 — Rede e isolamento](../README.md)
- **Referência didática:** DO280 — NetworkPolicy (egress).
- **Fichas de comando:** [`oc-networkpolicy`](../../../catalogo/fichas/oc-networkpolicy.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Aplicar "nega toda saída" no `ac16-rede`, ver o DNS quebrar, e liberar só o DNS do cluster.

**Indicador de sucesso:** `getent hosts web-azul` falha com a negação e volta a funcionar com `50-permitir-dns.yaml`.

```bash
oc get pods -n ac16-rede -l app=loja -o name       # web-azul e web-verde (NET-002)

t() { oc exec "$1" -n "$2" -- timeout 3 bash -c "exec 3<>/dev/tcp/$3/${4:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && tail -1 <&3" 2>/dev/null || echo FALHOU; }
t ac16-local ac16-rede web-azul                    # função de teste: imprime a página ou FALHOU
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Função de teste `t`** (definida no pré-flight): `t <pod> <projeto> <destino> [porta]` abre uma conexão HTTP de
> dentro do pod (sem `curl`, por `/dev/tcp`) e imprime a última linha da resposta — ou `FALHOU` em 3 s.
> Bloqueio por NetworkPolicy aparece como **timeout** (os pacotes são descartados), não como "connection refused".

Políticas de **saída** (`Egress`) controlam para onde os pods selecionados podem se conectar. Negar tudo bloqueia
também o DNS: nenhum nome resolve, e os erros parecem "o serviço sumiu". Os pods de DNS do OpenShift escutam na
**5353** (o Service usa 53 e traduz); por isso a liberação é para a porta 5353 em `openshift-dns`.

## Comandos guiados

```bash
oc exec ac16-local -n ac16-rede -- getent hosts web-azul && echo "DNS ok"
oc apply -f manifests/networkpolicies/40-negar-saida.yaml -n ac16-rede
oc exec ac16-local -n ac16-rede -- timeout 5 getent hosts web-azul || echo "DNS FALHOU"
t ac16-local ac16-rede web-azul                                         # FALHOU (nome nem resolve)
oc apply -f manifests/networkpolicies/50-permitir-dns.yaml -n ac16-rede
oc exec ac16-local -n ac16-rede -- getent hosts web-azul && echo "DNS ok"
t ac16-local ac16-rede web-azul                                         # ainda FALHOU: saída para a loja negada
```

## Repetições

1. Teste a saída por IP (sem DNS) para a loja: falha também?
2. (admin, leitura) `oc get pods -n openshift-dns -o wide` e `oc get svc dns-default -n openshift-dns -o yaml | grep -A3 ports`.
3. Libere o DNS só na porta 53 e veja continuar quebrado.
4. A negação de saída afeta as respostas a conexões de entrada? (não: respostas de conexões aceitas passam)
5. Escreva as duas políticas de memória.

## Desafio sem pista

Prove que a política de DNS precisa da 5353 e não da 53, trocando a porta em uma cópia e mostrando a diferença.

## Diagnóstico controlado

- **Sintoma:** depois de uma política de saída, todos os nomes falham (`getent hosts` vazio, `could not resolve`).
- **Hipóteses:** saída para o DNS do cluster não liberada (ou liberada na porta 53).
- **Investigação:** `oc get networkpolicy -n ac16-rede -o yaml | grep -A12 egress`.
- **Reversão:** aplique `50-permitir-dns.yaml`. Veja TS-050.

## Validação

```bash
oc exec ac16-local -n ac16-rede -- getent hosts web-azul >/dev/null && echo "DNS liberado"
```

Mantenha as duas políticas para o NET-009.
