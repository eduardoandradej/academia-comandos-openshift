## Conceito

O circuito diz **o que** obter, não **como**. Itens que exigiram consulta vão para a revisão D+1.

## Comandos guiados

Circuito sem pistas:

1. Plugin e faixas de rede do cluster (admin, leitura).
2. Matriz de conectividade de três clientes para dois backends.
3. Negação total de entrada.
4. Liberação do próprio projeto.
5. Liberação de um cliente específico de outro projeto (AND).
6. A mesma política escrita como OR, e a diferença.
7. Restrição por porta nomeada.
8. Route funcionando de novo depois do isolamento.
9. Negação de saída e liberação do DNS.
10. Saída do cliente só para a loja.
11. Políticas que selecionam um pod.
12. Ordem ANP → NetworkPolicy → BANP explicada.
13. Certificado de uma Route lido por SNI.
14. Certificado de serviço gerado e verificado.
15. Roteiro de conectividade aplicado a uma falha.

## Repetições

Repita o circuito em D+1, D+3 e D+7, anotando tempo e itens que exigiram consulta.

## Desafio sem pista

Faça o circuito completo sem consulta e encerre a trilha com a limpeza abaixo.

## Diagnóstico controlado

- **Sintoma:** depois da trilha, um projeto seu antigo "parou de funcionar".
- **Hipóteses:** uma política foi aplicada no projeto errado (sem `-n`, no projeto atual).
- **Investigação:** `oc get networkpolicy -A -l academy.openshift.dev/managed-by=academia 2>/dev/null` ou projeto a projeto.
- **Reversão:** apague as políticas da Academia pelo rótulo naquele projeto.

## Validação

```bash
for p in ac16-rede ac16-vizinho; do oc get project $p 2>&1 | grep -q NotFound && echo "$p removido"; done
```

## Limpeza segura

```bash
oc delete networkpolicy -l academy.openshift.dev/managed-by=academia -n ac16-rede
oc delete networkpolicy -l academy.openshift.dev/managed-by=academia -n ac16-vizinho
```

```bash
scripts/safe-cleanup.sh -n ac16-rede --execute --delete-project
scripts/safe-cleanup.sh -n ac16-vizinho --execute --delete-project
rm -f /tmp/ac16-*
```
