## Conceito

| Camada | Quem cria | Escopo | Avaliação |
|---|---|---|---|
| AdminNetworkPolicy (ANP) | admin | cluster | **primeiro**; pode `Allow`, `Deny` ou `Pass` (delegar) |
| NetworkPolicy | dono do projeto | namespace | depois, se a ANP passou adiante |
| BaselineAdminNetworkPolicy (BANP) | admin | cluster | **por último**: padrão quando nada decidiu |
| EgressFirewall (OVN) | admin | um namespace | saída para fora do cluster por `cidrSelector` ou `dnsName` |

Na Academia, todos aparecem só em leitura: criar qualquer um é decisão de administração de rede.

## Comandos guiados

```bash
oc api-resources | grep -iE 'adminnetworkpolic|egressfirewall'
oc get adminnetworkpolicies,baselineadminnetworkpolicies 2>/dev/null || echo "nenhuma ANP/BANP"
oc get egressfirewall -A 2>/dev/null || echo "nenhum EgressFirewall"
oc explain egressfirewall.spec.egress --api-version=k8s.ovn.org/v1 2>/dev/null | head -20
oc get networkpolicy -A --no-headers | awk '{print $1}' | sort | uniq -c | sort -rn | head
ac-dev
```

## Repetições

1. Que namespaces do sistema já têm NetworkPolicies? Por quê? (operadores se protegem)
2. Leia `oc explain adminnetworkpolicy.spec` (se o recurso existir).
3. Em que caso uma ANP com `Pass` devolveria a decisão à sua NetworkPolicy?
4. Por que EgressFirewall aceita `dnsName` e NetworkPolicy não?
5. Escreva a ordem de avaliação de memória.

## Desafio sem pista

Escreva (sem aplicar) um EgressFirewall para o `ac16-rede` que permita saída só para `registry.access.redhat.com` e
negue o resto, e valide-o com `--dry-run=server` como admin.

## Diagnóstico controlado

- **Sintoma:** sua NetworkPolicy libera um tráfego, mas ele continua bloqueado.
- **Hipóteses:** uma AdminNetworkPolicy com `Deny` é avaliada antes e decide.
- **Investigação:** `oc get adminnetworkpolicies -o yaml` (admin).
- **Reversão:** converse com o admin de rede; a NetworkPolicy não sobrepõe uma ANP.
