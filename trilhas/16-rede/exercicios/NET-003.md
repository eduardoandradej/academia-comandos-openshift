# NET-003 — Negar toda a entrada (default deny)

## Identificação

- **ID:** NET-003
- **Trilha:** [16 — Rede e isolamento](../README.md)
- **Referência didática:** DO280 — NetworkPolicy (isolamento).
- **Fichas de comando:** [`oc-networkpolicy`](../../../catalogo/fichas/oc-networkpolicy.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Aplicar a política "nega toda entrada" no `ac16-rede` e ver que ela vale até para pods do próprio projeto.

**Indicador de sucesso:** a matriz do NET-002 passa a mostrar `FALHOU` para todas as origens.

## Nível

**Nível:** Iniciante

## Duração e repetições

- **Duração sugerida:** 10 min
- **Repetições:** 5×

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `developer`
- **Projeto:** `ac16-rede`
- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL (1 NetworkPolicy)

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
scripts/preflight.sh                 # sem FALHA
oc whoami                            # developer
```

```bash
oc get pods -n ac16-rede -l app=loja -o name       # web-azul e web-verde (NET-002)
oc get pod ac16-cliente -n ac16-vizinho -o name    # cliente do projeto vizinho (NET-002)
oc get pod ac16-local -n ac16-rede -o name         # cliente do próprio projeto (NET-002)
t() { oc exec "$1" -n "$2" -- timeout 3 bash -c "exec 3<>/dev/tcp/$3/${4:-8080} && printf 'GET / HTTP/1.0\r\n\r\n' >&3 && tail -1 <&3" 2>/dev/null || echo FALHOU; }
t ac16-local ac16-rede web-azul                    # função de teste: imprime a página ou FALHOU
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

> **Função de teste `t`** (definida no pré-flight): `t <pod> <projeto> <destino> [porta]` abre uma conexão HTTP de
> dentro do pod (sem `curl`, por `/dev/tcp`) e imprime a última linha da resposta — ou `FALHOU` em 3 s.
> Bloqueio por NetworkPolicy aparece como **timeout** (os pacotes são descartados), não como "connection refused".

```yaml
spec:
  podSelector: {}        # todos os pods do projeto
  policyTypes: [Ingress] # sem lista "ingress": nada é permitido
```

Vale só para **entrada** dos pods selecionados; saída continua aberta. Não afeta tráfego entre contêineres do mesmo pod.

## Comandos guiados

```bash
cat manifests/networkpolicies/00-negar-entrada.yaml
oc apply --dry-run=server -f manifests/networkpolicies/00-negar-entrada.yaml -n ac16-rede
oc apply -f manifests/networkpolicies/00-negar-entrada.yaml -n ac16-rede
oc get networkpolicy -n ac16-rede
oc describe networkpolicy ac16-negar-entrada -n ac16-rede
t ac16-local   ac16-rede    web-azul
t ac16-cliente ac16-vizinho web-azul.ac16-rede.svc
oc exec ac16-local -n ac16-rede -- getent hosts web-azul       # DNS (saída) continua funcionando
```

## Repetições

1. Por que o cliente local também falhou?
2. O `ac16-local` ainda consegue sair para outro projeto? (`t ac16-local ac16-rede <algo em ac16-vizinho>`)
3. A Route da loja (se existir) responde? (NET-007)
4. Apague a política e repita a matriz.
5. Escreva o YAML de memória.

## Desafio sem pista

Aplique a negação só aos pods da loja (`app=loja`), deixando o `ac16-local` acessível por outros pods, e prove com a matriz.

## Diagnóstico controlado

- **Sintoma:** após a política, `t` demora 3 s e responde `FALHOU` (não "refused").
- **Hipóteses:** pacotes descartados pela política (comportamento esperado).
- **Investigação:** `oc get networkpolicy -n ac16-rede`; `oc describe networkpolicy`.
- **Reversão:** `oc delete networkpolicy ac16-negar-entrada -n ac16-rede`.

## Validação

```bash
[ "$(oc exec ac16-local -n ac16-rede -- timeout 3 bash -c '</dev/tcp/web-azul/8080' >/dev/null 2>&1; echo $?)" != 0 ] && echo "entrada negada"
```
