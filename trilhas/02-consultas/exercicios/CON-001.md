## Conceito

Todo objeto da API tem um **tipo** (Kind), servido por um **grupo/versão** (`apps/v1`, `route.openshift.io/v1`, ou o
grupo core `v1`). `oc api-resources` lista os tipos com:

| Coluna | Significado |
|---|---|
| `NAME` | nome plural usado na CLI (`deployments`) |
| `SHORTNAMES` | atalhos (`deploy`) |
| `APIVERSION` | grupo/versão |
| `NAMESPACED` | `true` = vive dentro de um namespace |
| `KIND` | nome do tipo no YAML (`Deployment`) |

Saber o escopo evita erros: `-n` não faz sentido para recursos de cluster (`nodes`, `clusteroperators`).

## Comandos guiados

```bash
oc api-resources | head -20
oc api-resources --namespaced=true | wc -l               # tipos com namespace
oc api-resources --namespaced=false | wc -l              # tipos de cluster
oc api-resources --api-group=apps                         # só o grupo apps
oc api-resources --api-group=route.openshift.io
oc api-resources --api-group=''                           # grupo core (v1)
oc api-resources -o wide | grep -E '^deployments '        # coluna VERBS
oc api-resources --verbs=list,watch -o name | head        # só tipos listáveis, nome canônico
oc api-resources --sort-by=name -o name | grep -i operator
```

## Desafio sem pista

## Diagnóstico controlado

- **Sintoma:** `error: the server doesn't have a resource type "deploymnet"`.
- **Hipóteses:** (a) erro de digitação; (b) tipo de um operador não instalado; (c) grupo errado.
- **Investigação:** `oc api-resources | grep -i deploy`; `oc api-resources --api-group=<grupo>`.
- **Reversão:** nada a reverter.

## Validação

```bash
oc api-resources -o name | grep -qx 'routes.route.openshift.io' && echo "Route encontrada"
```
