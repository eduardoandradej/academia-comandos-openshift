# CON-003 — Preparar o alvo de observação

## Identificação

- **ID:** CON-003
- **Trilha:** [02 — Leitura e inspeção](../README.md)
- **Referência didática:** DO180 — implantação de aplicações (preparação para leitura).
- **Fichas de comando:** [`oc-wait`](../../../catalogo/fichas/oc-wait.md), [`oc-get`](../../../catalogo/fichas/oc-get.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Criar `ac02-consultas` e implantar o alvo de observação (ConfigMap, Deployment com 2 réplicas e Service), com revisão e dry-run antes.

**Indicador de sucesso:** `oc wait` confirma o Deployment `obs-web` disponível e todos os objetos carregam o rótulo da Academia.

## Nível

**Nível:** Iniciante

## Duração e repetições

- **Duração sugerida:** 15 min
- **Repetições:** 5× (apagar e reaplicar)

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `developer` (e `admin` para a baseline opcional)
- **Projeto:** `ac02-consultas`
- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL (2 pods httpd, ~64 Mi de request cada)

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
scripts/preflight.sh                 # sem FALHA
oc whoami                            # developer
```

REQUER PREPARAÇÃO: o cluster precisa baixar `registry.access.redhat.com/ubi9/httpd-24`.

## Conceito

A Trilha 02 é de **leitura**, mas leitura precisa de algo para ler. O manifesto
`manifests/apps-exemplo/observacao-httpd.yaml` cria um alvo pequeno e previsível: rótulos `app`, `tier` e os da
Academia, uma anotação, um ConfigMap injetado como variáveis e uma readiness probe TCP.

`oc wait --for=condition=Available` bloqueia até a condição ser verdadeira ou o tempo acabar — melhor que repetir `oc get`.

## Comandos guiados

```bash
oc new-project ac02-consultas --display-name='Academia 02 - Consultas'
# (opcional, perfil admin) baseline de cota: ac-admin; oc apply -f manifests/baseline-seguro/quota-limitrange.yaml -n ac02-consultas; ac-dev
F=manifests/apps-exemplo/observacao-httpd.yaml
less "$F"                                               # revise
oc apply --dry-run=server -f "$F" -n ac02-consultas     # validação no servidor
oc apply -f "$F" -n ac02-consultas
oc wait --for=condition=Available deployment/obs-web -n ac02-consultas --timeout=180s
oc get all -n ac02-consultas                            # visão geral
oc get all,configmap -n ac02-consultas -l academy.openshift.dev/managed-by=academia
```

## Repetições

1. `oc delete -f "$F" -n ac02-consultas` e reaplique; meça com `time` o `oc wait`.
2. `oc apply -f "$F" -n ac02-consultas` duas vezes: o que a segunda saída diz?
3. `oc get pods -n ac02-consultas -l app=obs-web -o wide`.
4. `oc get events -n ac02-consultas --sort-by=.metadata.creationTimestamp | tail`.
5. `oc rollout status deployment/obs-web -n ac02-consultas` — compare com `oc wait`.

## Desafio sem pista

Recrie o alvo do zero (sem o projeto) em uma sequência que termine somente quando os dois pods estiverem prontos e que
falhe com código diferente de zero se isso não acontecer em 3 minutos.

## Diagnóstico controlado

- **Sintoma:** pods em `ErrImagePull`/`ImagePullBackOff`.
- **Hipóteses:** (a) sem acesso de saída à `registry.access.redhat.com`; (b) nome/tag errados; (c) registry com problema.
- **Investigação:** `oc describe pod -n ac02-consultas -l app=obs-web | sed -n '/Events:/,$p'`.
- **Reversão:** `scripts/safe-cleanup.sh -n ac02-consultas --execute`. Sem acesso a registries externos, a Trilha 02 fica **REQUER PREPARAÇÃO**; os exercícios CON-001, CON-002 e a parte de cluster do CON-015 continuam possíveis.

## Validação

```bash
oc get deployment obs-web -n ac02-consultas -o jsonpath='{.status.readyReplicas}/{.spec.replicas}{"\n"}'   # 2/2
```

## Limpeza segura

O alvo permanece até o CON-015. Para remover agora: `scripts/safe-cleanup.sh -n ac02-consultas --execute`.
