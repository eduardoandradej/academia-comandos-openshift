## Objetivo e indicador de sucesso

Acompanhar objetos em tempo real com `-w` e esperar condições com `oc wait`, inclusive por jsonpath e por exclusão.

**Indicador de sucesso:** um script curto que reinicia o alvo e só termina quando ele volta a ficar disponível, com timeout.

## Conceito

| Ferramenta | Uso |
|---|---|
| `oc get ... -w` | imprime cada mudança até Ctrl+C |
| `--output-watch-events` | prefixa `ADDED`/`MODIFIED`/`DELETED` |
| `--watch-only` | não lista o estado inicial |
| `oc wait --for=condition=X` | espera uma condição `status.conditions[type=X]=True` |
| `oc wait --for=jsonpath='{...}'=valor` | espera um campo ter certo valor |
| `oc wait --for=delete` | espera o objeto sumir |
| `--timeout=` | sem ele, o padrão é 30 s |

## Comandos guiados

```bash
oc get pods -n ac02-consultas -l app=obs-web -w --output-watch-events   # terminal 1 (Ctrl+C para sair)
# terminal 2:
oc rollout restart deployment/obs-web -n ac02-consultas
oc wait --for=condition=Available deployment/obs-web -n ac02-consultas --timeout=180s
oc scale deployment/obs-web --replicas=1 -n ac02-consultas
oc wait --for=jsonpath='{.status.readyReplicas}'=1 deployment/obs-web -n ac02-consultas --timeout=120s
oc scale deployment/obs-web --replicas=2 -n ac02-consultas
oc wait --for=jsonpath='{.status.readyReplicas}'=2 deployment/obs-web -n ac02-consultas --timeout=120s
oc wait --for=condition=Ready pod -l app=obs-web -n ac02-consultas --timeout=120s
```

## Repetições

1. Repita o restart 5×, observando no terminal 1 a ordem `ADDED`/`MODIFIED`/`DELETED`.
2. `oc get deploy obs-web -n ac02-consultas -w` durante o restart.
3. `oc get events -n ac02-consultas -w --watch-only` durante o restart.
4. Crie um ConfigMap rotulado temporário, apague-o em segundo plano e espere com `oc wait --for=delete configmap/<nome>`.
5. Rode `oc wait` com `--timeout=1s` e interprete o código de saída.

## Desafio sem pista

Escreva um script de até 5 linhas que reinicia `obs-web`, espera ele ficar disponível em até 3 minutos e imprime o tempo
gasto; em caso de timeout, imprime os eventos `Warning` e sai com código 1.

## Diagnóstico controlado

- **Sintoma:** `error: timed out waiting for the condition on deployments/obs-web`.
- **Hipóteses:** (a) timeout curto; (b) rollout travado (imagem, quota, recursos).
- **Investigação:** `oc rollout status deployment/obs-web -n ac02-consultas --timeout=5s`; `oc get events -n ac02-consultas --field-selector type=Warning`.
- **Reversão:** garanta `--replicas=2` e o Deployment disponível; em último caso, `oc rollout undo deployment/obs-web -n ac02-consultas`.

## Validação

```bash
oc get deployment obs-web -n ac02-consultas -o jsonpath='{.spec.replicas} {.status.readyReplicas}{"\n"}'   # 2 2
```

## Limpeza segura

Garanta o alvo em 2 réplicas (`oc scale deployment/obs-web --replicas=2 -n ac02-consultas`). Apague ConfigMaps
temporários pelo rótulo: `oc delete configmap -l academy.openshift.dev/managed-by=academia,app!=obs-web -n ac02-consultas`.
