## Conceito

Eventos são objetos curtos, gerados por controladores e pelo kubelet (`Scheduled`, `Pulling`, `Pulled`, `Created`,
`Started`, `ScalingReplicaSet`...). Eles **expiram** (por padrão, em torno de uma hora) — não servem de histórico longo.

`--sort-by=<caminho jsonpath>` ordena no cliente. Para eventos, `.metadata.creationTimestamp` é o campo mais confiável
(`lastTimestamp` pode estar vazio em eventos do formato novo).

## Comandos guiados

```bash
oc get events -n ac02-consultas --sort-by=.metadata.creationTimestamp
oc get events -n ac02-consultas --sort-by=.metadata.creationTimestamp | tail -5     # os mais recentes
oc get events -n ac02-consultas --field-selector type=Warning
oc get pods -n ac02-consultas --sort-by=.metadata.creationTimestamp
oc get pods -n ac02-consultas --sort-by='{.status.containerStatuses[0].restartCount}'
oc get events -n ac02-consultas -o custom-columns=QUANDO:.metadata.creationTimestamp,OBJETO:.involvedObject.name,MOTIVO:.reason --sort-by=.metadata.creationTimestamp
oc get events -n ac02-consultas -w        # acompanhe em tempo real; Ctrl+C para sair
```

## Repetições

1. Em outro terminal, rode `oc rollout restart deployment/obs-web -n ac02-consultas` (AMARELO, reversível: só recria os 2 pods) e observe o `-w`.
2. Depois do restart, reconstrua a sequência de eventos do novo ReplicaSet.
3. Ordene os ConfigMaps por nome (`--sort-by=.metadata.name`).
4. `oc describe pod <pod> -n ac02-consultas | sed -n '/Events:/,$p'` — compare com `oc get events`.
5. Quantos eventos `Normal` existem? E `Warning`?

## Desafio sem pista

Liste os eventos do projeto dos últimos 10 minutos, em ordem cronológica, com hora, objeto (`kind/nome`) e mensagem.

## Diagnóstico controlado

- **Sintoma:** `No resources found in ac02-consultas namespace.` ao pedir eventos de ontem.
- **Hipóteses:** eventos expiraram (TTL), não "sumiram por erro".
- **Investigação:** veja a idade do evento mais antigo: `oc get events -n ac02-consultas --sort-by=.metadata.creationTimestamp | head -2`.
- **Reversão:** nada a reverter. Para histórico, use logs ou o próprio `status` dos objetos.
