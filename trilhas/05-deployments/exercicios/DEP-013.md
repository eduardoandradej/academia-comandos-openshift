## Conceito

Imperativo (`create`, `scale`, `set`) é ótimo para explorar; declarativo (arquivo + `apply`) é o que se versiona e
repete. Para extrair um manifesto reaplicável de um objeto existente, remova `status`, `uid`, `resourceVersion`,
`creationTimestamp`, `generation`, `managedFields` e anotações geradas.

`oc diff -f` mostra o que o `apply` mudaria (código de saída 1 = há diferença). A Trilha 12 aprofunda o assunto.

## Comandos guiados

```bash
oc get deployment ac05-web -n ac05-deploy -o json \
  | jq 'del(.status, .metadata.uid, .metadata.resourceVersion, .metadata.creationTimestamp, .metadata.generation,
            .metadata.managedFields, .metadata.annotations["deployment.kubernetes.io/revision"])' > /tmp/ac05-web.json
oc diff -f /tmp/ac05-web.json -n ac05-deploy; echo "rc=$?"             # 0 = idêntico
jq '.spec.template.spec.containers[0].env = [{"name":"VERSAO","value":"declarativa"}]' /tmp/ac05-web.json > /tmp/ac05-web2.json
oc diff -f /tmp/ac05-web2.json -n ac05-deploy; echo "rc=$?"            # 1 = há diferença
oc apply -f /tmp/ac05-web2.json -n ac05-deploy
oc rollout status deployment/ac05-web -n ac05-deploy
oc diff -f /tmp/ac05-web2.json -n ac05-deploy; echo "rc=$?"            # 0
```

## Repetições

0. Se o `apply` avisar que falta a anotação `last-applied-configuration`, é esperado na primeira vez: ele a cria.
1. Converta o JSON em YAML legível: `oc apply -f /tmp/ac05-web2.json --dry-run=client -o yaml -n ac05-deploy > /tmp/ac05-web.yaml`.
2. Mude `replicas` no arquivo para 1 e use `oc diff`.
3. Faça `oc scale` para 2 e rode `oc diff` de novo: o que ele mostra?
4. `oc patch deployment ac05-web -n ac05-deploy --type=json -p '[{"op":"replace","path":"/spec/replicas","value":2}]'`.
5. Apague o Deployment e recrie-o só com `oc apply -f /tmp/ac05-web.yaml`.

## Desafio sem pista

Mantenha um manifesto `/tmp/ac05-web.yaml` como fonte da verdade: altere-o para 1 réplica e `VERSAO=arquivo`, aplique, e
prove que o cluster e o arquivo estão em acordo (`oc diff` vazio). Volte a 2 réplicas pelo arquivo.

## Diagnóstico controlado

- **Sintoma:** `oc apply` responde `the object has been modified; please apply your changes to the latest version`.
- **Hipóteses:** o arquivo contém `resourceVersion` antigo.
- **Investigação:** `grep -n resourceVersion /tmp/ac05-web*.json`.
- **Reversão:** nada foi gravado; remova o campo e repita.

## Validação

```bash
oc diff -f /tmp/ac05-web.yaml -n ac05-deploy >/dev/null && echo "cluster = arquivo"
```
