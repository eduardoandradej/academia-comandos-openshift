# DEP-011 — CronJobs: agendar sem sobrecarregar

## Identificação

- **ID:** DEP-011
- **Trilha:** [05 — Deployments e workloads](../README.md)
- **Referência didática:** DO280 — Jobs e CronJobs.
- **Fichas de comando:** [`oc-create-job-cronjob`](../../../catalogo/fichas/oc-create-job-cronjob.md)

## Objetivo e indicador de sucesso

Criar um CronJob **suspenso**, disparar execuções manuais a partir dele e controlar histórico, concorrência e fuso horário.

**Indicador de sucesso:** um CronJob que só roda quando você manda, com histórico limitado a 2 sucessos.

**Nível:** Intermediário

## Conceito

| Campo | Significado |
|---|---|
| `schedule` | cron de 5 campos: minuto hora dia mês dia-da-semana |
| `timeZone` | fuso (ex.: `America/Sao_Paulo`); sem ele, vale o do controlador (UTC, em geral) |
| `suspend` | `true` = não agenda novas execuções |
| `concurrencyPolicy` | `Allow`, `Forbid` (não sobrepõe) ou `Replace` |
| `successfulJobsHistoryLimit` / `failedJobsHistoryLimit` | quantos Jobs antigos manter |

No SNO, prefira CronJobs **suspensos** e execuções manuais (`oc create job --from=cronjob/...`) — nada de rodar a cada minuto esquecido.

## Comandos guiados

```bash
oc create cronjob ac05-relatorio --image=registry.access.redhat.com/ubi9/httpd-24:latest \
  --schedule='15 3 * * *' -n ac05-deploy -- /bin/sh -c 'echo "relatório $(date -u +%FT%TZ)"'
oc patch cronjob ac05-relatorio -n ac05-deploy --type=merge \
  -p '{"spec":{"suspend":true,"timeZone":"America/Sao_Paulo","concurrencyPolicy":"Forbid","successfulJobsHistoryLimit":2,"failedJobsHistoryLimit":1}}'
oc label cronjob ac05-relatorio academy.openshift.dev/managed-by=academia -n ac05-deploy
oc get cronjob ac05-relatorio -n ac05-deploy
for i in 1 2 3; do oc create job "ac05-relatorio-manual-$i" --from=cronjob/ac05-relatorio -n ac05-deploy; done
oc wait --for=condition=complete job/ac05-relatorio-manual-3 -n ac05-deploy --timeout=120s
oc get jobs -n ac05-deploy
oc logs job/ac05-relatorio-manual-1 -n ac05-deploy
```

## Repetições

1. Traduza para cron: "todo dia útil às 7h30", "a cada 15 minutos", "dia 1 de cada mês à meia-noite".
2. `oc get cronjob ac05-relatorio -n ac05-deploy -o jsonpath='{.spec.suspend} {.spec.timeZone} {.status.lastScheduleTime}{"\n"}'`.
3. Os Jobs criados com `--from` têm dono? (`ownerReferences`)
4. Troque o horário com `oc patch` e confira.
5. `oc explain cronjob.spec.concurrencyPolicy`.

## Desafio sem pista

Sem tirar o CronJob da suspensão, faça uma execução manual cujo nome inclua a data e hora atuais, e prove que ela
terminou com sucesso e qual mensagem gravou.

## Diagnóstico controlado

- **Sintoma:** os Jobs manuais não são apagados pelo `successfulJobsHistoryLimit`.
- **Hipóteses:** o limite vale para os Jobs **agendados** que o CronJob controla; Jobs criados com `--from` podem não ser contados da mesma forma.
- **Investigação:** compare `ownerReferences` de um Job manual com o de um Job agendado (se houver).
- **Reversão:** apague os manuais por nome ou rótulo.

## Validação

```bash
oc get cronjob ac05-relatorio -n ac05-deploy -o jsonpath='{.spec.suspend}{"\n"}'   # true
```

## Limpeza segura

```bash
oc get jobs -n ac05-deploy -o name | grep ac05-relatorio | xargs -r oc delete -n ac05-deploy
oc delete cronjob ac05-relatorio -n ac05-deploy
```
