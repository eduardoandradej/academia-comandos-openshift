# DEP-009 — oc new-app a partir de uma imagem

## Identificação

- **ID:** DEP-009
- **Trilha:** [05 — Deployments e workloads](../README.md)
- **Referência didática:** DO180 — implantar aplicações a partir de imagens.
- **Fichas de comando:** [`oc-create-deployment-scale`](../../../catalogo/fichas/oc-create-deployment-scale.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Implantar uma aplicação com `oc new-app --image`, listar tudo o que ele criou e limpar pelo rótulo.

**Indicador de sucesso:** um inventário dos objetos criados pelo `new-app` e a remoção completa só deles.

## Nível

**Nível:** Iniciante

## Duração e repetições

- **Duração sugerida:** 15 min
- **Repetições:** 5×

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `developer`
- **Projeto:** `ac05-deploy`
- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL (1 pod httpd + objetos auxiliares)

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
```

```bash
oc get project ac05-deploy -o name   # criado no DEP-001; se faltar: oc new-project ac05-deploy
```

REQUER PREPARAÇÃO: o cluster precisa baixar `registry.access.redhat.com/ubi9/httpd-24` (normalmente já em cache).

## Conceito

`oc new-app` é um gerador do OpenShift: a partir de uma imagem (ou de código-fonte, ou de template), ele cria de uma vez
os objetos necessários — tipicamente um **Deployment**, um **Service** para as portas expostas pela imagem e, para
imagens externas, um **ImageStream** que a rastreia.

`-l` acrescenta rótulos a **todos** os objetos criados — ótimo para limpar depois. `--dry-run -o yaml` mostra o que
seria criado.

## Comandos guiados

```bash
oc new-app --image=registry.access.redhat.com/ubi9/httpd-24:latest --name=ac05-app \
  -l academy.openshift.dev/managed-by=academia,app.kubernetes.io/part-of=ac05 -n ac05-deploy --dry-run -o yaml | grep -E '^kind:|^  kind:|name: ac05-app' | head -20
oc new-app --image=registry.access.redhat.com/ubi9/httpd-24:latest --name=ac05-app \
  -l academy.openshift.dev/managed-by=academia,app.kubernetes.io/part-of=ac05 -n ac05-deploy
oc get all,imagestreams -n ac05-deploy -l app.kubernetes.io/part-of=ac05
oc rollout status deployment/ac05-app -n ac05-deploy
oc get svc ac05-app -n ac05-deploy -o jsonpath='{.spec.ports}{"\n"}'
oc status -n ac05-deploy
```

## Repetições

1. Compare o Deployment criado pelo `new-app` com o do `oc create deployment` (rótulos, anotações, portas).
2. `oc get deployment ac05-app -n ac05-deploy -o jsonpath='{.metadata.annotations}' | jq .` — há anotações de gatilho de imagem?
3. Apague tudo por rótulo e recrie (5×).
4. `oc new-app --help | sed -n '/Examples:/,/Options:/p'`.
5. `oc new-app ... --as-deployment-config`? Verifique no `--help` se a opção existe nesta versão e por quê (DeploymentConfig é legado).

## Desafio sem pista

Remova **tudo** o que o `new-app` criou (incluindo o ImageStream) com um único comando por rótulo, sem afetar o `ac05-web`.

## Diagnóstico controlado

- **Sintoma:** depois de `oc delete all -l ...`, o ImageStream continua lá.
- **Hipóteses:** `all` não inclui ImageStreams em todas as versões/clientes.
- **Investigação:** `oc get imagestreams -n ac05-deploy -l app.kubernetes.io/part-of=ac05`.
- **Reversão:** inclua o tipo explicitamente: `oc delete all,imagestreams -l ...`.

## Validação

```bash
oc get all,imagestreams -n ac05-deploy -l app.kubernetes.io/part-of=ac05 -o name | wc -l    # 0 após o desafio
```

## Limpeza segura

```bash
oc delete deployment,service,imagestream -l app.kubernetes.io/part-of=ac05 -n ac05-deploy
```
