# DEP-014 — Ler o estado de um Deployment: condições e contadores

## Identificação

- **ID:** DEP-014
- **Trilha:** [05 — Deployments e workloads](../README.md)
- **Referência didática:** DO180 — diagnóstico de implantações.
- **Fichas de comando:** [`oc-rollout`](../../../catalogo/fichas/oc-rollout.md), [`oc-describe`](../../../catalogo/fichas/oc-describe.md)

## Objetivo e indicador de sucesso

Interpretar `status` de um Deployment — condições `Available`/`Progressing` e contadores — e usar `progressDeadlineSeconds` para detectar rollout travado.

**Indicador de sucesso:** você explica cada contador (`replicas`, `updatedReplicas`, `readyReplicas`, `availableReplicas`, `unavailableReplicas`) durante um rollout.

## Conceito

| Contador | Significado |
|---|---|
| `replicas` | pods existentes (todas as revisões) |
| `updatedReplicas` | pods já na revisão nova |
| `readyReplicas` | pods prontos |
| `availableReplicas` | prontos há pelo menos `minReadySeconds` |
| `unavailableReplicas` | faltando para o desejado |

Condições: `Available=True` (mínimo disponível atingido); `Progressing=True` com motivo `NewReplicaSetAvailable`
(terminou) ou `ReplicaSetUpdated` (em curso). Se não houver progresso em `progressDeadlineSeconds` (padrão 600), o
motivo vira `ProgressDeadlineExceeded` — o rollout **não** é desfeito sozinho.

## Comandos guiados

```bash
show() { oc get deployment ac05-web -n ac05-deploy -o jsonpath='rep={.status.replicas} upd={.status.updatedReplicas} ready={.status.readyReplicas} avail={.status.availableReplicas} unav={.status.unavailableReplicas}{"\n"}'; }
show
oc get deployment ac05-web -n ac05-deploy -o jsonpath='{range .status.conditions[*]}{.type}={.status} ({.reason}){"\n"}{end}'
oc patch deployment ac05-web -n ac05-deploy --type=merge -p '{"spec":{"minReadySeconds":10}}'
oc rollout restart deployment/ac05-web -n ac05-deploy
for i in 1 2 3 4 5 6; do show; sleep 3; done
oc rollout status deployment/ac05-web -n ac05-deploy
oc patch deployment ac05-web -n ac05-deploy --type=merge -p '{"spec":{"minReadySeconds":0}}'
oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.spec.progressDeadlineSeconds}{"\n"}'
```

## Repetições

1. Leia as condições durante e depois de um rollout.
2. `oc describe deployment ac05-web -n ac05-deploy | sed -n '/Conditions:/,/OldReplicaSets/p'`.
3. Explique por que `availableReplicas` demora mais que `readyReplicas` com `minReadySeconds`.
4. `oc wait --for=condition=Progressing deployment/ac05-web -n ac05-deploy --timeout=30s`.
5. Reduza `progressDeadlineSeconds` para 60 (volte para 600 depois) e leia `oc explain deployment.spec.progressDeadlineSeconds`.

## Desafio sem pista

Escreva uma função que diga, para qualquer Deployment, um destes estados: `estável`, `em rollout`, `travado` ou
`pausado`, usando apenas campos do objeto.

## Diagnóstico controlado

- **Sintoma:** `oc rollout status` termina com `error: deployment "ac05-web" exceeded its progress deadline`.
- **Hipóteses:** a revisão nova não ficou pronta dentro do prazo (imagem, probe, quota).
- **Investigação:** condição `Progressing` (motivo e mensagem); pods da revisão nova; eventos. Veja o cenário TS-016.
- **Reversão:** `oc rollout undo deployment/ac05-web -n ac05-deploy`.

## Validação

```bash
oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.status.conditions[?(@.type=="Progressing")].reason}{"\n"}'   # NewReplicaSetAvailable
```

## Limpeza segura

Volte `minReadySeconds` para 0 e `progressDeadlineSeconds` para 600, se alterou.
