# DEP-007 — Estratégias: RollingUpdate e Recreate

## Identificação

- **ID:** DEP-007

## Objetivo e indicador de sucesso

Comparar `RollingUpdate` (com `maxSurge`/`maxUnavailable`) e `Recreate`, observando quantos pods existem durante a troca.

**Indicador de sucesso:** você mostra, com `-w`, que no Recreate há um intervalo sem pods e no RollingUpdate não.

## Conceito

| Estratégia | Como troca | Indisponibilidade | Pods extras |
|---|---|---|---|
| `RollingUpdate` (padrão) | sobe novos e desce antigos aos poucos | nenhuma, se houver readiness | até `maxSurge` |
| `Recreate` | derruba todos, depois sobe os novos | sim, entre um e outro | nenhum |

`maxSurge` (padrão 25%) = quantos pods **acima** do desejado podem existir; `maxUnavailable` (padrão 25%) = quantos
podem faltar. Com 2 réplicas, 25% arredonda para 1 extra e 0 indisponíveis. Recreate é útil quando duas versões não
podem rodar juntas (por exemplo, migração de banco).

## Comandos guiados

```bash
oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.spec.strategy}{"\n"}'
# terminal 2: oc get pods -n ac05-deploy -l app=ac05-web -w
oc patch deployment ac05-web -n ac05-deploy --type=merge \
  -p '{"spec":{"strategy":{"type":"RollingUpdate","rollingUpdate":{"maxSurge":1,"maxUnavailable":0}}}}'
oc rollout restart deployment/ac05-web -n ac05-deploy && oc rollout status deployment/ac05-web -n ac05-deploy
oc patch deployment ac05-web -n ac05-deploy --type=merge \
  -p '{"spec":{"strategy":{"type":"Recreate","rollingUpdate":null}}}'
oc rollout restart deployment/ac05-web -n ac05-deploy && oc rollout status deployment/ac05-web -n ac05-deploy
oc get events -n ac05-deploy --field-selector involvedObject.kind=Deployment --sort-by=.metadata.creationTimestamp | tail -6
oc patch deployment ac05-web -n ac05-deploy --type=merge \
  -p '{"spec":{"strategy":{"type":"RollingUpdate","rollingUpdate":{"maxSurge":"25%","maxUnavailable":"25%"}}}}'
```

## Repetições

1. `maxSurge: 0, maxUnavailable: 1`: como fica a troca com 2 réplicas?
2. `maxSurge: 0, maxUnavailable: 0`: leia o erro de validação.
3. Compare os eventos `ScalingReplicaSet` das duas estratégias.
4. `oc explain deployment.spec.strategy.rollingUpdate.maxSurge`.
5. Com a baseline (6 pods), qual o maior `maxSurge` seguro para 2 réplicas?

## Desafio sem pista

Meça, para cada estratégia, quantos segundos o Deployment ficou com **zero** pods prontos durante um `rollout restart`.

## Diagnóstico controlado

- **Sintoma:** `spec.strategy.rollingUpdate: Forbidden: may not be specified when strategy type is 'Recreate'`.
- **Hipóteses:** ao trocar para Recreate, o bloco `rollingUpdate` antigo continua no objeto.
- **Investigação:** `oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.spec.strategy}'`.
- **Reversão:** nada foi alterado; inclua `"rollingUpdate":null` no patch.

## Validação

```bash
oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.spec.strategy.type}{"\n"}'   # RollingUpdate
```
