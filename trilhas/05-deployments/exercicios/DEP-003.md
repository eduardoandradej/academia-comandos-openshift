## Objetivo e indicador de sucesso

Disparar novas revisões alterando o template (variável de ambiente), acompanhá-las e registrar o motivo de cada uma.

**Indicador de sucesso:** `oc rollout history` mostra 3 revisões com `CHANGE-CAUSE` preenchido por você.

## Conceito

Qualquer mudança no **template dos pods** (`spec.template`) gera uma nova revisão: um ReplicaSet novo sobe e o antigo
desce, conforme a estratégia. Mudanças fora do template (réplicas, rótulos do Deployment) **não** geram revisão.

O histórico mostra a coluna `CHANGE-CAUSE`, lida da anotação `kubernetes.io/change-cause` do Deployment no momento da
revisão. Registrar o motivo é um hábito barato que salva diagnósticos.

## Comandos guiados

```bash
oc annotate deployment/ac05-web kubernetes.io/change-cause='v1: implantação inicial' --overwrite -n ac05-deploy
oc set env deployment/ac05-web VERSAO=v2 -n ac05-deploy
oc annotate deployment/ac05-web kubernetes.io/change-cause='v2: VERSAO=v2' --overwrite -n ac05-deploy
oc rollout status deployment/ac05-web -n ac05-deploy
oc set env deployment/ac05-web VERSAO=v3 -n ac05-deploy
oc annotate deployment/ac05-web kubernetes.io/change-cause='v3: VERSAO=v3' --overwrite -n ac05-deploy
oc rollout status deployment/ac05-web -n ac05-deploy
oc rollout history deployment/ac05-web -n ac05-deploy
oc get rs -n ac05-deploy -l app=ac05-web       # um RS por revisão; só o atual com pods
oc exec deploy/ac05-web -n ac05-deploy -- printenv VERSAO
```

## Repetições

1. Escale para 1 e depois para 2: o histórico ganhou revisão? Por quê?
2. Rotule o Deployment (`oc label deployment ac05-web teste=1`): nova revisão?
3. Rotule o **template** via `oc patch ... '{"spec":{"template":{"metadata":{"labels":{"teste":"1"}}}}}'`: e agora?
4. `oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.metadata.annotations.deployment\.kubernetes\.io/revision}{"\n"}'`.
5. Acompanhe uma revisão com `oc get pods -l app=ac05-web -w` e descreva a ordem de criação/remoção.

## Desafio sem pista

Faça a revisão `v4` mudando duas variáveis de uma vez (`VERSAO=v4` e `COR=azul`) gerando **uma única** revisão, com
motivo registrado. Prove que houve só uma revisão nova.

## Diagnóstico controlado

- **Sintoma:** a coluna `CHANGE-CAUSE` aparece `<none>`.
- **Hipóteses:** a anotação não foi definida antes/depois da mudança; ela é lida no instante em que o ReplicaSet é criado/atualizado.
- **Investigação:** `oc get rs -n ac05-deploy -l app=ac05-web -o custom-columns=RS:.metadata.name,REV:.metadata.annotations.deployment\.kubernetes\.io/revision,CAUSA:.metadata.annotations.kubernetes\.io/change-cause`.
- **Reversão:** anote o Deployment logo após cada mudança (a anotação é copiada para o ReplicaSet da revisão atual).

## Validação

```bash
oc rollout history deployment/ac05-web -n ac05-deploy | grep -c 'v[0-9]:'    # >= 2
```
