## Conceito

O Deployment é o **dono** dos ReplicaSets (veja `ownerReferences`). A cada ciclo de reconciliação, ele compara o
desejado com o real e corrige. Por isso:

- escalar o ReplicaSet atual: o Deployment devolve ao número dele;
- apagar o ReplicaSet atual: o Deployment cria outro igual;
- ReplicaSets antigos ficam com 0 réplicas até o limite de `revisionHistoryLimit`.

Regra prática: **altere sempre o dono** (Deployment), nunca o objeto gerado.

## Comandos guiados

```bash
RS=$(oc get rs -n ac05-deploy -l app=ac05-web --sort-by=.metadata.creationTimestamp -o name | tail -1)
echo "$RS"
oc get "$RS" -n ac05-deploy -o jsonpath='{.metadata.ownerReferences[0].kind}/{.metadata.ownerReferences[0].name}{"\n"}'
oc scale "$RS" --replicas=1 -n ac05-deploy
oc get "$RS" -n ac05-deploy -w        # volta para 2 em segundos; Ctrl+C
oc get rs -n ac05-deploy -l app=ac05-web -o custom-columns=RS:.metadata.name,DESEJADO:.spec.replicas,REV:.metadata.annotations.deployment\.kubernetes\.io/revision
```

## Repetições

1. Apague o ReplicaSet atual (`oc delete "$RS"`) e observe.
2. Mude um rótulo do template **no ReplicaSet** (`oc patch`) e veja se o Deployment reage.
3. Conte os ReplicaSets antigos e compare com `revisionHistoryLimit`.
4. `oc describe deployment ac05-web -n ac05-deploy | grep -E 'OldReplicaSets|NewReplicaSet'`.
5. Repita o item 1 com o Deployment pausado: o que muda?

## Desafio sem pista

Liste os ReplicaSets do `ac05-web` com revisão, réplicas desejadas, imagem e motivo, ordenados por revisão (numérica).

## Diagnóstico controlado

- **Sintoma:** "escalei o ReplicaSet para 1, mas ele voltou para 2 sozinho".
- **Hipóteses:** o Deployment dono reconcilia.
- **Investigação:** `ownerReferences` do ReplicaSet; eventos do Deployment.
- **Reversão:** nada a reverter; escale o Deployment.

## Validação

```bash
oc get deployment ac05-web -n ac05-deploy -o jsonpath='{.status.readyReplicas}{"\n"}'   # 2
```
