## Objetivo e indicador de sucesso

Descobrir, sem alterar nada, por que qualquer usuário autenticado pode criar projetos e onde ficaria o modelo de projeto.

**Indicador de sucesso:** você aponta o binding `self-provisioners`, o grupo envolvido e o estado do `projectRequestTemplate`.

## Conceito

A criação de projetos passa pelo recurso `projectrequests`, autorizado pela ClusterRole `self-provisioner`, ligada
por padrão ao grupo `system:authenticated:oauth` pelo binding `self-provisioners`. O `project.config.openshift.io/cluster`
pode apontar um **modelo** (`projectRequestTemplate`) com quota/LimitRange automáticos — é como a sala de aula aplica
limites. Mudar qualquer um deles é configuração de cluster: aqui, só leitura.

## Comandos guiados

```bash
oc get clusterrolebinding self-provisioners -o json | jq '{role: .roleRef.name, subjects}'
oc get clusterrole self-provisioner -o json | jq '.rules'
oc get project.config.openshift.io cluster -o jsonpath='{.spec}{"\n"}'
oc get templates -n openshift-config 2>/dev/null
oc adm create-bootstrap-project-template -o yaml | head -30          # gera o modelo padrão (não aplica)
ac-dev
```

## Repetições

1. Qual seria o efeito de remover `system:authenticated:oauth` do binding? (não faça)
2. Leia o modelo padrão gerado e encontre onde entraria uma quota.
3. Compare com o que a Academia faz à mão (ORI-012: baseline aplicada pelo admin).
4. Por que `oc new-project` funciona e `oc create namespace` não, para developer?
5. `oc auth can-i create namespaces` × `oc auth can-i create projectrequests`.

## Desafio sem pista

Escreva, sem aplicar, o `projectRequestTemplate` que criaria automaticamente a baseline da Academia
(`manifests/baseline-seguro/quota-limitrange.yaml`) em todo projeto novo, e liste o que precisaria ser feito no cluster para ativá-lo.

## Diagnóstico controlado

- **Sintoma:** um usuário diz que `oc new-project` responde `You may not request a new project via this API`.
- **Hipóteses:** o cluster desabilitou o self-provisioning para o grupo dele.
- **Investigação:** `self-provisioners` (sujeitos); `project.config` (`projectRequestMessage`).
- **Reversão:** decisão de administração; a Academia não altera.
