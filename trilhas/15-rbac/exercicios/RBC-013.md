## Conceito

| Objeto | O que representa |
|---|---|
| `oauth.config.openshift.io/cluster` | provedores de identidade (aqui: HTPasswd `homelab-users`) |
| `identity` | "fulano no provedor X" (`homelab-users:developer`) |
| `user` | a conta no OpenShift, criada no primeiro login |
| `group` | conjunto de usuários (local ou sincronizado) |

Acrescentar usuários (ex.: `leader`, `qa-engineer` do DO280) altera o Secret `homelab-users-htpasswd` em
`openshift-config` e reinicia o OAuth: **VERMELHO**, manual, com cópia de segurança — veja
[docs/12-preparacao-usuarios.md](../../../docs/12-preparacao-usuarios.md). Nunca remova o provedor original nem o `kubeadmin`.

## Comandos guiados

```bash
oc get oauth cluster -o jsonpath='{range .spec.identityProviders[*]}{.name}{" "}{.type}{" secret="}{.htpasswd.fileData.name}{"\n"}{end}'
oc get users -o custom-columns=USUARIO:.metadata.name,IDENTIDADES:.identities
oc get identities -o custom-columns=NOME:.metadata.name,PROVEDOR:.providerName,USUARIO:.user.name
oc get groups -o custom-columns=GRUPO:.metadata.name,MEMBROS:.users
oc get pods -n openshift-authentication -o wide | head -3           # leitura
oc get secret homelab-users-htpasswd -n openshift-config -o jsonpath='{.data}' | jq 'keys'   # só a chave, nunca o conteúdo
ac-dev
```

## Repetições

1. Qual é o `mappingMethod` do provedor e o que ele significa?
2. Um usuário que nunca fez login existe em `oc get users`?
3. O que acontece com o `user` se a `identity` for apagada? (conceitual)
4. Por que nunca imprimir o conteúdo do Secret do HTPasswd, mesmo com hashes?
5. Leia o roteiro de docs/12 e marque os pontos de não retorno.

## Desafio sem pista

Monte, só com leitura, o "caminho de autenticação" de cada usuário do cluster em uma linha: `provedor:nome → user → grupos`.

## Diagnóstico controlado

- **Sintoma:** depois de editar o HTPasswd, o login de **todos** os usuários falha.
- **Hipóteses:** arquivo HTPasswd malformado (linha quebrada, hash inválido) aplicado ao Secret.
- **Investigação:** pods do `openshift-authentication` reiniciando; `oc get co authentication`.
- **Reversão:** restaure o Secret da cópia de segurança (docs/12) usando o perfil de recuperação (`ac-recovery`).
