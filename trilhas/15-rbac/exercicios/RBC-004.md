## Conceito

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: {name: ac15-robo-view, namespace: ac15-rbac}
subjects:                                  # QUEM (User, Group, ServiceAccount)
  - kind: ServiceAccount
    name: ac15-robo
    namespace: ac15-rbac
roleRef:                                   # O QUÊ (imutável depois de criado)
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole                        # ou Role (do mesmo namespace)
  name: view
```

`oc adm policy who-can VERBO RECURSO -n NS` responde a pergunta inversa: quem pode isto?

## Comandos guiados

```bash
oc create rolebinding ac15-robo-view --clusterrole=view --serviceaccount=ac15-rbac:ac15-robo -n ac15-rbac --dry-run=client -o yaml
oc create rolebinding ac15-robo-view --clusterrole=view --serviceaccount=ac15-rbac:ac15-robo -n ac15-rbac
oc label rolebinding ac15-robo-view academy.openshift.dev/managed-by=academia -n ac15-rbac
oc get rolebindings -n ac15-rbac -o json | jq -r '.items[] | "\(.roleRef.kind)/\(.roleRef.name)\t<- \([.subjects[]? | "\(.kind):\(.name)"] | join(", "))\t(\(.metadata.name))"'
oc adm policy who-can get secrets -n ac15-rbac 2>/dev/null | sed -n '1,15p'
oc patch rolebinding ac15-robo-view -n ac15-rbac --type=merge -p '{"roleRef":{"name":"edit"}}'; echo "rc=$?"   # roleRef é imutável
```

## Repetições

1. Acrescente um segundo sujeito (`ac15-leitor`) ao mesmo binding com `oc patch --type=json`.
2. Compare `oc policy add-role-to-user` com `oc create rolebinding`: que nomes de binding cada um gera?
3. Escreva o binding em um arquivo e aplique com `oc apply` (Trilha 12).
4. `oc describe rolebinding ac15-robo-view -n ac15-rbac`.
5. `who-can create pods/exec -n ac15-rbac`.

## Desafio sem pista

Troque o papel do binding `ac15-robo-view` de `view` para `edit` — sabendo que `roleRef` é imutável — sem deixar a SA sem permissão em nenhum momento.

## Diagnóstico controlado

- **Sintoma:** `The RoleBinding "ac15-robo-view" is invalid: roleRef: Invalid value: ... cannot change roleRef`.
- **Hipóteses:** `roleRef` não pode mudar depois de criado.
- **Investigação:** a mensagem; `oc get rolebinding -o yaml`.
- **Reversão:** crie outro binding e apague o antigo (desafio). Veja TS-047.

## Validação

```bash
oc get rolebinding ac15-robo-view -n ac15-rbac -o jsonpath='{.roleRef.name}{"\n"}'
```

## Limpeza segura

```bash
oc delete rolebinding ac15-robo-view ac15-robo-edit -n ac15-rbac --ignore-not-found
```
