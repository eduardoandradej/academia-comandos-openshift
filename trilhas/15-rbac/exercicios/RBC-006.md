# RBC-006 — ClusterRole usada dentro de um projeto

## Identificação

- **ID:** RBC-006
- **Trilha:** [15 — Usuários, identidade e RBAC](../README.md)
- **Referência didática:** DO280 — RBAC (escopo).
- **Fichas de comando:** [`oc-policy-rbac`](../../../catalogo/fichas/oc-policy-rbac.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Criar (como admin) uma ClusterRole reutilizável e concedê-la **só em um projeto** via RoleBinding, e comparar com uma ClusterRoleBinding (sem criá-la).

**Indicador de sucesso:** a SA lê ConfigMaps em `ac15-rbac` e recebe Forbidden em qualquer outro projeto.

## Nível

**Nível:** Intermediário

## Duração e repetições

- **Duração sugerida:** 15 min
- **Repetições:** 3×

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `admin` (criar a ClusterRole) e `developer` (binding no projeto)
- **Projeto:** `ac15-rbac`
- **Impacto:** MUTAÇÃO DE CLUSTER (1 ClusterRole rotulada) · MUTAÇÃO LOCAL

## Conceito

| Binding | Papel referenciado | Vale em |
|---|---|---|
| RoleBinding | Role (do mesmo namespace) | um namespace |
| RoleBinding | **ClusterRole** | **um namespace** (a ClusterRole é só o "molde") |
| ClusterRoleBinding | ClusterRole | **o cluster todo** — VERMELHO na Academia |

ClusterRoles são objetos de cluster (só admin cria). Use-as como moldes reaproveitáveis e conceda por RoleBinding.

## Comandos guiados

```bash
ac-admin
oc create clusterrole ac15-leitor-configmaps --verb=get,list,watch --resource=configmaps
oc label clusterrole ac15-leitor-configmaps academy.openshift.dev/managed-by=academia academy.openshift.dev/trilha=15
ac-dev
oc create rolebinding ac15-robo-cm --clusterrole=ac15-leitor-configmaps --serviceaccount=ac15-rbac:ac15-robo -n ac15-rbac
oc auth can-i list configmaps -n ac15-rbac --as=system:serviceaccount:ac15-rbac:ac15-robo          # yes
ac-admin
oc auth can-i list configmaps -n default --as=system:serviceaccount:ac15-rbac:ac15-robo           # no
oc create clusterrolebinding ac15-NAO-CRIAR --clusterrole=ac15-leitor-configmaps \
  --serviceaccount=ac15-rbac:ac15-robo --dry-run=client -o yaml          # só para ver: valeria no cluster todo
ac-dev
```

## Repetições

1. Por que developer não consegue criar a ClusterRole? (`oc auth can-i create clusterroles`)
2. Leia a ClusterRole `view` e encontre o rótulo de agregação (`rbac.authorization.k8s.io/aggregate-to-view`).
3. Use a mesma ClusterRole em um segundo projeto seu.
4. Liste as ClusterRoleBindings que concedem `cluster-admin` (admin, leitura).
5. Explique por que a Academia trata ClusterRoleBinding como VERMELHO.

## Desafio sem pista

(admin, leitura) Liste todos os sujeitos que têm `cluster-admin` no cluster, indicando por qual ClusterRoleBinding.

## Diagnóstico controlado

- **Sintoma:** `clusterroles.rbac.authorization.k8s.io is forbidden: User "developer" cannot create resource "clusterroles" ... at the cluster scope`.
- **Hipóteses:** ClusterRole é objeto de cluster.
- **Investigação:** `oc auth can-i create clusterroles`.
- **Reversão:** peça ao admin ou use uma Role no projeto (RBC-005).

## Validação

```bash
oc auth can-i list configmaps -n ac15-rbac --as=system:serviceaccount:ac15-rbac:ac15-robo     # yes
```

## Limpeza segura

```bash
oc delete rolebinding ac15-robo-cm -n ac15-rbac --ignore-not-found
```

A ClusterRole `ac15-leitor-configmaps` é removida no RBC-015 (admin).
