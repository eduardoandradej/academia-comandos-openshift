## Objetivo e indicador de sucesso

Ver a identidade que um pod usa para falar com a API, emitir um token curto para uma SA e usá-lo sem jamais imprimi-lo.

**Indicador de sucesso:** `oc --token="$T" whoami` responde `system:serviceaccount:ac15-rbac:ac15-leitor`, e o token expira sozinho.

## Conceito

Todo pod roda com uma SA (padrão: `default`). O token dela é montado em
`/var/run/secrets/kubernetes.io/serviceaccount/token` (volume projetado, com validade curta e renovação automática).

| Comando | Efeito |
|---|---|
| `oc create token SA --duration=10m` | emite um token temporário (não fica guardado em Secret) |
| `oc set serviceaccount deploy/X SA` | troca a SA de um Deployment |
| `automountServiceAccountToken: false` | não monta o token (pods que não falam com a API) |

Tokens são credenciais: guarde só em variável, nunca em arquivo do repositório, histórico ou tela compartilhada.

## Comandos guiados

```bash
oc run ac15-quem --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac15-rbac \
  --labels=academy.openshift.dev/managed-by=academia --overrides='{"spec":{"serviceAccountName":"ac15-leitor"}}'
oc wait --for=condition=Ready pod/ac15-quem -n ac15-rbac --timeout=90s
oc get pod ac15-quem -n ac15-rbac -o jsonpath='{.spec.serviceAccountName}{"\n"}'
oc exec ac15-quem -n ac15-rbac -- ls /var/run/secrets/kubernetes.io/serviceaccount
oc exec ac15-quem -n ac15-rbac -- sh -c 'wc -c < /var/run/secrets/kubernetes.io/serviceaccount/token'   # tamanho, não o valor
T=$(oc create token ac15-leitor -n ac15-rbac --duration=10m)
oc --token="$T" whoami
oc --token="$T" get pods -n ac15-rbac | head -3                 # papel view do RBC-003
oc --token="$T" get secrets -n ac15-rbac 2>&1 | head -1          # Forbidden
unset T
```

## Repetições

1. Decodifique **só o cabeçalho e as reivindicações** do token (sem a assinatura) e leia `exp` e `sub` (com dado de treino, em variável).
2. Crie um Deployment com `automountServiceAccountToken: false` e confirme a ausência do diretório.
3. `oc set serviceaccount deployment/<x> ac15-robo`.
4. Por que não usar `oc whoami --show-token` do seu usuário em scripts de automação?
5. Liste os Secrets do tipo `kubernetes.io/service-account-token` do projeto (só nomes).

## Desafio sem pista

Prove que o token expira: emita um token de 10 minutos (o mínimo aceito) para a `ac15-robo`, anote o horário de
expiração lendo o campo `exp`, e explique como confirmaria a recusa depois do prazo — sem nunca exibir o token.

## Diagnóstico controlado

- **Sintoma:** `error: You must be logged in to the server (Unauthorized)` ao usar um token guardado ontem.
- **Hipóteses:** token expirado (curta duração) ou SA apagada/recriada.
- **Investigação:** campo `exp` do token; `oc get sa <nome> -o jsonpath='{.metadata.uid}'`.
- **Reversão:** emita um token novo (`oc create token`); não crie tokens "eternos".

## Validação

```bash
T=$(oc create token ac15-leitor -n ac15-rbac --duration=10m); oc --token="$T" whoami; unset T
```

## Limpeza segura

```bash
oc delete pod ac15-quem -n ac15-rbac --ignore-not-found
unset T
```
