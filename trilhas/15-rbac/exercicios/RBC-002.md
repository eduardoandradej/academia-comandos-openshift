## Conceito

> **Como testamos permissões sem criar usuários.** Uma *service account* (SA) do projeto faz o papel de "colega":
> `--as=system:serviceaccount:ac15-rbac:ac15-leitor` pergunta à API "e se fosse ela?". Quem é admin do projeto pode
> se passar por SAs do próprio projeto. Usuários do HTPasswd não são criados nesta trilha (RBC-013).

| Forma | Exemplo |
|---|---|
| verbo + recurso | `oc auth can-i delete deployments` |
| subrecurso | `oc auth can-i get pods/log`, `oc auth can-i create pods/exec` |
| nome específico | `oc auth can-i get configmap/ac15-cfg` |
| outra identidade | `--as=system:serviceaccount:<ns>:<sa>` (ou `--as=<usuário>` como admin) |
| silencioso | `-q` (só o código de saída: 0 sim, 1 não) |

## Comandos guiados

```bash
oc new-project ac15-rbac --display-name='Academia 15 - RBAC' 2>/dev/null || oc project ac15-rbac
oc create serviceaccount ac15-leitor -n ac15-rbac
oc create serviceaccount ac15-robo -n ac15-rbac
oc label sa ac15-leitor ac15-robo academy.openshift.dev/managed-by=academia -n ac15-rbac
for acao in "get pods" "get pods/log" "create pods/exec" "list secrets" "create deployments" "delete project"; do
  eu=$(oc auth can-i $acao -n ac15-rbac); sa=$(oc auth can-i $acao -n ac15-rbac --as=system:serviceaccount:ac15-rbac:ac15-leitor)
  printf '%-22s developer=%-4s ac15-leitor=%s\n' "$acao" "$eu" "$sa"
done
oc auth can-i --list -n ac15-rbac --as=system:serviceaccount:ac15-rbac:ac15-leitor | head
```

## Repetições

1. Por que a SA recém-criada quase não pode nada? (só os papéis de grupo `system:serviceaccounts`)
2. `oc auth can-i get pods -n default --as=...ac15-leitor`.
3. `oc auth can-i create pods/portforward` para você e para a SA.
4. Use `-q` em um `if` de script.
5. `oc auth can-i --as=developer ...` como developer: o que acontece? (impersonar usuários exige ser admin)

## Desafio sem pista

Escreva `pode <sa> <verbo> <recurso>...` que responda para várias ações de uma vez, em formato de tabela, para uma SA do projeto.

## Diagnóstico controlado

- **Sintoma:** `Error from server (Forbidden): users "developer" is forbidden: User "developer" cannot impersonate resource "users"`.
- **Hipóteses:** tentativa de impersonar um **usuário** sem ser admin do cluster.
- **Investigação:** `oc auth can-i impersonate users`.
- **Reversão:** use SA do projeto (`--as=system:serviceaccount:...`) ou o perfil admin.

## Validação

```bash
oc auth can-i list secrets -n ac15-rbac --as=system:serviceaccount:ac15-rbac:ac15-leitor; echo "(esperado: no)"
```
