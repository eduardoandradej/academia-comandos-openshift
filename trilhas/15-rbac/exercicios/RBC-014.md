## Objetivo e indicador de sucesso

Ler uma mensagem `Forbidden` por inteiro (quem, verbo, recurso, grupo de API, namespace, escopo) e chegar ao binding que falta.

**Indicador de sucesso:** para cinco recusas provocadas, você nomeia a parte da mensagem que revela a causa.

## Conceito

```text
Error from server (Forbidden): pods "x" is forbidden: User "system:serviceaccount:ac15-rbac:ac15-robo"
cannot get resource "pods/log" in API group "" in the namespace "ac15-rbac"
        └ verbo ┘        └ recurso/subrecurso ┘  └ grupo de API ┘    └ escopo ┘
```

| # | Pergunta | Comando |
|---|---|---|
| 1 | Quem a API viu? (usuário/SA certo?) | `oc whoami`; trecho `User "..."` |
| 2 | Qual verbo e recurso exatos? | a mensagem; `oc api-resources` |
| 3 | Em que escopo? (`in the namespace` × `at the cluster scope`) | a mensagem |
| 4 | Que bindings o sujeito tem lá? | `oc get rolebindings -o json \| jq` |
| 5 | O papel tem a regra? | `oc describe role/clusterrole` |

## Comandos guiados

```bash
S=system:serviceaccount:ac15-rbac:ac15-robo
oc logs pod/inexistente -n ac15-rbac --as=$S 2>&1 | head -1
oc get secrets -n ac15-rbac --as=$S 2>&1 | head -1
oc get pods -n default --as=$S 2>&1 | head -1
oc get nodes --as=$S 2>&1 | head -1                                  # at the cluster scope
oc create rolebinding x --clusterrole=view --user=fulano -n ac15-rbac --as=$S 2>&1 | head -1
oc auth can-i --list -n ac15-rbac --as=$S | head -8
```

## Repetições

1. Para cada linha, aponte verbo, recurso, grupo de API e escopo.
2. Qual das recusas nenhum RoleBinding resolveria? (escopo de cluster)
3. Crie o binding mínimo que resolve a recusa de `pods/log` e teste.
4. Provoque um Forbidden de `deployments.apps` e note o grupo `apps`.
5. Escreva o roteiro de memória.

## Desafio sem pista

Escreva `explica_forbidden` que lê uma mensagem Forbidden pela entrada padrão e imprime, separados: sujeito, verbo,
recurso, grupo de API e namespace (ou "cluster").

## Diagnóstico controlado

- **Sintoma:** `cannot list resource "deployments" in API group "apps"` mesmo com uma Role que tem `deployments`.
- **Hipóteses:** a regra da Role está com `apiGroups: [""]` (core) em vez de `["apps"]`.
- **Investigação:** `oc get role <nome> -o yaml`.
- **Reversão:** corrija `apiGroups` (o `oc create role --resource=deployments.apps` acerta sozinho).

## Validação

```bash
oc get nodes --as=system:serviceaccount:ac15-rbac:ac15-robo 2>&1 | grep -q 'cluster scope' && echo "escopo reconhecido"
```
