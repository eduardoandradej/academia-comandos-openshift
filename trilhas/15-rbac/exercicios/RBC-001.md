## Objetivo e indicador de sucesso

Descobrir a identidade completa da sessão (usuário, grupos, contexto) e listar o que ela pode fazer em um projeto e no cluster.

**Indicador de sucesso:** você explica de onde vem cada grupo da sua identidade e por que `developer` pode criar projetos mas não listar nós.

## Conceito

| Comando | Mostra |
|---|---|
| `oc whoami` | nome do usuário |
| `oc whoami --show-context` / `--show-server` | contexto e API em uso |
| `oc auth whoami` | usuário **e grupos** vistos pela API |
| `oc auth can-i VERBO RECURSO [-n NS]` | sim/não para uma ação |
| `oc auth can-i --list [-n NS]` | todas as regras efetivas |

Grupos virtuais: `system:authenticated` (todo usuário logado) e `system:authenticated:oauth` (logado via OAuth).
É por eles que `developer` recebe `self-provisioner` (criar projetos) e `basic-user`.

## Comandos guiados

```bash
oc whoami; oc whoami --show-context; oc whoami --show-server
oc auth whoami 2>/dev/null || oc get --raw /apis/user.openshift.io/v1/users/~ | jq '{name: .metadata.name, groups}'
oc auth can-i create projectrequests
oc auth can-i list nodes
oc auth can-i --list | head -25
oc auth can-i --list -n ac08-config 2>/dev/null | head -10 || echo "projeto ac08 não existe mais: use um seu"
```

## Repetições

1. Em quais regras do `--list` aparece `selfsubjectaccessreviews`? Para que servem?
2. `oc auth can-i get secrets` em um projeto seu e em `default`.
3. `oc auth can-i '*' '*'` como developer e (perfil admin) como admin.
4. Por que `oc whoami --show-token` é perigoso de rodar em tela compartilhada?
5. Repita de memória os cinco comandos da tabela.

## Desafio sem pista

Liste, com um comando, só os **recursos de cluster** (sem namespace) que `developer` pode `list` ou `get`.

## Diagnóstico controlado

- **Sintoma:** `oc auth whoami` responde `error: the server doesn't have a resource type "selfsubjectreviews"`.
- **Hipóteses:** versão do cliente ou da API sem o recurso.
- **Investigação:** `oc version`; `oc api-resources | grep -i selfsubject`.
- **Reversão:** use `oc get --raw /apis/user.openshift.io/v1/users/~` (forma do OpenShift).

## Validação

```bash
oc auth can-i list nodes; echo "(esperado: no)"
```
