## Objetivo e indicador de sucesso

Definir requests e limits com `oc set resources`, ver o efeito do LimitRange e da quota, e saber quem usa cada número.

**Indicador de sucesso:** você explica, para o `ac11-app`, qual valor o agendador usou, qual o kernel aplica e quanto da quota foi consumido.

## Conceito

| Número | Quem usa | Efeito |
|---|---|---|
| `requests.cpu/memory` | agendador e quota | reserva no nó; pod só é agendado se couber |
| `limits.cpu` | kernel (CFS) | **estrangula** (throttling) acima do teto |
| `limits.memory` | kernel (OOM killer) | **mata** o contêiner acima do teto (OOMKilled) |
| LimitRange do projeto | admissão | preenche valores ausentes e recusa os acima do máximo |
| ResourceQuota do projeto | admissão | soma dos requests/limits de todos os pods |

QoS (POD-012): `Guaranteed` (requests = limits), `Burstable` (algum request), `BestEffort` (nada).

## Comandos guiados

```bash
oc new-project ac11-resiliencia --display-name='Academia 11 - Resiliência'
oc create deployment ac11-app --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac11-resiliencia
oc label deployment ac11-app academy.openshift.dev/managed-by=academia -n ac11-resiliencia
oc get deployment ac11-app -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].resources}{"\n"}'   # vazio no template
oc get pod -n ac11-resiliencia -l app=ac11-app -o jsonpath='{.items[0].spec.containers[0].resources}{"\n"}'      # LimitRange preencheu (se houver)
oc set resources deployment/ac11-app --requests=cpu=50m,memory=64Mi --limits=cpu=100m,memory=128Mi -n ac11-resiliencia
oc rollout status deployment/ac11-app -n ac11-resiliencia
oc get pod -n ac11-resiliencia -l app=ac11-app -o jsonpath='{.items[0].status.qosClass}{"\n"}'
oc describe quota -n ac11-resiliencia 2>/dev/null || echo "sem quota neste projeto (aplique a baseline como admin, ORI-012)"
oc describe limitrange -n ac11-resiliencia 2>/dev/null
```

## Repetições

1. Torne o pod `Guaranteed` (requests = limits) e confira o `qosClass`.
2. Peça `limits.memory=1Gi`: o LimitRange (máximo 512Mi) recusa? Leia o evento do ReplicaSet.
3. Escale para 2 réplicas e veja a quota consumida dobrar.
4. Remova os limits (`oc set resources ... --limits=cpu=0,memory=0`) e veja o que o LimitRange devolve.
5. (admin, leitura) `oc describe node | sed -n '/Allocated resources/,/Events/p'`.

## Desafio sem pista

Calcule quantas réplicas do `ac11-app` (com os valores atuais) caberiam na quota do projeto e qual recurso esgota
primeiro — só com leitura.

## Diagnóstico controlado

- **Sintoma:** depois de `oc set resources`, nenhum pod novo; o ReplicaSet mostra `FailedCreate ... maximum memory usage per Container is 512Mi`.
- **Hipóteses:** valor acima do máximo do LimitRange.
- **Investigação:** `oc describe rs -l app=ac11-app -n ac11-resiliencia | sed -n '/Events:/,$p'`.
- **Reversão:** `oc set resources` com valores dentro do LimitRange (ou `oc rollout undo`).

## Validação

```bash
oc get deployment ac11-app -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].resources.limits.cpu}{"\n"}'   # 100m
```
