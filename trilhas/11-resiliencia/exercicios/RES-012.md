# RES-012 — Ler as decisões do HPA

## Identificação

- **ID:** RES-012
- **Trilha:** [11 — Resiliência](../README.md)
- **Referência didática:** DO280 — escalonamento automático (diagnóstico).
- **Fichas de comando:** [`oc-set-probe-autoscale`](../../../catalogo/fichas/oc-set-probe-autoscale.md)

## Objetivo e indicador de sucesso

Interpretar condições e eventos do HPA para responder "por que ele (não) escalou?" e criar um HPA declarativo (`autoscaling/v2`).

**Indicador de sucesso:** você explica as três condições (`AbleToScale`, `ScalingActive`, `ScalingLimited`) no estado atual.

## Conceito

| Condição | `True` significa | `False` típico |
|---|---|---|
| `AbleToScale` | pode alterar réplicas agora | `BackoffBoth`/`BackoffDownscale` (janela de estabilização) |
| `ScalingActive` | tem métricas para decidir | `FailedGetResourceMetric` (sem request ou sem métricas) |
| `ScalingLimited` | quereria ir além de min/max | `TooManyReplicas` / `TooFewReplicas` |

## Comandos guiados

```bash
oc get hpa ac11-app -n ac11-resiliencia -o json | jq -r '.status.conditions[] | "\(.type)=\(.status) \(.reason): \(.message)"'
oc get hpa ac11-app -n ac11-resiliencia -o json | jq '.status.currentMetrics'
oc get events -n ac11-resiliencia --field-selector involvedObject.kind=HorizontalPodAutoscaler --sort-by=.lastTimestamp | tail -5
oc get hpa ac11-app -n ac11-resiliencia -o yaml | sed -n '/^spec:/,/^status:/p'
oc explain hpa.spec.behavior --api-version=autoscaling/v2 | head -20
```

## Repetições

1. Com carga (RES-011), leia de novo as condições: qual ficou `ScalingLimited=True`?
2. Remova o `requests.cpu` do Deployment e leia `ScalingActive`.
3. Recoloque os requests.
4. Escreva o HPA equivalente em YAML (`autoscaling/v2`) e aplique com `oc apply` (apague o atual antes).
5. Acrescente uma métrica de memória (`averageUtilization: 80`) ao HPA.

## Desafio sem pista

Escreva um comando que resuma o HPA em uma linha: `atual/alvo de CPU`, `réplicas atuais/desejadas`, e o motivo da
última decisão (condição que não está `True` ou último evento).

## Diagnóstico controlado

- **Sintoma:** carga alta, `REPLICAS` parado em 2.
- **Hipóteses:** limite `maxReplicas` (comportamento desejado na Academia).
- **Investigação:** `ScalingLimited=True` com `TooManyReplicas`.
- **Reversão:** nada a reverter: o teto protege o SNO.

## Validação

```bash
oc get hpa ac11-app -n ac11-resiliencia -o jsonpath='{.status.conditions[?(@.type=="ScalingActive")].status}{"\n"}'   # True
```
