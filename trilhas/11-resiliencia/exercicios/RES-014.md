## Objetivo e indicador de sucesso

Aplicar um roteiro fixo a "a aplicação cai, reinicia ou não escala": reinícios, último término, probes, recursos, HPA e PDB.

**Indicador de sucesso:** para um Deployment quebrado de propósito, você chega à causa em até 6 comandos.

## Conceito

| # | Pergunta | Comando |
|---|---|---|
| 1 | Há reinícios? | `oc get pods -o custom-columns=NAME:.metadata.name,RESTARTS:.status.containerStatuses[0].restartCount` |
| 2 | Como terminou da última vez? | `lastState.terminated` (`OOMKilled`, código 137/143, `Error`) |
| 3 | Uma probe está falhando? | eventos `Unhealthy` (`Liveness`/`Readiness`/`Startup`) |
| 4 | Faltam recursos? | `oc adm top`; `cpu.stat`; requests × quota |
| 5 | O HPA tem métricas? | `oc describe hpa` (Conditions) |
| 6 | Um PDB bloqueia manutenção? | `oc get pdb` (`ALLOWED DISRUPTIONS`) |

## Comandos guiados

```bash
oc apply -f manifests/apps-exemplo/cenario-liveness-agressiva.yaml -n ac11-resiliencia
sleep 60
oc get pods -n ac11-resiliencia -l app=ac11-agressivo -o custom-columns=NAME:.metadata.name,RESTARTS:.status.containerStatuses[0].restartCount,ESTADO:.status.containerStatuses[0].state
oc get pods -n ac11-resiliencia -l app=ac11-agressivo -o jsonpath='{.items[0].status.containerStatuses[0].lastState.terminated}{"\n"}'
oc get events -n ac11-resiliencia --field-selector reason=Unhealthy --sort-by=.lastTimestamp | tail -3
oc get deployment ac11-agressivo -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].livenessProbe}{"\n"}'
```

## Repetições

1. Classifique a falha em um passo do roteiro.
2. Corrija só a probe e confirme que os reinícios param.
3. Provoque um OOMKill (`manifests/apps-exemplo/cenario-oomkilled.yaml`, Trilha 04) e passe pelo roteiro.
4. Crie um HPA para um Deployment sem requests e passe pelo roteiro.
5. Escreva o roteiro de memória.

## Desafio sem pista

Escreva `diag_res <deployment>` que imprima, em até 6 linhas, a resposta resumida de cada pergunta do roteiro.

## Diagnóstico controlado

- **Sintoma:** `Liveness probe failed: command timed out` a cada poucos segundos e reinícios em série.
- **Hipóteses:** `timeoutSeconds: 1` para um comando que leva 2 s.
- **Investigação:** a probe no YAML (`exec`, `timeoutSeconds`, `failureThreshold`).
- **Reversão:** `oc delete -f manifests/apps-exemplo/cenario-liveness-agressiva.yaml -n ac11-resiliencia`. Veja TS-034.

## Validação

```bash
oc get deployment ac11-agressivo -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].livenessProbe.timeoutSeconds}{"\n"}'
```
