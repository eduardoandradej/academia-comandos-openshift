# RES-005 — Liveness probe: reiniciar o que travou

## Identificação

- **ID:** RES-005
- **Trilha:** [11 — Resiliência](../README.md)
- **Referência didática:** DO180 — saúde de aplicações (probes).
- **Fichas de comando:** [`oc-set-probe-autoscale`](../../../catalogo/fichas/oc-set-probe-autoscale.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Configurar uma liveness probe por comando, "travar" a aplicação e ver o kubelet reiniciar o contêiner.

**Indicador de sucesso:** depois de remover o arquivo de vida, `RESTARTS` sobe e o evento `Liveness probe failed ... will be restarted` aparece.

**Nível:** Intermediário

## Conceito

A liveness responde "o processo ainda funciona?". Ao falhar `failureThreshold` vezes seguidas, o kubelet mata e
reinicia o contêiner (o pod e o IP continuam). Use para travamentos que a aplicação não percebe sozinha — e nunca
com um teste que dependa de serviços externos (um banco fora do ar reiniciaria todos os pods: TS-034).

## Comandos guiados

```bash
oc set probe deployment/ac11-app --liveness --initial-delay-seconds=5 --period-seconds=5 --failure-threshold=2 \
  -n ac11-resiliencia -- sh -c 'test -f /tmp/vivo || { [ ! -f /tmp/iniciado ] && touch /tmp/vivo /tmp/iniciado; }'
oc rollout status deployment/ac11-app -n ac11-resiliencia
P=$(oc get pod -n ac11-resiliencia -l app=ac11-app -o name | head -1)
oc exec -n ac11-resiliencia "$P" -- ls /tmp
oc exec -n ac11-resiliencia "$P" -- rm /tmp/vivo                    # "trava" a aplicação
sleep 20; oc get -n ac11-resiliencia "$P"                              # RESTARTS 1
oc get events -n ac11-resiliencia --field-selector involvedObject.name="${P#pod/}" --sort-by=.lastTimestamp | tail -4
oc get -n ac11-resiliencia "$P" -o custom-columns=NAME:.metadata.name,RESTARTS:.status.containerStatuses[0].restartCount
```

## Repetições

1. Calcule o tempo máximo entre o "travamento" e o reinício (`periodSeconds × failureThreshold`).
2. Depois do reinício, `/tmp/iniciado` ainda existe? Por quê?
3. Troque para uma liveness TCP na 8080 e derrube o httpd com `kill 1`.
4. Liste reinícios de todos os pods do projeto (catálogo 147).
5. Remova a liveness (`--liveness --remove`).

## Desafio sem pista

Mostre o motivo do último término do contêiner (`lastState.terminated`) e explique por que o código de saída é 137 ou 143.

## Diagnóstico controlado

- **Sintoma:** `RESTARTS` crescendo e `Liveness probe failed: ... command timed out`.
- **Hipóteses:** liveness lenta demais para o `timeoutSeconds` (padrão 1 s), não um travamento real.
- **Investigação:** `oc get deploy ac11-app -o jsonpath='{.spec.template.spec.containers[0].livenessProbe}'`.
- **Reversão:** aumente `--timeout-seconds` ou simplifique a verificação. Veja TS-034.

## Validação

```bash
oc get pods -n ac11-resiliencia -l app=ac11-app -o jsonpath='{.items[0].status.containerStatuses[0].restartCount}{"\n"}'    # >= 1
```

## Limpeza segura

```bash
oc set probe deployment/ac11-app --liveness --remove -n ac11-resiliencia
```
