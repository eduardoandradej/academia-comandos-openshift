## Objetivo e indicador de sucesso

Entender os cinco parâmetros das probes e calcular quanto tempo o cluster leva para tirar um pod do Service e para reiniciá-lo.

**Indicador de sucesso:** você prevê o tempo de reação de uma probe e o confirma com uma medição.

## Conceito

| Parâmetro | Padrão | Significado |
|---|---|---|
| `initialDelaySeconds` | 0 | espera antes da primeira verificação |
| `periodSeconds` | 10 | intervalo entre verificações |
| `timeoutSeconds` | 1 | tempo máximo de cada verificação |
| `failureThreshold` | 3 | falhas seguidas para agir |
| `successThreshold` | 1 | sucessos seguidos para voltar a "ok" (readiness) |

Tempo até agir ≈ `periodSeconds × failureThreshold` (+ `timeoutSeconds` de cada tentativa).

## Comandos guiados

```bash
oc set probe deployment/ac11-app --readiness --period-seconds=4 --failure-threshold=3 --success-threshold=2 --timeout-seconds=2 \
  -n ac11-resiliencia -- test ! -f /tmp/fora
oc rollout status deployment/ac11-app -n ac11-resiliencia
oc get deployment ac11-app -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].readinessProbe}{"\n"}'
P=$(oc get pod -n ac11-resiliencia -l app=ac11-app -o name | head -1)
oc exec -n ac11-resiliencia "$P" -- touch /tmp/fora; t0=$(date +%s)
until [ "$(oc get -n ac11-resiliencia "$P" -o jsonpath='{.status.containerStatuses[0].ready}')" = false ]; do sleep 1; done
echo "saiu do Service em $(( $(date +%s) - t0 )) s (previsto ~12 s)"
oc exec -n ac11-resiliencia "$P" -- rm /tmp/fora; t0=$(date +%s)
until [ "$(oc get -n ac11-resiliencia "$P" -o jsonpath='{.status.containerStatuses[0].ready}')" = true ]; do sleep 1; done
echo "voltou em $(( $(date +%s) - t0 )) s (previsto ~8 s: successThreshold 2)"
```

## Repetições

1. Repita com `--period-seconds=2 --failure-threshold=2` e compare.
2. Qual o custo de probes muito frequentes em um SNO com muitos pods?
3. Por que `successThreshold` precisa ser 1 em liveness e startup?
4. Volte a readiness para `--open-tcp=8080 --period-seconds=5`.
5. Escreva a fórmula de memória.

## Desafio sem pista

Proponha parâmetros de readiness e liveness para uma API que leva até 3 s para responder sob carga e não pode ficar
mais de 15 s recebendo tráfego quando trava. Justifique cada número.

## Diagnóstico controlado

- **Sintoma:** pods "piscando" entre pronto e não pronto (endpoints entrando e saindo).
- **Hipóteses:** `timeoutSeconds` baixo para o tempo de resposta real; `failureThreshold` 1.
- **Investigação:** eventos `Unhealthy` com `timeout`; parâmetros da probe.
- **Reversão:** aumente `timeoutSeconds`/`failureThreshold` com base em medição.

## Validação
