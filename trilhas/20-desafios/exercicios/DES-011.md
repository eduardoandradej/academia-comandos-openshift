## Diagnóstico controlado

- **Sintoma:** depois de várias correções, os pods ficam prontos, mas a Route ainda responde 503.
- **Hipóteses:** andar 7 tem mais de um defeito (Service, Route, política).
- **Investigação:** endpoints; `spec.to.name` da Route; NetworkPolicies.
- **Reversão:** um por vez, testando entre eles.

## Validação

```bash
ok() { if eval "$2" >/dev/null 2>&1; then echo "OK   $1"; else echo "FALHA $1"; fi; }
N=ac20-cego
ok "2 réplicas prontas"  "[ \"\$(oc get deploy ac20-loja -n $N -o jsonpath='{.status.readyReplicas}')\" = 2 ]"
ok "sem reinícios novos" "[ \$(oc get pods -n $N -l app=ac20-loja -o jsonpath='{range .items[*]}{.status.containerStatuses[0].restartCount}{\"\n\"}{end}' | sort -n | tail -1) -lt 3 ]"
ok "endpoints prontos"   "oc get endpointslices -n $N -l kubernetes.io/service-name=ac20-loja -o jsonpath='{.items[*].endpoints[*].conditions.ready}' | grep -q true"
ok "Route responde"      "curl -sS -m 5 http://\$(oc get route ac20-loja -n $N -o jsonpath='{.spec.host}')/ | grep -q 'loja ac20 no ar'"
```
