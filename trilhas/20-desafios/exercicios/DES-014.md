# DES-014 — Missão 14: migrar a loja para outro projeto sem perder nada

## Identificação

- **ID:** DES-014
- **Trilha:** [20 — Desafios integradores](../README.md)
- **Referência didática:** Metodologia própria da Academia (desafio integrador).
- **Fichas de comando:** [`oc-apply-patch-diff`](../../../catalogo/fichas/oc-apply-patch-diff.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Exportar a loja viva (com tudo o que as missões acrescentaram), recriá-la em `ac20-loja-nova` a partir de manifestos
limpos e provar que as duas são equivalentes.

**Indicador de sucesso:** a validação da missão 1 (adaptada ao novo projeto) toda `OK` e um `diff` das especificações sem diferenças além de nomes de projeto, hosts e hashes.

## Nível

**Nível:** Avançado

## Duração e repetições

- **Duração sugerida:** 45 min
- **Repetições:** 3× (D+1, D+7, D+30)

## Contexto

- **Terminal:** `student@ocp-admin`, na raiz do repositório clonado (`cd ~/academia-comandos-openshift`)
- **Perfil:** `developer`
- **Projeto:** `ac20-loja` → `ac20-loja-nova`
- **Impacto:** MUTAÇÃO LOCAL REVERSÍVEL

## Pré-flight

```bash
source scripts/perfis.sh && ac-dev   # perfil developer (ORI-004)
scripts/preflight.sh                 # sem FALHA; memória do nó abaixo de 85%
```

REQUER PREPARAÇÃO: pull de `registry.access.redhat.com/ubi9/httpd-24`; curinga `*.apps` resolvendo na `ocp-admin`.

## Conceito

> **Missão.** Você recebe **requisitos**, não comandos. Escolha as ferramentas das trilhas anteriores, cumpra todos os
> requisitos dentro do tempo e confira com a **Validação** (autoavaliação: cada linha deve responder `OK`). O gabarito
> mostra **uma** solução; outras que passem na validação são igualmente válidas.

**Requisitos**:

1. Exporte ConfigMaps, Secrets (valores fictícios), SA, Deployment, Service, Route, PDB, HPA, Roles, RoleBindings e NetworkPolicies do `ac20-loja` para `/tmp/ac20/migracao/` **limpos** (DCL-010).
2. Recrie em `ac20-loja-nova` só com `oc apply -f /tmp/ac20/migracao/`.
3. A Route nova tem host próprio (o gerado do projeto novo).
4. Prove a equivalência por `diff` de especificações normalizadas.
5. Os Secrets exportados ficam fora do repositório e são apagados ao final.

## Comandos guiados

```bash
mkdir -p /tmp/ac20/migracao
oc new-project ac20-loja-nova >/dev/null 2>&1 || true
# ... cumpra os requisitos (Trilha 12) ...
```

## Repetições

1. Que campos precisaram ser removidos de cada tipo?
2. O RoleBinding apontava para SAs do projeto antigo? Como ajustou?
3. A ImageStream (missão 5) veio junto? O gatilho funcionou no novo projeto?
4. Por que o `host` da Route foi removido?
5. Refaça em D+30.

## Desafio sem pista

Faça a migração em um único pipe (exportar → limpar → trocar o namespace dos `subjects` → aplicar), sem arquivos intermediários além do diretório final.

## Diagnóstico controlado

- **Sintoma:** no projeto novo, o Deployment não sobe: `serviceaccount "loja" not found`.
- **Hipóteses:** ordem de aplicação ou SA não exportada.
- **Investigação:** lista de arquivos exportados.
- **Reversão:** exporte a SA; reaplique o diretório.

## Validação

```bash
ok() { if eval "$2" >/dev/null 2>&1; then echo "OK   $1"; else echo "FALHA $1"; fi; }
N=ac20-loja-nova
ok "loja nova pronta"  "[ \"\$(oc get deploy loja -n $N -o jsonpath='{.status.readyReplicas}')\" -ge 1 ]"
ok "Route nova responde" "curl -sSk -m 5 https://\$(oc get route loja -n $N -o jsonpath='{.spec.host}')/ | grep -q loja"
ok "mesmas políticas"  "[ \$(oc get networkpolicy -n $N --no-headers | wc -l) = \$(oc get networkpolicy -n ac20-loja --no-headers | wc -l) ]"
```

## Limpeza segura

```bash
rm -rf /tmp/ac20/migracao
oc delete project ac20-loja-nova --ignore-not-found
```
