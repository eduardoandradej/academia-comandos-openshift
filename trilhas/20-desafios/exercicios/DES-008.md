## Repetições

1. Que papel pronto serviu para o `leitor`? E para o `ci`?
2. O `operador` precisou de Role própria? Com quais regras?
3. Algum ✔ a mais apareceu? Qual papel causou?
4. Troque o papel de um binding sem janela sem acesso (TS-047).
5. Refaça em D+7.

## Desafio sem pista

Automatize a verificação da matriz: um script que compara o resultado de `can-i` com a tabela esperada e lista as divergências.

## Diagnóstico controlado

- **Sintoma:** o `operador` escala via `oc scale`, mas recebe Forbidden ao `oc get deployment`.
- **Hipóteses:** Role com `deployments/scale` mas sem `get` em `deployments`.
- **Investigação:** `oc describe role`.
- **Reversão:** acrescente `get` em `deployments` (grupo `apps`).

## Validação

```bash
S=system:serviceaccount:ac20-loja
while read -r sa verbo recurso quer; do
  tem=$(oc auth can-i "$verbo" "$recurso" -n ac20-loja --as="$S:$sa")
  if [ "$tem" = "$quer" ]; then echo "OK   $sa $verbo $recurso"; else echo "FALHA $sa $verbo $recurso (esperado $quer, obtido $tem)"; fi
done <<'EOF'
leitor get pods yes
leitor get pods/log yes
leitor get secrets no
leitor update deployments.apps/scale no
leitor patch deployments.apps no
leitor create rolebindings no
operador get pods yes
operador get secrets no
operador update deployments.apps/scale yes
operador patch deployments.apps no
operador create rolebindings no
ci get secrets yes
ci update deployments.apps/scale yes
ci patch deployments.apps yes
ci create rolebindings no
EOF
```
