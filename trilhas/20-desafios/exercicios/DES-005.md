## Objetivo e indicador de sucesso

Fazer a loja seguir uma tag `prod` de ImageStream e promover uma versão nova com um único `oc tag`, com rollout automático e volta rápida.

**Indicador de sucesso:** uma promoção v1 → v2 e uma volta v2 → v1, cada uma com um comando, sem editar o Deployment.

**Requisitos** (projeto `ac20-loja`):

2. Tag `prod` apontando para `v1`.
3. Deployment `loja` disparado pela `loja:prod` (gatilho de imagem).
4. Promoção e volta só com `oc tag`.

## Desafio sem pista

Escreva `promove <tag>` que só promove se a tag existir e for diferente da `prod`, espera o rollout e roda as validações da missão 1 em seguida.

## Diagnóstico controlado

- **Sintoma:** `oc tag` mudou a `prod`, mas o Deployment não fez rollout.
- **Hipóteses:** gatilho ausente/pausado ou contêiner errado (TS-032).
- **Investigação:** `oc set triggers deployment/loja`.
- **Reversão:** recrie o gatilho com o nome certo do contêiner.

## Validação

```bash
ok() { if eval "$2" >/dev/null 2>&1; then echo "OK   $1"; else echo "FALHA $1"; fi; }
N=ac20-loja
ok "tags v1, v2 e prod"   "[ \$(oc get istag -n $N -o name | grep -cE 'loja:(v1|v2|prod)') = 3 ]"
ok "gatilho na prod"       "oc set triggers deployment/loja -n $N | grep -q 'loja:prod'"
ok "pod no digest da prod" "oc get pod -n $N -l app=loja -o jsonpath='{.items[0].spec.containers[0].image}' | grep -q \"\$(oc get istag loja:prod -n $N -o jsonpath='{.image.metadata.name}')\""
```
