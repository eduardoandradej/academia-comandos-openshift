## Objetivo e indicador de sucesso

Ler tudo o que o Cluster Version Operator sabe: versão atual, canal, histórico de atualizações, condições e
atualizações disponíveis (inclusive as condicionais), sem iniciar nada.

**Indicador de sucesso:** você responde "em que versão estou, desde quando, em que canal, e há atualização recomendada?" só com leitura.

## Conceito

> **Somente observação.** Nesta trilha nenhum comando altera operadores, `ClusterVersion`, `MachineConfig`, OLM ou
> o nó. Onde aparece uma mudança, ela vem com `--dry-run=server` (validada, não gravada) ou como plano escrito.
> No SNO, mexer nesses objetos pode reiniciar o único nó ou derrubar o cluster.

| Campo de `clusterversion/version` | Significa |
|---|---|
| `status.desired.version` | versão que o CVO está aplicando/mantendo |
| `status.history[]` | atualizações passadas (`Completed`/`Partial`) |
| `spec.channel` | canal (`stable-4.22`, `fast-4.22`...) |
| `status.availableUpdates` | atualizações recomendadas |
| `status.conditionalUpdates` | atualizações com riscos conhecidos |
| condições `Available`, `Progressing`, `Failing` | estado do CVO |

## Comandos guiados

```bash
oc get clusterversion
oc get clusterversion version -o jsonpath='{.status.desired.version} canal={.spec.channel}{"\n"}'
oc get clusterversion version -o json | jq -r '.status.history[] | "\(.state)\t\(.version)\t\(.startedTime) → \(.completionTime // "-")"'
oc get clusterversion version -o json | jq -r '.status.conditions[] | "\(.type)=\(.status) \(.message // "")"' | cut -c1-140
oc get clusterversion version -o json | jq -r '(.status.availableUpdates // [])[] | .version' | head
oc get clusterversion version -o json | jq -r '(.status.conditionalUpdates // [])[] | "\(.release.version): \([.risks[].name] | join(","))"' | head
```

## Repetições

1. Quando o cluster foi instalado? (primeiro item do histórico)
2. Há `availableUpdates`? E `conditionalUpdates`? Leia o risco de uma delas.
3. O que significaria `Progressing=True` agora?
4. Qual o `clusterID`? (`.spec.clusterID`)
5. Escreva os campos da tabela de memória.

## Desafio sem pista

Produza um "cartão de versão" de 4 linhas: versão atual, data da instalação/última atualização, canal e próxima versão recomendada (ou "nenhuma").

## Diagnóstico controlado

- **Sintoma:** `availableUpdates` vazio e condição `RetrievedUpdates=False`.
- **Hipóteses:** o cluster não alcança o serviço de grafos de atualização (rede, proxy) ou canal inexistente.
- **Investigação:** mensagem da condição `RetrievedUpdates`; `spec.channel`; `spec.upstream`.
- **Reversão:** nada a fazer pela Academia: é só informação (não impede o funcionamento).

## Validação

```bash
oc get clusterversion version -o jsonpath='{.status.conditions[?(@.type=="Available")].status}{"\n"}'    # True
```
