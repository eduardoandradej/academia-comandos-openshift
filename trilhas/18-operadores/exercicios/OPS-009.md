# OPS-009 — MachineConfig e MachineConfigPool: o que reinicia o nó

## Objetivo e indicador de sucesso

Ler os MachineConfigPools e MachineConfigs, a configuração renderizada atual e entender que mudanças disparam reinício
do nó — no SNO, do cluster inteiro.

**Indicador de sucesso:** você diz qual MachineConfig renderizado o nó usa, se o pool está atualizado e quais tipos de mudança reiniciariam o nó.

## Conceito

> **Somente observação.** Nesta trilha nenhum comando altera operadores, `ClusterVersion`, `MachineConfig`, OLM ou
> o nó. Onde aparece uma mudança, ela vem com `--dry-run=server` (validada, não gravada) ou como plano escrito.
> No SNO, mexer nesses objetos pode reiniciar o único nó ou derrubar o cluster.

O **Machine Config Operator** junta vários `MachineConfig` (arquivos, unidades systemd, kernel) em um **renderizado**
(`rendered-master-<hash>`) e o aplica aos nós do pool. Aplicar normalmente significa **drenar e reiniciar** o nó.
No SNO, isso derruba o cluster até o nó voltar. Também geram MachineConfig: mudanças de política de imagem (IMG-011),
de registries, de chrony, de kubelet.

**A Academia nunca cria, edita ou apaga MachineConfig/KubeletConfig/ContainerRuntimeConfig.**

## Comandos guiados

```bash
oc get mcp
oc get mcp master -o jsonpath='atual={.status.configuration.name}{"\n"}máquinas={.status.machineCount} atualizadas={.status.updatedMachineCount} degradadas={.status.degradedMachineCount}{"\n"}'
oc get mc --sort-by=.metadata.creationTimestamp | tail -12
N=$(oc get nodes -o jsonpath='{.items[0].metadata.name}')
oc get node "$N" -o jsonpath='{.metadata.annotations.machineconfiguration\.openshift\.io/currentConfig}{"\n"}{.metadata.annotations.machineconfiguration\.openshift\.io/state}{"\n"}'
oc get mc "$(oc get mcp master -o jsonpath='{.status.configuration.name}')" -o json | jq -r '.spec.config.storage.files[]?.path' | head
oc get kubeletconfig,containerruntimeconfig 2>/dev/null
```

## Repetições

1. Quais MachineConfigs compõem o renderizado atual? (`.status.configuration.source`)
2. O pool está `paused`? O que isso significaria?
3. Leia a condição `Updated`/`Degraded` do pool.
4. Que mudanças das trilhas anteriores teriam gerado MachineConfig se fossem aplicadas? (IMG-011, NET-001)
5. Explique por que um MachineConfig mal escrito pode deixar o SNO sem voltar.

## Desafio sem pista

Mostre a lista de MachineConfigs de origem do renderizado atual, com a data de criação de cada um, e aponte o mais recente — "a última coisa que mudou no nó".

## Diagnóstico controlado

- **Sintoma:** o MCP `master` mostra `UPDATING=True` por muito tempo, ou `DEGRADED=True`.
- **Hipóteses:** um MachineConfig novo foi criado e a aplicação travou (arquivo inválido, nó não drena).
- **Investigação:** condições do MCP; anotação `state`/`reason` do nó; MachineConfigs mais recentes.
- **Reversão:** manutenção do cluster (fora da Academia), com a apostila e o acesso de recuperação. Veja TS-056.

## Validação

```bash
oc get mcp master -o jsonpath='{.status.conditions[?(@.type=="Updated")].status}{"\n"}'    # True
```
