# OPS-011 — Planejar uma atualização (sem atualizar)

## Identificação

- **ID:** OPS-011
- **Trilha:** [18 — Operadores e manutenção](../README.md)
- **Referência didática:** DO280 — atualização do cluster (planejamento).
- **Fichas de comando:** [`oc-operadores-manutencao`](../../../catalogo/fichas/oc-operadores-manutencao.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Montar o checklist de pré-requisitos de uma atualização — operadores saudáveis, MCP atualizado, PDBs, `Upgradeable`,
admin-acks, backup do etcd, espaço e janela — e preenchê-lo com o estado real do HomeLab.

**Indicador de sucesso:** um checklist preenchido com "ok/pendente" para cada item, terminando com "pronto para planejar" ou a lista de pendências.

## Pré-flight

```bash
source scripts/perfis.sh && ac-admin
oc whoami                            # admin — SOMENTE LEITURA nesta trilha
scripts/preflight.sh                 # sem FALHA
```

## Conceito

> **Somente observação.** Nesta trilha nenhum comando altera operadores, `ClusterVersion`, `MachineConfig`, OLM ou
> o nó. Onde aparece uma mudança, ela vem com `--dry-run=server` (validada, não gravada) ou como plano escrito.
> No SNO, mexer nesses objetos pode reiniciar o único nó ou derrubar o cluster.

| Pré-requisito | Verificação |
|---|---|
| CVO sem falha | `Failing=False`, `Progressing=False` |
| operadores | nenhum `Degraded`; `Upgradeable` não `False` |
| MCP | `Updated=True`, sem `paused` |
| PDBs | nenhum com `disruptionsAllowed=0` que trave o nó |
| admin-acks | `oc get cm admin-acks -n openshift-config` (APIs removidas na próxima menor) |
| backup | etcd (procedimento oficial) e VM desligada copiada para o HD |
| recursos | memória do nó < 85%; espaço em `/var` do `kvm-server` |
| janela | tempo de indisponibilidade aceito (SNO não tem atualização sem parada) |

`oc adm upgrade` (sem argumentos) apenas **mostra** o estado; com `--to`, inicia a atualização — **nunca** pela Academia.

## Comandos guiados

```bash
oc adm upgrade 2>&1 | head -15                                                        # só exibe
oc get clusterversion version -o json | jq -r '.status.conditions[] | select(.type=="Failing" or .type=="Progressing") | "\(.type)=\(.status)"'
oc get co -o json | jq -r '.items[] | .metadata.name as $n | .status.conditions[] | select(.type=="Upgradeable" and .status=="False") | "\($n): \(.message)"'
oc get mcp master -o jsonpath='Updated={.status.conditions[?(@.type=="Updated")].status} paused={.spec.paused}{"\n"}'
oc get pdb -A -o json | jq '[.items[] | select(.status.disruptionsAllowed==0)] | length'
oc get cm admin-acks -n openshift-config -o jsonpath='{.data}{"\n"}' 2>/dev/null
oc get cm admin-gates -n openshift-config-managed -o jsonpath='{.data}{"\n"}' 2>/dev/null
oc adm top node
```

## Repetições

1. Algum `admin-gate` pede reconhecimento? O que ele diz?
2. Que APIs depreciadas o cluster ainda recebe? (`oc get apirequestcounts -o json | jq` com `removedInRelease`)
3. Quanto tempo o SNO ficaria indisponível numa atualização? (estimativa e justificativa)
4. Onde ficaria a cópia da VM (docs/09)?
5. Escreva o checklist de memória.

## Desafio sem pista

Escreva `pronto_para_atualizar` que verifica automaticamente os itens observáveis do checklist e imprime as
pendências; os itens manuais (backup, janela) devem aparecer sempre como "confirmar manualmente".

## Diagnóstico controlado

- **Sintoma:** `oc adm upgrade` mostra `Upgradeable=False` com mensagem sobre `admin-acks`.
- **Hipóteses:** a próxima versão remove APIs; o admin precisa reconhecer.
- **Investigação:** `admin-gates` e `apirequestcounts` (quem usa as APIs que serão removidas).
- **Reversão:** decisão do admin com o procedimento oficial — fora da Academia.

## Validação

```bash
oc get clusterversion version -o jsonpath='{.status.conditions[?(@.type=="Failing")].status}{"\n"}'    # False
```
