# OPS-007 — Instalar um operador: só no papel (dry-run de servidor)

## Identificação

- **ID:** OPS-007

- **Referência didática:** DO280 — OLM (instalação).
- **Fichas de comando:** [`oc-operadores-manutencao`](../../../catalogo/fichas/oc-operadores-manutencao.md)

## Objetivo e indicador de sucesso

Escrever o OperatorGroup e a Subscription para instalar um operador com aprovação **manual**, e validá-los com
`--dry-run=server` — sem instalar nada.

**Indicador de sucesso:** os dois objetos passam no dry-run de servidor, e você descreve o que aconteceria (InstallPlan pendente, CRDs, pods) se fossem aplicados.

## Conceito

> **Somente observação.** Nesta trilha nenhum comando altera operadores, `ClusterVersion`, `MachineConfig`, OLM ou
> o nó. Onde aparece uma mudança, ela vem com `--dry-run=server` (validada, não gravada) ou como plano escrito.
> No SNO, mexer nesses objetos pode reiniciar o único nó ou derrubar o cluster.

Instalar um operador cria **CRDs** (objetos de cluster), permissões e pods — é mudança de cluster, mesmo dentro de um
namespace. Com `installPlanApproval: Manual`, o OLM cria um InstallPlan e **espera** aprovação: um bom hábito para
SNO, onde cada operador consome CPU/memória do único nó.

A Academia só valida; a instalação real (ex.: LVMS da Trilha 09) é decisão do administrador do HomeLab.

## Comandos guiados

```bash
oc new-project ac18-ops --skip-config-write >/dev/null 2>&1 || true
oc label namespace ac18-ops academy.openshift.dev/managed-by=academia --overwrite
P=$(oc get packagemanifests -n openshift-marketplace -o name | grep -m1 -E 'cert-manager|lvms-operator' | cut -d/ -f2)
CAT=$(oc get packagemanifest "$P" -n openshift-marketplace -o jsonpath='{.status.catalogSource}')
CH=$(oc get packagemanifest "$P" -n openshift-marketplace -o jsonpath='{.status.defaultChannel}')
echo "pacote=$P catálogo=$CAT canal=$CH"
cat <<EOF | oc apply --dry-run=server -n ac18-ops -f -
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: ac18-og
spec:
  targetNamespaces: [ac18-ops]
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: ac18-sub
spec:
  name: $P
  channel: $CH
  source: $CAT
  sourceNamespace: openshift-marketplace
  installPlanApproval: Manual
EOF
oc get subscription,operatorgroup -n ac18-ops       # nada foi criado
```

## Repetições

1. Que `installModes` o CSV do pacote suporta (`OwnNamespace`, `AllNamespaces`)? O OperatorGroup escrito é compatível?
2. O que mudaria com `installPlanApproval: Automatic`?
3. Que CRDs o pacote criaria? (`.status.channels[].currentCSVDesc.customresourcedefinitions.owned[].name`)
4. Quanto de CPU/memória os Deployments do CSV pedem?
5. Escreva os dois objetos de memória.

## Desafio sem pista

Liste, para o pacote escolhido, tudo o que seria criado no cluster (CRDs, Deployments, permissões de cluster) a partir
do `currentCSVDesc`, sem instalar — o "impacto" que você apresentaria para aprovação.

## Diagnóstico controlado

- **Sintoma:** com um OperatorGroup de `targetNamespaces` e um operador que só suporta `AllNamespaces`, o CSV falha com `UnsupportedOperatorGroup`.
- **Hipóteses:** modo de instalação incompatível.
- **Investigação:** `installModes` no PackageManifest/CSV.
- **Reversão:** ajuste o OperatorGroup (num cenário real) — aqui, só no papel.

oc get subscription -n ac18-ops --no-headers 2>/dev/null | wc -l     # 0: nada instalado
