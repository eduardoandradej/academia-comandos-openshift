# CFG-004 — Atualizar configuração: arquivos se atualizam, variáveis não

## Identificação

- **ID:** CFG-004
- **Trilha:** [08 — ConfigMaps e Secrets](../README.md)
- **Referência didática:** DO180 — atualização de configuração de aplicações.
- **Fichas de comando:** [`oc-configmap-secret`](../../../catalogo/fichas/oc-configmap-secret.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Alterar um ConfigMap e observar a diferença: o arquivo montado muda sozinho (com atraso); a variável de ambiente só muda após reiniciar os pods.

**Indicador de sucesso:** você mostra, no mesmo pod, o arquivo novo e a variável antiga — e depois a variável nova após o restart.

## Conceito

| Consumo | Atualiza quando o ConfigMap muda? |
|---|---|
| volume (arquivos) | sim, após a sincronização do kubelet (dezenas de segundos a ~1 min) |
| volume com `subPath` | **não** |
| variáveis (`env`/`envFrom`) | **não**: lidas só na criação do contêiner |

A aplicação ainda precisa **reler** o arquivo (muitas só leem na inicialização). Para forçar, `oc rollout restart`.

## Comandos guiados

```bash
oc exec deploy/ac08-app -n ac08-config -- sh -c 'cat /etc/academia/app.conf; echo "MODO=$MODO"'
oc create configmap ac08-arquivo --from-file=/tmp/ac08/app.conf --from-literal=principal.conf='ServerName nova' \
  --dry-run=client -o yaml | oc apply -n ac08-config -f -        # muda principal.conf
oc create configmap ac08-literal --from-literal=MODO=producao --from-literal=NIVEL_LOG=debug \
  --dry-run=client -o yaml | oc apply -n ac08-config -f -        # muda MODO
for i in $(seq 12); do oc exec deploy/ac08-app -n ac08-config -- cat /etc/academia/principal.conf; echo; sleep 10; done | uniq
oc exec deploy/ac08-app -n ac08-config -- printenv MODO          # ainda treino
oc rollout restart deployment/ac08-app -n ac08-config && oc rollout status deployment/ac08-app -n ac08-config
oc exec deploy/ac08-app -n ac08-config -- printenv MODO          # producao
```

## Repetições

1. Cronometre o tempo até o arquivo mudar (5×).
2. Observe o link `..data` mudar de destino: `oc exec ... -- ls -la /etc/academia`.
3. Apague uma chave do ConfigMap e veja o arquivo sumir.
4. Use `oc set data configmap/ac08-literal MODO=treino -n ac08-config` como alternativa ao `apply`.
5. Explique por que reiniciar é necessário mesmo para arquivos quando a aplicação só lê na inicialização.

## Desafio sem pista

Faça uma mudança de configuração "à prova de esquecimento": altere o ConfigMap **e** garanta que os pods sejam
recriados automaticamente por causa disso, sem `rollout restart` manual (dica: uma anotação no template com o hash do conteúdo).

## Diagnóstico controlado

- **Sintoma:** o ConfigMap tem o valor novo, mas a aplicação continua usando o antigo.
- **Hipóteses:** (a) consumo por variável; (b) `subPath`; (c) a aplicação não relê o arquivo.
- **Investigação:** forma de consumo no Deployment (`envFrom`/`volumeMounts.subPath`); conteúdo do arquivo dentro do pod.
- **Reversão:** `oc rollout restart deployment/ac08-app -n ac08-config`. Veja TS-026.

## Validação

```bash
oc exec deploy/ac08-app -n ac08-config -- printenv MODO    # producao
```

## Limpeza segura

Volte `MODO=treino` se quiser: `oc set data configmap/ac08-literal MODO=treino -n ac08-config` e `oc rollout restart deployment/ac08-app -n ac08-config`.
