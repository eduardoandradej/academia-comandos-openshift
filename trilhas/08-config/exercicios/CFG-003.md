# CFG-003 — Montar ConfigMap como arquivos

## Identificação

- **ID:** CFG-003
- **Trilha:** [08 — ConfigMaps e Secrets](../README.md)
- **Referência didática:** DO180 — configuração de aplicações (volumes).
- **Fichas de comando:** [`oc-configmap-secret`](../../../catalogo/fichas/oc-configmap-secret.md), [`oc-set-volume`](../../../catalogo/fichas/oc-set-volume.md)
- **Status:** proposto — escrito e revisado estaticamente; ainda não executado contra o cluster pelo autor

## Objetivo e indicador de sucesso

Montar um ConfigMap como diretório de arquivos com `oc set volume`, escolher só algumas chaves (`items`) e ver como o kubelet organiza os arquivos.

**Indicador de sucesso:** `/etc/academia/app.conf` existe no pod com o conteúdo do ConfigMap, e você explica os links `..data`.

## Conceito

Montado como volume, cada chave vira um **arquivo** no diretório escolhido. O kubelet cria um diretório versionado e
links simbólicos (`..data` → `..2026_...`, `app.conf` → `..data/app.conf`), o que permite trocar todos os arquivos de
uma vez quando o ConfigMap muda (CFG-004).

Montar em um diretório **substitui** o conteúdo original dele no contêiner. Para pôr um único arquivo em um
diretório existente, use `subPath` (CFG-010) — com a ressalva de que ele não se atualiza.

## Comandos guiados

```bash
oc set volume deployment/ac08-app --add --name=cfg-arquivo --type=configmap \
  --configmap-name=ac08-arquivo --mount-path=/etc/academia -n ac08-config
oc rollout status deployment/ac08-app -n ac08-config
oc exec deploy/ac08-app -n ac08-config -- ls -la /etc/academia
oc exec deploy/ac08-app -n ac08-config -- cat /etc/academia/app.conf
oc set volume deployment/ac08-app -n ac08-config                       # lista os volumes
oc get deployment ac08-app -n ac08-config -o jsonpath='{.spec.template.spec.volumes}{"\n"}{.spec.template.spec.containers[0].volumeMounts}{"\n"}'
```

## Repetições

1. Monte também o `ac08-env` em `/etc/academia-env` e liste os arquivos.
2. Com `oc patch`, use `items` para montar só a chave `principal.conf` com o nome de arquivo `httpd-extra.conf`.
3. Defina `defaultMode: 0440` no volume e confira as permissões com `ls -l`.
4. Remova um volume com `oc set volume deployment/ac08-app --remove --name=<nome>`.
5. Monte em `/var/www/html` em um Deployment de teste e veja a página padrão sumir.

## Desafio sem pista

Monte apenas a chave `MODO` do `ac08-literal` como o arquivo `/etc/modo/atual` (somente leitura, modo 0444) e prove o
conteúdo e as permissões.

## Diagnóstico controlado

- **Sintoma:** após montar em `/etc/httpd/conf.d`, o httpd deixa de iniciar.
- **Hipóteses:** a montagem substituiu o diretório inteiro, apagando os `.conf` da imagem.
- **Investigação:** `oc logs deploy/ac08-app --previous`; `oc exec ... -- ls /etc/httpd/conf.d` em uma cópia de debug.
- **Reversão:** `oc set volume deployment/ac08-app --remove --name=<volume>` (ou use `subPath`, CFG-010).

## Validação

```bash
oc exec deploy/ac08-app -n ac08-config -- grep -q 'ServerName academia' /etc/academia/app.conf && echo OK
```

## Limpeza segura

Mantenha o volume `cfg-arquivo` para o CFG-004. Remova os de teste: `oc set volume deployment/ac08-app --remove --name=<nome> -n ac08-config`.
