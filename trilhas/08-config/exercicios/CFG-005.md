## Conceito

> **Valores fictícios.** Todo Secret desta trilha usa valores inventados (`senha-de-treino`, `token-ficticio`).
> Mesmo assim, trate a saída de comandos que mostram dados de Secret como sensível: não cole em chats, issues ou commits.

Um **Secret** tem a mesma forma de um ConfigMap, mas: os valores ficam em `data` codificados em **base64** (não é
cifra: qualquer um decodifica), o acesso é controlado por RBAC separado (o papel `view` não lê Secrets) e há tipos
com validação (`kubernetes.io/tls`, `kubernetes.io/dockerconfigjson`...).

Formas seguras de inspecionar: `oc describe secret` (mostra chaves e **tamanho em bytes**) e `jq 'keys'`. Formas que
**expõem**: `oc get secret -o yaml/json`, `oc extract`, `base64 -d`.

## Comandos guiados

```bash
oc create secret generic ac08-banco --from-literal=usuario=treino --from-literal=senha=senha-de-treino -n ac08-config
read -rs -p 'token fictício: ' T; echo
oc create secret generic ac08-api --from-literal=token="$T" -n ac08-config; unset T
oc label secret ac08-banco ac08-api academy.openshift.dev/managed-by=academia -n ac08-config
oc get secrets -n ac08-config -l academy.openshift.dev/managed-by=academia
oc describe secret ac08-banco -n ac08-config                                 # chaves e bytes, sem valores
oc get secret ac08-banco -n ac08-config -o json | jq -r '.data | keys[]'
oc get secret ac08-banco -n ac08-config -o json | jq -r '.data | to_entries[] | "\(.key): \(.value | @base64d | length) bytes"'
oc get secret ac08-banco -n ac08-config -o jsonpath='{.type}{"\n"}'
```

## Repetições

1. Por que `read -rs` é melhor que `--from-literal=token=...` para um valor real? (histórico do shell)
2. Crie um Secret a partir de arquivo (`--from-file`) com um conteúdo fictício e veja o tamanho.
3. `oc auth can-i get secrets -n ac08-config` como developer; e `--as=<um usuário com view>`? (perfil admin)
4. Compare `oc describe` de um ConfigMap e de um Secret.
5. Apague e recrie `ac08-api` de memória.

## Desafio sem pista

Prove, **sem imprimir o valor**, que a senha guardada em `ac08-banco` é exatamente `senha-de-treino` (dica: compare hashes).

## Diagnóstico controlado

- **Sintoma:** alguém colou em um chat a saída de `oc get secret ac08-banco -o yaml` dizendo que "está criptografado".
- **Hipóteses:** confusão entre base64 e criptografia.
- **Investigação:** `echo '<valor do campo>' | base64 -d` mostra o texto original.
- **Reversão:** trate como vazamento: troque o valor (aqui é fictício) e nunca compartilhe a saída `-o yaml` de Secrets.

## Validação

```bash
oc get secret ac08-banco -n ac08-config -o json | jq -e '.data | has("senha")' >/dev/null && echo "chave senha presente"
```
