## Objetivo e indicador de sucesso

Criar um pull secret (credenciais fictícias para um registry inexistente), ligá-lo à service account `default` e desligá-lo.

**Indicador de sucesso:** `oc get sa default -o jsonpath='{.imagePullSecrets}'` mostra o seu secret, e depois não mostra mais.

## Conceito

> **Valores fictícios.** Todo Secret desta trilha usa valores inventados (`senha-de-treino`, `token-ficticio`).
> Mesmo assim, trate a saída de comandos que mostram dados de Secret como sensível: não cole em chats, issues ou commits.

Para baixar imagens de um registry privado, o pod precisa de um Secret `kubernetes.io/dockerconfigjson`. Duas formas
de usá-lo: `imagePullSecrets` no pod, ou **ligar** o Secret à service account do pod (`oc secrets link ... --for=pull`),
que então o injeta em todos os pods que usam essa SA.

O HomeLab não tem registry privado (**NÃO DISPONÍVEL NO HOME LAB ATUAL**): o exercício usa um servidor inexistente
(`registry.exemplo.invalid`) só para praticar o mecanismo.

## Comandos guiados

```bash
read -rs -p 'senha fictícia: ' S; echo
oc create secret docker-registry ac08-pull --docker-server=registry.exemplo.invalid \
  --docker-username=treino --docker-password="$S" -n ac08-config; unset S
oc label secret ac08-pull academy.openshift.dev/managed-by=academia -n ac08-config
oc get secret ac08-pull -n ac08-config -o jsonpath='{.type}{"\n"}'
oc secrets link default ac08-pull --for=pull -n ac08-config
oc get sa default -n ac08-config -o jsonpath='{.imagePullSecrets}{"\n"}'
oc get secret ac08-pull -n ac08-config -o jsonpath='{.data.\.dockerconfigjson}' | base64 -d | jq -r '.auths | keys[]'   # só o servidor
oc secrets unlink default ac08-pull -n ac08-config
oc get sa default -n ac08-config -o jsonpath='{.imagePullSecrets}{"\n"}'
```

## Repetições

1. Crie um pod com `image: registry.exemplo.invalid/app:1` e `imagePullSecrets: [ac08-pull]` e leia o erro (DNS, não credencial).
2. Liste as service accounts do projeto e os pull secrets que o OpenShift já colocou nelas.
3. `oc describe sa default -n ac08-config`.
4. Explique a diferença entre `--for=pull` e `--for=mount`.
5. `oc create secret docker-registry --help | sed -n '/Examples:/,/Options:/p'`.

## Desafio sem pista

Crie uma service account `ac08-robo` que tenha o pull secret ligado, e um Deployment que use essa SA; mostre que o pod
herdou o `imagePullSecrets` sem que você o declarasse no Deployment.

## Diagnóstico controlado

- **Sintoma:** `Failed to pull image "registry.exemplo.invalid/app:1": ... no such host`.
- **Hipóteses:** (a) registry inexistente (o caso aqui); (b) credencial errada (`unauthorized`).
- **Investigação:** a mensagem diferencia DNS (`no such host`) de autenticação (`unauthorized`/`authentication required`).
- **Reversão:** apague o pod de teste.

## Validação

```bash
oc get secret ac08-pull -n ac08-config -o jsonpath='{.type}{"\n"}'   # kubernetes.io/dockerconfigjson
```

## Limpeza segura

```bash
oc secrets unlink default ac08-pull -n ac08-config 2>/dev/null || true
oc delete pod ac08-privado -n ac08-config --ignore-not-found
oc delete deployment ac08-robo -n ac08-config --ignore-not-found
oc delete sa ac08-robo -n ac08-config --ignore-not-found
```
