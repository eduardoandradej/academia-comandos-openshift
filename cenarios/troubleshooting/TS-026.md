# TS-026 — Alterei o ConfigMap e nada mudou

- **Trilha:** [08 — ConfigMaps e Secrets](../../trilhas/08-config/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O `ac08-literal` foi alterado para `MODO=producao` e o `ac08-httpd` para um cabeçalho novo. Dez minutos depois, a
aplicação ainda mostra `MODO=treino` e o cabeçalho antigo.

## Contexto

Projeto `ac08-config` com `ac08-app` (CFG-002/003) e `ac08-web` (CFG-010).

## Como reproduzir com segurança

```bash
oc set data configmap/ac08-literal MODO=producao -n ac08-config
oc set data configmap/ac08-httpd academia.conf='Header always set X-Academia "mudou"' -n ac08-config
sleep 90
oc exec deploy/ac08-app -n ac08-config -- printenv MODO
oc exec deploy/ac08-web -n ac08-config -- cat /etc/httpd/conf.d/academia.conf
```

## Hipóteses a testar

1. `MODO` é consumido como variável de ambiente.
2. O arquivo do httpd é montado com `subPath`.
3. O ConfigMap não foi realmente alterado.

## Investigação orientada

- `oc get configmap ac08-literal -n ac08-config -o jsonpath='{.data.MODO}{"\n"}'`
- `oc get deployment ac08-app -n ac08-config -o json | jq '.spec.template.spec.containers[0] | {envFrom, env}'`
- `oc get deployment ac08-web -n ac08-config -o json | jq '.spec.template.spec.containers[0].volumeMounts'`

## Critério de resolução

Você explica separadamente por que cada um dos dois não mudou e aplica a correção mínima.

## Limpeza

```bash
oc set data configmap/ac08-literal MODO=treino -n ac08-config
oc rollout restart deployment/ac08-app deployment/ac08-web -n ac08-config
```
