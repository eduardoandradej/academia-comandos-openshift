# TS-001 — "Funciona aqui, não funciona lá": o terminal está como system:admin

- **Trilha:** [00 — Orientação e segurança](../../trilhas/00-orientacao/README.md)
- **Nível:** Iniciante
- **Perfil:** o que estiver configurado
- **Impacto da reprodução:** LEITURA
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Em um terminal, `oc get nodes` funciona e `oc auth can-i create resourcequotas -n ac00-orientacao` responde `yes`.
Em outro, os mesmos comandos dão `Forbidden` e `no`. Você jura que "fez login como developer".

## Contexto

A `ocp-admin` exporta, no `~/.bashrc`, o kubeconfig do instalador. Cada terminal novo nasce como `system:admin`,
a menos que o perfil seja trocado.

## Como reproduzir com segurança

```bash
bash -l -c 'oc whoami'                                   # um shell de login novo
source scripts/perfis.sh && ac-dev && oc whoami          # o terminal atual, no perfil developer
```

## Hipóteses a testar

1. Os terminais usam kubeconfigs diferentes.
2. Um dos tokens expirou.
3. O RBAC do cluster mudou entre um comando e outro.

## Investigação orientada

- Em cada terminal: `printenv KUBECONFIG`, `oc whoami`, `oc whoami --show-context`.
- `grep -n KUBECONFIG ~/.bashrc`.
- `oc auth can-i '*' '*' --all-namespaces` em cada terminal.

## Critério de resolução

Você aponta, com evidência, qual terminal está em qual identidade e por quê, e deixa ambos no perfil adequado ao exercício.

## Limpeza

Nada é criado. Feche terminais de recuperação que não precisar mais.
