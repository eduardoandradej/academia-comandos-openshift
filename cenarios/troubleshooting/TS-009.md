# TS-009 — ImagePullBackOff: diagnosticar sem adivinhar

- **Trilha:** [02 — Leitura e inspeção](../../trilhas/02-consultas/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 Deployment que nunca chega a rodar)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Um Deployment novo fica com `0/1` pronto e o pod alterna entre `ErrImagePull` e `ImagePullBackOff`.

## Contexto

Projeto `ac02-consultas`, perfil developer. O manifesto do cenário usa uma tag de imagem inexistente de propósito.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-imagem-inexistente.yaml -n ac02-consultas
oc get pods -n ac02-consultas -l app=obs-quebrado -w     # Ctrl+C após ver ImagePullBackOff
```

## Hipóteses a testar

1. Tag inexistente.
2. Registry inacessível (rede/DNS de saída).
3. Registry exige autenticação (pull secret ausente).

## Investigação orientada

- `oc describe pod -n ac02-consultas -l app=obs-quebrado | sed -n '/Events:/,$p'`
- `oc get events -n ac02-consultas --field-selector involvedObject.kind=Pod,reason=Failed`
- Compare com o alvo saudável: `oc get pods -n ac02-consultas -l app=obs-web -o jsonpath='{.items[0].spec.containers[0].image}{"\n"}'`

## Critério de resolução

Você cita a linha de evento que prova a causa e explica por que as outras hipóteses foram descartadas.
