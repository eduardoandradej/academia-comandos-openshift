# TS-056 — MachineConfigPool travado em Updating

- **Trilha:** [18 — Operadores e manutenção](../../trilhas/18-operadores/README.md)
- **Nível:** Avançado
- **Perfil:** admin
- **Impacto da reprodução:** LEITURA (observação; não há reprodução segura)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

`oc get mcp` mostra `master` com `UPDATED=False`, `UPDATING=True` há mais de uma hora, e o nó com a anotação
`machineconfiguration.openshift.io/state: Working` ou `Degraded`. Ninguém "fez atualização".

## Contexto

Perfil `admin`. Cenário de **leitura**: a Academia nunca cria MachineConfig para reproduzi-lo.

## Como reproduzir com segurança

```bash
oc get mcp
N=$(oc get nodes -o jsonpath='{.items[0].metadata.name}')
oc get node "$N" -o jsonpath='{.metadata.annotations}' | jq 'with_entries(select(.key|startswith("machineconfiguration")))'
```

Se o seu cluster não estiver nesse estado, faça o diagnóstico "no papel" com as perguntas abaixo.

## Hipóteses a testar

1. Um MachineConfig novo foi criado (por alguém ou por uma mudança de configuração do cluster, como política de imagens).
2. Um MachineConfig inválido impede o nó de aplicar e reiniciar.
3. O pool está pausado.

## Investigação orientada

- `oc get mc --sort-by=.metadata.creationTimestamp | tail -5`
- `oc get mcp master -o jsonpath='{.spec.paused} {.status.conditions[?(@.type=="Degraded")].message}'`
- anotações `currentConfig`, `desiredConfig`, `state`, `reason` do nó
- (admin, leitura) `oc logs -n openshift-machine-config-operator -l k8s-app=machine-config-daemon --tail=30`

## Critério de resolução

Você identifica o MachineConfig que disparou a mudança e o motivo do travamento, e descreve a correção como manutenção.

## Limpeza

Nada a limpar (somente leitura).
