# TS-013 — CrashLoopBackOff: o contêiner sobe e cai

- **Trilha:** [04 — Pods e contêineres](../../trilhas/04-pods/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 pod pequeno que reinicia com backoff)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O pod `ac04-crash` mostra `STATUS CrashLoopBackOff` e a coluna `RESTARTS` não para de crescer. `oc logs` às vezes
não mostra nada.

## Contexto

Projeto `ac04-pods`. O contêiner termina com erro poucos segundos depois de iniciar.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-crashloop.yaml -n ac04-pods
oc get pod ac04-crash -n ac04-pods -w      # Ctrl+C após ver CrashLoopBackOff
```

## Hipóteses a testar

1. O processo principal termina com erro (configuração ausente, comando errado).
2. A liveness probe mata o contêiner.
3. O contêiner é encerrado por falta de memória (OOMKilled).

## Investigação orientada

- `oc logs ac04-crash -n ac04-pods --previous`
- `oc get pod ac04-crash -n ac04-pods -o jsonpath='{.status.containerStatuses[0].lastState.terminated}' | jq .`
- `oc describe pod ac04-crash -n ac04-pods | sed -n '/Last State:/,/Ready:/p;/Events:/,$p'`
- `oc get pod ac04-crash -n ac04-pods -o jsonpath='{.spec.containers[0].livenessProbe}{"\n"}'`

## Critério de resolução

Você cita o `reason`, o `exitCode` e a linha de log da instância anterior que explicam a falha.

## Limpeza

```bash
oc delete pod -l academy.openshift.dev/cenario=ts-013 -n ac04-pods
```
