# TS-044 — invalid ownership metadata: o objeto que o Helm não assume

- **Trilha:** [14 — Helm](../../trilhas/14-helm/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A instalação do chart `ac14-loja` como release `vitrine` falha: `rendered manifests contain a resource that already
exists ... ConfigMap "vitrine-pagina" ... invalid ownership metadata`.

## Contexto

Projeto `ac14-helm`. Alguém criou o ConfigMap `vitrine-pagina` com `oc` para testar.

## Como reproduzir com segurança

```bash
oc create configmap vitrine-pagina --from-literal=index.html=manual -n ac14-helm
helm install vitrine /tmp/ac14/ac14-loja -n ac14-helm --set route.enabled=false
```

## Hipóteses a testar

1. Objeto com o mesmo nome criado fora do Helm (sem rótulo/anotações de dono).
2. Outra release já é dona do objeto.
3. Falta permissão para criar ConfigMaps.

## Investigação orientada

- `oc get configmap vitrine-pagina -n ac14-helm -o jsonpath='{.metadata.labels}{"\n"}{.metadata.annotations}{"\n"}'`
- `helm list -n ac14-helm -a`

## Critério de resolução

Você escolhe entre renomear, remover ou adotar o objeto, justificando a escolha.

## Limpeza

```bash
helm uninstall vitrine -n ac14-helm 2>/dev/null || true
oc delete configmap vitrine-pagina -n ac14-helm --ignore-not-found
```
