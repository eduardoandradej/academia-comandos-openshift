# TS-058 — Tudo verde, mas a resposta está errada: o Service que pega duas versões

- **Trilha:** [19 — Troubleshooting transversal](../../trilhas/19-troubleshooting/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Pods prontos, endpoints prontos, nenhuma falha. Mas metade das respostas da loja vem com a página antiga (`azul`) e
metade com a nova (`verde`).

## Contexto

Projeto `ac19-casos`, com o cliente `ac19-cli` (DIA-003).

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/servicos-azul-verde.yaml -n ac19-casos
oc create service clusterip loja --tcp=8080:8080 -n ac19-casos --dry-run=client -o yaml | oc set selector --local -f - app=loja -o yaml | oc apply -n ac19-casos -f -
for i in $(seq 8); do oc exec ac19-cli -n ac19-casos -- bash -c 'exec 3<>/dev/tcp/loja/8080 && printf "GET / HTTP/1.0\r\n\r\n" >&3 && tail -1 <&3'; done | sort | uniq -c
```

## Hipóteses a testar

1. O seletor do Service é amplo demais e pega as duas versões.
2. Cache no cliente.
3. Um dos pods está com a página errada.

## Investigação orientada

- `oc get svc loja -n ac19-casos -o jsonpath='{.spec.selector}{"\n"}'`
- `oc get pods -n ac19-casos -l app=loja --show-labels`
- `oc get endpointslices -n ac19-casos -l kubernetes.io/service-name=loja -o jsonpath='{range .items[*].endpoints[*]}{.targetRef.name}{"\n"}{end}'`

## Critério de resolução

Você mostra que nada está "quebrado" e que o problema é de intenção (seletor), e corrige para uma versão só.

## Limpeza

```bash
oc delete -f manifests/apps-exemplo/servicos-azul-verde.yaml -n ac19-casos --ignore-not-found
oc delete service loja -n ac19-casos --ignore-not-found
```
