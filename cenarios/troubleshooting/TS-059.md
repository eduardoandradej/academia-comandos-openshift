# TS-059 — Funciona pelo IP do pod, falha pelo Service: a porta nomeada

- **Trilha:** [19 — Troubleshooting transversal](../../trilhas/19-troubleshooting/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

De dentro do cluster, `t <IP-do-pod> 8080` funciona, mas `t <service> 8080` recusa a conexão. O Service tem endpoints.

## Contexto

Projeto `ac19-casos`, com o cliente `ac19-cli`.

## Como reproduzir com segurança

```bash
oc create deployment ac19-ts059 --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac19-casos --port=8080
oc patch deployment ac19-ts059 -n ac19-casos --type=json -p '[{"op":"add","path":"/spec/template/spec/containers/0/ports/0/name","value":"http"}]'
oc create service clusterip ac19-ts059 --tcp=8080:web -n ac19-casos
sleep 20; oc get endpointslices -n ac19-casos -l kubernetes.io/service-name=ac19-ts059 -o jsonpath='{.items[0].ports}{"\n"}'
```

## Hipóteses a testar

1. `targetPort` é um **nome** (`web`) que não existe no contêiner (que chama a porta de `http`).
2. NetworkPolicy no projeto.
3. O pod não está pronto.

## Investigação orientada

- `oc get svc ac19-ts059 -n ac19-casos -o jsonpath='{.spec.ports}{"\n"}'`
- `oc get deployment ac19-ts059 -n ac19-casos -o jsonpath='{.spec.template.spec.containers[0].ports}{"\n"}'`
- `oc get networkpolicy -n ac19-casos`

## Critério de resolução

Você explica por que o IP do pod funciona e o Service não, e corrige pela porta nomeada certa.

## Limpeza

```bash
oc delete deployment,service ac19-ts059 -n ac19-casos --ignore-not-found
```
