# TS-049 — Isolei o projeto e a Route caiu: 503 com pods saudáveis

- **Trilha:** [16 — Rede e isolamento](../../trilhas/16-rede/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (NetworkPolicies)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Depois de aplicar "nega toda entrada" e "libera o próprio projeto" no `ac16-rede`, a Route da loja passou a responder
`Application is not available` (503). Pods prontos, endpoints corretos, Route admitida.

## Contexto

Projetos `ac16-rede` e `ac16-vizinho` (NET-002). Curinga `*.apps` resolvendo na `ocp-admin`.

## Como reproduzir com segurança

```bash
oc delete networkpolicy -l academy.openshift.dev/managed-by=academia -n ac16-rede
oc apply -f manifests/networkpolicies/00-negar-entrada.yaml -f manifests/networkpolicies/10-permitir-mesmo-projeto.yaml -n ac16-rede
oc expose svc/web-azul -n ac16-rede 2>/dev/null || true
curl -sS -m 5 -o /dev/null -w '%{http_code}\n' "http://$(oc get route web-azul -n ac16-rede -o jsonpath='{.spec.host}')/"
```

## Hipóteses a testar

1. O router, em `openshift-ingress`, não é "o próprio projeto" e foi bloqueado.
2. Service sem endpoints.
3. Route não admitida.

## Investigação orientada

- `oc get endpointslices -n ac16-rede -l kubernetes.io/service-name=web-azul`
- `oc get route web-azul -n ac16-rede -o jsonpath='{.status.ingress[0].conditions[0].status}{"\n"}'`
- `oc get networkpolicy -n ac16-rede` (alguma libera o grupo de ingress?)

## Critério de resolução

Você libera só o router, só na porta da aplicação, sem abrir o projeto para todos.

## Limpeza

```bash
oc delete networkpolicy -l academy.openshift.dev/managed-by=academia -n ac16-rede
```
