# TS-050 — Depois da política de saída, nenhum nome resolve

- **Trilha:** [16 — Rede e isolamento](../../trilhas/16-rede/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (NetworkPolicies)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Para "travar" o projeto, foi aplicada uma política que nega toda saída. Agora a aplicação registra
`could not resolve host` para tudo, inclusive para Services do próprio projeto.

## Contexto

Projeto `ac16-rede` com o cliente `ac16-local` (NET-002).

## Como reproduzir com segurança

```bash
oc delete networkpolicy -l academy.openshift.dev/managed-by=academia -n ac16-rede
oc apply -f manifests/networkpolicies/40-negar-saida.yaml -n ac16-rede
oc exec ac16-local -n ac16-rede -- timeout 5 getent hosts web-azul || echo "não resolve"
```

## Hipóteses a testar

1. A saída para o DNS do cluster foi bloqueada junto com o resto.
2. O DNS do cluster está fora do ar.
3. O Service foi apagado.

## Investigação orientada

- `oc exec ac16-local -n ac16-rede -- cat /etc/resolv.conf` (nameserver = Service do DNS)
- `oc get networkpolicy -n ac16-rede -o jsonpath='{range .items[*]}{.metadata.name}{" "}{.spec.policyTypes}{"\n"}{end}'`
- `oc get svc web-azul -n ac16-rede`
- em outro projeto sem políticas: `getent hosts kubernetes.default.svc` funciona?

## Critério de resolução

Você mostra que o DNS do cluster funciona para outros projetos e libera só o DNS deste.

## Limpeza

```bash
oc delete networkpolicy -l academy.openshift.dev/managed-by=academia -n ac16-rede
```
