# TS-043 — another operation is in progress: a release travada

- **Trilha:** [14 — Helm](../../trilhas/14-helm/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (release de treino)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Um `helm upgrade --wait` foi interrompido (terminal fechado, `Ctrl+C`, queda da VPN). Agora qualquer operação na
release `loja` responde `Error: UPGRADE FAILED: another operation (install/upgrade/rollback) is in progress`.

## Contexto

Projeto `ac14-helm` com a release `loja` (HLM-004). Perfil `developer` conferido (`oc whoami`).

## Como reproduzir com segurança

```bash
timeout 5 helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --set image.tag=tag-que-nao-existe --wait --timeout 5m
helm history loja -n ac14-helm | tail -2
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm
```

## Hipóteses a testar

1. A última revisão ficou `pending-upgrade` porque o cliente morreu no meio.
2. Outra pessoa está fazendo upgrade agora.
3. O Secret da release está corrompido.

## Investigação orientada

- `helm history loja -n ac14-helm` (status da última revisão)
- `oc get secrets -n ac14-helm -l owner=helm,name=loja -o custom-columns=NOME:.metadata.name,STATUS:.metadata.labels.status`
- `pgrep -af 'helm upgrade'` (há algum processo ativo?)

## Critério de resolução

Você confirma que não há operação real em andamento e destrava a release sem apagar o histórico.

## Limpeza

Nada além da correção: a release termina em `deployed`.
