# TS-031 — ImagePullBackOff com nome curto: o ImageStream que o pod não encontra

- **Trilha:** [10 — Imagens e registries](../../trilhas/10-imagens/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 Deployment)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O Deployment `ac10-curto` usa `image: ac10-web:v1`. O ImageStream `ac10-web` existe no projeto e a tag `v1` também,
mas o pod fica em `ErrImagePull`/`ImagePullBackOff`.

## Contexto

Projeto `ac10-imagens` com o ImageStream `ac10-web` (IMG-005).

## Como reproduzir com segurança

```bash
oc set image-lookup ac10-web --enabled=false -n ac10-imagens
oc create deployment ac10-curto --image=ac10-web:v1 -n ac10-imagens
sleep 30; oc get pods -n ac10-imagens -l app=ac10-curto
```

## Hipóteses a testar

1. O ImageStream não tem `lookupPolicy.local` ligado.
2. A tag `v1` não existe.
3. O registry de origem está inacessível.

## Investigação orientada

- `oc set image-lookup -n ac10-imagens`
- `oc get istag ac10-web:v1 -n ac10-imagens`
- `oc describe pod -n ac10-imagens -l app=ac10-curto | sed -n '/Events:/,$p'`

## Critério de resolução

Você mostra que o nome chegou ao runtime sem ser resolvido e corrige com o mínimo de mudança.

## Limpeza

```bash
oc delete deployment ac10-curto -n ac10-imagens --ignore-not-found
oc set image-lookup ac10-web -n ac10-imagens
```
