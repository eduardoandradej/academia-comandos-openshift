# TS-048 — O binding para o grupo existe, mas o acesso não

- **Trilha:** [15 — Usuários, identidade e RBAC](../../trilhas/15-rbac/README.md)
- **Nível:** Intermediário
- **Perfil:** admin
- **Impacto da reprodução:** MUTAÇÃO DE CLUSTER (grupo de treino rotulado) · MUTAÇÃO LOCAL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A equipe pediu acesso `edit` ao projeto `ac15-alheio` para o grupo da equipe. O binding foi criado, `developer` está
no grupo, mas continua recebendo Forbidden.

## Contexto

Perfil `admin`. Projeto `ac15-alheio` e grupo `ac15-equipe` (RBC-007).

## Como reproduzir com segurança

```bash
source scripts/perfis.sh && ac-admin
oc get group ac15-equipe -o name || { oc adm groups new ac15-equipe; oc label group ac15-equipe academy.openshift.dev/managed-by=academia academy.openshift.dev/trilha=15; }
oc adm groups add-users ac15-equipe developer
oc policy add-role-to-group edit ac15-equipes -n ac15-alheio
oc auth can-i create deployments -n ac15-alheio --as=developer
```

## Hipóteses a testar

1. O binding cita um grupo com nome diferente (`ac15-equipes`).
2. O usuário não está no grupo.
3. O binding foi criado em outro projeto.

## Investigação orientada

- `oc get rolebindings -n ac15-alheio -o json | jq -r '.items[] | "\(.roleRef.name) <- \([.subjects[]? | "\(.kind):\(.name)"] | join(","))"'`
- `oc get group ac15-equipe -o jsonpath='{.users}{"\n"}'`
- `oc get group ac15-equipes 2>&1`

## Critério de resolução

Você encontra a diferença entre o nome no binding e o grupo real e corrige sem deixar binding órfão.

## Limpeza

```bash
oc adm groups remove-users ac15-equipe developer
ac-dev
```
