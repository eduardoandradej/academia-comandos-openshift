# TS-062 — Depois da migração, o Deployment tem 0 pods e nenhum evento no pod

- **Trilha:** [20 — Desafios integradores](../../trilhas/20-desafios/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A loja foi recriada em outro projeto a partir dos manifestos exportados. O Deployment existe, mas fica `0/1` e
`oc get pods` não mostra nada — nem pod com erro.

## Contexto

Projeto `ac20-cenarios`.

## Como reproduzir com segurança

```bash
oc new-project ac20-cenarios >/dev/null 2>&1 || true
oc create deployment ac20-ts062 --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac20-cenarios --dry-run=client -o json \
  | jq '.spec.template.spec.serviceAccountName="loja" | .metadata.labels["academy.openshift.dev/managed-by"]="academia"' \
  | oc apply -n ac20-cenarios -f -
sleep 10; oc get deployment,pods -n ac20-cenarios -l app=ac20-ts062
```

## Hipóteses a testar

1. O ReplicaSet não consegue criar pods: falta a ServiceAccount `loja` no projeto novo.
2. A quota do projeto está esgotada.
3. O agendador não encontra nó.

## Investigação orientada

- `oc get rs -n ac20-cenarios -l app=ac20-ts062`
- `oc describe rs -n ac20-cenarios -l app=ac20-ts062 | sed -n '/Events/,$p'`
- `oc get deployment ac20-ts062 -n ac20-cenarios -o jsonpath='{.status.conditions[?(@.type=="ReplicaFailure")].message}{"\n"}'`

## Critério de resolução

Você encontra o evento `FailedCreate` no ReplicaSet e explica por que não há pod para descrever.

## Limpeza

```bash
oc delete deployment ac20-ts062 -n ac20-cenarios --ignore-not-found
oc delete sa loja -n ac20-cenarios --ignore-not-found
```
