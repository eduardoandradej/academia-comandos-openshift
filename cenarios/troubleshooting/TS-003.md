# TS-003 — Forbidden ao rotular o próprio projeto

- **Trilha:** [00 — Orientação e segurança](../../trilhas/00-orientacao/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** LEITURA (a requisição é negada; nada é gravado)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

```text
Error from server (Forbidden): namespaces "ac00-orientacao" is forbidden: User "developer" cannot patch resource "namespaces" ...
```

"Mas o projeto é meu!"

## Contexto

O projeto foi criado por `oc new-project` como developer (ORI-011).

## Como reproduzir com segurança

```bash
oc label namespace ac00-orientacao academy.openshift.dev/managed-by=academia
```

## Hipóteses a testar

1. O papel `admin` do projeto não cobre o objeto Namespace (escopo de cluster).
2. O projeto pertence a outro usuário.
3. Há uma política especial bloqueando rótulos.

## Investigação orientada

- `oc get project ac00-orientacao -o jsonpath='{.metadata.annotations.openshift\.io/requester}{"\n"}'`
- `oc auth can-i patch namespaces/ac00-orientacao`
- `oc auth can-i create configmaps -n ac00-orientacao`

## Critério de resolução

Você explica por que a mesma identidade pode criar ConfigMaps no projeto, mas não alterar o Namespace, e quem pode.

## Limpeza

Nada é criado.
