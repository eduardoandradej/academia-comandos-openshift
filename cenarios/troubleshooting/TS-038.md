# TS-038 — O apply desfaz a escala (e briga com o HPA)

- **Trilha:** [12 — Manifestos declarativos](../../trilhas/12-declarativo/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O `ac12-web` foi escalado para 2 réplicas (por `oc scale` ou por um HPA). A cada execução do pipeline, que roda
`oc apply -f app.yaml`, ele volta a 1 réplica — e o HPA sobe de novo minutos depois.

## Contexto

Projeto `ac12-declarativo` com a aplicação do DCL-003.

## Como reproduzir com segurança

```bash
oc scale deployment/ac12-web --replicas=2 -n ac12-declarativo
oc apply -f /tmp/ac12/app.yaml -n ac12-declarativo
oc get deployment ac12-web -n ac12-declarativo -o jsonpath='{.spec.replicas}{"\n"}'
```

## Hipóteses a testar

1. `replicas` está declarado no manifesto e o apply o reimpõe.
2. O HPA tem `maxReplicas: 1`.
3. Um `oc rollout undo` está sendo executado.

## Investigação orientada

- `grep -n replicas /tmp/ac12/app.yaml`
- `oc apply view-last-applied deployment/ac12-web -n ac12-declarativo | grep replicas`
- `oc rollout history deployment/ac12-web -n ac12-declarativo` (réplicas não geram revisão)

## Critério de resolução

Você tira `replicas` do controle do manifesto sem causar uma queda para 1 réplica no primeiro apply.

## Limpeza

```bash
cp manifests/apps-exemplo/declarativo-app.yaml /tmp/ac12/app.yaml
oc apply -f /tmp/ac12/app.yaml -n ac12-declarativo
```
