# TS-019 — Service com endpoints, mas conexão recusada

- **Trilha:** [06 — Services e DNS](../../trilhas/06-servicos/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 Service)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O Service `loja-errada` tem seletor correto e a EndpointSlice lista o pod azul como pronto, mas o cliente recebe
`Connection refused`.

## Contexto

Projeto `ac06-servicos` com os backends e o pod cliente do SVC-001.

## Como reproduzir com segurança

```bash
oc create service clusterip loja-errada --tcp=8080:8081 -n ac06-servicos
oc set selector svc/loja-errada app=loja,cor=azul -n ac06-servicos
oc exec ac06-cliente -n ac06-servicos -- bash -c 'timeout 3 bash -c "</dev/tcp/loja-errada/8080"' || echo "recusada"
```

## Hipóteses a testar

1. `targetPort` diferente da porta em que o contêiner escuta.
2. Pod não pronto.
3. NetworkPolicy bloqueando.

## Investigação orientada

- `oc get svc loja-errada -n ac06-servicos -o jsonpath='{.spec.ports[0].port}->{.spec.ports[0].targetPort}{"\n"}'`
- `oc get pods -n ac06-servicos -l cor=azul -o jsonpath='{.items[0].spec.containers[0].ports}{"\n"}'`
- `oc get endpointslices -n ac06-servicos -l kubernetes.io/service-name=loja-errada -o yaml | grep -A4 -E 'ports|conditions'`
- `oc get networkpolicy -n ac06-servicos`

## Critério de resolução

Você aponta o campo errado, corrige-o sem recriar o Service e mostra a resposta `azul`.

## Limpeza

```bash
oc delete svc loja-errada -n ac06-servicos
```
