# TS-046 — Lê os pods, mas não os logs

- **Trilha:** [15 — Usuários, identidade e RBAC](../../trilhas/15-rbac/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (Role e binding de teste)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A SA de monitoramento `ac15-robo` lista os pods do projeto sem problema, mas `oc logs` falha com Forbidden.
"Ela tem permissão de pods!"

## Contexto

Projeto `ac15-rbac` (Trilha 15), com a SA `ac15-robo`.

## Como reproduzir com segurança

```bash
oc create role ac15-so-pods --verb=get,list,watch --resource=pods -n ac15-rbac
oc create rolebinding ac15-ts046 --role=ac15-so-pods --serviceaccount=ac15-rbac:ac15-robo -n ac15-rbac
oc run ac15-alvo --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac15-rbac
S=system:serviceaccount:ac15-rbac:ac15-robo
oc get pods -n ac15-rbac --as=$S
oc logs ac15-alvo -n ac15-rbac --as=$S
```

## Hipóteses a testar

1. `pods/log` é um subrecurso separado e não está na Role.
2. O pod não existe.
3. O binding está em outro projeto.

## Investigação orientada

- a mensagem: `cannot get resource "pods/log"`
- `oc describe role ac15-so-pods -n ac15-rbac`
- `oc auth can-i get pods/log -n ac15-rbac --as=$S`

## Critério de resolução

Você acrescenta só o subrecurso necessário, sem dar `view` inteiro.

## Limpeza

```bash
oc delete rolebinding ac15-ts046 -n ac15-rbac --ignore-not-found
oc delete role ac15-so-pods -n ac15-rbac --ignore-not-found
oc delete pod ac15-alvo -n ac15-rbac --ignore-not-found
```
