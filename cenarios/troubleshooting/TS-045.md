# TS-045 — --reuse-values: o padrão novo do chart que não chegou

- **Trilha:** [14 — Helm](../../trilhas/14-helm/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A versão nova do chart mudou o padrão de `pagina.conteudo` em `values.yaml`. O pipeline rodou
`helm upgrade loja <chart novo> --reuse-values`, a revisão subiu, mas a página continua com o texto antigo.

## Contexto

Projeto `ac14-helm` com a release `loja`; cópia do chart em `/tmp/ac14/ac14-loja`.

## Como reproduzir com segurança

```bash
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --set replicaCount=1
sed -i 's/conteudo: "loja da academia (helm)"/conteudo: "loja da academia (chart 0.2.0)"/' /tmp/ac14/ac14-loja/values.yaml
sed -i 's/^version: 0.1.0/version: 0.2.0/' /tmp/ac14/ac14-loja/Chart.yaml
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm --reuse-values
helm get values loja -n ac14-helm --all | grep -A1 '^pagina:'
```

## Hipóteses a testar

1. `--reuse-values` reaproveitou **todos** os valores calculados da revisão anterior, inclusive os padrões antigos.
2. O ConfigMap não foi atualizado por falta de rollout.
3. O chart novo não foi usado.

## Investigação orientada

- `helm list -n ac14-helm` (coluna CHART: 0.2.0?)
- `helm get values loja -n ac14-helm --all --revision <anterior>` × atual
- `helm show values /tmp/ac14/ac14-loja | grep conteudo`

## Critério de resolução

Você mostra que o chart novo foi usado e que o valor veio da revisão anterior, e faz o upgrade correto.

## Limpeza

```bash
rm -rf /tmp/ac14/ac14-loja && cp -r manifests/helm/ac14-loja /tmp/ac14/
helm upgrade loja /tmp/ac14/ac14-loja -n ac14-helm
```
