# TS-020 — O nome do Service não resolve em outro projeto

- **Trilha:** [06 — Services e DNS](../../trilhas/06-servicos/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (projeto rascunho com 1 pod)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Uma aplicação no projeto `ac06-consumidor` não encontra `web-azul`: `getent hosts web-azul` não devolve nada.
De dentro de `ac06-servicos`, o mesmo nome funciona.

## Contexto

Dois projetos de laboratório: `ac06-servicos` (backends) e `ac06-consumidor` (cliente).

## Como reproduzir com segurança

```bash
oc new-project ac06-consumidor --skip-config-write
oc run consumidor --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac06-consumidor --command -- sleep 900
oc wait --for=condition=Ready pod/consumidor -n ac06-consumidor --timeout=120s
oc exec consumidor -n ac06-consumidor -- getent hosts web-azul || echo "não resolve"
```

## Hipóteses a testar

1. Nome curto usado fora do namespace do Service.
2. DNS do cluster indisponível.
3. Isolamento de rede entre projetos.

## Investigação orientada

- `oc exec consumidor -n ac06-consumidor -- grep search /etc/resolv.conf`
- `oc exec consumidor -n ac06-consumidor -- getent hosts kubernetes.default.svc.cluster.local` (o DNS funciona?)
- `oc exec consumidor -n ac06-consumidor -- getent hosts web-azul.ac06-servicos`

## Critério de resolução

Você mostra o nome que funciona de qualquer projeto e explica por que o curto falhou.

## Limpeza

```bash
oc delete project ac06-consumidor
```
