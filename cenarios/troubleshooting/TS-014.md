# TS-014 — Pending para sempre: nenhum nó serve

- **Trilha:** [04 — Pods e contêineres](../../trilhas/04-pods/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 pod que nunca é agendado; não consome recursos)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O pod `ac04-pendente` está em `Pending` há minutos. Não há `ContainerCreating` nem erro de imagem.

## Contexto

Projeto `ac04-pods`, nó único `ocp-sno`.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-pending-nodeselector.yaml -n ac04-pods
oc get pod ac04-pendente -n ac04-pods -o wide
```

## Hipóteses a testar

1. Restrição de agendamento (nodeSelector/afinidade) sem nó compatível.
2. Recursos insuficientes (requests maiores que o disponível).
3. Quota do projeto esgotada.

## Investigação orientada

- `oc describe pod ac04-pendente -n ac04-pods | sed -n '/Events:/,$p'` (procure `FailedScheduling`)
- `oc get pod ac04-pendente -n ac04-pods -o jsonpath='{.spec.nodeSelector}{"\n"}{.spec.containers[0].resources.requests}{"\n"}'`
- (admin) `oc get node ocp-sno.ocp.example.lab --show-labels | tr ',' '\n' | grep academy || echo "nó sem esse rótulo"`

## Critério de resolução

Você explica a mensagem do `FailedScheduling` e por que a quota não é a causa.

## Limpeza

```bash
oc delete pod -l academy.openshift.dev/cenario=ts-014 -n ac04-pods
```
