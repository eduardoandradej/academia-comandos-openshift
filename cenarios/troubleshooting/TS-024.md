# TS-024 — O hostname da Route não resolve em lugar nenhum

- **Trilha:** [07 — Routes e Ingress](../../trilhas/07-rotas/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 Route)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A Route `vitrine` foi criada com `--hostname=vitrine.ocp.example.lab`. Ela está admitida, mas
`curl http://vitrine.ocp.example.lab/` falha com `Could not resolve host`.

## Contexto

Projeto `ac07-rotas`. O DNS do HomeLab tem curinga só para `*.apps.ocp.example.lab`.

## Como reproduzir com segurança

```bash
oc expose svc/web-azul --name=vitrine --hostname=vitrine.ocp.example.lab -n ac07-rotas
curl -sS http://vitrine.ocp.example.lab/ || true
```

## Hipóteses a testar

1. O hostname está fora do curinga `*.apps.ocp.example.lab`.
2. A Route não foi admitida.
3. O router está fora do ar.

## Investigação orientada

- `getent ahostsv4 vitrine.ocp.example.lab` × `getent ahostsv4 vitrine.apps.ocp.example.lab`
- `oc get route vitrine -n ac07-rotas -o jsonpath='{.status.ingress[0].conditions[0].status}{"\n"}'`
- `curl -sS -H 'Host: vitrine.ocp.example.lab' http://192.168.10.200/`

## Critério de resolução

Você prova que a Route funciona (teste com `Host`) e que o problema é só de resolução de nome, e propõe duas correções.

## Limpeza

```bash
oc delete route vitrine vitrine2 -n ac07-rotas --ignore-not-found
```
