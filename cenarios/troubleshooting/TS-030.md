# TS-030 — Pod Evicted: o disco também tem limite

- **Trilha:** [09 — Storage](../../trilhas/09-storage/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (grava 32 MiB)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Um pod de processamento termina com `STATUS Evicted` (ou `Error`/`ContainerStatusUnknown`) poucos segundos depois de
iniciar. Não há OOMKilled nem erro nos logs.

## Contexto

Projeto `ac09-storage`. Manifesto `manifests/apps-exemplo/cenario-evicted-efemero.yaml`.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-evicted-efemero.yaml -n ac09-storage
sleep 60; oc get pod ac09-guloso -n ac09-storage
```

## Hipóteses a testar

1. O contêiner passou do `limits.ephemeral-storage`.
2. Pressão de disco no nó (despejo por `DiskPressure`).
3. Falta de memória.

## Investigação orientada

- `oc get pod ac09-guloso -n ac09-storage -o jsonpath='{.status.reason}: {.status.message}{"\n"}'`
- `oc get pod ac09-guloso -n ac09-storage -o jsonpath='{.spec.containers[0].resources}{"\n"}'`
- (admin, leitura) `oc get node -o jsonpath='{.items[0].status.conditions[?(@.type=="DiskPressure")].status}{"\n"}'`

## Critério de resolução

Você distingue despejo por limite do pod de despejo por pressão no nó, com base na mensagem.

## Limpeza

```bash
oc delete -f manifests/apps-exemplo/cenario-evicted-efemero.yaml -n ac09-storage --ignore-not-found
```
