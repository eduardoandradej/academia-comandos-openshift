# TS-029 — Os dados sumiram depois do deploy

- **Trilha:** [09 — Storage](../../trilhas/09-storage/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A equipe gravou arquivos de upload em `/uploads` do `ac09-app`. Depois de um `oc set env` qualquer, os arquivos
desapareceram. "Mas o volume está declarado no Deployment!"

## Contexto

Projeto `ac09-storage` com o `ac09-app` (STO-003). Não exige preparação.

## Como reproduzir com segurança

```bash
oc set volume deployment/ac09-app --add --name=uploads --type=emptyDir --mount-path=/uploads -n ac09-storage
oc rollout status deployment/ac09-app -n ac09-storage
oc exec deploy/ac09-app -n ac09-storage -- sh -c 'echo foto > /uploads/foto.txt; ls /uploads'
oc set env deployment/ac09-app VERSAO=2 -n ac09-storage && oc rollout status deployment/ac09-app -n ac09-storage
oc exec deploy/ac09-app -n ac09-storage -- ls /uploads
```

## Hipóteses a testar

1. O volume é `emptyDir`: morre com o pod, e a mudança de template criou pods novos.
2. O caminho de montagem mudou.
3. Alguém apagou os arquivos.

## Investigação orientada

- `oc get deployment ac09-app -n ac09-storage -o json | jq '.spec.template.spec.volumes[] | select(.name=="uploads")'`
- `oc rollout history deployment/ac09-app -n ac09-storage`
- idade e nome dos pods antes e depois (`oc get pods -l app=ac09-app`)

## Critério de resolução

Você mostra o tipo do volume, liga a perda ao rollout e propõe o armazenamento correto.

## Limpeza

```bash
oc set volume deployment/ac09-app --remove --name=uploads -n ac09-storage
oc set env deployment/ac09-app VERSAO- -n ac09-storage
```
