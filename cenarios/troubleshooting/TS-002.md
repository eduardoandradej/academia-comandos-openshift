# TS-002 — A API "sumiu": no such host, refused ou timeout?

- **Trilha:** [00 — Orientação e segurança](../../trilhas/00-orientacao/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** LEITURA
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

`oc get pods` responde com uma destas mensagens:

- `dial tcp: lookup api.ocp.example.lab: no such host`
- `dial tcp 192.168.10.200:6443: connect: connection refused`
- `dial tcp 192.168.10.200:6443: i/o timeout`

## Contexto

As três mensagens parecem iguais para quem tem pressa, mas apontam camadas diferentes.

## Como reproduzir com segurança

```bash
oc --server=https://api.ocp.example.lab.invalid:6443 whoami          # DNS
oc --server=https://api.ocp.example.lab:6444 whoami --request-timeout=5s   # porta sem serviço
oc --server=https://192.0.2.10:6443 whoami --request-timeout=5s      # IP de documentação, sem rota/resposta
```

Os três comandos só afetam aquela execução (`--server` não é gravado).

## Hipóteses a testar

1. Resolução de nome.
2. Host alcançável, mas sem serviço na porta (API reiniciando).
3. Host ou rota indisponível (VM desligada, rede).

## Investigação orientada

- `getent ahostsv4 api.ocp.example.lab`
- `timeout 3 bash -c '</dev/tcp/api.ocp.example.lab/6443' && echo aberta`
- `curl -ksS https://api.ocp.example.lab:6443/readyz`
- Com autorização, no `kvm-server`: `virsh domstate ocp-sno` (leitura).

## Critério de resolução

Para cada mensagem, você nomeia a camada e o primeiro comando de confirmação.

## Limpeza
