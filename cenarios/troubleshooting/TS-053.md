# TS-053 — Projeto novo e vazio, mas sem cota: a ClusterResourceQuota compartilhada

- **Trilha:** [17 — Administração de recursos](../../trilhas/17-admin/README.md)
- **Nível:** Intermediário
- **Perfil:** admin
- **Impacto da reprodução:** MUTAÇÃO DE CLUSTER (CRQ rotulada) · MUTAÇÃO LOCAL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A equipe criou o projeto `ac17-equipe-c` hoje. O primeiro pod já é recusado com `exceeded quota: ac17-equipe`, embora
`oc get resourcequota -n ac17-equipe-c` não mostre nenhuma quota.

## Contexto

Perfil `admin`. ClusterResourceQuota `ac17-equipe` (ADM-007) e projetos da equipe com pods rodando.

## Como reproduzir com segurança

```bash
source scripts/perfis.sh && ac-admin
oc apply -f manifests/admin/clusterresourcequota-ac17.yaml
oc new-project ac17-equipe-c --skip-config-write >/dev/null
oc label namespace ac17-equipe-c academy.openshift.dev/equipe=ac17 academy.openshift.dev/managed-by=academia
oc apply -f manifests/admin/limitrange-completo.yaml -n ac17-equipe-c
oc get clusterresourcequota ac17-equipe -o jsonpath='{.status.total.used.pods}/{.status.total.hard.pods}{"\n"}'
oc run y --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac17-equipe-c
```

## Hipóteses a testar

1. A cota é de **cluster** e compartilhada; outros projetos da equipe já a consumiram.
2. Existe uma ResourceQuota escondida no projeto.
3. O LimitRange recusou o pod.

## Investigação orientada

- `oc get resourcequota -n ac17-equipe-c` (vazio)
- `oc describe appliedclusterresourcequota -n ac17-equipe-c`
- `oc describe clusterresourcequota ac17-equipe` (uso por namespace)

## Critério de resolução

Você mostra de onde vem a recusa e qual projeto consumiu a cota.

## Limpeza

```bash
oc delete project ac17-equipe-c --ignore-not-found
ac-dev
```
