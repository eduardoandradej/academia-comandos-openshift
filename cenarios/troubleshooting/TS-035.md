# TS-035 — HPA com TARGETS `<unknown>`

- **Trilha:** [11 — Resiliência](../../trilhas/11-resiliencia/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 Deployment + 1 HPA)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O HPA `ac11-sem-req` foi criado com `--cpu-percent=50`, mas `oc get hpa` mostra `TARGETS <unknown>/50%` há vários
minutos e nunca escala.

## Contexto

Projeto `ac11-resiliencia`. Depende da Metrics API para a correção ser visível.

## Como reproduzir com segurança

```bash
oc create deployment ac11-sem-req --image=registry.access.redhat.com/ubi9/httpd-24:latest -n ac11-resiliencia
oc patch deployment ac11-sem-req -n ac11-resiliencia --type=json -p '[{"op":"add","path":"/spec/template/spec/containers/0/resources","value":{"limits":{"cpu":"100m","memory":"128Mi"},"requests":{"cpu":"0","memory":"64Mi"}}}]' 2>/dev/null || true
oc autoscale deployment/ac11-sem-req --min=1 --max=2 --cpu-percent=50 -n ac11-resiliencia
sleep 60; oc get hpa ac11-sem-req -n ac11-resiliencia
```

## Hipóteses a testar

1. O contêiner não tem `requests.cpu` (ou tem 0): não há base para a porcentagem.
2. A Metrics API está indisponível.
3. O HPA aponta para o Deployment errado.

## Investigação orientada

- `oc describe hpa ac11-sem-req -n ac11-resiliencia | sed -n '/Conditions:/,$p'`
- `oc get deployment ac11-sem-req -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].resources}{"\n"}'`
- `oc adm top pods -n ac11-resiliencia`

## Critério de resolução

Você separa "sem métricas" de "sem request" com base na mensagem e corrige.

## Limpeza

```bash
oc delete hpa ac11-sem-req -n ac11-resiliencia --ignore-not-found
oc delete deployment ac11-sem-req -n ac11-resiliencia --ignore-not-found
```
