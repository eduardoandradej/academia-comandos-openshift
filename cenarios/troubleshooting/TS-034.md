# TS-034 — Reinícios em série: a liveness que mata o que está saudável

- **Trilha:** [11 — Resiliência](../../trilhas/11-resiliencia/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 Deployment)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O `ac11-agressivo` reinicia a cada poucos segundos. Os logs do httpd não mostram erro nenhum, e um `oc exec` logo
após o início mostra a aplicação respondendo normalmente.

## Contexto

Projeto `ac11-resiliencia`. Manifesto `manifests/apps-exemplo/cenario-liveness-agressiva.yaml`.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-liveness-agressiva.yaml -n ac11-resiliencia
sleep 60; oc get pods -n ac11-resiliencia -l app=ac11-agressivo
```

## Hipóteses a testar

1. A liveness tem `timeoutSeconds` menor que o tempo do próprio comando.
2. A aplicação trava de verdade.
3. Falta memória (OOMKilled).

## Investigação orientada

- `oc get events -n ac11-resiliencia --field-selector reason=Unhealthy --sort-by=.lastTimestamp | tail -3`
- `oc get pods -n ac11-resiliencia -l app=ac11-agressivo -o jsonpath='{.items[0].status.containerStatuses[0].lastState.terminated}{"\n"}'`
- `oc get deployment ac11-agressivo -n ac11-resiliencia -o jsonpath='{.spec.template.spec.containers[0].livenessProbe}{"\n"}'`

## Critério de resolução

Você mostra que a probe falha por tempo e não por defeito da aplicação, e corrige sem desligar a liveness.

## Limpeza

```bash
oc delete -f manifests/apps-exemplo/cenario-liveness-agressiva.yaml -n ac11-resiliencia --ignore-not-found
```
