# TS-010 — Service sem endpoints: o seletor que não casa

- **Trilha:** [03 — Projetos e metadados](../../trilhas/03-projetos/README.md)
- **Nível:** Iniciante
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (um Service sem pods)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O Service `obs-errado` existe, tem ClusterIP e porta, mas qualquer acesso falha e `oc describe svc` mostra
`Endpoints: <none>`. Os pods do `obs-web` estão `Running`.

## Contexto

Projeto `ac03-projetos`, com o alvo `obs-web` implantado (PRJ-008).

## Como reproduzir com segurança

```bash
oc create service clusterip obs-errado --tcp=8080:8080 --dry-run=client -o yaml \
  | oc label --local -f - academy.openshift.dev/managed-by=academia -o yaml | oc apply -n ac03-projetos -f -
oc describe svc obs-errado -n ac03-projetos | grep -E 'Selector|Endpoints'
```

## Hipóteses a testar

1. Seletor do Service não casa com os rótulos dos pods.
2. Pods não estão prontos (readiness).
3. `targetPort` errado.

## Investigação orientada

- `oc get svc obs-errado -n ac03-projetos -o jsonpath='{.spec.selector}{"\n"}'`
- `oc get pods -n ac03-projetos --show-labels`
- `oc get pods -n ac03-projetos -l "<seletor do Service>"`
- `oc get endpointslices -n ac03-projetos -l kubernetes.io/service-name=obs-errado -o yaml | grep -A3 endpoints`

## Critério de resolução

O Service passa a ter 2 endpoints, e você explica por que a hipótese 3 não produziria `Endpoints: <none>`.

## Limpeza

```bash
oc delete svc obs-errado -n ac03-projetos
```
