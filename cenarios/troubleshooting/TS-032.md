# TS-032 — Mudei a tag e a aplicação continua na versão antiga

- **Trilha:** [10 — Imagens e registries](../../trilhas/10-imagens/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A equipe moveu `ac10-web:prod` para a imagem nova (`v2`). O ImageStream mostra o digest novo, mas os pods do
`ac10-app` continuam rodando a versão anterior — e até pods recriados mostram o digest antigo.

## Contexto

Projeto `ac10-imagens` com `ac10-app` e gatilho do IMG-008.

## Como reproduzir com segurança

```bash
oc set triggers deployment/ac10-app --from-image=ac10-web:prod --containers=nome-errado -n ac10-imagens 2>&1 | tail -1
oc set triggers deployment/ac10-app --manual --from-image=ac10-web:prod --containers="$(oc get deploy ac10-app -n ac10-imagens -o jsonpath='{.spec.template.spec.containers[0].name}')" -n ac10-imagens
oc tag ac10-web:v2 ac10-web:prod -n ac10-imagens
sleep 15; oc rollout history deployment/ac10-app -n ac10-imagens | tail -2
```

## Hipóteses a testar

1. O gatilho está pausado (`--manual`) ou ausente.
2. O gatilho aponta para um contêiner com nome errado.
3. O template usa digest fixo e nada o atualiza; pods recriados usam o mesmo digest.

## Investigação orientada

- `oc set triggers deployment/ac10-app -n ac10-imagens`
- `oc get deployment ac10-app -n ac10-imagens -o jsonpath='{.metadata.annotations.image\.openshift\.io/triggers}{"\n"}'`
- `oc get deployment ac10-app -n ac10-imagens -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'`

## Critério de resolução

Você explica por que até pods recriados ficaram na versão antiga e reativa a atualização automática.

## Limpeza

```bash
oc tag ac10-web:v1 ac10-web:prod -n ac10-imagens
```
