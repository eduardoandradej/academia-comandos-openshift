# TS-015 — OOMKilled: estourou o limite de memória

- **Trilha:** [04 — Pods e contêineres](../../trilhas/04-pods/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 pod limitado a 48 Mi)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O pod `ac04-oom` terminou com `STATUS OOMKilled` (ou `Error`) segundos depois de iniciar.

## Contexto

Projeto `ac04-pods`. O processo acumula memória até o limite declarado de 48 Mi; nunca passa disso.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-oomkilled.yaml -n ac04-pods
oc get pod ac04-oom -n ac04-pods -w      # Ctrl+C após ver OOMKilled
```

## Hipóteses a testar

1. O contêiner excedeu o seu `limits.memory`.
2. O nó está sem memória e despejou o pod (Evicted).
3. A aplicação falhou por outro motivo e saiu com erro.

## Investigação orientada

- `oc get pod ac04-oom -n ac04-pods -o jsonpath='{.status.containerStatuses[0].state.terminated.reason} {.status.containerStatuses[0].state.terminated.exitCode}{"\n"}'`
- `oc get pod ac04-oom -n ac04-pods -o jsonpath='{.spec.containers[0].resources}{"\n"}'`
- `oc get pod ac04-oom -n ac04-pods -o jsonpath='{.status.reason}{"\n"}'` (Evicted apareceria aqui)
- (admin) `oc adm top nodes`

## Critério de resolução

Você distingue OOMKilled de Evicted pelos campos do status e explica o código de saída.

## Limpeza

```bash
oc delete pod -l academy.openshift.dev/cenario=ts-015 -n ac04-pods
```
