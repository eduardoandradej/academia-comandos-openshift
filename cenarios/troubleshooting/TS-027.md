# TS-027 — Senha certa, autenticação errada: o Secret com bytes a mais

- **Trilha:** [08 — ConfigMaps e Secrets](../../trilhas/08-config/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (Secret fictício)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A aplicação recusa a senha guardada no Secret `ac08-credencial`, embora "a senha esteja certa". Quem criou o Secret
diz que usou `echo` e `base64`.

## Contexto

Projeto `ac08-config`. Valor fictício `senha-de-treino` (15 bytes).

## Como reproduzir com segurança

```bash
oc create secret generic ac08-credencial --from-file=senha=<(echo senha-de-treino) -n ac08-config
oc label secret ac08-credencial academy.openshift.dev/managed-by=academia -n ac08-config
oc describe secret ac08-credencial -n ac08-config | grep senha
```

## Hipóteses a testar

1. Quebra de linha final no valor (`echo` sem `-n`).
2. Valor codificado em base64 duas vezes.
3. Chave com nome diferente do esperado pela aplicação.

## Investigação orientada

- `oc describe secret` mostra o tamanho em bytes: compare com `printf '%s' senha-de-treino | wc -c`
- `oc get secret ac08-credencial -n ac08-config -o jsonpath='{.data.senha}' | base64 -d | od -c | tail -2` (só com dado fictício)
- `oc get secret ac08-credencial -n ac08-config -o json | jq -r '.data | keys[]'`

## Critério de resolução

Você identifica o byte extra sem exibir o valor em texto e recria o Secret com o tamanho exato.

## Limpeza

```bash
oc delete secret ac08-credencial -n ac08-config --ignore-not-found
```
