# TS-061 — HTTPS responde, HTTP diz "Application is not available"

- **Trilha:** [20 — Desafios integradores](../../trilhas/20-desafios/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

A loja nova abre por `https://`, mas quem digita o endereço sem `https` recebe a página "Application is not
available" do router. A aplicação está saudável.

## Contexto

Projeto `ac20-cenarios`.

## Como reproduzir com segurança

```bash
oc new-project ac20-cenarios >/dev/null 2>&1 || true
oc create deployment ac20-ts061 --image=registry.access.redhat.com/ubi9/httpd-24:latest --port=8080 -n ac20-cenarios
oc expose deployment ac20-ts061 --port=8080 -n ac20-cenarios
oc create route edge ac20-ts061 --service=ac20-ts061 -n ac20-cenarios
oc label deployment,service,route ac20-ts061 academy.openshift.dev/managed-by=academia -n ac20-cenarios
H=$(oc get route ac20-ts061 -n ac20-cenarios -o jsonpath='{.spec.host}')
curl -sk -o /dev/null -w 'https %{http_code}\n' "https://$H/"; curl -s -o /dev/null -w 'http %{http_code}\n' "http://$H/"
```

## Hipóteses a testar

1. A Route edge não aceita HTTP: `insecureEdgeTerminationPolicy` vazio equivale a `None`.
2. O DNS do curinga resolve diferente para HTTP.
3. Uma NetworkPolicy bloqueia só a porta 80.

## Investigação orientada

- `oc get route ac20-ts061 -n ac20-cenarios -o jsonpath='{.spec.tls}{"\n"}'`
- `curl -sv "http://$H/" 2>&1 | grep -E '^< HTTP|Connected'` (conectou no router? então não é DNS)
- `oc explain route.spec.tls.insecureEdgeTerminationPolicy`

## Critério de resolução

Você explica a resposta 503 do HTTP e escolhe entre `Redirect` e `Allow`.

## Limpeza

```bash
oc delete route,service,deployment ac20-ts061 -n ac20-cenarios --ignore-not-found
```
