# TS-036 — Evicção recusada: o PDB que trava a manutenção

- **Trilha:** [11 — Resiliência](../../trilhas/11-resiliencia/README.md)
- **Nível:** Avançado
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (PDB + tentativa de evicção)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O time de plataforma relata que a manutenção "travou" esperando um pod do projeto `ac11-resiliencia`. A ferramenta
repete `Cannot evict pod as it would violate the pod's disruption budget`.

## Contexto

Projeto `ac11-resiliencia` com `ac11-app` em 1 réplica. A evicção é feita pela API, pod a pod — **nunca** com drain do nó.

## Como reproduzir com segurança

```bash
oc create poddisruptionbudget ac11-trava --selector=app=ac11-app --min-available=1 -n ac11-resiliencia
P=$(oc get pod -n ac11-resiliencia -l app=ac11-app -o jsonpath='{.items[0].metadata.name}')
printf '{"apiVersion":"policy/v1","kind":"Eviction","metadata":{"name":"%s","namespace":"ac11-resiliencia"}}' "$P" > /tmp/ac11-evict.json
oc create --raw "/api/v1/namespaces/ac11-resiliencia/pods/$P/eviction" -f /tmp/ac11-evict.json
```

## Hipóteses a testar

1. `minAvailable` igual ao número de réplicas: nenhuma interrupção permitida.
2. O pod não está pronto, então o PDB já está "devendo".
3. Dois PDBs selecionam o mesmo pod.

## Investigação orientada

- `oc get pdb -n ac11-resiliencia` (`ALLOWED DISRUPTIONS`)
- `oc get pdb -n ac11-resiliencia -o json | jq '.items[] | {name: .metadata.name, selector: .spec.selector, expected: .status.expectedPods, healthy: .status.currentHealthy}'`
- `oc get deployment ac11-app -n ac11-resiliencia -o jsonpath='{.spec.replicas} {.status.readyReplicas}{"\n"}'`

## Critério de resolução

Você mostra por que a evicção é recusada e propõe duas correções, explicando qual protege melhor a aplicação.

## Limpeza

```bash
oc delete pdb ac11-trava -n ac11-resiliencia --ignore-not-found
rm -f /tmp/ac11-evict.json
```
