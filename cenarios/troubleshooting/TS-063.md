# TS-063 — O Job de manutenção expira com DeadlineExceeded depois do isolamento de rede

- **Trilha:** [20 — Desafios integradores](../../trilhas/20-desafios/README.md)
- **Nível:** Avançado
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

Depois que o projeto recebeu as políticas "nega saída" e "permite DNS", o Job manual do relatório (que lê a página da
loja pelo Service) passou a falhar com `DeadlineExceeded`. A loja continua respondendo pela Route.

## Contexto

Projeto `ac20-cenarios`.

## Como reproduzir com segurança

```bash
oc new-project ac20-cenarios >/dev/null 2>&1 || true
N=ac20-cenarios
oc create deployment ac20-ts063 --image=registry.access.redhat.com/ubi9/httpd-24:latest --port=8080 -n $N
oc expose deployment ac20-ts063 --port=8080 -n $N
oc apply -f manifests/networkpolicies/40-negar-saida.yaml -f manifests/networkpolicies/50-permitir-dns.yaml -n $N
oc create job ac20-ts063-rel --image=registry.access.redhat.com/ubi9/httpd-24:latest -n $N --dry-run=client -o json \
  -- /bin/bash -c 'exec 3<>/dev/tcp/ac20-ts063/8080 && echo conectou' \
  | jq '.spec.activeDeadlineSeconds=30 | .spec.backoffLimit=0 | .metadata.labels["academy.openshift.dev/managed-by"]="academia"' \
  | oc apply -n $N -f -
oc label deployment,service ac20-ts063 academy.openshift.dev/managed-by=academia -n $N
sleep 40; oc get job ac20-ts063-rel -n $N
```

## Hipóteses a testar

1. A política de saída negada também seleciona o pod do Job: a conexão ao Service fica sem resposta até o prazo.
2. O Service `ac20-ts063` não tem endpoints.
3. O DNS foi bloqueado junto.

## Investigação orientada

- `oc get job ac20-ts063-rel -n ac20-cenarios -o jsonpath='{.status.conditions[*].reason}{"\n"}'`
- `oc get networkpolicy -n ac20-cenarios -o custom-columns=NOME:.metadata.name,SELETOR:.spec.podSelector,TIPOS:.spec.policyTypes`
- `oc get endpointslices -n ac20-cenarios -l kubernetes.io/service-name=ac20-ts063`

## Critério de resolução

Você mostra que a política de saída seleciona todos os pods (inclusive os de Jobs) e libera só o necessário.

## Limpeza

```bash
N=ac20-cenarios
oc delete job ac20-ts063-rel -n $N --ignore-not-found
oc delete deployment,service ac20-ts063 -n $N --ignore-not-found
oc delete networkpolicy -n $N -l academy.openshift.dev/managed-by=academia --ignore-not-found
oc delete project ac20-cenarios --ignore-not-found      # depois dos três cenários
```
