# TS-021 — Service sem tráfego: o pod roda, mas nunca fica pronto

- **Trilha:** [06 — Services e DNS](../../trilhas/06-servicos/README.md)
- **Nível:** Intermediário
- **Perfil:** developer
- **Impacto da reprodução:** MUTAÇÃO LOCAL REVERSÍVEL (1 pod e 1 Service)
- **Status:** proposto — ainda não reproduzido contra o cluster pelo autor

## Sintoma

O pod de `web-lento` está `Running` (0/1 em `READY`), e o Service `web-lento` não entrega nada: `Endpoints` aparece
vazio ou só com endereços não prontos.

## Contexto

Projeto `ac06-servicos`. O manifesto do cenário tem uma readiness probe HTTP em um caminho inexistente.

## Como reproduzir com segurança

```bash
oc apply -f manifests/apps-exemplo/cenario-nao-pronto.yaml -n ac06-servicos
oc get pods -n ac06-servicos -l app=lento
oc describe svc web-lento -n ac06-servicos | grep Endpoints
```

## Hipóteses a testar

1. Readiness probe falhando.
2. Seletor do Service errado.
3. Contêiner em CrashLoopBackOff.

## Investigação orientada

- `oc describe pod -n ac06-servicos -l app=lento | sed -n '/Readiness:/p;/Events:/,$p'`
- `oc get endpointslices -n ac06-servicos -l kubernetes.io/service-name=web-lento -o jsonpath='{range .items[*].endpoints[*]}{.addresses[0]} ready={.conditions.ready}{"\n"}{end}'`
- `oc get pods -n ac06-servicos -l app=lento -o jsonpath='{.items[0].status.containerStatuses[0].restartCount}{"\n"}'`

## Critério de resolução

Você mostra o evento de falha da probe, o endpoint `ready=false` e corrige a probe para o pod ficar pronto.

## Limpeza

```bash
oc delete -f manifests/apps-exemplo/cenario-nao-pronto.yaml -n ac06-servicos
```
